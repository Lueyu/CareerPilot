业务落地 · Q7

如何设计 Agent 的个性化能力?

⭐⭐⭐⭐ #个性化#Memory#Agent
30秒电梯稿

"个性化 = 画像(静态属性+动态偏好)+ 动态注入(检索内容、Prompt、记忆三层个性化)+ 反馈学习闭环(显性点踩修正 + 隐性行为信号)。落地三步:先做'低风险显性偏好'(称呼、语言、格式),再做'行为隐学'(根据反馈调整风格),最后做'预测式个性化'。两条红线主动讲:隐私合规(个性化=在处理用户数据,要同意和可关)和过滤气泡/谄媚(只顺着用户说,是产品事故不是个性)。

通俗类比

像一个相处久了的贴身助理:知道你姓李、习惯早上回消息(静态画像);记得你喜欢简洁回复、讨厌废话(显性偏好——你说过的);发现你每次都跳过长表格,就主动改成要点列表(隐性行为学习);但他不会因为你想听好话就把坏消息说成好消息(谄媚红线),你的资料他也绝不会未经允许给别人看(隐私红线)。

详细拆解

1. 画像:个性化的原材料

类型内容来源
静态属性称呼、语言、时区、岗位、行业注册信息、设置
动态偏好回答风格(简洁/详细)、专业度水平、常用格式显性:用户设置/对话中说"以后简短点";隐性:行为统计
领域记忆用户的项目、过去的问题、常用工具Memory 系统(第一部分 Q7)

2. 三层注入(个性化作用在哪)

  • Prompt 层:系统提示动态拼装——"该用户偏好简洁中文回答,是产品经理,专业术语可用"——便宜立见效,第一版就做这个。
  • 检索层:相同 query 按用户身份检索不同范围/排序(销售问"渠道政策"和消费者问,检索内容不同)。
  • 记忆层:从 Memory 捞用户相关的历史事实注入上下文(与 Memory 题联动)。

3. 反馈学习闭环

  • 工程要点:偏好更新要防单次噪声(一次点踩不代表永久偏好,置信度累积);用户可查看和重置自己的画像(合规+体验双保险)。

4. 两条红线(主动讲,面试官眼前一亮)

  • 隐私:个性化=在处理个人数据,先过同意和开关(用户可以一键"关闭个性化",退化为通用 Agent);画像数据遵守上一题的全套治理。
  • 谄媚(sycophancy):模型被个性化调成"顺着用户说",用户错了也附和——质量红线。对策:偏好只影响形式(风格、详略、格式),不允许影响事实立场;评估集里放"用户前提错误"的测试题,模型必须纠正。
面试官追问
Q:个性化怎么评估有没有效果?
AB 实验:开/关个性化对比——重问率、满意度、会话深度;主观:抽样看个性化答案是否真的"更对味";警惕虚荣指标(用户没说不好≠个性化有价值)。
Q:多人共用一个 Agent(团队 Agent),画像冲突吗?
画像按"用户+空间"双维度存:个人空间用个人画像,共享空间用团队画像(称呼、术语约定)——冲突时以当前交互身份为准;这也是 B 端产品的真实需求点。
术语卡
画像(Profile):用户属性的集合。
谄媚:模型一味迎合用户。
过滤气泡:只接触同质信息导致视野变窄。
