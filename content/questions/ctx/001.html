系统设计 · Q7

设计一个 Memory 管理系统(长期记忆)

⭐⭐⭐⭐ #Memory#存储#检索
30秒电梯稿

"我按人的记忆分三层:工作记忆(当前对话,滑动窗口)→ 会话摘要(压缩过的历史)→ 长期记忆(从对话中抽取的事实和偏好,向量化+结构化存储)。写入走『抽取 → 冲突消解 → 更新』管道,读取按当前话题检索 top-k 注入上下文;遗忘用时间衰减 + 访问频率;个性化就是 user 级隔离的长期记忆。业内参考 Mem0(抽取+检索)和 Zep(时间感知知识图谱)。"

通俗类比

想想你自己的脑子:工作记忆是"手头正在聊的事"(聊到哪了,得记清);今天发生的事过几天就模糊成摘要("上周聊过报销的事");而"我同事小王不吃香菜"这种沉淀下来的事实才是长期记忆,下次点菜自动想起来。人还会遗忘不重要的琐碎(时间衰减),重要的事常想起就记得牢(访问频率加成)——Memory 系统完全照抄这套认知逻辑。

详细拆解

1. 三层存储模型

层级存什么怎么存生命周期
工作记忆当前对话最近 N 轮原文Redis 列表会话期间
会话摘要超窗口的历史压缩成摘要Redis + DB数天~数周
长期记忆事实("用户base在上海")、偏好("回答要简洁")、事件向量库 + 结构化属性表永久(可衰减)

2. 写入管道(核心亮点)

3. 读取:按需检索注入

  • 每轮生成前,用当前话题的 embedding 去 Memory 库检索 top-k(5~10 条)相关记忆,拼进 system prompt。不是全量塞——记忆越多 token 越贵、噪音越大,相关性排序是关键。
  • 结构化高频字段(称呼、语言偏好)直接走属性表,不走向量检索。

4. 遗忘机制

  • 记忆打分 = 近期性(时间衰减,如半衰期 30 天)× 访问频率(每次被检索加分,类 LFU)× 重要性(LLM 初始标注)。
  • 低分记忆降级到冷存储(不参与默认检索,但可显式搜索);用户明确说的("记住这个")重要性封顶,几乎不衰减。
  • 用户可查看、可删除——这是合规硬要求(个保法),面试提一句很加分。

5. 个性化:user_id 强隔离;画像 = 静态属性(注册信息)+ 动态偏好(从行为和反馈学习,如"用户总追问细节 → 回答风格调详细")。效果上等价于"系统提示词动态生成"。

6. 参考产品(展示知识面)

  • Mem0:轻量,抽取-更新管道 + 向量/图存储,易集成,社区活跃。
  • Zep / Graphiti:把记忆组织成时间感知知识图谱(实体+关系+生效时间区间),能回答"用户上个月还是素食者,现在呢"这种时序问题,适合重度记忆场景。
  • LangChain Memory:接口规范,但内置实现偏基础,生产一般自己写或用上面两个。
面试官追问
Q:记忆越存越多,检索会不会变慢、变吵?
分层:高频热记忆单独小索引;检索时先属性过滤再向量;定期做记忆"GC"(合并、归档低分记忆);控制注入条数(k≤10)。
Q:抽取出的记忆是错的(模型幻觉)怎么办?
抽取时带置信度和来源对话 ID;低置信度标记待确认;用户纠正时反向删除/覆盖;重要决策不单靠记忆。
Q:怎么评估记忆系统的好坏?
构造"多会话延续性"测试:跨会话问之前提过的事,看回答是否一致;用 LOCOMO 这类长对话记忆基准;线上看"用户重复告知率"(用户老得重新自我介绍就是记忆差)。
术语卡
工作记忆:当前上下文窗口内的对话。
冲突消解:新旧事实矛盾时的覆盖/合并策略。
时间衰减:记忆分数随时间指数下降。
知识图谱记忆:实体+关系+时间的记忆组织方式。
