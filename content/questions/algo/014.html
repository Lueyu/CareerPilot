Agent算法 · Q13

小模型蒸馏策略设计

⭐⭐⭐⭐ #蒸馏#模型压缩#优化
先说人话:这题问的是:手里有个 70B 的老师模型,业务嫌它贵嫌它慢,怎么「带」出一个成本约 1/10 的 7B 学生,还保住九成本事。面试官爱考它,因为开口就分两类人——上来背 KL 散度公式的是背书党,先反问「90% 拿什么基准、怎么测」的才是真做过的。
30秒电梯稿

"我的总纲是黑盒蒸馏打底、白盒蒸馏提上限:① 数据是灵魂——不是随便拿一堆 prompt,而是围绕目标能力的分布采样(通用能力 + 领域能力 + 推理链数据);② 用 70B 教师离线生成高质量输出,黑盒做 SFT;③ 有条件时白盒蒸馏,用温度缩放的软标签 + KL 散度让学生学教师的『概率分布』而非只学硬答案;④ 训练上配多任务数据、课程学习防灾难性遗忘;⑤ 用权威 benchmark 量化『90%』并留兜底。要诚实地说:90% 是目标,现实通常在 80~90% 之间,取决于数据质量。"

通俗类比

整个蒸馏就是「老师傅带徒弟」(学术名知识蒸馏,Hinton 2015 年提出):70B 教师像干了十年、什么疑难杂症都见过的资深工程师,7B 学生像脑子快但见识少的新人。「保留 90% 能力」= 徒弟能独立顶老师 90% 的活。黑盒蒸馏是徒弟只能看老师傅交付的成品——工单怎么结的、报告怎么写的,照着练;白盒蒸馏是老师傅把「这种告警八成是光模块、一成半是交换机」这类把握度也写下来,徒弟学到的就不只是结论,还有判断的分寸——这个「分寸」就是软标签。

哪里像:带徒弟和做备份策略一样讲究覆盖度——只练一类题,就像容灾演练只演练断电、不演练存储故障,真出事必翻车;所以训练数据要按「通用 : 领域 : 推理链」配开,不能刷一堆同质题。哪里不像:① 备份是比特级复刻,理论上 100% 可还原;蒸馏是有损的——所以目标才叫「保留 90%」而不是 100%;② 老师傅带徒弟一次一个、很慢,蒸馏是离线批产,把教师经验「印成教材」一次、部署 7B 到处——70B 推理要约 140GB 显存的多卡集群,7B 约 14GB 单卡就跑,这就是它的经济学意义。

「90%」怎么验收:像容灾验收不能只报一个「整体成功率」,要按业务系统逐项核 RTO——蒸馏同理,数学一科、代码一科、指令遵循一科分开打分,再算「学生分 ÷ 教师分」的保留率。总分好看不代表没有一科悄悄崩了;面试时能主动把 90% 翻译成「分科目的保留率」,就已经赢了一半。

详细拆解

1. 先讲清"90% 能力"怎么定义(面试第一句就显严谨)

90% 不先定义,后面全是空话——这和汇报容灾能力不说 RTO/RPO、只说「挺能扛的」是同一个毛病。把「能力」拆到可测的 benchmark 上,每个数字才有出处:

  • "能力"必须落到可测指标上:MMLU / C-Eval(通用知识)、GSM8K / MATH(数学)、HumanEval(代码)、指令遵循(MT-Bench / AlpacaEval)、垂域任务集。没指标,90% 就是空话。
  • 经验现实:单靠 SFT 蒸馏,7B 通常达到同数据下 70B 的 75%~88%;加白盒蒸馏、偏好对齐(DPO)、更高质量数据能再逼近。要诚实报区间,不吹"一定 90%"。

保留率 = 学生分 ÷ 教师分,而且要逐科目算。示例(数字仅演示算账方法):

能力维度代表基准教师 → 学生保留率
通用知识MMLU70 → 6390%
数学推理GSM8K82 → 7085%
代码生成HumanEval45 → 3680%
指令遵循MT-Bench8.2 → 7.490%

看总分更要看分科——总分 88% 可能掩盖「数学只剩 70%」的单项崩盘;分科定位,后面的补训才有的放矢。

2. 黑盒蒸馏 vs 白盒蒸馏(方法论主线)

一句话分辨:黑盒 = 只学成品,白盒 = 连过程一起学。先解释表里的 logits——它是教师「动笔之前」对词表里每个候选词打的原始分数,天然携带「A 是首选、B 紧随其后、C 差得远」的排序和距离信息,比最终文本多出一整层「落选者们各差多少」的知识。类比:黑盒像只拿到恢复出来的成品库;白盒像把备份链、增量日志、元数据全拿到手,保真度自然更高。

维度黑盒蒸馏(响应蒸馏)白盒蒸馏(概率/特征蒸馏)
要什么教师的最终输出文本教师的 logits / 隐层特征 / 注意力分布
对教师要求只有 API 即可(闭源也能做)需要权重或 logits 接口(通常开源)
学生学到"答什么"还学到"为什么这么有把握"、中间表示
效果上限中(受数据质量限制)高(信息更丰富,通常再涨几个点)
成本/门槛低,最常用高,需要工程配合
典型损失对教师文本做交叉熵(普通 SFT)KL 散度对齐软分布 + 交叉熵兜底

实战默认黑盒打底、白盒提上限:黑盒几乎零门槛,教师只要有个 API,先把 80 分的基线拿下来;白盒要在教师侧开 logits 接口、改训练框架,是冲刺 90 分的手段——两者不是二选一,是先后关系。

3. 完整落地流程(讲成管道)

管道五段,每段各有坑,逐段展开:

  • ① 数据工程:围绕目标能力分布采样,是整条管道权重最大的一段——数据覆盖度决定学生「见过什么」。类比:备份策略先定覆盖范围,哪些业务必须全量、哪些可以增量;没覆盖到的场景,学生永远答不好,而且回炉成本远高于事前配好。
  • ② 教师生成:70B 离线批量产出,同一道题用不同温度/提示词多样采样,相当于把老师傅的经验「印成教材」。这步是纯离线批处理,一次性算力开销,换的是之后每次推理都便宜。
  • ③ 清洗去重:格式校验、去重、规则 + 模型打分过滤。类比:备份前做源端校验和去重——垃圾进垃圾出,教师的幻觉输出混进教材,学生就把错误当知识学。
  • ④ 学生训练:SFT + KD(白盒蒸馏损失)+ DPO 组合,7B 训练只要单卡到数卡,和教师一次推理的集群开销相比可以忽略。
  • ⑤ 评估:分科目算保留率,不达标的科目回到①补数据再来一轮——是闭环,不是训完直接上线。

4. 损失函数(白盒蒸馏的核心公式)

# 软标签:教师/学生的 logits 除以温度 T 再 softmax
q_i = softmax(z_teacher / T)_i        # 教师软分布
p_i = softmax(z_student / T)_i        # 学生软分布
# 蒸馏损失 = 学生软分布 逼近 教师软分布(KL 散度)
L_KD = T² · KL(q || p)                # T² 修正温度缩放带来的梯度量级
# 总损失 = 蒸馏损失 + 硬标签 SFT 损失(交叉熵)
L = α · L_KD + (1-α) · L_CE(y, softmax(z_student))

逐行翻译:前两行,把教师/学生的原始分数除以温度 T 再过 softmax,得到两个「软分布」;第三行用 KL 散度量学生分布和教师分布差多远并最小化它——学生不是背答案,而是把自己的把握度调到和老师一样;最后一行在蒸馏项之外再拼一份普通交叉熵(硬标签),α 控制「像老师」与「答对题」的配比。

关键点:温度 T 放大"教师不确定的那部分信息"——T 越大,分布越平滑,"A 和 B 都接近"这种隐式知识越能传给学生;T 太小就退化成硬标签。经验值 T ∈ [2, 10],α ∈ [0.5, 0.9]。

温度到底在干嘛?看一个「告警定位」任务的三种教法:

硬标签(黑盒 SFT):      换光模块。                        ← 只传了 1 bit:选哪个
软标签 T=1(近乎硬):    换光模块 95% | 查交换机 3% | 其他 2%   ← 第一名之外几乎全是噪声
软标签 T=6(白盒 KD):   换光模块 42% | 查交换机 31% | 查驱动 19% | 其他 8%
                              ↑ 第二、第三怀疑对象浮现——这才是老师傅的"暗知识"

T=1 时分布很「尖」,传过去约等于硬标签;T 调大后分布被摊平,落选项之间的相对高低显形了——这些「我不是最怀疑你但也很怀疑」的信息,论文里叫「暗知识」(dark knowledge),恰恰是老手和新手的真正差距。T 也不能无限大:分布糊成一条直线,连教师自己的首选都看不清。至于公式里乘 T²,是因为分布被摊平后梯度会同步变小,乘回去补偿量级,保证训练信号不消失。

5. 保留 90% 能力的实战 trick

  • 数据配比(最关键):纯垂域数据会让通用能力崩;通常通用 : 领域 : 推理链 ≈ 5:3:2,并用指令多样性撑开覆盖面。5:3:2 像备份资源按业务重要性分配——核心库全量高频、边缘系统低频;配比失衡不会立刻报错,是在评估表上现形的。
  • 思维链(CoT)数据(Chain-of-Thought):让教师先想再答,学生继承推理能力——数学/代码题效果尤其显著。徒弟光抄结论不长本事,要抄的是排查思路。
  • 课程学习(Curriculum Learning):先易后难,或先用全量粗训再难样本精训,防止一开始被难题带崩——像演练先练单点故障、再练机房级事故,一上来全断电,队伍直接练散。
  • 防灾难性遗忘(Catastrophic Forgetting):混入通用数据 + 回放(留一点原始 SFT 数据),或对教师 logits 做 EMA 平滑。回放就是训练侧的「CI 回归测试」——不跑一遍,你不知道修新功能时顺手改坏了哪个老接口。
  • 教师集成:多个教师(或同一教师多次采样)取最高置信答案,提升伪标签质量——像三副本存储的 quorum 仲裁,多数派一致的答案才写进教材,单次口误被投票滤掉。

6. 兜底与工程:7B 天然快、便宜(推理成本约 1/10)——显存账:70B FP16 权重约 140GB,要多卡 A100/H100 集群伺候;7B 约 14GB,单卡甚至消费级显卡就能跑,这正是 Agent 这类高频调用场景非要小模型的原因。蒸馏不达标时,退而求其次用 7B + RAG / 工具增强补能力,或上 LoRA 微调多个垂域小模型分而治之;还有一记更朴素的组合拳是分级路由——简单题走 7B、难题升级 70B,像存储分层,热数据放 SSD、冷数据放磁带,按访问成本分流。最后留一句期望管理:蒸馏是有损压缩,敢承诺 90%、也讲清楚丢的那 10% 是什么,是工程师的诚实,也是面试的加分项。

面试官追问
Q:"90% 能力"你具体怎么量化给面试官看?
人话:90% 不是形容词,是一道可复算的除法——学生分除以教师分,而且要分科目算,不能只报一个总分。类比:像容灾验收,只说"整体成功率 90%"没人买账,要按业务系统逐个核 RTO——总分会被强项稀释,弱项才是上线后炸锅的地方。技术:选一组覆盖业务的 benchmark(MMLU/GSM8K/HumanEval/垂域集),教师学生各跑一遍,保留率 = 学生分/教师分,并逐题对拍定位差距;教师 MMLU 70 分、学生 63 分,保留率即 90%。再配人工抽检集,补通用 benchmark 测不到的指令遵循。
Q:黑盒和白盒怎么选?什么时候必须上白盒?
人话:先用便宜的黑盒拿基线,发现"答案对但火候差"再上白盒;教师不给概率接口就只能黑盒。类比:像做备份恢复——先拿恢复出来的成品库,能用就先用;要更高保真,才去要备份链和元数据来重建;源端不给元数据接口,成品就是你能拿到的全部。技术:分类、排序、拒答这类吃"把握度"的任务白盒收益最大(KL 学的是分布而非答案);闭源教师可用"多次采样 + 教师打分"伪造成软标签近似;黑盒上限受数据质量卡住,白盒通常能再涨几个点。
Q:蒸馏后学生某类能力崩了(比如数学),怎么定位修复?
人话:先定位再修,别上来就重训。分科目打分找到崩的是哪类,再顺着"数据配比 → 教师质量 → 训练顺序"逐项排查。类比:像某类备份作业失败率突然飙升——先按业务分桶统计,再查是模板配置、源端数据还是调度顺序变了;修完要挂回归集防复发。技术:分项评估定位能力维度;查该类数据在训练集占比是否过低、教师在该类的输出质量是否本来就差;补高质量 CoT 数据、上调配比权重、针对性精训;同时建能力回归集,之后每次改动全量跑一遍,防再次退化。
Q:为什么不直接用 70B 做量化压缩,而要蒸馏到 7B?
人话:量化是同一个模型减肥,压到 4-bit 骨架还是 70B,推理仍然重;蒸馏是重造一个结构上就小的模型,天生便宜。类比:量化像对备份集做压缩去重——体积小了,但恢复时那套全量流程没变;蒸馏像按"只保留必要表"重建一个精简库,天生轻,查询快一个量级。技术:两者常叠加使用:70B → 7B 蒸馏,再对 7B 做 4-bit 量化;端侧/高并发场景只有"结构上小"才跑得动——显存账 140GB 对 14GB,量化的 70B 依然回不到单卡。
Q:教师自己也会答错,把错误答案教给学生怎么办?
人话:教师不是标准答案机,它也会幻觉;蒸馏最大的隐藏风险,是把教师的错误当知识印进学生。类比:像告警要交叉确认——单一来源可能误报,多个监控信号多数派一致才写进 runbook;新人不能老师傅说啥记啥。技术:同一题以不同温度多次采样取多数答案(自洽性,Self-Consistency);低置信样本直接过滤、不进训练集;黄金集人工或规则校验;必要时多教师集成投票。"垃圾进垃圾出"在蒸馏里加倍成立,清洗阶段的投入直接决定学生的上限。
术语卡
知识蒸馏:大模型(教师)向小模型(学生)迁移知识的技术,拿教师输出当教材。
软标签:教师对每个候选答案给出的完整概率分布——"A 六成、B 两成半"全在里面,信息量远大于一个硬答案。
温度 T:softmax 的平滑旋钮,调高让分布变软、放大教师的"暗知识",蒸馏经验值 2~10。
KL 散度:衡量两个概率分布差多远的尺子,白盒蒸馏靠它让学生分布贴着教师分布学。
灾难性遗忘:模型学新任务时把老本事弄丢,防法是混通用数据回放——训练侧的回归测试。
课程学习:训练数据由易到难排序着喂,防止开局被难题带崩。
CoT(思维链):让教师"先想再答"的推理链数据,蒸馏时把思考过程一并传给学生,数学/代码尤其显著。
DPO:不需要奖励模型的偏好对齐方法,蒸馏后补一刀,让 7B 更听指令。
