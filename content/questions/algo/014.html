小模型蒸馏策略设计

⭐⭐⭐⭐ #蒸馏#模型压缩#优化
30秒电梯稿

"我的总纲是黑盒蒸馏打底、白盒蒸馏提上限:① 数据是灵魂——不是随便拿一堆 prompt,而是围绕目标能力的分布采样(通用能力 + 领域能力 + 推理链数据);② 用 70B 教师离线生成高质量输出,黑盒做 SFT;③ 有条件时白盒蒸馏,用温度缩放的软标签 + KL 散度让学生学教师的『概率分布』而非只学硬答案;④ 训练上配多任务数据、课程学习防灾难性遗忘;⑤ 用权威 benchmark 量化『90%』并留兜底。要诚实地说:90% 是目标,现实通常在 80~90% 之间,取决于数据质量。"

通俗类比

就是老师傅(70B)带徒弟(7B):老师傅把每一类活都亲手做一遍,徒弟照着成品练(黑盒蒸馏);更高级的是老师傅不光给成品,还给『这道题我 60% 觉得是 A、25% 觉得是 B』这种把握度(软标签),徒弟学到的是"判断的尺度"而不是死记答案(白盒蒸馏)。要让徒弟达到老师 90% 的水平,关键在于练的题要全、要像真实考场,而不是刷一堆同质题。

详细拆解

1. 先讲清"90% 能力"怎么定义(面试第一句就显严谨)

  • "能力"必须落到可测指标上:MMLU / C-Eval(通用知识)、GSM8K / MATH(数学)、HumanEval(代码)、指令遵循(MT-Bench / AlpacaEval)、垂域任务集。没指标,90% 就是空话。
  • 经验现实:单靠 SFT 蒸馏,7B 通常达到同数据下 70B 的 75%~88%;加白盒蒸馏、偏好对齐(DPO)、更高质量数据能再逼近。要诚实报区间,不吹"一定 90%"。

2. 黑盒蒸馏 vs 白盒蒸馏(方法论主线)

维度黑盒蒸馏(响应蒸馏)白盒蒸馏(概率/特征蒸馏)
要什么教师的最终输出文本教师的 logits / 隐层特征 / 注意力分布
对教师要求只有 API 即可(闭源也能做)需要权重或 logits 接口(通常开源)
学生学到"答什么"还学到"为什么这么有把握"、中间表示
效果上限中(受数据质量限制)高(信息更丰富,通常再涨几个点)
成本/门槛低,最常用高,需要工程配合

4. 损失函数(白盒蒸馏的核心公式)

# 软标签:教师/学生的 logits 除以温度 T 再 softmax
q_i = softmax(z_teacher / T)_i        # 教师软分布
p_i = softmax(z_student / T)_i        # 学生软分布
# 蒸馏损失 = 学生软分布 逼近 教师软分布(KL 散度)
L_KD = T² · KL(q || p)                # T² 修正温度缩放带来的梯度量级
# 总损失 = 蒸馏损失 + 硬标签 SFT 损失(交叉熵)
L = α · L_KD + (1-α) · L_CE(y, softmax(z_student))

关键点:温度 T 放大"教师不确定的那部分信息"——T 越大,分布越平滑,"A 和 B 都接近"这种隐式知识越能传给学生;T 太小就退化成硬标签。经验值 T ∈ [2, 10],α ∈ [0.5, 0.9]。

5. 保留 90% 能力的实战 trick

  • 数据配比(最关键):纯垂域数据会让通用能力崩;通常通用 : 领域 : 推理链 ≈ 5:3:2,并用指令多样性撑开覆盖面。
  • 思维链(CoT)数据:让教师先想再答,学生继承推理能力——数学/代码题效果尤其显著。
  • 课程学习:先易后难,或先用全量粗训再难样本精训,防止一开始被难题带崩。
  • 防灾难性遗忘:混入通用数据 + 回放(留一点原始 SFT 数据),或对教师 logits 做 EMA 平滑。
  • 教师集成:多个教师(或同一教师多次采样)取最高置信答案,提升伪标签质量。

6. 兜底与工程:7B 天然快、便宜(推理成本约 1/10);蒸馏不达标时,退而求其次用 7B + RAG / 工具增强补能力,或上 LoRA 微调多个垂域小模型分而治之。

面试官追问
Q:"90% 能力"你具体怎么量化给面试官看?
选一组覆盖你业务目标能力的 benchmark,分别对 70B 教师和 7B 学生打分,算保留率 = 学生分 / 教师分(逐题对拍比只看总分更细)。例如教师 MMLU 70 分、学生 63 分,保留率 90%。再加一个人工抽检的指令遵循集,因为通用 benchmark 未必反映真实业务。
Q:黑盒和白盒怎么选?什么时候必须上白盒?
能用教师 API 先跑黑盒 SFT 拿基线;发现答案对但『判断尺度』差(尤其分类、排序、拒答这类需要"把握度"的任务)时上白盒。教师是闭源(拿不到 logits)就只能黑盒,这时可以用"教师打分 + 多次采样软标签"近似替代。
Q:蒸馏后学生某类能力崩了(比如数学),怎么定位修复?
先按能力维度做分项评估定位是哪一类崩;再看训练数据里该类占比是否过低、教师在该类的输出质量是否本来就差;修复手段:补充该类高质量 CoT 数据、提高其在配比中的权重、针对性精训,并设回归集防再次退化。
Q:为什么不直接用 70B 做量化压缩,而要蒸馏到 7B?
量化和蒸馏是两条路,常叠加使用:量化是把 70B 压到 4-bit 省显存,但模型参数量没变、推理仍然重,7B 这种"结构上就小"的模型端侧/高并发场景才能跑。实战常见组合是:70B 教师 → 7B 学生 → 再对 7B 量化,层层减负。
术语卡
知识蒸馏:大模型(教师)把知识迁移给小模型(学生)。
软标签:教师输出的完整概率分布,而非单一答案。
温度 T:softmax 的平滑系数,越高分布越"软"。
KL 散度:衡量两个概率分布差异的指标,KD 用它对软标签。
灾难性遗忘:微调后模型丢掉原有通用能力。
课程学习:按由易到难的顺序喂训练数据。
