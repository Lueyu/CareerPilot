Agent核心 · Q43

Function Calling 和 Toolformer 的本质区别是什么？各自在训练/推理阶段如何工作？

⭐⭐⭐ #Function Calling#Toolformer 字节(真题)
30秒电梯稿

两者最本质的区别是「工具能力装在哪里」：Function Calling 是推理期接口——模型权重不变，靠开发者传入的 JSON Schema 让模型学会"要不要调、调哪个、传什么参数"，真正执行由外部运行时负责；Toolformer 是训练期方法——用自监督信号构造"带 API 调用标注"的语料继续微调，把"何时用工具"内化进模型权重。一句话：Function Calling 给模型"接工具"，Toolformer 教模型"学会用工具"。

通俗类比

Function Calling 像给一台智能手机装 App：手机（模型）本身没变，只是系统（运行时）提供了一排可点按钮，模型说"我想打开地图、导航到 X"，实际导航由 App 完成，结果再显示回屏幕。Toolformer 则像把一个人从小训练成会用地图和计算器：他遇到算账、找路的场景，会本能地掏出工具并用对——"会用工具"已经刻进大脑里了。前者改"使用说明书"，后者改"大脑"。

详细拆解

1. 定位：训练期 vs 推理期（先抓住矛盾主线）

维度Function CallingToolformer
本质推理期接口 / 对齐能力训练期方法 / 论文
工具清单每次调用由开发者用 schema 传入训练时内化进权重
谁执行工具外部运行时（开发者代码）外部运行时，但调用决策由模型自学
是否改权重用户侧使用时不改是，用增强语料继续微调
学习信号指令微调 + 工具调用对齐（厂商做）自监督：调用是否降低后续 token 损失
典型场景ChatGPT / Claude 等产品接口学术研究、让基座模型自学工具

2. Function Calling 怎么工作（推理期）

  • 关键点：模型只产出"调用意图"，不执行；参数合法性由 schema + 运行时二次校验兜底。
  • 训练层面：商用模型的 Function Calling 能力来自厂商的指令微调 + 工具调用数据对齐，让模型学会"识别该调用、生成合法 JSON"。但对开发者而言，这是推理期的现成接口，不涉及改权重。

3. Toolformer 怎么工作（训练期，四步）

  • 损失过滤是精髓：不是所有候选调用都有用——如果"插入调用"没有让后续文本更好预测，就丢弃。这样模型只学会"有用的工具使用"。
  • 推理时：模型自回归生成，遇到 API 调用 token 时暂停解码 → 执行调用 → 结果插回 → 继续生成。

4. 两者关系与 trade-off（面试加分句）

  • 二者不是对立而是互补：Function Calling 是工程上最省事、可控的方式（工具可换、可审计）；Toolformer 思路用于"让模型更自主地决定用不用工具、用什么"，减少显式路由。
  • Function Calling 的代价：依赖厂商训练、工具集合受 schema 约束、复杂嵌套调用仍需工程编排；Toolformer 的代价：需要构造/筛选训练数据、成本高、工具知识固化后难动态增删。
  • 可以总结为：Function Calling 把"决策 + 格式"交给模型、"执行 + 清单"交给系统；Toolformer 把"何时用工具"这件事训练进权重，但执行仍靠系统——共同点是"模型只做决策，不亲自执行副作用"。
面试官追问
Q:Function Calling 模型也是训练出来的，那和 Toolformer 的区别还剩什么？
区别在"工具使用能力的来源与更新方式"：Function Calling 的"会不会用工具"由厂商在训练时对齐好，开发者使用时不改权重，换工具只需换 schema；Toolformer 是一套公开的训练 recipe，让任意基座模型用自己的数据自学工具调用，代价是要自己跑筛选与微调。更本质一点：Function Calling 是"产品接口"，Toolformer 是"训练方法论"，二者不互斥——可以"用 Toolformer 的思路训练，再以 Function Calling 的形式对外提供"。
Q:模型生成的函数参数错了怎么办？
三层兜底：① schema 约束 + 结构化解码（让输出天然合法）；② 运行时参数校验（类型/范围/必填），非法则把错误信息回填让模型重试；③ 对副作用操作做两段式（预览 → 确认）与幂等，避免"参数错但已执行"造成损失。
Q:Toolformer 为什么用"损失降低"当过滤信号，而不是全部保留？
因为模型会生成大量无意义或错误的调用候选（把不需要计算的地方也标了、或调用格式不对）。以"调用结果是否让后续文本预测损失下降"作为自监督信号，等价于只保留"确实帮助预测下一个词"的调用，相当于无人工标注地筛出高质量工具使用样本——这是它的核心创新。
术语卡
Function Calling:模型输出结构化调用、由外部运行时执行的接口。
Toolformer:自监督构造 API 调用样本并微调、让模型自学用工具的论文方法。
JSON Schema:描述函数参数结构的声明式规范。
自监督信号:用数据本身构造的监督，无需人工标注。
交叉熵损失:衡量模型预测下一个 token 的难度。
