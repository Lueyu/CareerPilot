Agent算法 · Q19

推导 KL 散度在 RLHF 中的作用

⭐⭐⭐⭐ #KL散度#RLHF#理论 无公司
先说人话:这道题问的是:RLHF 训练时,为什么要在「挣奖励」之外额外减去一项 KL 散度、这一项在数学上怎么落到每个 token 的账上。面试官爱考它,因为它是「背过 RLHF 流程」和「真懂原理」的分水岭——只会答「防跑偏」不够,能写出 per-token log-ratio、说清 β 的松紧才算及格。答错的典型暴露点:把 KL 当成对称的「距离」、说不清参考模型为什么必须冻结。
30秒电梯稿

"RLHF 里加 KL 散度,本质是给策略模型 π_θ 套一条安全带。PPO 目标是:最大化奖励的同时,约束新策略 π_θ 不要偏离参考模型 π_ref(通常是 SFT 后冻结的那个)太远,目标函数 = E[r(x,y) − β·KL(π_θ ‖ π_ref)]。为什么要约束?因为奖励模型是个只会打分的代理考官,本身有漏洞,策略一旦放飞就会用复读、谄媚这类怪话骗高分(reward hacking),KL 项把它持续拉回正常说话的轨道。实现上 π_ref 全程冻结,KL 按 token 近似为 log π_ref − log π_θ——策略每吐一个 token 就记一笔「偏移账」,乘 β 从奖励里扣;β 控制安全带松紧,β 太小学出坏毛病,太大原地踏步。"

通俗类比

先把考场看清楚:奖励模型是个代理指标,而代理指标一定会被钻空子。RLHF 真正想优化的是「人类的真实偏好」,但真实偏好写不成目标函数,只好先训一个奖励模型(RM)来替人打分。这个处境你太熟了:想度量「备份系统好不好」,最后落到纸面的只有「备份成功率」「RTO 达标率」几个指标——指标永远只是目标的代理,而 古德哈特定律(Goodhart's Law)早就预警:一旦某个度量变成优化目标,它就不再是好的度量。类比:「备份成功率」一旦上了 KPI,就有人把「失败即跳过」刷成默认策略——KPI 满分,可恢复性归零。RLHF 里一模一样:策略发现复读「好的好的」、堆砌溢美之词、输出高置信但空洞的话能骗 RM 给高分,这就是 reward hacking——为分数优化,不为任务优化。

KL 散度就是那条安全带:给「新版本」和「已验证基线」的行为差异记笔账。把训练中的策略模型 π_θ 当成「待发布的新版本」,把参考模型 π_ref(冻结的 SFT 模型)当成「已通过验证的基线版本」,KL 散度就是两个版本行为差异的度量——不是比参数差多少字节,而是比「同一个上文往下接,两边会做出多不一样的选择」。目标函数 J = E[奖励 − β·KL] 的意思就是:你可以自由演进挣分,但每偏离基线一步都要按 β 计价交罚金;β 就是变更审批的松紧度,β 小 = 审批形同虚设,β 大 = 变更冻结。哪里像:都是「允许优化、但禁止偏离已验证基线太远」,罚金按偏移量实时计价。哪里不像:运维的基线漂移检测是事后审计、出了事故才回滚;KL 是内嵌在训练目标里的实时约束——每生成一个 token 立刻记账,不等复盘;而且它度量的是概率分布的行为差异,不是数据的字节差异。

详细拆解

第 0 步:看清 KL 在 RLHF 全景里的位置

[阶段1] 人类写示范答案 ──SFT监督微调──→ π_sft ──复制一份冻结──→ π_ref(锚点/安全带)
                                                     │
[阶段2] 人类对两个答案排序 ──训练──→ 奖励模型 r_φ(代理考官,只会打分)
                                                     │
[阶段3] π_θ 一边生成一边算两本账:
        ├─→ r_φ(x,y) 打分        →  挣的钱
        └─→ 与 π_ref 逐 token 比  →  违规罚款 = β · log(π_θ/π_ref) 的账

        总目标:最大化  E[ r_φ(x,y) − β·KL(π_θ ‖ π_ref) ]
                 即「挣的分 − 偏离基线的罚款」

下面按「KL 是什么 → 为什么非要它 → 数学上怎么实现 → β 怎么调」四步走。

1. 先讲清 KL 散度是什么

  • 定义:KL(P ‖ Q) = Σ P(x)·log(P(x)/Q(x)),衡量"用 Q 去近似 P 时损失的信息量"。换个更直觉的读法:它是期望对数似然比 E_{x~P}[log(P(x)/Q(x))]——站在 P 的立场、按 P 的口吻统计「我常说的事,你怎么给这么低的概率」。
  • 它是非负、非对称的:P = Q 时取 0;KL(P ‖ Q) ≠ KL(Q ‖ P)。非对称可以类比成增量备份的方向性:「从生产推到副本」和「从副本推回生产」记的账本不一样。RLHF 里取 KL(π_θ ‖ π_ref),按新策略实际生成的 token 加权——策略走到哪、账记到哪,像增量备份只记实际变化的块,没写到的地方不计费。
  • 单位是 nats(以 e 为底的对数,见 nat):log-ratio = 2.3 nats ≈ 概率差 10 倍,4.6 nats ≈ 差 100 倍。

拿一个 token 例子把「按 π_θ 加权」看实:

tokenπ_θ 给的概率π_ref 给的概率log-ratio对 KL 的贡献(×π_θ)
"好评!"0.500.05+2.3 nats0.50×2.3 = +1.15,重罚
"您"0.050.50−2.3 nats0.05×(−2.3) = −0.115,轻减

看明白两件事:① 策略把 ref 不看好的词概率抬得越高、说得越勤,罚得越狠——这正是我们要的「重点盯防你实际说出口的话」;② 在低概率处压低某个词,减免很少——KL 不奖励你「装低调」,只惩罚「高调跑偏」。

2. 为什么要约束 KL(核心动机)

  • 奖励模型是"有偏的代理目标",不是真正的目标。RM 只在人类标注过的分布上可靠,是分布外的脆件:策略一旦把生成分布推到 RM 没见过的区域,RM 的分数就退化成噪声。策略只讨好 RM,就会找到 reward hacking 的后门:输出重复短语、极端谄媚、高置信但空洞的话——InstructGPT 论文(Training language models to follow instructions)实证过这些崩坏模式,并靠 KL 惩罚压住。
  • KL 项把策略锚定在 SFT 模型的良好行为附近,防止语言能力崩坏、多样性坍塌。顺带一笔:KL 约束还间接托住了策略的熵(输出分布的信息论不确定性,见熵(信息论))——不许往 ref 的低概率区狂跳,自然就保留了用词多样性,不至于只会复读一个高频 token。
  • 本质是正则化(见 regularization):防止策略过拟合到奖励模型这一"噪声标签"上,和备份领域「按一个抖动指标做容量规划必然翻车」是同一个道理。

3. 数学上如何实现(推导)

# RLHF-PPO 目标:每 token 加 KL 惩罚
J(θ) = E_{x~D, y~π_θ(·|x)}[ r(x,y) − β · KL( π_θ(·|x) ‖ π_ref(·|x) ) ]

# KL 散度定义(离散分布)
KL(P ‖ Q) = Σ_x P(x) · log( P(x) / Q(x) )

# 实际按 token 估计:π_ref 冻结,其熵项对 θ 是常数,不参与梯度
KL(π_θ ‖ π_ref) ≈ log π_ref(y|x) − log π_θ(y|x)

推导要点:KL(P ‖ Q) = Σ P·log P − Σ P·log Q = −H(P) + Σ P·log(P/Q)。对 θ 求梯度时,−H(π_θ) 这部分由 PPO 的 surrogate objective 间接处理,工程上最常用的做法是直接用 log-ratio:每生成一个 token,把 log π_ref − log π_θ 作为 KL 的蒙特卡洛估计,乘 β 后从奖励里扣掉。

把上面这步掰开细讲(面试时要能白板推出来):

  • 第一步,整句 KL 拆成 token 之和:自回归模型生成整句 y = (a_1, …, a_T),联合概率是各 token 条件概率的连乘 π(y|x) = Π_t π(a_t|前文, x);取 log 连乘变连加,于是整句 KL = E_{y~π_θ}[ Σ_t log(π_θ(a_t)/π_ref(a_t)) ]——「对句子的期望」天然拆成「逐 token 的对数比值再求和」。类比:像块级增量备份,整卷的变更量天然等于各块的变更量之和。
  • 第二步,期望用采样来算:外层期望 E_{y~π_θ} 不好解析,直接用当前 batch 实际生成的句子来当样本——这就是蒙特卡洛估计:策略真实说了什么,就按什么记账,无偏且零额外成本。
  • 第三步,为什么 π_ref 冻结后熵项不参与梯度:展开 KL = E[log π_θ] − E[log π_ref] = −H(π_θ) − E[log π_ref]。π_ref 参数全程冻结,log π_ref 对 θ 无梯度;−H(π_θ) 这部分由 PPO 的 surrogate objective 间接处理(即 pre 里那行近似的来历)。落到工程上,per-token 记账项 k_t = log π_θ(a_t) − log π_ref(a_t),把 −β·k_t 逐 token 混进 reward(token-level 奖励塑形),KL 的梯度就自动出现在 PPO 更新里。
  • 第四步,两种实现位置:① 主流做法(InstructGPT / TRL 系实现)是把 −β·log-ratio 加进 per-token reward,KL 混在「分数」里被 PPO 一起消化;② 少数实现把 β·KL 作为独立损失项加在 loss 端。面试提一句「reward 端塑形是主流」,是加分的工程细节。

4. β 的 trade-off

  • β 太小:奖励涨但语言质量崩、reward hacking;策略可能学出一堆无意义的 token 组合。
  • β 太大:策略几乎不动,学不到人类偏好。
  • 经验值 β 通常在 0.01~0.1 量级,需调;进阶做法是自适应 KL:设一个 target KL(如 6 nats),实时监控,超出就自动加大 β、低于就减小。
β 设定训练表现背后发生了什么运维世界的样子
β → 0(不设防)奖励猛涨,输出复读/谄媚/怪话策略钻 RM 漏洞刷分无变更审批,指标全绿但全是坏变更
β 合适奖励与人工评估同步上升在基线附近探索高价值偏移正常演进:小步快跑、灰度护航
β 过大KL ≈ 0,奖励也不动,RLHF 白训梯度被罚金抵消,策略原地踏步变更冻结,业务原地停摆

自适应 KL 的机制值得单独记:它是一个反馈控制器——实时测实际 KL,逼近 target 就加 β(勒紧),回落就减 β(放松),把策略稳定在「基线附近的一条走廊」里。类比:和 TCP 拥塞控制的 AIMD、和「按队列积压动态调限流阈值」是同一族思想——用反馈把一个风险指标锁在设定区间,而不是写死一个静态参数祈祷它合适。

5. 延伸一笔:KL 没有消失,只是换了住处

  • 后来不少方法把显式 KL 项省掉了,最典型是 DPO:它从「带 KL 约束的 RL 目标」出发做数学变形,把 KL 约束解析地融进了损失函数——不是不需要安全带,而是安全带焊死在公式里,不再现场记账。面试里能讲出这层演进,直接上分。
面试官追问
Q:为什么用 KL 散度,换成 L2 距离或别的度量不行吗?
人话:L2 量的是「两组数字差多少」,KL 量的是「两个概率分布差多少」——策略的本质是分布,度量就得对着分布去。类比:判断两个服务版本行为是否一致,看平均延迟差多少没意义(平均都 50ms 但一个方差爆炸),要看请求在各个接口上的占比分布——风控里检测数据漂移用的 PSI(Population Stability Index),底子就是 KL,业界早就默认「漂移要用分布散度看,不能用均值差看」。技术:① L2 直接比参数或输出向量,对分布形状不敏感:两个模型可能句子几乎相同但 logits 尺度差很远;② KL 是概率框架下信息论正确的度量,且天然化成 log-ratio——只差一次 log 运算,和 PPO 的 token 级奖励无缝融合,实现极简;③ KL 用对数放大低概率区的偏离:概率差 10 倍就是 +2.3 nats,差 100 倍就是 +4.6 nats,「偷偷把某个 token 抬 100 倍」会被重罚,恰好是防跑偏最想要的性质。
Q:RLHF 里 KL 是对每个 token 加,还是对整句加?
人话:工程上几乎都按 token 一笔笔记账、再汇到整句,整句级只活在定义里。类比:像备份做块级校验而不是整卷一个总校验和——粒度细,哪个块偏了看得见,定位准、信号也稳;只有一个总的,出了偏移只知道「有偏」,不知道偏在哪。技术:整句 KL = E_{y~π_θ}[ Σ_t log-ratio ],这个「对句子的期望」用当前 batch 真实生成的句子做蒙特卡洛估计,就是「实际句子的 per-token log-ratio 求和/求均值」;实现上把 −β·log π_ref − log π_θ 的差值逐 token 混进对应位置的 reward(token-level KL 奖励塑形),梯度方差小、训练更稳。整句级要先对整个词表归一化出分布再算散度,计算贵、信号糙,没有工程优势。
Q:KL 惩罚太大,模型"学不动"了怎么办?
人话:安全带勒太紧,第一步是松安全带,不是硬踩油门。类比:限流阈值把正常流量全挡在门外,先调阈值,再考虑升级成「按实时队列长度动态调阈值」的反馈控制器——静态参数定不准,就该让它自己跟着负载走。技术:① 直接调小 β;② 自适应 KL——设 target KL(经验约 6 nats),实时监控实际 KL,超出就加大 β、低于就减小 β,把偏移锁在走廊内;③ 检查参考模型选型是否过强/过弱,必要时换 ref;④ 换 DPO 这类不需要显式参考模型和 KL 项的方法——它把 KL 约束解析地融进了目标函数,安全带内置,不存在「现场勒太紧」的调参问题。
Q:reference model 为什么通常选 SFT 模型,而不是初始的 pretrain 模型?
人话:安全带要拴在「你出发的地方」,而不是拴在「三年前的老机房」。类比:变更管理的基线必须是「当前生产版本」,不是远古架构——拿 pretrain 模型当 ref,等于拿一个还没学会对话的底座当行为标准,KL 会拼命把策略往「不会对话」的方向拽,优化方向整个错乱。技术:RLHF 的起点本身就是 SFT 模型(已经会对话、会遵循指令),ref 选它意味着「优化时不偏离已经学会的对话能力」,两者 KL 距离近、惩罚项才起「微调护栏」而非「压制学习」的作用;同时 ref 全程冻结、不随训练更新——锚点自己会漂,锚就没意义了。一句话总结:ref 是「当前能力的地基」,和初始策略保持一致最合理。
Q:训练结束时 KL 应该是多少?target KL(比如 6 nats)是怎么定出来的?
人话:KL 不是越小越好——为 0 等于白训;也不是越大越好——大了就是失控。健康的终点是「在偏移预算内把奖励挣到头」,target KL 就是这条预算线。类比:像 RPO——不追求零数据偏移(那等于禁止一切写入),而是给偏移量设预算上限,逼近预算就收紧惩罚、远离就放松,自适应 KL 就是那套实时对账机制。技术:把整句 KL ≈ 6 nats 摊到约 100 个 token 上,平均每 token 的 log-ratio ≈ 0.06 nats,即平均每个词的概率只比 ref 高约 6%——温和偏移、够学新偏好又够不着 reward hacking 的悬崖;6 nats 是 PPO/RLHF 实践的量级经验值,各家在 3~12 之间随任务调。面试加分点:能现场做「nats → 每 token 概率倍数」的换算,说明你不是背数字,是真懂单位。
术语卡
KL 散度:两个概率分布差异的信息论度量,非负、非对称;RLHF 里按策略实际生成的 token 加权记账。
参考模型(π_ref):RLHF 中冻结的锚点,通常由 SFT 复制而来——锚点自己会漂,锚就没意义了。
Reward hacking:策略钻奖励模型漏洞刷分,而非真正完成任务;是「为度量优化 ≠ 为目标优化」的模型版翻车。
β(惩罚系数):KL 项的权重,控制策略偏离参考模型的幅度——审批松紧度,经验值 0.01~0.1 量级。
PPO:RLHF 常用的近端策略优化算法,KL 惩罚以 per-token log-ratio 的形式混进它的奖励流。
自适应 KL 控制器:按实际 KL 与 target(经验约 6 nats)的偏差动态调 β 的反馈控制,同族思想是 TCP 的 AIMD 与动态限流。
DPO:把 KL 约束解析融进损失函数的偏好对齐方法——安全带不是没了,是焊死在公式里了。
