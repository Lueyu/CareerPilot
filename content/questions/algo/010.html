DPO 与 PPO 的理论对比

⭐⭐⭐⭐ #DPO#PPO#RLHF
先说人话:这题在问:把「人类偏好」装进大模型的两条主流路线——PPO 的「奖励模型+在线强化学习」和 DPO 的「一条分类损失」——到底是什么关系、怎么选。面试官爱考它,因为一道题同时压着数学推导和工程选型;只会背「DPO 更简单」、推导讲不出、坑说不清的,一下就暴露没真训过对齐。
30秒电梯稿

"先把结论钉死:两者优化的是同一个目标——在「不许离参考策略太远」的 KL 约束下最大化人类偏好奖励,区别只在怎么逼近。PPO 走两步:先训一个奖励模型当裁判,再用带 KL 罚款、clip 限步长的在线强化学习,让策略亲自下场试错、小步更新;DPO 走一步:从 Bradley-Terry 偏好模型推出最优策略的闭式解,把「达到这个解」直接改写成一条二分类损失,奖励模型和整个 RL 循环全省掉。所以数学上两者目标同源;工程上 DPO 简单、稳定、便宜,但依赖离线偏好数据、容易分布偏移;PPO 贵、难调,但在线探索和过程奖励让它上限更高。"

通俗类比

先搞懂这题的前提(用你熟的备份调度想):一个刚做完 SFT 的模型,像一套「能跑但不够讨喜」的调度策略——功能都在,但人类对其中取舍各有偏好。麻烦在于人类给不了绝对分,只会说「这次比上次好」;RLHF 的全部原料就是这种「A 比 B 好」的偏好对,PPO 和 DPO 只是消化这批原料的两条产线。

PPO 像「在线容灾演练 + 评审团」:每一轮都真的把当前预案拉出来演练(在线采样),评审团(奖励模型)按人类口味打分,再按分数小步修订预案(策略梯度);clip 是变更管理里「单批变更幅度锁死在 ±ε」,KL 惩罚是回滚半径——改动再诱人,离基线预案太远就按距离罚款。哪里像:试错→打分→小步改、离基线太远就回退,和滚动变更治理完全同构。哪里不像:演练的分数是客观 KPI,PPO 的裁判是训出来的模型,自己会看走眼,还可能被「选手」反向刷分(奖励 hacking)——真实世界没有「评分系统被考核对象骗到」这一层,所以 PPO 才需要 clip、KL 这一堆护栏。

DPO 像「复盘历史演练报告做离线改进」:不跑新演练,把档案里同一故障场景下「好方案 vs 差方案」的报告对拿出来,把好方案的决策权重调高、差方案调低,一条损失训到底。给「谁比谁好」排出隐含实力分的数学是 Bradley-Terry 模型,它就是天梯排位背后的公式:每位棋手一个实力分,胜负概率由分差决定;人类裁判只说 A 赢了 B,攒够对局,实力分自然浮出。哪里像:相对比较攒出绝对水平,和积分赛不用人人交手一样。哪里不像:真演练可以注入新故障(探索),离线复盘只能学档案里出现过的故障模式——DPO 学不到分布外的新解法;而且档案是老预案跑出来的,和改到一半的新预案天然有偏差(分布偏移)。

一句话收束:PPO 是真演练练出来的预案——贵,但见多识广;DPO 是复盘报告改出来的预案——便宜稳当,天花板是档案库的覆盖面。

详细拆解

第 0 步:先看清两条流水线各自在干嘛

SFT 教会模型「照示范干活」,但「两个答案里人类更喜欢哪个」这种口味 SFT 教不会——这是 InstructGPT 提出三阶段 RLHF 时就定下的命题。PPO 和 DPO 是消化「偏好对」的两派解法,一派在线、一派离线:

PPO 路线(三步:先造裁判,再让选手下场边打边学):
  SFT 模型 ──→ ① 用「人类偏好对」训练奖励模型 r_φ(造一个替人类打分的裁判)
      │                          ↓
      └── 冻结一份当 π_ref ──→ ② PPO 在线训练 π_θ(选手亲自上场)
                                  每轮:当前策略生成 → r_φ 打分 → 扣 KL 罚款
                                        → 算优势 → 小步更新,循环往复

DPO 路线(一步:裁判和选手合并成一个模型):
  SFT 模型 ──→ 冻结一份当 π_ref ──→ 直接把「偏好对」当二分类数据训练 π_θ
                                   整条链路没有采样、没有裁判、没有 critic

下面分别把两边的数学讲透,再回头看「为什么说它们优化同一个目标」。

1. PPO 的数学(RLHF 标准流程,要能写 clipped objective)

RLHF 里 PPO 通常挂着四个模块:策略 π_θ、参考策略 π_ref(SFT 模型)、奖励模型 r_φ、价值模型 V(估计优势函数)。核心损失:

L_CLIP(θ) = 𝔼_t[ min( r_t(θ)·Â_t , clip(r_t(θ), 1−ε, 1+ε)·Â_t ) ]
r_t(θ) = π_θ(a_t|s_t) / π_θold(a_t|s_t)      # 新旧策略的概率比
Â_t = Σ_{l≥0} (γλ)^l · δ_{t+l}              # GAE 优势估计
δ_t = r_t + γ·V(s_{t+1}) − V(s_t)            # TD 残差

这四行面试常要白板默写,先逐行翻译成人话,再背字母:

  • 第 1 行 · clip 目标:min(·, clip(·)) 的意思是——更新方向有利时,收益封顶在 1+ε;方向不利时,损失托底在 1−ε。相当于变更管理把「单批变更幅度」硬性锁死:宁可分多批小步走,不许一步到位。
  • 第 2 行 · 概率比:策略的本质是「给定上文,给下一个 token 分配概率」;新旧策略对同一动作的概率之比,度量这批更新把该动作的概率挪动了多少。
  • 第 3 行 · 优势:Â_t 回答「这步比预期好多少」。为什么不用原始奖励?因为奖励带基线波动,减掉价值模型的预估才露出这步动作的净贡献——像增量同步看「实际传输量 − 预估传输量」,正数才说明这步真省了。
  • 第 4 行 · TD 残差:δ_t 是「实际所得 + 折现后的未来预期」与「当前估值」的差;γ 是折扣(越远的回报越打折),λ 是偏差-方差旋钮(λ=0 只看眼前一步,方差小偏差大;λ=1 看完整条轨迹,反之)。

四个模块在系统里的角色,对号入座:

模块作用分布式系统里的对应物
π_θ 策略被优化的主角,每个 token 由它决定正在迭代中的调度策略
π_ref 参考策略(冻结)基线,衡量「偏离多远」的锚点已验证的基线配置/已知良好版本
r_φ 奖励模型给整段回答打「人类满意度」分替人类口味代打分的质检评分系统
V 价值模型(critic)预估「从当前状态走到结束还值多少分」剩余时间/开销预估,用来算「超预期多少」
  • clip 的作用:把概率比限制在 [1−ε, 1+ε],防止一次更新步子太大把策略"摔崩"——这是 PPO 比普通 policy gradient 稳的关键。
  • KL 惩罚:奖励里通常再扣一项 β·KL(π_θ ‖ π_ref),防止模型为了刷分偏离人类语言分布太远(胡言乱语但 reward 高)。
  • 代价:要在线采样(每轮更新都要当前策略生成)、要维护 critic,训练不稳定、超参多、还吃 GPU。

为什么 KL 惩罚必不可少(PPO 路线最大的暗礁):奖励模型是人标出来的,一定有盲区;无约束的策略梯度会精准找到盲区去刷分——就像为了缩短备份窗口把校验环节全砍掉,窗口指标漂亮、恢复全挂,奖励 hacking 与此同构。KL 散度是「新策略离基线多远」的距离表,β·KL 就是按距离收的罚款:刷分省下的收益如果不够交罚款,这个方向就不划算,模型于是只保留「人类真觉得好的偏离」。

2. DPO 的数学(直接偏好优化,一步到位)

偏好数据给的是"赢家 y_w 输家 y_l"对,Bradley-Terry 模型把"更喜欢谁"建模为奖励差的 sigmoid:

这行假设用人话念:① 人类只做相对比较——「A 比 B 好」,给不出绝对分;② 「A 胜出的概率」由两者的奖励差过一层 sigmoid 决定,差为 0 五五开,差越大越一边倒。它和象棋天梯是同一个数学:单场胜负有随机,攒够对局,实力分(隐含奖励)自然浮出水面。

p(y_w ≻ y_l | x) = σ( r(x, y_w) − r(x, y_l) )     # BT 偏好模型

带 KL 约束的 RLHF 目标 max 𝔼[r(x,y)] − β·KL(π ‖ π_ref) 存在闭式最优解:

这行闭式解用人话念:最优策略 = 参考策略按奖励做指数放大,再归一化成概率分布。奖励比 β 高一截的回答,概率被指数级放大;β 越小,放得越狠、分布越尖。Z(x) 是配分函数——把所有可能回答的贡献加总、凑成合法概率分布的归一化项。它的存在也解释了为什么这行公式不能直接拿来用:构造 π* 得对每个 prompt 遍历所有回答,算不动。于是出现全题的胜负手:PPO 选择「迭代逼近」这个解,DPO 选择「绕开」这个解。

π*(y|x) = π_ref(y|x) · exp( r(x,y)/β ) / Z(x)     # Z(x) 是归一化项(配分函数)

把它反解出奖励,就得到 DPO 的隐式奖励,代入 BT 模型后 Z(x) 恰好约掉,只剩策略对数比。推导分两步,每步都不玄:

  • 第一步,反解奖励:对闭式解两边取 log 移项,得 r(x,y) = β·log(π*(y|x)/π_ref(y|x)) + β·log Z(x)。多出来的 β·log Z(x) 只依赖 prompt x,和具体回答 y 无关。
  • 第二步,代回 BT 让 Z 约掉:BT 用的是「win 的奖励 − lose 的奖励」,同一个 prompt 下 Z(x) 是公共常数,做差精确抵消——像比较两条备份链路谁更快,公共的排队底噪在相减时自动消失。于是损失里连 Z 都不用算,只剩纯策略对数比。
r_θ(x, y) = β · log( π_θ(y|x) / π_ref(y|x) )      # 隐式奖励:奖励即"相对参考策略的抬升"
L_DPO = −𝔼[ log σ( β·( log(π_θ(y_w|x)/π_ref(y_w|x)) − log(π_θ(y_l|x)/π_ref(y_l|x)) ) ) ]
  • 妙处:没有显式奖励模型、没有采样、没有 critic,两个模型(π_θ + π_ref)就能训,损失就是一条二分类交叉熵,超级稳定。
  • β 是温度:控制"离参考策略多远"。β 越小,模型越敢偏离 ref 去贴合偏好,但越容易过拟合/奖励 hacking。
  • 训练形态就是监督学习:每个偏好对是一道二分类题——「y_w 应该拿更高的隐式分」。整条流水线拿捏它只需要普通的交叉熵训练经验,这是 DPO 对工程团队如此亲民的原因。
  • 拿一对数据看它怎么动:若当前 π_θ 对某回答的概率和 π_ref 相同,log 比值为 0;训练把 win 的比值拉正、lose 的比值压负——赢家生成概率被抬高、输家被压低,π_ref 全程冻结只当参照系。
  • β 的工程直觉:β 大 = KL 预算紧 = 紧贴 ref、保守;β 小 = 预算松 = 敢大改,但容易被数据噪声带偏。它和 PPO 里那个 β 概念同源,只是罚款从「奖励里扣」变成「损失里隐含」,常见量级 0.01~0.1。

3. 两者关系(本题核心,能讲清这层就是高分)

把两边放进同一张图看:它们优化的是同一个目标函数——上面那个带 KL 约束的奖励最大化,分歧只在解法:PPO 不知道最优策略长什么样,靠在线采样做数值迭代逼近;DPO 先把最优解写成闭式,再把「达到这个解」改写成能直接梯度下降的损失,走解析路线。这里有个高频追问点:「数学等价」说的是目标等价,不等于实验效果等价——数据流不同(PPO 用当前策略在线造数据,DPO 吃固定的离线集)、归纳偏置不同(PPO 有探索,DPO 没有)、训练动力学不同;同一个目标,两边实际到达的终点并不重合。能主动把这层讲出来,这题就稳了大半。

一句话记住:PPO 解的是「怎么逼近」,DPO 直接拿「解本身」当损失。

4. 场景选择(用 trade-off 说话)

维度PPODPO
数据需求需要 reward model 标注 + 在线采样只需离线偏好对(win/lose)
模块/成本4 个模型,RL 基础设施,慢、贵、不稳2 个模型,纯监督式训练,快、稳、省
探索能力在线采样,能发现新行为、配合过程奖励离线,学不到分布外的新东西
主要坑不稳定、奖励 hacking、工程复杂分布偏移、长度偏好、奖励过拟合
适用要探索上限、有多步/过程奖励、预算足数据现成、追求稳和快、中小团队
选型决策流(先过三问,再谈算法):
  ① 有现成的离线偏好对吗?
       没有 → 先攒数据(SFT/合成偏好),两个算法都无从谈起
       有   → 往下走
  ② 奖励能机器验证吗(代码过单测、数学答案对错)?
       可验证 + 算力足 → PPO/GRPO 类在线 RL,探索上限最高
       不可验证(纯人类口味) → 往下走
  ③ 有 RL 基础设施和调参人力吗?
       没有 → DPO 起步;赢率饱和或开始退化 → 上 iterative DPO 折中
       有   → PPO,或「DPO 打底 + 在线 RL 冲刺」组合拳

2027 年的实际行情:口味类对齐(helpful/harmless)基本 DPO 系打底,可验证能力(数学、代码、Agent 工具调用)用在线 RL 冲刺——面试里能报出这个组合打法,比单独背熟任何一家算法的得分都高。

一句话:数据离线且求稳 → DPO;要在线探索和复杂奖励、预算充足 → PPO;工程上常从 DPO 起步,再上 iterative/online DPO 折中。

面试官追问
Q:DPO 的隐式奖励 r=β·log(π/π_ref) 是怎么推导出来的?
人话:它不是拍脑袋定义的——把「最优策略长什么样」的闭式解反过来解,就得到奖励的表达式,比较时约不掉的公共项再约掉。类比:已知「理想恢复计划 = 基线计划按收益指数放大再归一化」,反推出「收益 = β×log(新计划/基线计划)」;对比两份计划优劣时,共同分摊的归一化项 Z 做差自动抵消——像比较两条备份链路谁快,公共排队底噪一减就没了。技术:对 max 𝔼[r] − β·KL(π‖π_ref) 求变分极值得 π*(y|x)=π_ref·exp(r/β)/Z(x);取对数移项得 r=β·log(π*/π_ref)+β·log Z(x);代回 BT 模型时同一 prompt 下 Z(x) 是常数,win/lose 相减恰好约掉,只剩 β·log(π/π_ref)——奖励不被单独训练,由策略参数隐式给出。
Q:DPO 省掉了奖励模型,为什么还能学出对错?
人话:裁判没有消失,而是并进了选手——策略参数同时干「答题」和「打分」两份工,偏好信号直接写在损失里。类比:像下线独立的校验服务,让存储引擎在读写路径内嵌校验逻辑、共用同一份代码。哪里不像:两者共享参数,「裁判」会跟着「选手」一起漂移——选手学到的偏见裁判照样有,不会像独立裁判那样硬顶着。技术:损失逼着 win 样本的 β·log(π_θ/π_ref) 抬升、lose 压低,等价于在隐式奖励空间做判别;隐式奖励与策略同参同步更新,代价是它只在偏好数据覆盖的区域内可靠,分布外的区域这个内置裁判会乱打分。
Q:DPO 最典型的两个坑是什么?怎么缓解?
人话:一是偏好数据是「别的/旧的模型」生成的,和当前策略分布对不上,越训越偏;二是模型钻空子,最常见是把「答得长」当「答得好」。类比:前者像拿三年前的业务流量画像做容量规划,画像和真实负载早脱节;后者像为了备份窗口达标偷偷砍掉校验环节——窗口指标漂亮,恢复质量崩盘,都是「指标好看了,系统变坏了」。技术:① 分布偏移 → iterative DPO:每轮训完用当前模型重新采样、重新标偏好、再训,让数据分布追上策略;② 长度偏好 → 训练加长度归一化/惩罚、数据配平长短样本,或换 SimPO 这类去掉参考模型、自带长度校正的变体。
Q:训练到后期 DPO 会退化吗(赢率不升反降)?
人话:会,而且是已知现象:loss 还在降,真实赢率却不升反降——优化目标和你要的东西脱钩了。类比:像为了追同步指标把副本数压到极限,数字越来越好看,冗余(多样性)却没了,一点扰动就全挂;模型同样把 win/lose 的隐式分差越拉越极端,输出坍缩成几句车轱辘话。技术:log(π_θ/π_ref) 是无界量,持续压 loss 会把 logit 推向极端——过度自信、多样性崩塌、概率质量坍缩到少数样本。缓解:β 别太小;评估看赢率别只看 loss,及时早停;对 log 比值加 clip;引入长度/熵正则。
Q:为什么顶级模型的数学/代码能力还在用 PPO/GRPO 这类在线 RL,DPO 不够用吗?
人话:不是 DPO 差,是场景变了:数学、代码有「可验证奖励」——单测过没过、答案对不对一测便知,有免费且骗不了的裁判,这时在线探索的价值是真金白银。类比:容灾演练若有确定性 KPI(RTO 是否达标机器可判),当然值得真演练、注入新故障;只有主观口味(「哪个回答更讨喜」)才需要先训一个会看走眼的裁判。技术:可验证奖励(RLVR)配上 GRPO 等 on-policy 算法,模型能采出偏好数据里根本没有的新解法——离线 DPO 只能复读旧卷。工程常见组合:口味对齐用 DPO 系打底,可验证能力用 PPO/GRPO 在线冲刺。
术语卡
PPO:近端策略优化——把新旧策略概率比 clip 在 [1−ε, 1+ε],小步更新防摔崩,RLHF 的标准在线算法。
DPO:直接偏好优化——把 RLHF 目标的闭式解改写成一条二分类损失,免掉奖励模型与 RL 循环。
Bradley-Terry 模型:用奖励差的 sigmoid 建模「两两谁更优」,象棋 ELO 天梯背后的数学。
隐式奖励:DPO 里 r=β·log(π_θ/π_ref),不单独训练,由策略参数间接表达,只在偏好数据覆盖区可靠。
GAE:广义优势估计,用 TD 残差的指数加权组合估计「这步比预期好多少」,平衡偏差与方差。
KL 散度:度量两个分布差多远;RLHF 里当「离参考策略太远就罚款」的护栏。
