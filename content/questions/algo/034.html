Flash Attention 的优化原理

⭐⭐⭐⭐ #论文解读#FlashAttention#优化
30秒电梯稿

"Flash Attention 的核心洞察是:attention 的瓶颈不是算力,而是访存——标准实现把 N×N 的 attention 矩阵和中间结果反复写回显存(HBM),又慢又占内存。它用两个技巧解决:① tiling(分块),把 Q、K、V 切块搬到片上的 SRAM 里就地算,用 online softmax 分块累加,结果和全局 softmax 精确一致;② 重计算(recomputation),前向不保存 N×N 矩阵,反向时现算,用一点额外算力换回显存。效果是显存从 O(N²) 降到 O(N) 级别,训练推理快 2~4 倍,让长序列、大 batch 成为可能。"

通俗类比

把 GPU 想成一个只有一张小工作台(SRAM)、旁边是大仓库(HBM)的车间。标准 attention 是:每算一步中间结果,都要把半成品从工作台搬回仓库、下次再搬出来——搬运(N×N 那么大的一张纸)比干活还累。Flash Attention 的做法是:把原料切成小块,一次只搬一小块到工作台上,当场加工、当场合并,草稿纸用完就扔、下次要了再现算(重计算),省掉来回搬运,所以又快又省地方。

详细拆解

1. 先理解 GPU 内存层次(为什么会有这个优化)

HBM(高带宽显存)SRAM(片上缓存)
容量几十 GB每个 SM 约 100KB~192KB,总量约 20MB
带宽约 1.5~3 TB/s约 19 TB/s(快一个数量级)
角色存所有数据(Q/K/V、输出)算力单元旁边的小工作台

注意力计算本身是几个矩阵乘,FLOPs 不高;真正贵的是把 N×N 的中间矩阵在 HBM 和计算单元之间搬来搬去。所以这是一个 memory-bound 问题,不是 compute-bound。

2. 标准 attention 的问题在哪

  • 显存占用 O(N²):N=4k 时单层单头就是 16M 个 float,多头多卡下直接爆显存。
  • 访存 O(N²):读 Q 算一行、写 S、再读 S 算 softmax、写 P、再读 P……重复读写,带宽全耗在搬运上。

3. 核心技巧一:Tiling(分块)+ Online Softmax

  • 把 Q 按行切块、K/V 按列切块;一次只把一小块 K、V 载入 SRAM,对每块算局部 softmax,结果累加到输出,完成即弃——N×N 矩阵从头到尾不需要完整存在 HBM 里。
  • 难点是 softmax 要除以整行的和(归一化),分块时拿不到。解法是 online softmax:维护一个运行最大值 m 和运行和 l,每处理一块就用新最大值修正旧累加值,数学上与一次算完的全局 softmax 完全等价(不是近似)。
# softmax 数值稳定写法:先减行最大值 m
p_ij = exp(s_ij − m_i) / Σ_j exp(s_ij − m_i) ,   m_i = max_j s_ij
# 分块时维护 running max / running sum,合并时用旧 max 修正旧 sum

4. 核心技巧二:Recomputation(重计算)

  • 反向传播需要 P 和 S 来算梯度,但前向不存它们(省 O(N²) 显存),反向时用 Q、K、V 重新算一遍。
  • 代价是额外 FLOPs;收益是省掉巨量显存和访存——在 memory-bound 场景下净收益为正,这正是"用算力换访存"的思路,和 gradient checkpointing 同源。

5. 复杂度对比与结论

# IO 复杂度(访存量)
标准 attention : 物化 N×N 矩阵, 访存 O(N²)
FlashAttention : O(N²·d² / M)    # M 为片上 SRAM 容量
# 典型 d=64, M≈100KB → 访存下降一个数量级以上
显存: O(N²) → O(N) 级别
  • 效果(论文结论,经验值):训练速度约 2~4×,显存降低 10~20×;因为省显存,可以用更长序列、更大 batch。
  • trade-off:重计算让总 FLOPs 略增;且实现高度依赖 block 尺寸、head 维度等超参,对某些变体(如稀疏 attention、跨长序列的 KV 缓存新布局)需要专门适配。后续 FlashAttention-2 又优化了工作分配和并行调度,继续榨 GPU 利用率。
面试官追问
Q:Flash Attention 不减 FLOPs 反而略增,为什么还更快?
因为 attention 是 memory-bound:瓶颈在 HBM 读写带宽而不是算力。用 roofline 模型看,标准实现的算术强度(每字节访存能换多少算力)很低,卡在带宽墙上;Flash Attention 大幅减少访存、提高算术强度,虽然多算了点,但整体 wall-clock 更快。答出"先判断是 compute-bound 还是 memory-bound"是这道题的加分点。
Q:分块 softmax 怎么保证和全局结果完全一致而不是近似?
关键在 online softmax:维护运行最大值 m 和运行和 l。新处理一块时,若出现更大的新 max m_new,就把旧累加和按 l_new = l_old·exp(m_old − m_new) + Σexp(s − m_new) 修正,最后用 l 归一化。这和"先全局求 max、再减 max 求 exp 求和"的两遍法在数学上等价,只是流式完成,所以是精确结果。
Q:反向传播不存 attention 矩阵,梯度怎么算?
用重计算:前向只保存 O(N·d) 量级的 Q/K/V 和一些统计量(如 logsumexp),反向时用它们重新算一遍 P 和 S 来求梯度。这是典型的"算力换显存",和 gradient checkpointing 一个思想;代价是前向/反向各多一遍计算,但对访存敏感的 attention 净收益仍为正。
Q:Flash Attention 有什么局限,后续怎么改进的?
局限:① 实现和 block 尺寸、head 维度耦合,不是所有形状都最优;② 主要面向普通 GPU 的稠密 attention,稀疏/新注意力变体要专门实现;③ 重计算带来的额外算力在高算术强度场景下收益会收窄。后续 FlashAttention-2 优化了线程间通信和并行划分(减少非 matmul 部分的浪费),进一步贴近 GPU 理论峰值。
术语卡
HBM/SRAM:GPU 两级内存,容量与带宽互换(HBM 大而慢,SRAM 小而快)。
Memory-bound:瓶颈在访存带宽而非算力的计算。
Tiling(分块):把大矩阵切块在片上就地处理,避免整块搬运。
Online Softmax:流式维护 max 与 sum 的分块 softmax,结果精确。
Recomputation:反向时重算中间结果,用算力换显存。
IO 复杂度:衡量算法读写存储量(访存)的指标。
