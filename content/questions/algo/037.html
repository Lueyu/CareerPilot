评估讨论 · Q13

你如何看待Agent领域的"涌现能力"？我们应该追求更强大的基础模型，还是更精巧的Agent架构？

⭐⭐⭐ #涌现能力#技术路线 字节 / 阿里
先说人话:这题是两问:『涌现能力』是真实现象还是统计错觉;资源该砸给更强基座,还是更精巧的架构。面试官爱考它,因为它专治站队——把涌现吹成玄学的,和一口咬定全是炒作的,都暴露你没做过真实选型;干过活的人会先拆题、谈取舍,拿评测数据说话。
30秒电梯稿

"我分四句讲。第一,涌现是真实存在但被过度神化的现象——像思维链、上下文学习这类能力,确实常在模型规模越过某个临界点后突然显现,但它是事后观察到的统计结果,不是能写进方案的工程原理。第二,反方证据也要认:换把平滑的尺子,不少『突变』会还原成平缓爬坡,说明部分涌现是评测指标量出来的错觉。第三,基座和架构不是二选一:基座决定能力上限,架构决定这个上限在具体任务上能兑现几成,是乘法不是加法。第四,我的工程路线是『基座为底、架构为桥、评估为尺』——基座选强不选怪,架构做薄不做厚,谁好谁上,拿评测数据仲裁。"

通俗类比

涌现(用备份系统的重删率曲线想):先别管论文定义,想一条你见过的曲线——数据去重率随数据集规模的变化:存量小的时候重复块稀稀拉拉,重删率平平无奇;等存量跨过某个规模,每日增量高度相似,重删率陡然蹿升,像系统突然"学会"了省空间。涌现就是这个现象的模型版:某些能力(多步推理、在上下文里现学新任务)在规模跨过临界点前接近随机猜,跨过后突然显现。

哪里像:都是"规模带来的新性质"——盯着单份数据或单步训练,完全预测不出整体行为。哪里不像:重删率跃升的机理清清楚楚(重复块命中概率随规模上升),可复现、可规划;而涌现的内部机制至今还在研究,临界点在哪、涌现什么,事先不可知,只能事后观察——这决定了它不能当工程依据。

基座与架构(用介质上限与系统设计想):把基础模型想成存储介质的原生能力——盘的顺序吞吐、单盘 IOPS 是硬上限;把 Agent 架想去成缓存、条带、预读、调度这层软件设计——它决定你实际兑现上限的几成。至于涌现本身,更像水到 100°C 的相变:温度(规模)连续升,沸腾(能力)却在阈值处突然出现。

哪里像:两者是乘法——单盘再快,没有缓存与调度照样被随机小 IO 打死;软件调校再好,也造不出介质没有的带宽,这正是"基座定上限、架构管兑现"。哪里不像:介质升级是所有人都能买到的外部红利,而你的架构与评测资产是内部沉淀——对手能买到同一款 NVMe,买不走你的分层策略和失败样本库;另外新盘不继承旧盘状态,新基座却往往继承并放大旧能力,所以模型升级的红利比换介质更平滑。

详细拆解

1. 涌现的证据与反方观点(先把"它存不存在"讲清楚)

  • 正方:Wei et al. (2022) Emergent Abilities of Large Language Models 给过明确定义:某能力在小模型上"不存在、且不能由小模型的表现外推预测",在大模型上"突然出现且表现陡增"。像 few-shot 上下文学习、思维链推理、多步算术这类任务,在小模型上曲线贴着随机猜的水平,规模越过某个量级后性能突然跃升,呈现"涌现"特征——能力在规模轴上不是渐显,而像被开关一下打开。
  • 反方:Schaeffer et al. (2023) Are Emergent Abilities a Mirage? 提出这类"突变"很可能是评测指标的伪影——用"精确匹配""多项选择全对才给分"这类非光滑指标衡量时,模型内部连续平滑的提升会被拍平成"0→1"跳变;作者甚至反过来人为构造指标,证明只要尺子选得够"刁",涌现想要多陡有多陡;换成平滑指标(困惑度、逐 token 对数概率)后,多数"涌现"还原成平缓单调的改进。
  • 为什么多步任务最容易"看起来涌现":因为链路是串联的。假设单步内部成功率随规模从 60% 平滑爬到 95%,那么十步全对的总成功率就是 0.6¹⁰≈0.6% 到 0.95¹⁰≈60%——内部每一步都在缓慢变好,链路却在某个规模段"突然能用"。这不是玄学,是串联系统的老数学,做过备份链路成功率统计的人一眼就熟。
  • 我的综合判断:涌现"部分真实、部分是被指标放大"。确实存在质变(如能稳定执行多步推理),但把它当成"只要堆规模就自动获得一切能力"的神话,是错的。更稳的表述是:能力随规模连续爬坡,而应用只认"过线",于是体感上出现"从不可用到可用"的跳变。
  非光滑指标:"全对才给分"              平滑指标:逐 token 对数概率

 成功率 1.0 ┤               ╭─────   对数概率 0 ┤           ╭────
            │            ╱                      │         ╱
            │           ╱                       │       ╱
            │          ╱   ← 规模轴上"突然会了"  │     ╱  ← 内部一直在缓慢变好
          0 ┼─────────╯                    -3.0 ┼─────╯
            └─────────────► 模型规模           └─────────────► 模型规模

        同一条能力曲线,左边量出"涌现式跳变",右边量出"平缓爬坡"

顺带把理论底座摆出来:支撑"堆规模"路线的是缩放定律(Kaplan et al., 2020)——损失随参数量、数据量、算力呈幂律下降,"更大=更好"可以外推;后来 Chinchilla 修正了参数与数据的最优配比,但幂律本身没有被推翻。涌现之争,本质是这条幂律曲线上"哪里有拐点、拐点是不是指标造成的"的争论。

2. 为什么"涌现"不能作为工程依据

  • 不可规划:你没法在立项书上写"等模型再大 10 倍,这个能力会涌现出来"——临界点在哪、涌现出什么,事先不可知。就像没人敢在备份容量规划里写"数据将来会自己高度重复,重删比到时候自然上去"——容量规划只认实测重删比,不认感觉。
  • 不可依赖:就算观察到某能力"涌现",它也可能随 prompt 的微小变化、版本升级而回退,不能当稳定 API 用。给业务方承诺 SLA 时,只能建立在被评测回归覆盖的能力上,不能建立在"最近感觉它变聪明了"上。
  • 正确用法:把"涌现"当成探索期的信号——它提醒你"这个方向值得加评测盯着、值得拿新模型小流量试",而不是"直接全量上线"。工程上只认评测回归和灰度发布,不认"感觉变强了":新基座先进灰度流量,验证通过率没有回退再逐步放量,这是把涌现红利变成可交付能力的唯一安全路径。

3. 基座 vs 架构:拆掉这个伪对立,先把它写成能算的式子

路线之争之所以吵成二选一,多半是没把关系写清楚。我的模型是一条乘法:

        任务真实成功率 ≈ 基座能力上限 × 架构兑现率

   ┌─────────────────┬──────────┬──────────┬──────────┐
   │ 组合             │ 基座上限  │ 兑现率    │ 实际成绩  │
   ├─────────────────┼──────────┼──────────┼──────────┤
   │ 强基座 + 薄架构  │   90     │   0.80   │   72     │
   │ 弱基座 + 厚架构  │   50     │   0.95   │   47.5   │
   │ 弱基座 + 薄架构  │   50     │   0.60   │   30     │
   └─────────────────┴──────────┴──────────┴──────────┘

   架构把兑现率从 0.60 抬到 0.95 已是优秀工程,仍救不回 40 分的上限差
   ——这是"基座选强不选怪"的算术版;反过来,90 分上限配 0.3 的兑现率
   也只有 27 分,只堆基座不修架构同样翻车。
维度更强的基础模型更精巧的 Agent 架构
解决什么推理、知识、指令遵循的"硬上限"把能力定向兑现到具体任务、控制成本与可靠性
典型收益少写 prompt 补丁、少做兜底、边界能力直接解锁成本降一个量级、可观测可控、可迭代回滚
典型代价贵、慢、不可控,且"更强"很快被追平研发成本高、过度设计会变脆、易过拟合场景
何时优先任务难、通用性强、预算宽裕任务边界清晰、量大、需要稳定低成本
失效方式版本升级后能力回退、接口漂移,所有接入点要重测场景一漂移,过拟合的设计失效,补丁越叠越难维护
谁能复制外部红利,竞对同样买得到内部资产,沉淀的是流程与失败样本库

读表的姿势是按行对照自己的项目,真问题永远是:当前项目的瓶颈因子是哪一个。还有一行容易被忽视——"谁能复制":基座是外部红利,护城河不在基座里,而在架构与评测资产的沉淀里,这也是"基座选强"通常对、"全靠基座"通常不对的原因。

补一个实战边界情形:弱基座+厚架构,在窄场景里确实能逼近强基座+薄架构,但那是拿过拟合场景换的——用户问法一漂移、长尾请求一多,厚架构里的补丁开始互踩,维护成本反噬;而强基座的泛化能力是白送的。所以:窄而稳、量又大的存量任务,可以上"弱+厚"省钱;新场景、开放任务,默认"强+薄"起步。

4. 我的落地结论:基座为底、架构为桥、评估为尺

         │                                       │

  升级基座,买硬上限                       修架构,提兑现率

        对照实验:谁的任务成功率/成本比高,谁先进灰度
             (评测回归盯住无回退后,再逐步放量)
  • 基座选强不选怪:直接选当前性价比最高的一线模型,别在"用弱模型堆架构"上浪费精力——弱模型的判断力不足集中在工具选择、计划质量、错误恢复这些环节,恰好是架构最难补的。这也是 Rich Sutton 的The Bitter Lesson 的工程翻译:长期看,押注算力与规模的通用路线,总会吃掉押注人类先验的精巧设计。
  • 架构做薄不做厚:先用"单 Agent + 少量工具"(比如一个 ReAct 式的推理-行动循环)把业务跑通,再按真实瓶颈(成本、失败率、可观测)逐层加编排,而不是一上来画一张 10 节点的 Multi-Agent 大图。每加一层都过评测回归,并且默认"下一版基座会碾掉这层补丁",把它做成薄、可拆卸的模块。
  • 用评测仲裁:同任务上做"强基座+简单架构" vs "弱基座+复杂架构"的对照,谁的任务成功率/成本比高就上谁;新基座到岗先灰度放量,评测回归盯住回退再全量。路线之争的终点,永远是数据,不是情怀。
面试官追问
Q:有人说涌现只是评测指标的假象(Schaeffer),你怎么反驳或认同?
人话:我一半认同:拿不合适的尺子量,确实能量出假涌现;但也有换什么尺子都还在的真跳变,不能一棍子打死。类比:就像看备份演练的"整链路成功率":内部每步成功率从 60% 平滑爬到 95%,十步全对的总成功率却从 0.6% 猛跳到 60%——链路本身没突变,是"全对才算成功"这把尺子把连续爬坡拍成了跳变。技术:Schaeffer et al. (2023) 证明非光滑指标(精确匹配、多项选择)会把平滑提升非线性放大成"涌现",并用人为设计的指标复现了假涌现;但多步推理等能力换用对数概率等连续指标后仍有明显不连续。我的结论:突变幅度被高估,能力质变真实存在。
Q:如果预算有限,只能二选一:升级更强的模型,还是花人力优化架构?
人话:先测再选:失败是"模型不行"就升基座,是"编排不行"就修架构,拍脑袋选哪边都可能白花钱。类比:备份吞吐上不去,老师傅从不先买 SSD——先 profile 看瓶颈在介质层还是调度层:介质原生带宽不够,加缓存无用,换盘(对应升模型);介质够快而调度烂,换盘白花钱,改软件(对应改架构)。技术:先跑基准评测并逐条归因:判断力类失败(答非所问、推理断裂、幻觉)指向升基座,吃持续的外部红利;工程类失败(工具调用错、上下文超限、成本超支)指向修架构,收益一次性但有上限。再算账:模型升级是经常性账单,架构人力是一次性投入,拿"成功率/成本"对照后拍板。
Q:你怎么判断一个能力是"真涌现"还是"指标幻觉"?
人话:换尺子量、换环境锤、拆开看机理,三关全过才认。类比:像验证 RTO:不能只看一次演练"切换成功",要拆开看每步耗时是否稳定达标,确认是机制在起作用,还是恰好没有脏数据、没有并发冲突的运气好。技术:① 跨指标:把精确匹配换成连续指标(逐 token 对数概率、语义相似度),看曲线是否仍跳变;② 跨 prompt/跨版本:做措辞扰动和版本回归,看能力是否稳健、会不会随小改动回退;③ 归因拆解:检查中间推理步骤是否真的正确,排除高频模式背诵。三关都过,才敢写进能力清单。
Q:"小模型+复杂架构"能不能打平"大模型+简单架构"?什么情况下值得这么赌?
人话:窄场景能打平甚至更省钱,但任务一宽、输入分布一漂,复杂架构的脆性和维护成本就会反噬,不该当默认路线。类比:像用一批 SATA 盘加精巧的缓存分层去追一块企业级 NVMe:固定读模型下能调出好看的数字,一旦变成随机写、长尾请求一多,就得推倒重调;而 NVMe 是生下来就快,赢在介质不在调校。技术:弱模型的短板集中在工具选择、规划质量、错误恢复——恰是架构最难兜的环节;重试与强制流程能兜住已知模式,对分布外输入泛化差。建议反过来做:先用强模型跑通拿到真实日志,再按难度把低风险流量路由给小模型分级降本——先有基线,再谈降本。
Q:基座每代都在变强,今天做的架构优化会不会被下一代基座"碾过"、白做?
人话:会有一部分被碾过,所以要先分清:补模型短板的优化会作废,业务固有的不会,优先沉淀后者。类比:介质从磁带换到 SSD,一茬一茬地换,但"恢复优先于备份"的原则、校验与演练流程不随介质淘汰;而"为换带延迟专门写的优化"确实随介质升级作废。技术:把架构拆两类对待:补短板型(幻觉校验、强制格式化)做成薄的可拆卸模块,新基座到位时用评测回归快速清理;业务固有型(权限、审计、成本路由、多步流程的状态管理、评测资产)持续沉淀。这样每次基座升级都是红利到账,而不是重构灾难。
术语卡
涌现:能力随模型规模跨过临界点而突然出现的现象,事后可观察、事前难规划。
缩放定律:模型性能随参数量、数据量、算力呈幂律变化的经验规律,是"堆规模"路线的理论底座。
思维链:让模型把中间推理步骤显式写出来再作答,大幅提升多步任务表现。
上下文学习:不更新权重,仅凭上下文里的 few-shot 示例完成新任务。
非光滑指标:"全对才给分"的一类评测指标,会把平滑提升拍成伪跳变,是"涌现幻觉"的主要来源。
苦涩教训:Sutton 的论断——长期看,押注算力与规模的通用方法总会胜过押注人类先验的精巧设计。
