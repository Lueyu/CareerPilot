Agent核心 · Q15

训练 LoRA 模型时，你是如何选择冻结层的？依据是什么？

⭐⭐⭐ #LoRA#层选择 字节(真题)
先说人话:这题在问:微调大模型时,哪些层锁死不动、哪些层允许改,你的决策依据是什么。面试官爱考它,是因为它一眼分清「只会调库的人」和「懂模型结构的人」——只会调库的人答"LoRA 自动处理",连自己动了哪些权重都说不出;能讲清"改调度还是改存储"这套取舍的,才是干过活的。
30秒电梯稿

"结论先行:冻结全部预训练权重(基座),只在注意力层的投影上挂低秩适配器。默认起点是在 Q/K/V/O 四个投影层各挂一个 LoRA(工程上也有只挂 Q/V 或 Q/K/V 的省参数变体);Embedding 和 LayerNorm 通常也一并冻结。依据三条:① 参数效率——冻结基座让可训练参数降到百万级,显存和算力下降几个数量级;② 效果够用——原论文表明只调注意力投影就足以逼近全参微调;③ 防灾难性遗忘——基座只读,通用能力物理上不可能被洗掉。任务更难、要灌新知识时,再扩展到 FFN 层或调大 rank,每一步扩展都拿任务分和通用能力回归分护航。"

通俗类比

先搞懂「冻结」到底冻的是什么(用存储快照想):LoRA 相当于给基座权重打一张只读快照——任何改动不允许落在原卷上,全部写进旁边一块极小的 overlay 卷(低秩适配器)。前向计算时数据走两条路:一条读原卷(W₀·x),一条读 overlay(B·A·x),结果相加输出。哪里像:和备份系统里「基线卷只读、增量落差异卷」一模一样——基线永远干净,回滚等于卸载 overlay,一份基线还能挂多块不同 overlay 服务不同任务(多 LoRA 共享一个基座)。哪里不像:存储里 overlay 只是为了省空间和一致性,LoRA 是为了省显存加防遗忘;而且这块「增量卷」本身还要被低秩压缩一次——rank 就是给增量预留的带宽,后面细讲。还有个精妙对应:LoRA 把 B 矩阵零初始化,等于 overlay 初始为空——训练第 0 步模型行为与基座分毫不差,一切变化从零累积,挂上去不会立刻改变行为。

为什么挂注意力、冻 FFN(用「调度层 vs 存储层」想):一个 Transformer block 里,注意力层像查询引擎/调度器——决定这一步「看哪些信息、取多少」;FFN(前馈层)像背后的存储集群——研究认为大模型的事实知识主要存在 FFN 权重里。所以选层的逻辑和你改系统一样:要改「怎么干活」(风格、格式、指令遵循)就动调度;要灌「新数据」(领域知识)就得动存储。Embedding 则是所有层共享的全局编址表,动它牵一发动全身;LayerNorm 是链路上的归一化配置,参数极小但影响每一笔「读写」,默认不碰。

详细拆解

1. LoRA 的数学原理(先讲清楚在冻结什么)

把权重更新分解成两个低秩矩阵的乘积,只训练这两个小矩阵:

h = W₀·x + ΔW·x = W₀·x + (B·A)·x
# W₀: 冻结的原始权重  d×k
# A ∈ R^(r×k): 降维矩阵, 高斯初始化
# B ∈ R^(d×r): 升维矩阵, 零初始化
# r << min(d,k): 秩, 常取 8/16/32
# 缩放因子 α/r; B 初始为 0, 保证训练开始时 ΔW=0

冻结的正是 W₀:不参与反向传播、不存梯度与优化器状态;可训练参数只剩 A、B。这一下省掉的显存是三个数量级——全参微调时(AdamW + 混合精度),每个可训练参数常备约 16 字节(fp16 权重 + fp32 主权重 + 梯度 + 一阶/二阶动量各一份),7B 模型光这些就要 100GB 量级,单卡 80G 根本放不下;挂 LoRA 后可训练参数只有几千万,这部分开销变成几百 MB,几乎归零。这就是「冻结」二字的全部含金量——等于把全量重写改成只写增量,且增量还要低秩压一道(LoRA 原理见 LoRA 论文,低秩近似背景见 low-rank approximation)。

为什么低秩可行?因为 ΔW 名义上是 d×k 的大矩阵,但「任务需要的改变量」信息密度极低——就像增量备份里整个卷看起来很大,相对基线真正变化的块只占一小部分;相关研究(内在维度)表明大模型适配一个任务真正需要的自由度远小于参数量,LoRA 论文正是据此提出「权重更新的本征秩很低」这个核心假设。

前向计算:数据走两条路,一路只读、一路可写,结果相加(就是"基线卷只读 + overlay 卷可写")

              ┌──────────────────────┐
   x ────────►│  W₀   (冻结,只读快照)    │────┐
              └──────────────────────┘    │    (+) ──► h 输出
              ┌──────────────────────┐    │
   x ────────►│  B·A  (可训练,小增量卷)  │────┘
              └──────────────────────┘

   回滚 = 卸载增量卷,基线原封未动;换任务 = 换一块增量卷,基线直接复用

2. 冻结什么、训练什么(层级清单)

先把一个 Transformer block 剖开,看清楚各模块的位置和体量,再谈谁动谁不动:

一个 Transformer Block 的剖视图(每层都长这样,大模型堆几十上百层)

                 输入 x
                    │
            ┌───────┴────────┐
            │    注意力部分     │        ← 挂 LoRA 的主战场
            │  Q投影  K投影  V投影│        (四个 d×d 方阵,共 4d²,
            │    ↓     ↓     ↓  │         约占 block 参数的 1/3)
            │      注意力计算    │
            │        ↓        │
            │      O投影       │
            └───────┬────────┘
                    │
            ┌───────┴────────┐
            │   FFN/MLP 部分   │        ← 默认冻结
            │   升维 d→4d     │         (两个大矩阵共 8d²,
            │      激活       │          约占 2/3,被认为
            │   降维 4d→d     │          存放着知识)
            └───────┬────────┘
                    │
        (层间还有 LayerNorm ×2,参数极小,默认一并冻结)
                 输出 → 下一层

注意力的四个投影用检索类比很好记:Q 是查询语句、K 是索引里的键、V 是存的内容——用查询去匹配键,按匹配度加权取回值;O 投影把取回的信息汇总整形往下游送。在 Q/K/V/O 上挂 LoRA,改的就是「查询和取数的方式」。落到清单上:

模块默认处理原因
注意力 Q/K/V/O挂 LoRA(核心)语义表征最敏感,收益最大
FFN / MLP 层通常冻结存储"知识",动它易忘且参数更多
Embedding冻结(除非换词表)大且与任务无关,微调易过拟合
LayerNorm冻结或极小 lr 训练参数量小但影响分布,一般不动

这张表再补一个体量感:Embedding 是「词表大小 × 隐藏维度」的查找表(如 5 万词 × 4096 维 ≈ 2 亿参数),是全局共享的编址表——任何一个下游任务去改它,收益低、风险大,像让某个应用去改共享元数据服务一样不划算。

3. 为什么"挂注意力、冻 MLP"(选择依据)

  • 效果依据:原始 LoRA 论文(Hu et al., 2021)在 GPT-3 上的实验表明,只对注意力层的 Q、V(甚至仅 Q/V 的一部分)加 LoRA 就能匹配全参微调——rank=8 时可训练参数仅约 4.7M,检查点体积缩小约一万倍;挂到全注意力层(Q/K/V/O)通常是最稳的默认起点,收益曲线更平、不挑任务。
  • 成本依据:注意力投影的参数量比 FFN 小一个量级(每 block 约 4d² 对 8d²),挂 LoRA 后可训练参数只占基座的万分之一到千分之一,显存、多卡梯度通信、检查点体积全面下降——检查点从「每层 GB 级」变「每层 MB 级」,多实验并行迭代时这是实打实的吞吐。
  • 遗忘依据:全参微调的更新直接覆盖原权重,像在唯一生产卷上原地改写——新任务的梯度会把旧能力所在的权重方向冲掉,这就是灾难性遗忘;冻结基座从机制上杜绝了"学新任务把旧能力洗掉",这是做多任务/持续学习时的关键诉求。

4. 什么时候打破默认(重要 trade-off)

  • 下游任务与预训练分布差异大(如从通用语料微调到代码/医疗专域),可加挂 FFN 的 LoRA 或调大 rank,补足容量——因为这时缺的是「新知识」,调度改得再漂亮也查不到不存在的东西(FFN 存知识的证据见 Transformer FFN as Key-Value Memories)。
  • 数据少、任务简单:r=8~16 已够,挂 Q/V 甚至更省;数据多、任务难:r=32~64,并考虑 Q/K/V/O + FFN 全挂。原则:把容量预算花在验证集涨分的地方。
  • QLoRA:把基座量化到 4-bit 再冻结,LoRA 反向传播时反量化计算,进一步把显存压到单卡可微调大模型;这是资源受限时的首选(原理见 QLoRA 论文)。类比:像把归档做成压缩态存放、读时按需解压——体积换一点解压开销,对备份工程师再熟悉不过。
  • 先冻结后解冻:也有"LoRA 预热 + 最后解冻 LayerNorm/部分层小幅精调"的做法,但工程上收益不稳定,默认不推荐(面试里补一句"试过、不稳"反而显得真做过实验)。
  • 护栏:每次扩层或调 rank 都跑两套指标——下游任务分 + 通用能力黄金集回归(改动必跑恢复演练的习惯),防止「任务分涨了,基座的通用能力被适配器带崩」。

最后把决策收拢成一张施工单,面试照这个顺序讲就是完整闭环:

默认起点:冻结全部基座 + 注意力 Q/K/V/O 挂 LoRA(r=16, α=2r)
    ↓ 验证集效果不够?
任务偏"风格/指令遵循"  → 先改数据与 prompt,再考虑加大 r
任务要注入"新知识"    → 加挂 FFN 层的 LoRA
分布偏移大(代码/医疗) → Q/K/V/O + FFN 全挂, r=32~64
显存仍吃紧           → 降级 QLoRA(4-bit 冻结基座)
全程双护栏:下游任务分 + 通用能力回归分,一降就回退

能把「默认全冻 + 注意力挂载、按需扩 FFN/调 rank、双护栏验证」讲成一条决策链,这道题就从背答案变成了做工程。

面试官追问
Q:为什么不微调 Embedding 层?
人话:词表嵌入是所有层共用的「全局编址表」,动它成本高、收益低,还容易把整表语义带偏。类比:像备份系统里全局共享的块编址/元数据表——某个应用改它的收益很小,但改坏了所有引用它的数据全乱;正确姿势是保持只读,除非真的要换编址方案(换词表)。技术:① 参数规模大(词表 × 隐藏维度,5 万词 × 4096 维 ≈ 2 亿,占模型相当比例),微调它优化器显存显著上涨;② 它学的是通用 token 语义(word embedding),对单个下游任务收益低且易过拟合;③ 冻结有利于跨任务一致性。例外:扩词表注入领域新 token 时,新增行必须训练,旧行仍冻结。
Q:只挂注意力层什么时候不够?
人话:当任务要「学新事实」而不只是「换种说法」时,只动注意力就不够了。类比:注意力是调度层,FFN 是存储层——只改调度,查询计划再漂亮,后端存的还是旧数据;要灌新知识必须动存储。技术:研究(FFN as Key-Value Memories)表明事实知识主要存在 FFN 权重里,冻结 FFN 时模型难以真正吸收新事实,只能靠注意力重组旧知识。所以风格迁移、指令遵循这类「已有知识重排」的任务只挂注意力很稳;注入大量领域知识、分布远离预训练时要挂 FFN、调大 rank,甚至考虑全参微调。能区分「重排已有知识」和「学习新知识」,是这道题的高分点。
Q:rank 怎么选?
人话:从小往大试,验证集收益趋平就停,不要一上来就 256。类比:像给增量备份预留带宽——先小档,压不住再升档;一上来顶格配置既浪费容量,还容易把噪声也存进去(过拟合)。技术:经验:小任务 r=8~16 足够,复杂任务 r=32~64;理论上 ΔW 是低秩的,秩太小欠拟合、太大过拟合且逼近全参的成本,LoRA 论文引出的「intrinsic rank」说明任务真正需要的秩往往远小于满秩。另外注意 α/r 缩放:调 rank 时要同步调 α(一般保持 α ≈ 2×r 的比例),否则有效学习率会漂,实验得出「调了 r 反而变差」多半栽在这里。
Q:为什么 B 用零初始化、A 用高斯初始化,反过来行不行?
人话:保证挂上适配器那一刻,模型行为和基座分毫不差,一切变化从零开始累积,且训练能正常起步。类比:overlay 卷初始必须是空的——若初始就有脏数据,挂载瞬间生产流量行为就变了,回滚和排查都无从谈起;而 A 保持非零,相当于「写通道是通的」,第一个增量才写得进去。技术:B=0 ⇒ ΔW=BA=0,前向输出严格等于基座;A 若也为零,则 A、B 的梯度互相依赖对方,双双恒为零,适配器永远学不动(梯度死锁);A 高斯初始化打破对称,梯度经由 A 流向 B,ΔW 平滑地从 0 长出来。反过来(A 零、B 高斯)同样满足 ΔW=0,数学上对称可行,但社区约定俗成前者——关键是「乘积为零起步 + 至少一侧非零」这两个条件。
Q:训练完的 LoRA 能合并回基座吗?什么时候该合、什么时候不该?
人话:能,把 B·A 算出来直接加到 W₀ 上,模型变回一个普通模型,推理零额外开销。类比:像给增量卷做一次「合成全量备份」——此后读路径不再两跳(基线+增量),单卷直读,还省掉 overlay 的挂载管理。技术:W' = W₀ + BA,与前向两路相加数值完全等价,可离线合并再部署,推理框架无感知。取舍:合并后这份权重只服务这个任务;要多任务共享基座(各任务挂各的 LoRA、运行时热切换),就保留基座 + 按需加载适配器——一份基线镜像服务多个差异副本,这正是 LoRA 在部署侧比全参微调优雅得多的地方。
术语卡
LoRA:冻结基座、把「权重该改多少」压缩成两个小矩阵的乘积来训练的微调方法。
低秩分解:用「瘦高 × 矮胖」两个小矩阵的乘积近似大矩阵,LoRA 省参数的全部魔法所在。
rank:低秩矩阵的秩,适配器的容量旋钮——小了装不下改变量,大了费显存、易过拟合。
QLoRA:把冻结的基座再压成 4-bit 只读存放、训练时反量化计算,单卡微调大模型。
灾难性遗忘:学新任务把旧能力洗掉;冻结基座等于机制级防遗忘。
FFN(Key-Value Memory):Transformer 的前馈层,被认为是大模型存放事实知识的地方——灌新知识绕不开它。
Embedding:把 token 映射成向量的全局查找表,所有层共享,像全局编址表,默认冻结。
