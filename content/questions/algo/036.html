最近读过的 Agent 前沿论文

30秒电梯稿

"我按「问题 → 方法 → 实验 → 局限」四段讲一篇。以 ReAct 为例:问题是传统把推理(CoT)和行动(调工具)割裂——纯推理会幻觉、过时知识;纯行动短视、没规划。方法是让 LLM 生成 Thought → Action → Observation 交替的轨迹,在 few-shot prompt 里就实现,不改参数。实验在 HotpotQA/Fever 上,ReAct 超过纯行动 baseline,与 self-consistency 结合后达到当时最优,且更少幻觉、更可解释。局限是工具单一、长轨迹易发散。一句话:它证明了"推理和行动能互相增益",奠定了后续 Agent 工具调用的范式。"

通俗类比

就像考试时答题的三种学生:第一种"只想不查"(纯 CoT)——逻辑头头是道,但知识点记错了还硬编;第二种"只查不想"(纯行动)——翻书翻到哪算哪,漫无目的;ReAct 是第三种"想一步、查一步、看结果、再想一步"——先想"我该查什么",查完看结果再判断下一步。外部事实纠正了瞎编,推理又给翻书指了方向,两者配合才答得又快又对。

详细拆解

1. 备选论文速览(面试先亮菜单,证明你在跟踪前沿)

论文一句话:解决什么问题 → 怎么做
ReAct(2023)推理与行动割裂 → 让 LLM 生成 Thought/Action/Observation 交织轨迹
Toolformer(2023)模型不会主动用工具 → 自监督学会在文本里插入 API 调用
Reflexion(2023)一次试错就完蛋 → 用「语言化反思」存进记忆,重试时吸取教训
Voyager(2023)开放世界里技能不会积累 → 代码当技能 + 技能库,终身学习
MetaGPT(2023)多 Agent 缺乏组织 → 模拟软件公司 SOP,角色分工流水线协作

2. 以 ReAct 为例:问题(Problem)

  • CoT 只推理不查外部信息,面对多跳问答、需要最新事实的任务会幻觉、用过时知识硬编。
  • Act-only 只调用工具不推理,缺乏规划,检索/行动像无头苍蝇。
  • 核心假设:推理和行动不是二选一,而是互补——推理给行动提供目标与分解,行动给推理提供外部事实、抑制幻觉。

3. 方法(Method):交织的 Thought/Action/Observation 轨迹

  • 用 few-shot 提示给模型几条标注好的轨迹,模型照格式生成,不更新参数。
  • Thought 负责:分解问题、跟踪进度、处理异常(检索结果不对就换词);Action 调用外部工具(论文里是 Wikipedia Search);Observation 是工具返回,喂回给下一步。

4. 实验(Experiment)

设置HotpotQA(EM,多跳问答)
仅行动(Act)约 25.7
仅推理(CoT)约 29.4
ReAct约 27.4
ReAct + CoT-SC(自洽采样)约 35.1(当时最优)

数字来自论文的 prompting 设置,不同模型/复现略有出入,精确值以原文为准。结论方向是稳的:ReAct > 纯行动,且与 CoT 自洽结合后反超纯 CoT。

  • 关键结论:① ReAct 显著优于 act-only(证明"推理引导行动"有用);② ReAct+CoT-SC 优于 CoT-SC(证明"行动提供的真实信息反哺推理");③ 在 Fever(事实验证)上同样优于纯行动,且生成内容更少幻觉、更可解释。

5. 局限与改进(主动讲,面试官爱听)

  • 工具单一(只有 Wikipedia 检索),真实场景要扩展到多工具/代码/API。
  • 长轨迹容易发散、重复调用、token 成本高 → 后续用反思(Reflexion)、工具结果缓存、轨迹压缩解决。
  • few-shot 依赖人工标注轨迹 → 可用合成数据/自举减少标注。
  • 不更新模型参数,深层规划能力受限 → 可结合微调或强化学习。

6. 讲论文的通用框架(方法论,换任何一篇都成立):① 先点痛点(之前方法为什么不行);② 一句话说清方法核心机制;③ 给实验证据(对比了谁、赢在哪、数字约多少);④ 主动谈局限与可改进。四段齐全,面试官就知道你是"读过"而非"刷过摘要"。

面试官追问
Q:为什么不选更新的论文(如 Voyager / MetaGPT),而选 ReAct 这种稍早的?
ReAct 是"推理+行动"范式的奠基工作,ReWOO、Reflexion、Toolformer 乃至现在的 function calling 都建立在它之上,把它讲透最能体现基本功;同时我会补一两篇新论文说明我在跟踪前沿。反过来讲,选新论文的关键是能说清"它比 baseline 到底新在哪、牺牲了什么"——讲不出增量,再新的论文也白搭。
Q:ReAct 的贡献不就是 prompt 里多写几个词吗,创新点到底在哪?
表面是 prompt 工程,实质是两个洞察:① 从实验上证明"推理和行动互补"——推理提升信息检索与事实一致性,行动给推理提供外部事实、抑制幻觉,单干都不行;② 给出了可复用的 Thought/Action/Observation 轨迹格式,成为后续工具调用、Agent 循环(观察→思考→行动)的通用骨架。范式价值和实验证据一起,才是它被大量引用的原因。
Q:你会怎么改进 ReAct 的局限?
四方向:① 扩展到多工具与代码执行,并加工具选择的纠错;② 引入反思与记忆(Reflexion 思路),把失败经验存下来避免重复犯错;③ 用轨迹压缩/摘要控制长上下文成本,防止发散;④ 从纯提示升级到微调或 RL,让模型内化规划能力,而不是每次都靠 few-shot 示范。
Q:面试官问你"最近读了什么论文",最在意什么?
在意四件事:① 能说清问题痛点和"为什么之前方法不行";② 方法核心机制能一句话讲透,而不是背摘要;③ 实验证据——对比了谁、赢在哪、数量级大概多少;④ 敢讲局限。四段齐全说明真读过;只会背标题和结论,大概率是二手摘要。
术语卡
ReAct:Reasoning + Acting,推理与行动交织的提示范式。
Chain-of-Thought:让模型一步步写出推理过程再给答案。
Few-shot prompting:给几个示例引导模型按指定格式输出。
Observation:工具返回的结果,供模型下一步思考。
Self-Consistency:多次采样投票取多数,提升推理准确性。
Thought/Action/Observation:Agent 工具调用的通用循环骨架。
