长上下文建模的注意力机制优化

⭐⭐⭐⭐⭐ #Attention#长上下文#复杂度优化
30秒电梯稿

"标准注意力是 O(n²·d),降复杂度有四条路:① 稀疏化——只算局部窗口 + 少量全局/跨块连接,复杂度约 O(n);② 核技巧线性注意力——用 φ(Q)φ(K)ᵀ 重排乘法顺序,降到 O(n·d²);③ 哈希/聚类近似——用 LSH 或层次树把 token 合并,落到 O(n log n)(题里要的这档);④ FlashAttention——注意它降的是内存/IO(O(n)),时间还是 O(n²),别答错。O(n log n) 的本质是'分层开会':近邻直接看、远处通过代表间接看。真正的代价是长程依赖精度。"

通俗类比

标准注意力是开会时 n 个人两两握手,要 n² 次。O(n log n) 的做法是分层开会:先在小组内讨论(局部注意力),每个小组选个代表到上一层开会(层次合并),代表们再聚、再往上……总握手次数降到 n log n。代价是"你和远处的张三不再直接握手",只能靠中间代表层层转达——近处信息精确、远处信息被压缩,这就是长程依赖精度的损失来源。

详细拆解

1. 复杂度从哪来(先写清楚)

Attention(Q,K,V) = softmax( Q·Kᵀ / √d ) · V
Q,K,V ∈ R^{n×d}   →  Q·Kᵀ 是 n×n   →  时间 O(n²·d)、显存 O(n²)

n 是序列长度、d 是头维度。长上下文(n 到 10⁴~10⁶)时,平方项立刻爆炸,这是所有优化要消灭的瓶颈。

2. 四条降复杂度路线(先给全景,再重点讲 O(n log n))

路线代表工作复杂度核心思路 / 代价
稀疏注意力Sparse Transformer、Longformer、BigBirdO(n·w)≈O(n)只算局部窗口+少量全局/随机边;靠任务"局部性"假设
线性注意力Performer、Linear AttentionO(n·d²)核技巧 φ(Q)φ(K)ᵀ,先算 KᵀV;精度常不如 softmax
哈希/分层近似Reformer(LSH)、层次 TransformerO(n log n)用 LSH 或树合并 token,近邻精确、远处压缩
IO 优化FlashAttention时间 O(n²)、显存 O(n)分块+重算,不降时间、降显存/IO

3. O(n log n) 这一族怎么做到(重点展开)

  • LSH 注意力(Reformer):用局部敏感哈希把"相似的 Q、K"分到同一个桶,只在同一桶内算注意力。每个 token 只和桶内少数几个 token 交互,总交互量约 O(n log n),且能近似"只关注最相关的 token"。
  • 层次注意力:把 token 按块聚合(每块算局部注意力),块再往上聚合(代表向量),层层叠加。第 l 层感受野呈指数扩大,总计算 O(n log n)。代价是跨块信息要靠"代表"转达,有信息压缩损失。
  • 分块 + 跨块:块内全连接 + 块间稀疏连接(如每个 token 再连少量全局锚点),介于 O(n) 和 O(n²) 之间,是工程上最常用的折中。

4. 必须澄清的易错点:FlashAttention 没有降时间

  • FlashAttention 用 分块(tiling)+ 在线 softmax + 反向重算 避免把 n×n 注意力矩阵落到 HBM,显存从 O(n²) 降到 O(n),从而可以跑更长序列。
  • 但它每个 Q 仍要和所有 K 点积,时间复杂度还是 O(n²·d)——面试官常拿这个挖坑,"降 IO 不降计算"要主动说清。

5. 精度 / 长程依赖的 trade-off(收尾要辩证)

  • 稀疏/线性/哈希这些"近似注意力"都依赖一个假设:绝大多数信息在局部或少数相关 token 上。对长文档摘要、代码补全通常成立;但对"需要逐字对照全文"的任务(长程精确匹配、多跳依赖)会掉精度。
  • 工程实践常是混合:局部窗口保证效率 + 全局/稀疏锚点保留长程通道 + 关键任务用检索增强把"远但相关"的 token 显式找回来(Attention Sink、RoPE 外推也是配套手段)。
  • 选型的判断标准:先问"这个任务长程依赖有多强",再决定敢不敢用近似、近似到什么程度。
面试官追问
Q:FlashAttention 把复杂度从 O(n²) 降下来了吗?
没有。它降的是显存和 IO——通过分块和重算,把中间 n×n 注意力矩阵的显存从 O(n²) 压到 O(n),但每个 query 依然要和全部 key 做点积,计算量还是 O(n²·d)。它的价值是"用更少的显存跑更长的序列 + 更好利用 GPU",而不是算法意义上的降阶。这是高频挖坑点,一定要主动区分"时间复杂度"和"空间/IO 复杂度"。
Q:线性注意力已经到 O(n) 了,为什么题目还要 O(n log n)?
因为线性注意力用核函数 φ 近似 softmax,精度损失通常更大:它把"点积相似度"替换成"特征内积",对需要精确、稀疏聚焦的长程依赖不友好,实践中 Performer 这类往往比 sparse/层次方案更容易掉点。O(n log n) 这一族(LSH、层次)保住了"真正算 softmax 注意力"的形式,只是限制在哪些 token 对之间算,近似更可控、精度折损更小——所以更常作为"高保真降阶"的候选。
Q:长程依赖在稀疏/分层注意力里怎么保留?
几招:① 全局锚点——固定若干 token(如 BigBird 的 global token / Longformer 的全局注意力)和所有 token 相连,兜住全局信息;② 分层传递——远处信息通过逐层代表间接传到,层数足够时感受野指数覆盖全长;③ 检索式兜底——需要精确远距离对齐时,先检索出"远但相关"的 token 再精确算注意力,把"全量长程"变成"按需长程";④ 位置编码用 RoPE + 长度外推(如 NTK/YaRN)配合,否则序列一长位置信息先崩,优化复杂度也没意义。
Q:实际工程里你会怎么选?
先测任务的长程依赖强度:短上下文(< 8k)直接标准注意力 + FlashAttention 吃满算力,不折腾;中等(8k~128k)优先 FlashAttention + 滑动窗口 + 全局锚点,用稀疏把显存和时间都压住;超长(> 128k)或显存受限再上分层/LSH 近似,并对关键任务用检索增强把"远距离精确信息"单独喂进去。核心原则:先在真实任务上测精度掉多少,再决定近似到什么程度,不要为了 O(n log n) 的漂亮而牺牲下游质量。
术语卡
Attention:softmax(QKᵀ/√d)·V,时间 O(n²·d)。
稀疏注意力:只算局部窗口+少量全局边,近似 O(n)。
线性注意力:核技巧重排乘法顺序,降到 O(n·d²)。
LSH:局部敏感哈希,把相似 token 分桶,桶内算注意力。
FlashAttention:分块+重算降显存到 O(n),时间仍 O(n²)。
感受野:一个 token 能"看到"的范围,分层结构可指数扩大。
