推导 ROPE 的数学原理

⭐⭐⭐⭐⭐ #ROPE#位置编码#数学推导
先说人话:这道题是少见的纯手推题:现场证明 RoPE 怎么做到「位置按绝对坐标注入,注意力打分却只剩相对距离」。面试官爱考它,一题双筛——推到「m、n 相消」那步就卡壳的,基本只会背「RoPE 就是旋转」;而它是主流 LLM 的默认位置编码,答不上等于没碰过真模型。
30秒电梯稿

"RoPE(旋转位置编码)要造一种「两头都占」的位置编码:注入的是绝对位置,打分时显形的却是相对位置。做法:把 q、k 的维度按 (2i, 2i+1) 两两配对,每对看成平面上的一个点,位置 m 时旋转 m·θ_i,θ_i = 10000^(−2i/d)。靠的是旋转可加:R(mθ)^T·R(nθ) = R((n−m)θ),所以 q_m 与 k_n 的点积里 m、n 自动相消,只剩 (n−m)。三个卖点收尾:天然相对位置、零新增参数、有长度外推潜力(配插值/调频技巧)——这就是 LLaMA、Qwen 等主流开源模型都选它的原因。"

通俗类比

先解决一个前置疑问:模型为什么需要位置编码(用备份日志想)。注意力机制本质是"集合运算":把输入 token 顺序打乱,每个词查到的还是同一批词、打分公式一字不变——没有位置编码的 Transformer 就是个词袋,分不清"日志写完了备份"和"备份写完了日志"。这就像把一整晚的备份日志剥掉序列号和时间戳再倒进麻袋:每行内容都对,但谁先谁后讲不清了,重放顺序全乱。Embedding 只回答"这行是什么",位置编码负责"它排第几"。哪里像:都是给乱序数据补上顺序信号。哪里不像:日志序号是明文写在数据里的;RoPE 把顺序"旋转"进向量,平时看不见,只在两条日志互相打分那一刻才显形。

RoPE 的核心机关:表盘指针——不看各自几点,只看夹角差。把每个 token 想成表盘上的一根指针:位置越靠后,转过的角度越大(位置 m 就转 m·θ)。两个 token 的注意力分数,只由两根指针的夹角差决定——于是"第 3 个词"和"第 5 个词"的关系,与"第 103 个"和"第 105 个"完全一样(都差 2 格),模型对"隔 2 个词"的规律学一次就能到处复用。精妙之处在于:RoPE 注入的明明是绝对角度(每个位置按自己的序号转),打分时却自动只剩角度差——这就是详细拆解第⑤步要证明的"绝对注入、相对显形"。至于为什么是 d/2 对指针、各转各的速度,拆解里用监控看板细讲。

两条矩阵性质,用快进/倒带想。磁带机快进 a 分钟再快进 b 分钟,等于一次快进 a+b 分钟——这就是旋转可加:R(a)·R(b) = R(a+b);倒带是快进的逆操作——这就是转置等于反转:R(a)^T = R(−a)。第⑤步的全部推导就靠这两句话:q 侧先倒带 m、k 侧再快进 n,一倒一顺相乘,净位移只剩 n−m。这和主从复制的位点对账是同构的:主库位点 10200、备库 10180,运维关心的从来是"落后 20 条"这个差值,不是绝对位点。哪里像:都把绝对量坍缩成相对量。哪里不像:对账的差值要人去显式计算,RoPE 的差值在乘法结构里自动长出来——连"算差"这一步都省了,而且注意力要的不是差值本身,是一个"只依赖差值的打分函数"。

详细拆解 
# 推导路线图(第⑤步是全场核心,前四步都在给它递工具):
  ① 目标 —— 想造一种编码:按绝对位置注入,打分时只剩相对位置
        ↓
  ② 工具 —— 2D 旋转矩阵的两条性质(保长度 + 旋转可加)
        ↓
  ③ 组装 —— d 维拆成 d/2 对,第 i 对按自己的速度 θ_i 转,位置 m 转角 m·θ_i
        ↓
  ④ 施工 —— 只旋 q、k(value 不动)
        ↓
  ⑤ 核心证明 —— 点积里绝对位置 m、n 相消,只剩 (n−m)   ← 面试主战场
        ↓
  ⑥ 落地 —— 不建大矩阵,逐维查预计算的 cos/sin 表
        ↓
  ⑦ 辩证 —— 优势、局限、外推技巧

1. 目标:绝对编码,但只留相对信息

位置编码要解决两件事:① 让模型知道 token 的绝对位置;② 更希望注意力权重只依赖相对位置(这是自然语言的关键性质,也更利于长度外推)。原始 Transformer 的正弦编码是把位置向量加到词向量上,而 RoPE 是用旋转——"乘"进去,这是本质区别。

再往深问一层:为什么相对位置是自然语言的关键性质?"追 / 上来 / 一只 / 蚂蚁"里,"追"和"蚂蚁"隔几个词,比它们各自排第几位重要得多——语言规律大多平移不变。用增量备份链校准这个直觉:恢复点之间隔几个增量决定恢复路径,恢复点的绝对日期只是背景信息。至于注入方式:正弦编码(频率设计见 原始 Transformer 论文)把位置加进词向量,像把序号内联拼进数据块——位置和内容搅在同一组数字里,相对关系只能指望模型自己学;RoPE 把位置乘进 q/k(对它们做旋转),像匹配时才做坐标变换——内容向量本身不动、长度不变,相对关系由数学结构保证直接进入打分公式。这一"加"一"乘",就是两者的分水岭。

2. 第一步:2D 旋转矩阵

# 平面内逆时针旋转 θ 角的矩阵
R(θ) = [ cos θ   −sin θ ]
       [ sin θ    cos θ ]
# 性质1:正交矩阵,R(θ)^T R(θ) = I(旋转不改变向量长度)
# 性质2:旋转可加,R(a)·R(b) = R(a+b)(两次旋转 = 一次转 a+b)

这三行是全部推导的地基,逐条配白话(正交、可加的正式定义见 旋转矩阵与正交矩阵):

性质数学式白话(磁带版)在第⑤步的作用
正交(保长度)R(θ)^T·R(θ) = I指针转到几点,针长不变打分尺度不随位置漂移
旋转可加R(a)·R(b) = R(a+b)快进 a 再快进 b = 一次快进 a+b两次旋转合并成一次
转置 = 反转R(a)^T = R(−a)倒带是快进的逆操作让 m 侧、n 侧角度相减

补一句后面要用的运算法则:(A·B)^T = B^T·A^T——矩阵乘积的转置要把顺序倒过来翻,第⑤步第一行变形全靠它。另外,分块对角矩阵的每条性质都按块成立,所以把 2D 结论推广到 d 维不用重新证明。

3. 第二步:把位置 m 变成"旋转 m·θ"

把 d 维向量按相邻两维配对,分成 d/2 个 2D 块。第 i 对(i = 0, 1, …, d/2−1)使用自己的基频 θ_i,位置 m 时旋转角度为 m·θ_i:

θ_i = 10000^(−2i/d)      # 高频在前(转得快),低频在后(转得慢)
# 位置 m 的分块对角旋转矩阵(每对 2D 块转 m·θ_i)
R(m·Θ) = blockdiag( R(m·θ_0), R(m·θ_1), …, R(m·θ_{d/2−1}) )

blockdiag(分块对角)的意思是 d/2 个 2×2 小旋转互不干涉,像 d/2 台各自计时的秒表装在同一块面板上。真正值得细品的是 θ_i 的几何级数设计——用监控体系类比:一套看板同时挂秒级、分钟级、小时级三个粒度,近的事件用秒级看、远的事件用小时级看,远近都能对齐:

维度对θ_i(d=128 为例)旋转周期(撞一圈)分工(看板类比)
i=0(最高频)1 弧度/位置约 6 个位置秒级看板:分得清相邻 token,超过约 6 个位置就分不清(撞圈)
中间各对指数递减从几十到几万分钟/小时级看板:负责中程距离
i=63(最低频)≈1.16×10^-4 弧度/位置约 5.4 万个位置日级看板:分不清相邻,但长序列内绝不撞圈

高频对周期短,超过周期就"撞圈"——像 12 小时制的挂钟分不清上午 3 点和下午 3 点,所以第 3 个和第 103 个位置在最高频对上根本无法区分。但这没关系:近程分不清的有高频管,远程分不清的有低频管,几十对维度叠在一起,任何距离尺度都有"看得清"的那几对。这也提前埋下第⑦步外推问题的伏笔:训练只覆盖 0~L 的"表盘组合",超出去就露馅。

4. 第三步:只对 q、k 施加旋转(关键设计)

q_m = R(m·Θ) · (W_q x_m)     # query 旋 m·θ
k_n = R(n·Θ) · (W_k x_n)     # key 旋 n·θ;value 不旋转

两个细节都是面试官爱抠的:① 旋转发生在投影之后——先算 W_q·x_m 把内容变成查询向量,再按位置旋转,内容和位置两套信息解耦、互不污染;② 只旋 q、k 不旋 v,用缓存语义想:q/k 是带位置的匹配键,v 是打完分之后取回的内容——匹配键要带版本号,取回的 value 原样交付,往内容里掺位置戳只会污染下游。

5. 第四步:证明点积只依赖相对位置(面试核心一步)

先补一个最基础的事实:注意力打分用的是点积(两向量对应位置相乘再求和),q·k 的大小决定"谁看谁、看多少"。现在推 q_m^T·k_n:

q_m^T · k_n
= (R(m·Θ) q)^T (R(n·Θ) k)
= q^T · R(m·Θ)^T · R(n·Θ) · k
= q^T · R((n−m)·Θ) · k        # 用到 R(a)^T R(b) = R(b−a)
# 结果只含 (n−m),即相对位置!绝对位置 m、n 自己"消掉了"

四行逐行过一遍(面试的主战场):

  • 第 1→2 行:代入 + 转置翻转。q_m 就是"旋了 m·Θ 的 q",展开后用 (A·B)^T = B^T·A^T 把 q 侧的旋转矩阵翻到最前面。
  • 第 2→3 行:两条性质合谋。R(m·Θ)^T = R(−m·Θ)(倒带是快进的逆),再叠加可加性:先倒 m 再进 n = 净前进 n−m。
  • 第 3 行:收网。乘积里只剩 (n−m)。m、n 不是被谁刻意删掉的,是代数结构自动把它们约掉了。
  • 这是 RoPE 的精髓:旋转角以"绝对位置"注入,但点积里自动坍缩成"相对位置"。
  • 为什么只旋 q、k:注意力分数只由 q·k 决定,value 只做加权求和,旋 v 无意义(反而破坏输出)。

拿数字自检:位置 m=3、n=5 与 m=103、n=105,代入后都是 q^T·R(2·Θ)·k——两根指针夹角差都是 2 格,打分完全一致。分块对角的性质按块成立,所以整条推导对 blockdiag 版本同样成立,不是只在 2D 玩具里成立。能讲出"绝对角度注入、点积里自动只剩角度差"这句话,面试官就知道你不是背的。

6. 工程实现形式(实际代码里怎么算)

# 复用了"乘以旋转矩阵 = 交替翻转并乘 sin/cos"的等价式
f(q, m) = [ q_0, q_1 ; q_2, q_3 ; … ]  # 按 (2i, 2i+1) 配对
q'_0 = q_0·cos(mθ_i) − q_1·sin(mθ_i)
q'_1 = q_0·sin(mθ_i) + q_1·cos(mθ_i)
# 实现时不构造大矩阵,直接按维度乘预计算的 cos/sin 表,零额外参数

抓两点就懂了:① 为什么不用大矩阵——把 2×2 旋转矩阵乘开就是两行逐元素公式(一个分量减 sin 项、一个加 sin 项),根本不需要构造 d×d 的稀疏矩阵;② cos/sin 表是预计算的——m·θ_i 只和位置、维度对有关,和 token 内容无关,开机算一次存成两张表,之后全是查表 + 逐元素乘,复杂度 O(d)、零新增参数、零结构改动。这和你在存储里预生成校验/CRC 查找表是同一种工程直觉:一次性算好,热路径只查表。再送一个加分视角:把每对 (q_0, q_1) 看成复数 q_0 + i·q_1,旋转就等价于乘以 e^(im·θ)——RoPE 论文最初就是用复数推的,面试提一句"复数视角"很提气。

7. 优势与局限(展示辩证)

  • 优势:天然相对位置;不增加可学习参数;理论上支持长度外推(训练短、推理长);与线性注意力兼容(旋转保范数)。
  • 局限:直接外推仍有性能下降,常用 NTK-Aware / YaRN 等改频技巧改善;对"绝对位置敏感"的任务(如开头结尾位置)不如显式绝对编码直观。
  • 对比:正弦编码是相加且只编码绝对位置;ALiBi 用相对偏置直接衰减;RoPE 是乘性旋转,是当前主流 LLM(LLaMA、Qwen 等)的默认选择。

三套方案摆到一张表里对比着记:

方案注入方式相对位置代表
正弦编码相加(x + PE)隐式,靠模型自己学原始 Transformer
ALiBi给注意力分数加线性距离偏置显式,直接按距离衰减BLOOM 等
RoPE对 q/k 乘旋转矩阵显式,数学上保证只剩 n−mLLaMA、Qwen 等主流开源 LLM

外推的机制,一句话说透:训练只见过 0~L 的位置,也就只见过这些位置对应的表盘组合;推理长度一旦 > L,低频指针第一次转进没见过的扇区,整个 d/2 对维度的角度组合都是新样本,打分就飘了。改频技巧(线性插值、NTK-Aware 放大底数、YaRN 分频段调频)干的是同一件事:把没见过的角度重新映射回训练见过的范围——像把只在 24 小时量程内校准过的看板,重新标定成一周量程再上线。结论要辩证地说:RoPE 具备外推潜力但不是自动无限外推,"潜力 + 技巧配合"才是标准答案。

作答节奏建议:面试手推时,先花 20 秒把"目标(绝对注入、相对显形)→ 两条性质(可加、转置=反转)"的路线图讲给面试官,再写第⑤步那四行——就算中间细节记不全,只要 R(a)^T·R(b) = R(b−a) 这一行你能现场推出来,这题的分就到手大半;反过来,这一行推不出来,背再多"RoPE 是旋转"都救不了。

面试官追问
Q:再推一遍——为什么点积只依赖相对位置?
人话:两条性质合谋:旋转可加 + 转置等于反转。q 侧先"倒回"m,k 侧再"前进"n,一倒一进相乘,绝对角度抵消,只剩差值。类比:磁带从计数 m 倒带再快进到 n,净走带量永远等于 n−m,和绝对起点无关——主从复制对位点同理,运维关心落后几条,不关心绝对 LSN。技术:R(a)^T·R(b) = R(−a)·R(b) = R(b−a);代入得 q_m^T·k_n = q^T·R((n−m)Θ)·k,m、n 各自消失。正交性保证范数不变,可加性保证角度相减,缺一不可。
Q:RoPE 和原始 Transformer 正弦位置编码的本质区别?
人话:一个把位置"加"进内容、指望模型自己悟出远近;一个把位置"乘"进打分公式、由数学保证只看远近。类比:加法像把序号内联拼进数据块,元数据和内容混在一个字段;旋转像匹配时才做坐标变换,内容本体不动——存的时候不掺位置,查的时候才带位置。技术:① 注入方式:正弦是 x+PE 相加,RoPE 是对 q/k 乘旋转矩阵;② 相对性:正弦只显式给绝对位置、相对关系靠模型自己学,RoPE 靠 R(a)^T·R(b) = R(b−a) 让分数显式只依赖 (n−m),归纳偏置更强;③ 频率设计同源,θ_i 都是 10000^(−2i/d)。
Q:θ_i 为什么设计成 10000^(−2i/d)?
人话:让不同维度对以指数递减的速度转,快的管近处、慢的管远处,一套"多尺度表盘"覆盖所有距离尺度。类比:监控同时挂秒级、分钟级、小时级看板:秒级分得清相邻两个事件、但很快就撞圈;小时级分不清相邻、但能量程到很久之前——多层看板拼起来远近都能对齐。技术:几何级数频率沿袭原始正弦编码:θ_i 从 1 一路指数衰减到约 10^-4 量级,高低频差好几个数量级,相当于把位置信息做多尺度分解;底数 10000 是经验值,NTK-Aware/YaRN 正是通过调它换外推空间。
Q:RoPE 真的能无限外推吗?
人话:不能白嫖。训练只在 0~L 的位置上见过"表盘组合",推理超过 L 后低频指针第一次转进没见过的扇区,打分就飘了。类比:监控看板只在 24 小时量程内校准过,突然拿 3 天的指标来对表——高频盘早就绕晕失去参考,低频盘第一次进入未校准区间,读数自然不可信。技术:直接外推会掉点;常用改频手段:线性插值(位置除以缩放因子压回 0~L)、NTK-Aware 放大底数、YaRN 分频段调频,把未见角度映射回训练见过的范围。结论:有外推潜力 + 需技巧配合,不是自动无限外推。
Q:为什么只旋转 q 和 k,value 不用转吗?
人话:位置信息只在一个地方有用——打分(决定谁看谁、看多少),打分只用 q·k;v 是打完分后"取回的内容",不需要位置戳。类比:缓存匹配要用带版本号的 key,命中后返回的 value 原样交付——位置戳只该出现在匹配阶段,掺进取回的内容只会污染下游。技术:softmax(q·k^T/√d)·V 里位置只该影响 qk^T 一项;若给 v 乘 R(m·Θ),输出会变成"多个不同角度向量的加权和",落在哪个坐标系都说不清,后续 W_o 对同一 token 的不同位置会得到不同表示,难以稳定学习。
Q:RoPE 和 KV Cache 是什么关系?
人话:RoPE 天生缓存友好:位置 n 的 k 一旦按 n 转完存进缓存就永远有效,新 token 只旋自己的 q 去和旧 k 打分,历史从不用重算。类比:像预生成好的备份元数据:每个恢复点的元数据算一次就存着,新增恢复点只算自己的增量,从不回刷历史。技术:RoPE 的旋转角只由位置决定、与上下文无关,缓存里存 R(nΘ)·W_k·x_n 一劳永逸;对比依赖"查询位置"的相对编码方案——每来一个新 token,所有历史 k 的相对距离都变了,缓存就得跟着改。推理引擎默认 RoPE,缓存好维护是现实原因之一。
术语卡
RoPE:Rotary Position Embedding,旋转位置编码——LLaMA、Qwen 等主流开源 LLM 的默认位置编码方案。
旋转矩阵:2D 平面绕原点转 θ 角的正交矩阵,转置等于反转——整个推导全靠它的两条性质。
相对位置:两个 token 的位置差 n−m;RoPE 保证注意力打分只依赖它,与绝对位置无关。
基频 θ_i:10000^(−2i/d),第 i 对维度的转速——高频管近程,低频管远程,多尺度覆盖各种距离。
长度外推:训练见过的序列长度为 L,推理超过 L 仍能用;RoPE 有此潜力,但要配插值/调频技巧。
NTK-Aware / YaRN:通过缩放底数、分频段调频来改善 RoPE 外推的两类主流技巧。
