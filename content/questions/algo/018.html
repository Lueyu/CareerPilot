Agent算法 · Q17

推导 Attention 机制的计算复杂度

⭐⭐⭐⭐ #Attention#复杂度分析
先说人话:这题让你在白板上算清两件事:注意力到底花多少算力、多少显存;FlashAttention 为什么快、却没降复杂度。面试官爱考它,是因为一石二鸟——既验推导基本功,又看你懂不懂 GPU 的 IO 瓶颈。答错的暴露点:只会喊 O(n²) 却说不清 d 项从哪来,或把 FlashAttention 说成「降复杂度的近似算法」——前者基本功虚,后者方向全错。
30秒电梯稿

"设序列长 n、每个头维度 d:标准 self-attention 的时间 O(n²·d)、空间 O(n²)。瓶颈在 QK^T 产生的 n×n 注意力矩阵——时间上要算 n² 个点积(每个是 d 维向量内积,这就是 d 项的来历),空间上要存 n² 个标量。FlashAttention 不降低理论复杂度,而是用 tiling + 内核融合减少 HBM 读写,把显存从 O(n²) 降到 O(n) 级、实际快 2~4 倍——省的是 IO,不是 FLOPs。长序列要真正降复杂度,得靠稀疏/线性注意力或状态空间模型。"

通俗类比

为什么是 n²(用全互联灾备组网想):n 个 token 的自注意力,像 n 个机房要组一张全互联备份网:每两台机器都要建一条专线互备,线路数随节点数平方涨——4 个节点 6 条专线还扛得住,40 个节点就是 780 条,预算瞬间立起来。attention 更狠:专线是一次性建设成本,而注意力矩阵是每次前向传播都把 n² 个配对从头算一遍——更像每次做全量一致性校验都要 n² 次两两比对,算完就扔,下个请求推倒重来。哪里像:工作量都由「两两配对」这个结构决定,所以是平方增长。哪里不像:网络拓扑建一次用十年,attention 是每层、每个请求都要重新付的持续成本。

FlashAttention 省的是什么(用你天天干的「落盘 vs 流式」想):标准实现像一条笨重的 ETL 流水线——每算完一步(相似度矩阵、softmax 归一化后的权重矩阵),就把 n×n 的中间大表写回磁盘阵列、再读出来喂给下一步,落盘-回读来来回回,真正干活的时间反而不占大头。FlashAttention 像流式直通管道:把数据切成小块,块进了内存就把「相乘、归一、加权」一口气算完,中间结果从不落盘,只滚动维护两个统计量,最后只写出最终答案——和你做流式校验不落中间产物是同一个思路。哪里像:都在砍「慢存储的来回读写」。哪里不像:备份里砍落盘往往省的是容量,这里省的是带宽;而且 FlashAttention 的分块在数学上严格等价——它不是有损压缩,不是近似算法。

详细拆解

1. 定义与符号(先把假设说清)

一句话版本:每个 token 拿着自己的「查询」去和所有 token 的「标签」比对,按匹配程度把大家的「内容」加权抄回来。先用备份检索的世界对齐一下三个角色,后面推导就不会迷路:

角色形状语义类比(存储/检索世界)
Q(Query,查询)n×d第 i 个 token 想找什么信息一次检索请求
K(Key,键)n×d每个 token 的元数据标签,用来被匹配索引项/元数据
V(Value,值)n×d每个 token 真正会被取走的内容数据块本身
  • 输入 X ∈ ℝ^{n×d},经三个线性投影得 Q, K, V ∈ ℝ^{n×d}(d 是每个头的维度)。
  • 注意力输出:O = softmax(QK^T / √d) · V。逐行看:每个 query 和所有 n 个 key 算相似度,加权求和所有 value。

这一步面试时要先声明假设:「n 是序列长度,d 是单头维度」,不声明就开推,面试官会立刻追问单位,当场乱阵脚。

2. 三步复杂度推导(白板写出来)

# 步骤1:相似度矩阵 S = Q·K^T
(n×d) · (d×n) → n×n           # 每格一个 d 维点积 → O(n²·d)
# 步骤2:行 softmax(除以 √d 再归一化)
P = softmax(S / √d)           # n×n 个元素 → O(n²)
# 步骤3:加权求和 O = P·V
(n×n) · (n×d) → n×d           # → O(n²·d)
# 结论:总时间 O(n²·d) = O(n²d);总空间 O(n²)(存 S 和 P)
  • n² 项来自"每个 query 对每个 key 都算一次";d 项来自"每次点积是 d 维向量内积"。写成你熟悉的形态:这就是两层 for 循环套一个 d 维内积——外层 n 个 query、内层 n 个 key、最里层 d 次乘加,写 Python 后台的天天见。
  • 当 n ≫ d 时(长序列),复杂度由 n² 主导;当 n 小、d 大时 d 的贡献也显著,所以公式要写成 O(n²·d) 而非笼统 O(n²)。

带个数感受量级:n=1024、d=64 时,n²·d ≈ 6700 万次乘加(单头、单层);一层 32 个头就是 21 亿;GPT-3 级 96 层,一次前向光注意力就是两千亿级乘加——还没算反向传播。这就是为什么这道题是所有推理优化故事的起点。

3. 空间复杂度:QK^T 的 n×n 注意力矩阵要整体驻留显存,softmax 前还要存完整 S——所以标准实现 空间 O(n²),长序列直接显存爆炸(如 n=32k 时 n²≈10 亿个浮点)。按 FP16 两个字节算,这张表约 2GB——而且是单头、单层的账;32 头 96 层再乘上去,任何一张卡都装不下。这个细节是最容易算漏的:面试时主动说「这还只是一个头一层」,立刻显出你真在管理过显存。

4. 多头的复杂度:设总维度 d_model = h·d(h 个头)。多头各自算一遍 O(n²·d),加起来 h·O(n²·d) = O(n²·d_model)——和"一个头维度 d_model"总量相同,即多头不改变复杂度量级,只是切分并行。类比:把一份 1PB 的校验作业按维度拆成 32 份并行跑——份数多了,单份小了,总数据量一克没少。面试官问「多头是不是贵了」时,答案是不变量级、只换并行方式。

5. Flash Attention:不降理论复杂度,降的是 IO

先建立地图:GPU 里有两种存储,速度差近 10 倍,而大表偏偏放在慢的那种里——这就是所有问题的根源。

存储层容量带宽类比你熟悉的对应物
HBM(显存)几十 GB(A100 为 40GB)约 1.5TB/s磁盘阵列:容量大、相对慢
SRAM(片上缓存)约 20MB(108 个 SM×192KB)约 19TB/s内存缓存层:容量小、极快
标准实现:每步的中间结果都写回显存再读回来(像 ETL 每阶段落盘):
  Q ─→ 算 S=QK^T ─→ S写回HBM ─→ 读回S ─→ softmax ─→ P写回HBM ─→ 读回P ─→ 算P·V ─→ O写回
        └──────── n×n 大表来回搬运好几趟,IO 成了主角 ────────┘

FlashAttention:分块 + 融合,中间结果不落盘(像流式管道一次通过):
  Q块 ┐
  K块 ┼─→ SRAM 内一口气算完:S块 → softmax块 → ×V块 ─→ 只写回最终 O(n×d)
  V块 ┘    (在线 softmax 维护 running max/running sum,块间精确合并)
  n×n 矩阵从不整体出现在显存里 → 显存 O(n),IO 少一个量级
  • 问题本质:标准实现反复在 HBM(显存,大但慢)读写 n×n 矩阵,而真正计算发生在 SRAM(片上,小但快)。GPU 的瓶颈是访存带宽而非算力,于是 IO 成为墙。翻译成备份语言:磁带库容量够、机械臂也够,备份窗口却超了——瓶颈不在「存了多少」而在「来回起落多少次」。
  • tiling(分块):把 Q、K、V 切成小块,每块在 SRAM 里完整算完 softmax 的局部再合并(在线 softmax 技巧保证分块结果与全局一致),n×n 矩阵从不在 HBM 里整体落盘。难点在 softmax:它是「整行一起归一化」的算子,看起来没法切块。解法见 在线 softmax:softmax 的分母只依赖「行内最大值 + 指数和」两个统计量,都可以滚动维护——每来一个新块,若出现更大的最大值,就把已累计的和按比例降权再继续加。这和你做流式校验时只维护 running max / running sum、新数据到来增量修正,是同一个数学骨架。
  • 内核融合:把 QK^T、softmax、×V 融合进一个 CUDA kernel,中间结果不写回 HBM。类比:三次独立作业(算相似度→归一→加权)合并成一条流式管道,阶段间的落盘全部消灭。
  • 重计算:反向传播时按需重算注意力矩阵,而不是存着它——省显存换一点算力。这是存储工程师最熟悉的取舍:恢复时宁可在现场重算派生数据,也不为它长期占用存储——「不保存可重算的中间产物」。
  • 结果:显存 O(n)(只存分块 + 输出),速度快 2~4 倍(随序列变长更明显),数学结果与标准 attention 完全一致——这点很重要,它不是近似。面试时必须主动强调这一句,否则很容易被误判成「又一个牺牲精度的 trick」。

6. 真正降低 n² 的路(延伸,展示广度)

FlashAttention 只是把常数做小,n² 的阶还在。要真降阶,得动结构本身:

路线代表复杂度代价
稀疏注意力Longformer/BigBird局部窗口 O(n·w·d)结构有偏,超窗口的长程关系要靠全局 token 补
线性注意力Performer(核函数近似)对 n 线性是近似,精度有损失
状态空间模型MambaO(n)直接换掉 attention 架构,任务适配性要逐一验证

稀疏注意力(局部窗口 + 全局 token,如 Longformer/BigBird)、线性注意力(核函数近似,如 Performer)、状态空间模型(Mamba 用 O(n) 的序列模型绕开 attention)。面试核心是先讲透 O(n²·d),再说 FlashAttention 怎么省 IO,最后点一句"要真正降阶另有路线"——三层递进,每一层都站在上一层地基上,这正是面试官想听的叙事顺序。

面试官追问
Q:Flash Attention 复杂度还是 O(n²d),为什么能快?
人话:乘法次数一次没少,省的全是「搬运数据」的时间——GPU 算得飞快,慢在把大表来回倒。类比:备份窗口超标的排查经验:磁带容量和驱动器都够,超的是「落盘-回读、换带起落」的次数;把三次独立落盘作业合并成一条流式直通,窗口立刻缩下来。技术:标准实现把 n×n 的 S 和 P 反复写回 HBM 再读出,IO 量随 n² 走;FlashAttention 用 tiling 让每块在 SRAM 里算完,用内核融合消灭中间写回,反向用重计算替代存储。FLOPs 不变、IO 掉一个量级,墙上时间快 2~4 倍,且 n 越长收益越明显。
Q:空间复杂度从 O(n²) 怎么降到 O(n) 的?
人话:那张「谁关注谁」的 n×n 大表再也不整体保存——算一块、用一块、扔一块。类比:像流式校验备份日志:不把中间结果全量落盘,只滚动维护两个统计量(当前最大值、当前累加和),新块来了增量修正,最终结果和全量算一遍完全一致。技术:在线 softmax 为每个 query 行维护 running max 和 running sum,新块到来若刷新最大值,旧累加部分按 e^{旧max−新max} 重缩放后继续累加——数学严格等价,不是近似;最终只把 O(n×d) 的输出写回 HBM,注意力矩阵从不整体驻留,显存峰值从 O(n²) 降为 O(n)。
Q:n 变大到什么程度,attention 会成为不可接受的瓶颈?
人话:先爆显存、再爆时间,而且爆得很陡——平方增长意味着 n 翻倍、开销翻四倍。类比:像全互联灾备组网:4 个节点 6 条专线没事,40 个节点 780 条,成本曲线突然立起来;n 从 4k 涨到 32k,显存需求乘 64。技术:按 FP16 算:n=8k 时注意力矩阵约 128MB(可接受);n=32k 时约 10 亿个元素、2GB(单卡吃力,且这只是单头单层);n=100k 时约 20GB(基本不可行,哪怕用 FlashAttention 也要仔细权衡分块)。所以长文档场景必须换稀疏/线性注意力或 Mamba 这类 O(n) 结构。
Q:因果注意力(decoder)的复杂度一样吗?
人话:公式不变、量级不变,但实际计算量减半——因为一半的格子被 mask 根本不用算。类比:像增量备份只碰已变化的数据块:全量扫描是 n²,「只看过去」的思路天然砍掉未来那一半,量级一样、绝对量减半。技术:decoder 要屏蔽未来 token,只算下三角的约 n²/2 个点积,渐近仍是 O(n²d)。FlashAttention 实现里按 block 粗判:Q 块整体位于 K 块之后的整块直接跳过,部分重叠的块内用掩码——省的不只是算力,还有相应的 IO。
Q:点积之后为什么要除以 √d?不除会怎样?
人话:不除的话,d 越大点积数值越大,softmax 会被推成「一家独大」,梯度趋近于零,模型学不动。类比:像监控指标没做归一化:样本维度一多方差就膨胀,告警阈值全被极端值带偏——先除以标准差再比较,才公平。技术:若 q、k 各分量独立、零均值、方差 1,则点积 q·k 的方差是 d;除以 √d 后方差回到 1,softmax 输出分布不随 d 骤变,梯度保持健康。这就是 Transformer 原论文里 scaled dot-product 的设计动机——面试里被追问 d 项时能顺势接上,非常加分。
术语卡
Self-Attention:序列内部每个 token 与所有 token 算相关性的机制,n² 工作量的来源。
softmax:把一排分数变成「和为 1 的权重」的归一化算子——全局归一,所以天生难分块。
O(n²·d):attention 的时间复杂度,n² 来自两两配对,d 来自每对要做 d 维点积。
HBM/SRAM:显存(几十 GB,约 TB/s 级)和片上缓存(约 20MB,约 19TB/s)——大而慢 vs 小而快,IO 优化的整场戏都在这两层之间。
Tiling(分块):把 Q/K/V 切成小块逐块在 SRAM 里算完,n×n 矩阵从不整体落盘。
在线 softmax:分块算 softmax 的技巧,靠 running max / running sum 滚动修正,保证分块结果与全局严格一致。
内核融合:把 QK^T、softmax、×V 合进一个 CUDA kernel,中间结果不写回显存——省的全是 IO。
线性注意力:用核函数近似把 O(n²) 降为 O(n) 的方案,有精度代价;Mamba 则换掉 attention 直接做到 O(n)。
