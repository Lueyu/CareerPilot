系统设计 · Q8

设计一个 Function Calling 微调数据生成系统

⭐⭐⭐⭐ #FunctionCalling#数据生成#微调
30秒电梯稿

"本质是用强模型当老师给小模型造题(知识蒸馏):先定义工具 Schema,再程序化+LLM 结合生成多样化场景(重点是要覆盖不需要工具的负样本和多工具选择样本),强模型产出『用户话术 → 工具调用 → 参数』样本,然后过四道质检:Schema 合法性校验、参数沙箱执行验证、结果一致性检查、LLM 打分去重,人工抽检后转成目标模型的 chat template 格式。质量控制是这套系统的灵魂。"

通俗类比

就是老师傅出题带徒弟:老师傅(强模型)按考纲(工具 Schema)编各种模拟题——有的要用扳手、有的其实啥工具都不用、有的得先量再拧;自己做出标准答案(标注),再实际拧一遍验证答案能跑通(沙箱校验),装订成册(数据集)给徒弟(小模型)刷题(微调)。徒弟练完后专门会这几样活,又快又便宜。

详细拆解

1. 输入:工具 Schema 定义

每个工具一份 JSON Schema:名称、描述(要写清什么时候该用/不该用,这直接决定模型选对工具的率)、参数类型、必填项、枚举值。这份 Schema 同时服务于生成和校验,一处定义多处复用。

2. 场景生成(多样性是关键)

  • 正样本:单工具调用、多工具组合(先查天气再订餐厅)、多轮(参数不足先反问用户)、参数边角案例(日期格式、枚举边界、空值)。
  • 负样本(必须占 20~30%):闲聊、无关请求 —— 没有负样本,模型会得上"工具上瘾症",见谁都想调一下,这是 FC 微调最常见的翻车点。
  • 生成方式:程序化模板(保证覆盖)+ LLM 扩写(保证自然)+ 真实日志回流(bad case 沉淀,最值钱)。

3. 标注:强模型生成

用旗舰模型 + few-shot 示例,输入场景输出结构化三元组:(user_query, assistant_tool_call, tool_response + final_answer)。温度调高多生成几个变体。

4. 质量验证(四道关卡,系统核心)

5. 格式标准化

  • 目标模型的 chat template 各不相同(Qwen、Hermes、Llama 格式对 tool_call 的标签写法不一样),写转换器按模板渲染;工具定义按 OpenAI tools 字段组织。
  • 配比建议:工具调用样本 + 通用对话样本混着训(如 7:3),防止微调后通用能力遗忘(只会调工具不会聊天)。
  • 数据集版本化:和训练配置绑定,可复现。

6. 效果评估:留出测试集(不参与训练),测三个指标——工具选择准确率(该不该调、调哪个)、参数精确匹配率(EM/F1)、负样本拒绝率。

面试官追问
Q:需要多少条数据?
经验值:单一工具场景 1~2K 起步就能显著提升;工具多(20+)、场景复杂的要 1~5 万;质量 > 数量,脏数据 500 条不如干净数据 100 条。
Q:为什么不直接用带 FC 的大模型?
三个场景必须微调:① 成本(小模型便宜 10~50 倍,高频调用);② 私有化/合规(数据不能出内网);③ 垂类工具特别多且专有,大模型没见过、选择准确率低。
Q:线上效果怎么持续改进?
线上 bad case(选错工具/参数错)自动捕获 → 回流数据工厂 → 定期增量微调 → 灰度上线,形成数据飞轮。
术语卡
知识蒸馏:强模型的输出当弱模型的训练数据。
负样本:不该调用工具的样本,治"工具上瘾"。
Chat Template:各模型的对话格式模板。
EM/F1:参数精确匹配/部分匹配指标。
数据飞轮:bad case 回流→再训练→效果提升的循环。
