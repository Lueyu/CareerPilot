Agent核心 · Q17

如果你要在 GPU 资源有限的条件下同时提供推理和微调服务，如何做资源分配和任务调度以保证时延和吞吐？

⭐⭐⭐⭐ #资源管理#调度策略 字节(真题)
30秒电梯稿

"核心原则:在线推理 SLA 优先,离线微调让路、可抢占。资源上用 MIG 或显存配额把 GPU 切分隔离;调度上给推理配高优先级、微调配低优先级,支持抢占式调度——推理流量上来,微调自动降速/暂停并落 checkpoint;微调侧用 QLoRA/PEFT 把显存压到单卡可容;推理侧用动态批处理 + 量化小模型提吞吐;再加弹性扩缩容:闲时把卡还给训练,忙时收回。"

通俗类比

像一台机器同时当"前台叫号机"和"后台跑报表":前台(推理)是实时服务,客人一来必须立刻响应,所以它最高优先级;后台报表(微调)是离线活,可以先暂停、存个进度(checkpoint),等前台不忙了接着跑(抢占 + 恢复)。为让两者塞进同一台小机器,报表用更省的算法(QLoRA 量化),前台用小模型 + 拼单(动态批处理);白天前台优先,夜里前台闲下来报表全力跑。

详细拆解

1. 先讲清矛盾(这是这道题的立意)

在线推理要低时延、稳定(P99 不能抖),离线微调要持续吃算力、长时独占;两者抢的是同一批 GPU 的算力和显存。硬凑在一起,推理时延会抖、微调会 OOM。所以答案是"隔离 + 优先级 + 抢占 + 弹性"四件套。

2. 资源隔离方案(对比选型)

方案粒度特点适用
MIG 硬隔离物理切分 GPU显存/算力强隔离,互不干扰A100/H100,固定配比
显存配额逻辑限制灵活但算力仍可能争抢显存是主要瓶颈时
容器 + 时间片K8s 调度按时间/权重轮换多任务混合

3. 调度策略(优先级 + 抢占 + 弹性)

  • 优先级:推理 = 在线服务,永远优先;微调 = 批处理任务,可延迟、可中断。
  • 抢占式调度:推理需要算力时,微调任务被挂起(写 checkpoint)释放 GPU,忙完再恢复——比"杀掉重跑"省大量时间。
  • 弹性:按推理 QPS 预测,低谷期把卡划给训练,高峰期收回;配合 K8s 或云上弹性实例。

4. 微调侧省显存(让离线"挤得进去")

  • QLoRA/PEFT:基座量化到 4-bit + 低秩适配器,把全参微调的显存需求压 1~2 个数量级,单卡即可微调大模型。
  • 梯度累积 + 小 batch:降低瞬时显存峰值,换训练吞吐。
  • 定期 checkpoint:让抢占随时可安全发生,不丢进度。

5. 推理侧保时延 + 提吞吐

  • 动态批处理:攒请求成 batch,吞吐上升;但 batch 大 → 排队久 → 时延高,要按 SLA 反推最大 batch 和最长排队。
  • 量化/蒸馏小模型:显存和算力占用小,单位 GPU 能并发更多请求。
  • 模型分级:简单请求走小模型,复杂请求才上大模型,把大模型的稀缺算力留给真正需要的。

6. 保证 SLA 的最后一道:对推理做严格的并发上限和队列超时;一旦算力吃紧,宁可拒绝/降级新请求(排队提示),也不让已接受请求的时延失控——这是"保时延优先于保吞吐"的取舍。

面试官追问
Q:抢占微调时,训练进度会丢吗?
会,但可控:训练框架定期存 checkpoint(每 N 步或每 N 分钟),抢占前强制再落一次盘,恢复时从最近 checkpoint 续训,损失的只是最近一小段。关键是抢占动作要"优雅"——先发信号让任务在安全点停,而不是直接 kill 进程(直接 kill 可能损坏 checkpoint)。还可以给微调设最小运行时间片,避免频繁抢占导致来回切换的开销大于收益。
Q:单张卡上能同时跑推理和微调吗?
能,但不推荐硬共享:靠显存配额 + 进程隔离可以共存,风险是算力争抢导致推理 P99 抖动,且显存碎片化容易 OOM。更稳的做法是物理/逻辑隔离——有 MIG 就 MIG 切块(推理、微调各一块,显存算力都隔开);没有 MIG 就按"推理优先 + 微调可抢占"的方式分时复用,而不是让两者在微观上抢同一时刻。一句话:能共存,但共存的质量取决于隔离是否彻底。
Q:时延和吞吐怎么权衡(batch 到底设多大)?
这是典型的跷跷板:batch 越大,GPU 利用率越高、吞吐越高,但排队时延越长。做法是从 SLA 反推——比如 P99 要 < 800ms,其中排队 + 计算要压进这个预算,从而定出"最大允许 batch × 最长排队长度";再配合动态批处理(不是固定 batch,而是"攒到上限或超时(如 5ms)就发车"),在吞吐和时延之间取动态平衡点。核心:先立时延红线,再在红线内最大化吞吐。
术语卡
MIG:把一块 GPU 物理切分成多个隔离实例。
抢占式调度:高优先级任务可挂起低优先级任务。
QLoRA:量化基座 + LoRA,微调省显存。
动态批处理:攒请求成 batch 一起算提吞吐。
Checkpoint:训练进度快照,用于安全中断与恢复。
SLA:服务等级协议,约束时延/可用性目标。
