Agent核心 · Q16

大规模 Agent 系统在多线程/多进程场景下的资源调度策略如何设计？

⭐⭐⭐⭐ #资源调度#并发 字节(真题)
30秒电梯稿

"按'选型 → 分层 → 限流 → 隔离 → 可观测'讲。选型上,Python 受 GIL 限制,采用多进程 + 协程(asyncio)组合:IO 密集的 LLM/工具调用走协程,CPU 密集或需强隔离的任务走进程池。分层上用任务队列 + Worker 池解耦生产消费,配优先级队列和信号量限并发;GPU 侧用动态批处理提吞吐;再做按租户/任务类型的资源隔离和背压,最后用队列深度、利用率、P99 等指标驱动扩缩容。"

通俗类比

像餐厅后厨:前台接单(请求)→ 传菜口按单排队(任务队列)→ 灶台分档口(进程/协程)——炖菜档(长任务)和快炒档(短任务)分开,避免一个慢菜堵死整条出菜线;每个档口同时最多炒几锅(信号量限并发);高峰期外面取号排队(背压),不让后厨被压垮;老板看翻台率(监控)决定加灶还是撤灶(扩缩容)。

详细拆解

1. 并发模型选型(GIL 是关键考点)

  • GIL让 CPython 的线程无法并行执行 Python 字节码——多线程对纯 CPU 计算无加速,只对 IO 等待(等 LLM、等下游 API)有效。
  • 所以 Agent 系统的组合拳:协程(asyncio)扛 IO 并发——成千上万个 LLM 调用在等网络,单线程事件循环就能高并发;多进程扛 CPU/隔离——重度计算(如本地 Embedding、规则引擎)或需强隔离的任务丢进进程池。
  • 需要真并行的 CPU 密集 + IO 混合时,用"多进程 + 每个进程内跑协程"的经典结构。

2. 分层架构

3. 并发控制(限流三件套)

  • 信号量:每 Worker 内限制"同时在跑的 LLM 调用数",防止把模型网关打挂。
  • 令牌桶:对下游内部 API 限速(如订单系统只扛 100 QPS),Agent 超了就排队或降级。
  • 优先级队列:高优先(交互请求、付费用户)先消费,低优先(批量、离线)让路。

4. 资源调度策略

策略做法适用
公平调度轮询/加权轮询分摊多租户均等场景
优先级 + 抢占高优先级抢占低优先级资源在线 > 离线
亲和性同会话路由到同 Worker需要局部顺序/缓存
背压队列满则拒绝/排队凭证削峰防雪崩

5. GPU 资源调度(Agent 特有)

  • 推理服务用动态/连续批处理:把到达的请求攒成 batch 一起算,吞吐大幅提升;但 batch 越大、排队越久、时延越高,要在"吞吐 vs 时延"间调超参。
  • 显存并发度单独控:并发请求数 × 单请求 KV cache 不能超显存,否则 OOM。
  • 长连接任务(流式生成)要单独记账:流式期间一直占用计算和显存,调度器要把它当"常驻负载"看待。

6. 隔离与可观测

  • 隔离:按租户/任务类型分队列或分池,单个租户的流量尖峰不拖垮全局。
  • 指标:队列深度与积压、CPU/内存/GPU 利用率、并发上限、P50/P95/P99 延迟、任务失败率——用队列积压驱动自动扩缩容(K8s HPA)。
面试官追问
Q:Python 里多线程到底能不能用?
能,但要分清负载类型:IO 密集(等网络、等模型)多线程有效,因为线程在等 IO 时释放 GIL;CPU 密集多线程无效(被 GIL 串行化),甚至因切换开销更慢。所以 Agent 场景里"LLM/工具调用"这类 IO 等待可以用线程或协程,而"本地推理、数据处理"要用多进程或用 C 扩展库(NumPy 等内部会释放 GIL)。一句话:IO 用协程/线程,CPU 用进程。
Q:GPU 推理并发怎么控才不 OOM?
三层:① 上游限流——信号量把并发请求数压到显存能承受的阈值;② 服务端显存预算——按"并发上限 × 单请求最大 KV cache"预估峰值显存,留安全余量;③ 动态批处理里 batch 大小也受显存约束,超了就排队。还有工程手段:KV cache 量化、paged attention(vLLM)复用显存、超长输入先截断或摘要。核心是显存是硬上限,调度必须先算这个账。
Q:怎么避免一个超长任务饿死其他任务?
靠分级 + 限时 + 隔离:长任务和短任务分不同队列/池,短任务永远有独立资源;单个任务设硬超时(如 30s)和 token 预算,超了就降级或转人工;若同池不可避免,用公平调度(轮询)而非"先来先服务一条道跑到黑",并在任务内做阶段性 checkpoint,让长任务可被暂停让路、之后恢复。
术语卡
GIL:全局解释器锁,限制 CPython 线程并行。
协程:单线程内的轻量并发,扛 IO 等待。
信号量:限制同时执行数量的并发原语。
背压:下游慢/满时向上游反压减速。
动态批处理:攒请求成 batch 一起推理提吞吐。
