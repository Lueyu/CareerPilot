Agent核心 · Q36

如果子agent回复不对怎么办？反思？跳不出去怎么办？限制次数？

⭐⭐⭐ #错误处理#反思机制 字节(真题)
30秒电梯稿

"分三步:① 先发现错误——靠校验器(格式/规则/工具结果校验)+ 置信度阈值 + Critic 复查,而不是盲目信子 Agent;② 再反思纠正——把错误原因作为反馈喂回去,让子 Agent 重试,或换提示/换模型/降级重做,最多 2~3 轮;③ 防跳不出去——设硬上限(最大反思轮次、总 token/时间预算),并检测"连续无实质变化",超限就走兜底策略:取历史最优、降级直答、或转人工。原则是允许失败,但必须有退出机制和兜底,不能让用户卡死。"

通俗类比

就像实习生交作业 + 带教老师把关:实习生交上来的作业(子 Agent 输出),老师先检查(校验器)发现不对;不是直接骂一顿,而是告诉他"这里错了,原因是 XX,重做"(带反馈重试);但老师不会让他无限重做——最多改 2~3 次,还不行就换个人做(换模型)或老师自己上手(降级直答),实在搞不定就上报领导(转人工)。关键是:重试有反馈、有限次、有兜底。

详细拆解

1. 先解决"怎么知道它错了"(没有检测,反思无从谈起)

  • 规则/格式校验:输出必须是合法 JSON、必须引用来源、数值必须在合理区间——可程序化判定,最可靠。
  • 工具结果校验:子 Agent 调工具拿回的结果是否符合预期(为空、报错、类型不对)。
  • 置信度阈值:让子 Agent 附带 self-confidence 分数,低于阈值视为不可信。
  • Critic/Verifier 复查:另一个 Agent 或强模型对结果打分/找茬,不通过即判错。

2. 反思纠正:怎么"修"而不是"重试"

  • 带反馈重试(关键):把"错在哪、为什么错、怎么改"作为新上下文喂回子 Agent,而不是原样重跑(原样重跑大概率还是错)。
  • 渐进升级:第一轮改提示重试 → 仍错则换工具/换检索 → 再错则换更强模型或换策略(如拆更小的子任务)。
  • 反思要落地到具体动作:让模型输出"我上一步哪里错了 + 下一步改做什么",而非空泛的"我会更小心"。

3. 防"跳不出去":三重硬约束

  • 限制反思轮次:通常 2~3 轮,超限强制退出——这是最直接的闸门。
  • 预算上限:总 token / 时间 / 成本预算,任一超限即停,防烧钱。
  • 无进展检测:连续两轮输出无实质变化(哈希/关键字段比对),判定陷入死循环,熔断。

4. 兜底策略(退出之后去哪)

策略做法适用
取历史最优反思全程保留各轮结果,退出时选评分最高的一版已有"不完美但可用"的结果
降级直答放弃多步 Agent,单模型基于已有信息直接给答案并说明不确定性用户等不起、答案可接受部分偏差
转人工明确告知 + 提交工单/人工接管高风险、敏感、用户已不耐烦
面试官追问
Q:反思会不会越改越差,甚至改坏本来对的部分?
会,这是反思机制的已知风险。对策:① 全程保留各版本,退出时按校验分选最优,而不是默认取最后一版;② 反馈要聚焦具体错误、约束"只改错误点";③ 设硬上限防恶性循环;④ 用测试集验证"反思后准确率是否真的提升",提升才启用反思,否则宁可不反思。
Q:子 Agent 一直"自信地说对",但其实错了(高置信度错误)怎么办?
模型置信度不可全信,所以不能只靠自评。上独立的校验器:有标准答案的用规则/程序校验,开放的用 Critic Agent 或 LLM-as-judge 交叉检查;高危操作(写库、扣款)再叠一层"二次确认/人工审批"。
Q:反思轮次设多少合适,依据是什么?
没有绝对标准,经验值 2~3 轮:多数反思类研究/工程里第 1~2 轮收益最大,之后边际递减、成本继续涨,还易发散。实际按测试集上"轮次 vs 正确率/成本"曲线来定拐点,并针对不同任务分级(简单任务不反思,复杂任务才开)。
Q:转人工前,怎么避免让用户觉得"机器很蠢、白等了"?
尽早转、带上下文转:检测到高失败风险或用户负面情绪就提前转,而不是拖到超限才转;转接时把已收集的信息、已完成的步骤打包给人工,避免用户重复描述;话术上明确"已为您转接专员",减少挫败感。
术语卡
Reflection:让模型审视并修正自己输出的机制。
Self-confidence:模型对自身答案的自评置信度。
Critic/Verifier:独立于生成者的校验/评审角色。
兜底(fallback):主路径失败后的降级出口。
熔断:异常反复时强制中断,防止失控。
