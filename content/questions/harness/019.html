Agent核心 · Q32

你是如何利用多Agent协同来提高推理正确率的？调度策略如何实现？

⭐⭐⭐⭐ #Multi-Agent#调度策略 字节(真题)
30秒电梯稿

"多 Agent 提正确率的核心是用多样性换可靠性,三类主流打法:① 并行投票——多个异构模型/角色对同一问题独立作答,多数投票或加权取优(self-consistency 思想);② 生成-批判闭环——一个 Agent 作答,另一个专挑毛病,反复修正;③ 角色分工——Planner 拆解、Executor 执行、Verifier 校验,各管一段。调度上用 Supervisor 或 DAG 工作流:并行分支用 fan-out/fan-in,失败分支按置信度决定重试还是换策略。"

通俗类比

就像专家组会诊 vs 单个医生:一个医生可能误诊,但把内科、影像、病理几个医生拉来会诊,观点一致才下结论(投票),或者一个医生下诊断、另一个专门当"挑刺的审稿人"找漏洞(批判闭环),正确率自然更高。代价是要花几倍的会诊费和时间——所以只在"答错了代价高"的场景才上多 Agent,这就是 trade-off。

详细拆解

1. 为什么多 Agent 能提正确率(先讲清原理)

  • 单模型单次采样容易"自信地犯错";多次采样 + 投票能显著压低随机错误(学术界称为 self-consistency)。
  • 模型在"生成"和"评判"两种任务上的能力不对称:一个模型答题可能错,但让它检查别人的答案往往能发现错误——利用这种不对称做"生成-批判"闭环。
  • 复杂任务拆给聚焦的小 Agent,每个上下文更短、提示更专,单步正确率就更高。

2. 三种提正确率的协同范式

  • 并行投票:N 个 Agent(不同模型/不同提示/不同温度)独立作答,按答案一致性投票;可加权(置信度高、历史表现好的 Agent 权重更高)。
  • 生成-批判(Reflection/Debate):Critic 针对答案逐条质疑,Generator 据反馈修正;可迭代多轮直到 Critic 通过或超预算。学术界叫 multi-agent debate,实证上确实能提正确率,但成本线性上升。
  • 角色分工:Planner 把大问题拆成子任务,DAG 编排;Executor 逐个子任务执行;Verifier 端到端校验结果是否符合要求,不符合打回。

3. 调度策略如何实现

  • 静态 DAG:任务结构已知时,把协同关系画成有向图,引擎按依赖调度——可控、可观测、易回放。
  • Supervisor 动态路由:主管 Agent 读当前状态决定"下一步派给谁、并行还是串行",适合流程不固定的任务。
  • 并行调度:条件边返回多个目标 = fan-out,结果用 asyncio.gather/线程池汇聚 = fan-in;投票场景天然并行。
  • 失败处理:单分支失败可重试;置信度低时触发"换策略"(换模型、降级、追加 Agent);全程设最大轮次/token 预算防死循环。

4. 必须主动讲的 trade-off

  • 多 Agent 提正确率是拿成本、延迟、复杂度换的:3 路投票 = 3 倍 token。实际落地要分级:简单任务单 Agent 直答,高价值/高风险任务才上多 Agent 会诊。
  • 投票只在答案可枚举、分歧明确(如选择、分类、数值)时最好用;开放式长文本用"生成-批判"更合适。
面试官追问
Q:多个 Agent 用同一个模型有意义吗,还是必须不同模型?
有意义。即使同一个模型,调高温度、换提示词、换角色设定都能产生多样性,多次采样投票依然能提正确率(self-consistency 就是这么来的)。当然,异构模型(不同厂商/不同架构)多样性更大,投票增益通常更明显,还能互相纠偏——但接入和维护成本也更高。
Q:投票遇到并列(票数相同)怎么办?
不能简单随机取。优先级:① 用置信度/理由质量加权打破平局;② 引入一个独立的"裁决 Agent"专看平局项;③ 都拿不准就把分歧如实返回给用户让其选择,而不是硬编一个答案。
Q:怎么量化"正确率确实提升了"而不是拍脑袋?
离线用带标准答案的测试集(如数学、代码、多跳问答)做 AB:单 Agent vs 多 Agent 的准确率、以及成本/延迟增量;在线对高价值链路做灰度实验看关键指标(任务成功率、返工率)。没有基线对比,多 Agent 就是烧钱。
Q:Critic 和 Generator 会互相"敷衍"或陷入循环怎么办?
给 Critic 明确的、可判定的评判标准(而非"你觉得好不好");限制反思轮次(如 2~3 轮)和总预算;每一轮要求必须产生实质修改,若连续两轮无实质变化或 Critic 总是通过/总是打回,则提前终止并按规则取最优历史版本或转人工。
术语卡
Self-consistency:多次采样取多数一致答案,降随机错误。
Reflection:生成后自我/他者批判再修正的闭环。
Fan-out/Fan-in:并行发散执行、再汇聚结果。
Supervisor:主管 Agent 动态路由子 Agent 的调度模式。
Multi-agent debate:多 Agent 辩论迭代收敛答案。
