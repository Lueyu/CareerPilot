系统设计 · Q4

设计一个 Agent 工作流引擎(类似 LangGraph)

⭐⭐⭐⭐⭐ #Agent#工作流#状态机
30秒电梯稿

"本质是把流程图变成可执行的程序:节点是函数或 Agent 调用,边分固定边和条件边,共享一个 State 对象在节点间流转。核心设计四件事:① State 每步落库做 checkpoint,支持断点恢复和人工审批挂起;② 条件边实现分支,循环用最大迭代次数 + 状态变化检测双保险防死循环;③ 节点级重试 + 指数退避 + 超时;④ 支持 fan-out/fan-in 并行节点。LangGraph 就是这套思路的标杆实现。"

通俗类比

把它想成高铁调度系统:线路图(有向图)规定列车能从哪站到哪站;每站(节点)做一件事(检票/装卸);信号灯(条件边)决定下一站开往哪里;调度中心每过一站就记录"列车已到 X 站"(checkpoint);列车趴窝了从最近一站重新发车(恢复);晚点就启用备用交路(重试/降级)。没有调度记录,一趟车半路出事就只能从头再跑——这就是 checkpoint 的价值。

详细拆解

1. 图定义(DSL 设计)

  • 节点 = 一个函数:输入 State,输出 State 的增量更新。开发者用代码注册:graph.add_node("retrieve", fn)。
  • 边 = 跳转规则:固定边(A 完了一定去 B)和条件边(一个函数读当前 State,返回下一个节点名,可返回多个实现并行)。
  • 入口/出口:START → … → END;图对象编译后生成可执行单元(编译期做静态检查:悬空节点、不可达节点、无出口环)。
# 用户侧 API 大致长这样
g = Graph()
g.add_node("understand", understand_fn)     # 意图理解
g.add_node("retrieve", retrieve_fn)         # 检索
g.add_node("generate", generate_fn)         # 生成
g.add_node("review", review_fn)             # 质量审查
g.add_edge(START, "understand")
g.add_edge("understand", "retrieve")
g.add_edge("retrieve", "generate")
g.add_conditional_edges("generate", # 条件边:不合格打回重做
    lambda s: "retrieve" if s.need_retry else END)
app = g.compile(checkpointer=RedisSaver())  # 带持久化编译

2. 状态设计与持久化

  • State 是一个带 schema 的字典:输入、中间产物、迭代计数、错误信息分区存放,避免互相覆盖(可用 reducer 函数定义合并策略,如追加列表)。
  • Checkpoint 策略:每个超节点执行完写一次(内容 + 图位置 + 版本号)到 Redis(热,供快速恢复)/ DB(冷,供审计回放)。
  • 恢复:进程重启或人工审批通过后,load 最新 checkpoint,从记录的节点继续执行。时间旅行调试:回放任意历史 checkpoint 重跑,定位问题神器。

3. 分支与循环的安全

  • 循环必须配 max_iterations(如 5 次)和预算上限(token/时间),超限强制走降级出口。
  • 环检测:同一节点连续执行 N 次而 State 关键字段无变化 → 判定死循环,熔断。

4. 错误处理

  • 节点级重试:可配置(次数、指数退避、哪些异常类型可重试——网络错误可重试,参数错误重试也没用)。
  • 超时:节点级 + 全图级双层。
  • 补偿:已产生副作用的节点(如已扣款)失败时执行补偿动作(退款)——参考 Saga 模式。
  • 最终失败:状态标记 failed + 保留完整 trace 供排查。

5. 并行执行

  • 条件边返回多个目标 = fan-out 并行执行,全部完成(或任一完成,可配)后再 fan-in。
  • 子图支持:节点本身可以是另一张图,实现分层编排。
  • 人工节点(HITL):执行到审批节点时图挂起,状态入库,人批完再 invoke 恢复——这是和普通工作流引擎最大的差异点之一。
面试官追问
Q:和 Airflow 这类传统工作流引擎有什么区别?
Airflow 面向定时批处理 DAG(天级/小时级任务,失败明早重跑);Agent 引擎面向交互式、低延迟、含 LLM 决策的执行:条件边由模型输出驱动、毫秒级响应、支持人工介入挂起恢复、循环常见。
Q:状态很大(几 MB 对话历史)每步都存吗?
增量存储:只存 diff + 指针,大对象(文档原文)外置对象存储引用。
Q:怎么保证同一张图不被并发执行出问题?
同一线程(thread_id)的执行加分布式锁或用队列串行化;不同线程天然隔离。
术语卡
DAG:有向无环图;Agent 工作流常放宽允许有环(带防护)。
Checkpoint:执行进度快照,恢复/回放的依据。
Saga 模式:长事务拆成小步,失败逐步补偿。
Fan-out/Fan-in:并行发散/汇聚。
HITL:人工介入节点,执行挂起等人。
