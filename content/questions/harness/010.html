了解 A2A 框架吗？它和普通 Agent 框架的区别在哪，挑一个最关键的不同点说明。

⭐⭐⭐ #Agent#A2A#前沿技术
30秒电梯稿

"了解。A2A(Agent2Agent)是 Google 2025 年提出的开放互操作协议,解决"不同厂商、不同框架的 Agent 之间怎么互相发现、互相协作"。它和普通 Agent 框架(LangChain/AutoGen)根本不是一类东西:框架管"单个 Agent 内部怎么做",A2A 管"Agent 与 Agent 之间怎么对话"。最关键的一个不同点:框架是构建 Agent 的 SDK,A2A 是Agent 之间的通信标准——用 Agent Card 描述能力、用 JSON-RPC 2.0 over HTTP 传任务与消息,与具体框架无关,相当于"Agent 世界的 HTTP"。"

通俗类比

框架是给一个人配的"内部工作方法"(怎么拆任务、怎么用工具);A2A 是人与人之间的"通讯录 + 通话标准"(对方是谁、会什么、任务怎么发、结果怎么回)。一个人再强,和陌生人协作也得先有"自我介绍 + 统一通话协议"——A2A 就是这个:它不管你内部怎么干活,只规定你们怎么对接。

详细拆解

1. A2A 是什么(先厘清定位)

  • 全称 Agent2Agent,Google 主导的开源协议,目标是让异构 Agent(不同厂商、不同框架、不同语言)能即插即用地互操作,避免每个 Agent 都要为别人写一套私有适配。
  • 它解决的是一类新问题:Agent 生态互联互通——类似"HTTP 之于 Web 服务"。而普通框架解决的是"如何快速搭出一个 Agent"。

2. 核心机制(记住四个词)

3. 与 MCP 的关系(面试常被一起问)

4. 最关键的不同点(只挑一个讲透)

框架是"构建 Agent 的内部脚手架",A2A 是"Agent 之间的外部接口标准"。普通框架抽象的是单个 Agent 内部的模型调用、工具执行、状态流转;A2A 完全不碰这些,它抽象的是跨 Agent 的发现、寻址、任务协商与结果回传。所以一个 A2A 兼容的 Agent 完全可以用 LangChain 实现——框架决定它"怎么想、怎么做",A2A 决定它"怎么被别的 Agent 找到、派活",两者正交、可叠加。

面试官追问
Q:A2A 和 MCP 是什么关系,二选一还是都要?
不冲突,解决不同问题:MCP 给 Agent 接工具和数据(context),A2A 让 Agent 之间互相对接(communication)。一个要"用好工具"的 Agent 用 MCP,一个要"跟别的 Agent 协作"的系统用 A2A,很多场景两者同时用:MCP 管单个 Agent 的能力,A2A 管 Agent 群的协作。
Q:A2A 的 Agent Card 里最关键的是什么?
最关键的是能力的机器可读描述 + 安全/认证信息:别人靠它判断"这个 Agent 能干什么、我能不能调用、怎么鉴权"。能力描述要足够结构化(而非一句自由文本),否则发现机制无法可靠路由——这直接决定互操作能不能真的落地。
Q:为什么选 JSON-RPC 2.0 over HTTP 这种"老"技术?
因为它成熟、无状态、跨语言、基础设施全兼容(网关/代理/观测都好接)。协议的价值在"低门槛被广泛实现",不在"技术炫";用现有标准能让异构 Agent 最快接入,而不是再造一套没人会实现的重协议。
术语卡
A2A:Agent2Agent,Agent 间互操作协议。
Agent Card:Agent 的能力/端点/认证自描述。
MCP:Model Context Protocol,连接工具与数据源的协议。
JSON-RPC 2.0:轻量的远程调用协议,A2A 的传输基础。
互操作性:异构系统无需私有适配即可协作。
