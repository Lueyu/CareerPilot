Agent核心 · Q19

如果一个agent误判导致策略冲突，如何处理？

⭐⭐⭐ #错误处理#容错机制 字节(真题)
30秒电梯稿

"我把它拆成事前预防、事中拦截、事后闭环三步。事前:给动作设置信度阈值,低置信度或高风险动作先草拟不落地;事中:用一个冲突检测器在执行前拦截矛盾动作——规则校验先行(毫秒级),拿不准再上 LLM 做一致性判断,冲突时按『安全 > 业务 > 体验』的优先级仲裁,实在定不了转人工;事后:把动作设计成可逆/可补偿的,已经产生副作用的走补偿或人工修复,并把这次 bad case 记下来回流优化判断器。核心思想是让冲突在执行前就被拦住,而不是执行后收拾烂摊子。"

通俗类比

像一家公司里两个部门同时下互相打架的指令:销售说要"给客户破例放行",风控说"必须拦截"。解决办法是设一个总调度台:重要决策先过一遍规则看有没有冲突(事前预演),真有矛盾就按"安全第一"拍板(仲裁),拿不准的报给老板(转人工);万一指令已经发出去造成损失,启动善后流程把钱退回来(补偿)。最重要的是——下次同类指令,调度台记住了这个坑,不再犯(闭环回流)。

详细拆解

1. 先定义清楚:什么叫"策略冲突"

  • 两个(或多个)策略/模块针对同一个状态输出矛盾的动作。典型例子:风控策略要求"拦截这笔转账",而客服 Agent 为了满足用户要求输出"放行";或者路由层把请求发往 A 流程、而规划层认为应该走 B 流程。
  • 冲突有两种来源:① 真冲突——两条策略本身目标就对立(安全 vs 体验);② 误判冲突——模型看错了输入(把"不发货"理解成"发货"),导致动作本不该冲突却冲突了。面试时先区分这两类,是加分项。

2. 事前预防(让误判少发生)

  • 置信度阈值:判断器输出带概率,低于阈值(如 < 0.7)不自动执行,改为反问澄清或转人工。
  • 动作白名单 + 分级授权:读操作可以自动,写操作/敏感操作(退款、改单、外呼)必须二次确认或人工审批,把"可能犯错"的动作限制在最小圈。
  • 两段式工具:先"预览"出将要执行的动作让上层校验,校验通过才"执行"。

3. 事中检测与仲裁(核心)

  • 仲裁优先级:安全策略 > 业务策略 > 体验优化;确定性规则 > 模型判断;高置信度 > 低置信度。
  • 规则先行:把"绝对不允许"的约束写成确定性规则(白名单/黑名单/状态机),这些不该交给 LLM 判断——规则是兜底的最后一道墙。
  • 失败降级:检测到冲突但无法仲裁时,绝不硬着头皮选一个,而是回退到安全默认值(如"拦截")或转人工,保证宁可慢,不可错。

4. 事后回滚与补偿

  • 可逆设计:动作尽量设计成可撤销(带 undo 能力),状态变更走事务/状态机落库,支持回放。
  • 补偿(Saga 思想):副作用已发生时(如已扣款),触发补偿动作(退款/恢复),而不是指望模型自己"认错"。
  • 审计留痕:决策理由、置信度、仲裁结果全程记录,既能归因,也能作为后续优化数据。

5. 事后闭环:把每次冲突存成 bad case → 定期复盘是"真冲突"还是"误判" → 误判类回流到判断器(补数据/调阈值/加规则),让系统越用越稳。

面试官追问
Q:你怎么判断这次是"误判"而不是"两个策略真的矛盾"?
回溯整条决策链:看输入是否歧义、判断器置信度多少、换强模型重判结果是否一致。如果强模型也左右摇摆,说明是输入歧义导致的误判,该修输入或加澄清;如果多策略在正确输入下仍天然对立,就是真冲突,该在策略层定优先级而不是怪模型。
Q:加一层冲突检测会不会拖慢响应?
分两档:规则检测是内存判断,微秒~毫秒级,对全量请求跑;语义层(LLM)只对"高风险动作 + 规则未拦截"的少数请求跑,占比很低。整体多出的延迟通常在几十毫秒,且只在敏感操作路径上,可接受。
Q:动作已经执行、副作用无法回滚怎么办?
三层兜底:① 能补偿的走补偿(退款/恢复原状);② 不能补偿的立即告警 + 人工介入修复,并对用户道歉话术;③ 用幂等键保证不会因为重试把错误放大。最后把这次事故回写进规则,同类动作今后默认走人工审批。
术语卡
策略冲突:多个策略对同一状态给出矛盾动作。
仲裁:按优先级/置信度从冲突动作中拍板。
补偿(Saga):长事务拆小步,失败逐步抵消副作用。
HITL:Human-in-the-loop,关键环节人工介入。
置信度阈值:低于阈值不自动执行,转澄清或人工。
两段式工具:先预览再执行,防误操作。
