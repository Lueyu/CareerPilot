Agent核心 · Q25

如果要做电商agent，你会选择哪些模态的信息作为输入？比如文本评论、图像、视频、购买记录？

⭐⭐ #场景设计#多模态#电商Agent 字节(真题)
30秒电梯稿

"我的原则是按收益/成本比选模态,不是越多越好。电商 Agent 我选四层:① 结构化数据——购买记录、订单、价格、库存,这是决策主干,最便宜最可靠;② 文本——商品标题、评论、客服对话,是语义理解的主力,embedding 和检索成本可控;③ 图像——只在需要视觉判断时上,如商品主图、售后凭证 OCR、以图搜图;④ 视频——基本不作为实时输入,离线抽关键帧+摘要即可。一句话:能结构化就不上多模态,能文本就不上图像视频,每加一个模态都要回答'它带来什么增量、花多少成本'。"

通俗类比

把它想成金牌导购员接待顾客:他先看你的购物小票和会员档案(结构化数据),快速了解你买过什么、预算多少;再听你口头描述需求(文本)抓关键信息;看不清的商品他才拿起来仔细端详(图像,比如你指着一件衣服问"有没有同款");至于你发的开箱视频,他只会快进扫几眼(视频离线抽帧),不会一帧帧看。老练的导购不会什么都看,只会看"最有用、最省事"的那几样——选模态也是这个道理。

详细拆解

1. 为什么模态不是越多越好(先立观点)

  • 每个模态都对应一条独立管道:图像要视觉模型,视频要抽帧+时序建模,结构化要解析清洗。
  • 多模态 = 多一套模型 + 多一份延迟 + 多一份成本 + 多一个出错点,模态之间还要做对齐/融合。
  • 选型判据(定性):信息增益 ÷ (延迟 + 成本 + 复杂度),增益小成本高的模态坚决砍掉。

2. 四层模态定位

模态电商场景典型信息角色成本/延迟
结构化数据购买记录、浏览轨迹、订单、库存、价格决策主干极低,毫秒级
文本商品标题、评论、客服对话、搜索词语义主力低,embedding+检索
图像商品主图、售后凭证、用户上传图按需视觉判断中,视觉模型
视频开箱视频、直播切片、买家秀几乎不实时高,抽帧+摘要

3. 具体怎么选(分任务对齐)

  • 商品推荐/个性化:结构化购买记录 + 文本评论语义 + 图像风格特征(可选),视频基本不用。
  • 售后客服:文本对话 + 图像凭证(破损照片 OCR/识别)+ 订单结构化数据。
  • 以图搜图/找同款:图像 embedding 必须,文本辅助描述。
  • 直播带货 Agent:视频只做离线理解(关键帧+字幕),在线输入仍是结构化+文本。

4. 融合方式(视频先"降维")

5. 关键 trade-off

  • 端到端多模态大模型(GPT-4V/Qwen-VL)能直接吃图,但贵且慢;工程上常用"视觉模型抽取成结构化描述 → 再喂便宜文本 LLM"的分层方案。
  • 在线 vs 离线:能离线预处理的(视频摘要、图像特征入库)绝不放到在线实时算。
面试官追问
Q:为什么不直接上一个多模态大模型,把图、文、视频都丢进去?
端到端多模态大模型省事,但有三个代价:① 贵——视觉 token 比文本贵得多,每次请求都带图成本翻倍;② 慢——首字时间和吞吐都受影响;③ 不可控——一个模型管所有模态,出了问题难定位。工程折中是"多模态感知 + 文本决策":视觉模型只做抽取(识别/字幕/结构化描述),结果转成文本再交给便宜的文本 LLM 推理。只有场景强依赖细粒度视觉(看复杂表格/截图)时才上端到端多模态。
Q:购买记录这类隐私敏感数据,作为输入要注意什么?
三点:① 最小化——只取和当前意图相关的字段,不全量吐给模型;② 脱敏——手机号、地址、卡号等 PII 进模型前脱敏;③ 权限与审计——读用户数据需用户授权,访问日志可审计。另外结构化数据尽量走确定性逻辑(规则/检索)而非让 LLM 自由发挥,既省 token 又防泄漏。
Q:视频为什么基本不作为实时输入?
视频单条信息密度低、解码和时序建模成本极高,实时喂模型不划算(延迟和成本都扛不住)。常规做法是离线管道:抽关键帧 → 图文识别 → 摘要,把一段视频压缩成几张关键图 + 几句话,在线只用这个摘要。只有在"必须理解动态过程"(如动作质检)的垂直场景才做在线视频理解,且通常用专用小模型。
术语卡
多模态(Multimodal):同时处理文本、图像、音频等多种信息形态。
结构化数据:有固定 schema 的记录型数据(订单、库存),可直接程序处理。
视觉 embedding:把图像编码成向量,用于以图搜图/相似度计算。
关键帧抽取:从视频里挑出代表性画面,降低后续处理量。
收益/成本比:选型判据——新增模态的价值是否盖过它的成本。
