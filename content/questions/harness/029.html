Agent 自我修正算法优化

⭐⭐⭐⭐ #Agent#Reflection#优化
30秒电梯稿

"Reflexion 贵在每个回合都要多一次评估/反思调用,还要把整段轨迹塞进上下文。优化从三路下手:第一少反思——只对失败回合触发反思,成功就不浪费;第二精反思——把长篇自省压成一条可复用的 lesson(教训),存进记忆,不存整段轨迹;第三沉淀反思——把高频 lesson 蒸馏进系统提示或直接 SFT 进模型,把'运行时反思'变成'事前已内化'。再配三件套:早停(提升低于阈值就停)、预算上限(超了走直答/转人工)、以及用并行采样 + best-of-N 用宽度换深度。"

通俗类比

Reflexion 像学生每次做错都写一篇八百字检讨再整本重做——反思充分但成本爆表。优化后变成:只有错题才写检讨(选择性反思)、检讨只写一句"这题我错在忽略了边界条件"(压缩成 lesson)、考前把错题本上的教训背进脑子、以后不再现场翻本子(蒸馏进 prompt/模型)。再加一条:想不通就先平行做三道、挑最好的一份交卷(best-of-N 用宽度换深度)。

详细拆解

1. Reflexion 为什么贵(先量化成本来源)

  • 标准 Reflexion(Shinn et al. 2023)每轮 = 生成(1 次 LLM)+ 评估/反思(1~2 次 LLM),重试 3 轮就是 6~9 次调用;且反思内容 + 历史轨迹都压进下轮 prompt,上下文越来越长,token 成本线性累积。
  • 自省里还经常是"正确的废话"(如"下次要更仔细"),对下一步无信息量,纯烧钱。

2. 优化策略全景(按"少/精/沉淀"三路展开)

方向手段收益
少反思只对失败/低分回合触发;成功即止砍掉无谓的评估调用
少反思早停:连续两轮提升 < 阈值就停止避免为 0.5% 的提升烧 3 轮钱
精反思反思压缩成 1 条结构化 lesson(错误类型 → 修正策略),不存整段轨迹上下文短、检索快、可复用
精反思Self-Refine:生成与反思用同一模型,一轮反馈一轮改写少一个独立 critic,省一半调用
沉淀高频 lesson 蒸馏进 system prompt 或 SFT 进模型把"运行时反思"变成"零成本内化"
架构并行采样 + best-of-N:多个候选,挑最优用宽度换深度,规避串行反思长尾

3. 关键:反思要"可复用 + 可检索"(记忆化)

  • 反思的 ROI 来自跨任务复用:如果每次反思只服务当前这一题,成本永远摊不掉;只有沉淀成"这类题我老犯 X 错"的元认知,才能越用越省。
  • lesson 要结构化(错误模式 + 触发条件 + 修正动作),否则检索时语义漂移、注入后也是噪音。

4. 蒸馏:把反思从"运行时"搬到"事前"

  • System prompt 层:把高频教训写成几条"先检查边界条件""先复述需求再动手"的固定规则——零额外推理成本。
  • SFT 层:把"带反思的成功轨迹"作为训练数据微调模型,让它直接产出"反思后的正确行为",推理时根本不再需要显式反思环。这是把 Reflexion 的收益固化进权重,彻底消掉多轮成本。

5. Trade-off(必答)

  • 反思轮数 ↑ → 精度通常 ↑(先升后平),但成本线性 ↑、延迟 ↑。
  • 反思也可能负优化:模型过度自信地"改坏"本来对的答案,或陷入反复横跳。所以要配"改进才接受、否则保留原答案"的接受准则 + 早停。
面试官追问
Q:Reflexion 和 Self-Refine 的区别?
Self-Refine(单任务内、一轮反馈一轮改写、无跨任务记忆)更轻;Reflexion 的核心增量是 episodic memory——把这次反思存起来、跨回合跨任务复用,所以更适合需要"多次重试同类任务"的场景(代码、决策)。可以这样讲:Self-Refine 是"当场改",Reflexion 是"当场改 + 记进错题本"。优化方向里"蒸馏进 prompt/模型"其实是把 Reflexion 的记忆能力再往前推一层。
Q:反思会不会让模型越改越错?
会,这是"自我修正的悖论":critic 和 generator 如果是同一能力水平,它可能分不清哪个版本更好,反而把对的改错。缓解:① 接受准则——只有评估分/验证器确认更优才替换,否则保留原答案;② 引入外部强信号(代码跑测试、结果对拍)而不是只靠自评;③ 给反思定结构(先列"我哪步可能错"再改),减少盲目重写。
Q:lesson 蒸馏进 system prompt 会不会越积越多?
会,所以要做"记忆治理":① 去重 + 泛化——同模式合并成一条通用规则;② 设上限——system prompt 里的教训控制在 N 条以内,按命中频率保留 top-k;③ 分层——冷 lesson 存检索库、热 lesson 进 prompt、最热且稳定的进 SFT,形成"检索 → 注入 → 内化"的漏斗,避免无限膨胀。
Q:怎么评估反思到底有没有用(而不是自我感动)?
做消融对照:同一批任务跑"直答 / +1 轮反思 / +3 轮反思 / +反思且蒸馏"四组,比三样——任务成功率(真分)、平均 token/延迟(成本)、成功率随轮数的曲线(增益是否递减)。若 +3 轮相比 +1 轮成功率提升 < 2% 而成本翻倍,就砍到 1 轮。结论必须用"成功率/成本"比说话,而不是"模型反思得很认真"。
术语卡
Reflexion:生成-评估-反思-重试,反思存入情节记忆复用。
Self-Refine:同一模型自反馈自改写,单轮、无记忆。
episodic memory:按回合存储的经验/教训库。
best-of-N:并行生成 N 个候选取最优,用宽度换深度。
蒸馏:把反思收益固化进 prompt 或模型权重。
早停:增益低于阈值即停止迭代,控制成本。
