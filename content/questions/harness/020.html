Agent整体流程是怎么做的？包括哪些模块？

⭐⭐ #Agent架构#模块设计 字节 / 阿里
30秒电梯稿

"标准 Agent 是一个『感知 → 规划 → 行动 → 观察』的循环(即 ReAct 范式),由五个模块组成:① LLM 推理核心——大脑,负责理解和决策;② 规划模块——拆解任务、生成计划;③ 工具调用模块——把模型意图转成真实 API 调用并拿回结果;④ 记忆模块——短期(上下文)+ 长期(向量库);⑤ 状态/编排模块——维护会话状态、控制循环与重试。整体流程:用户输入 → 理解意图 → 规划 → 调用工具 → 拿到观察结果 → 反思是否完成 → 未完成继续循环、完成则输出。"

通俗类比

Agent 就是一个带工具、会做计划的实习生:老板(用户)布置任务 → 实习生先想"这事要分几步、需要什么资料"(规划)→ 打开电脑查数据库、调系统(工具)→ 看一眼查回来的结果对不对(观察)→ 不够就再查一轮,够了就交报告(输出)。他桌上贴着便签记当前进度(短期记忆),笔记本里存着长期经验(长期记忆)。

详细拆解

1. 核心循环(ReAct:Reasoning + Acting)

每一轮模型都看到"历史 + 最新观察",据此决定下一个动作(Thought→Action→Observation 循环),这是 LangChain/LangGraph 等框架的通用范式。

2. 五大模块逐一拆

  • LLM 推理核心:一切决策的起点。负责理解意图、决定调用哪个工具、组织最终答案。能力上限基本由它决定。
  • 规划模块:复杂任务先拆子任务(可静态拆解,也可每步动态规划);输出"下一步做什么"。
  • 工具调用模块:把模型输出转成 function call,做参数校验、执行、超时控制、错误归一化;工具描述(schema)要喂给模型。
  • 记忆模块:短期=当前对话/中间结果(上下文窗口,有限);长期=向量库/知识库/用户画像(检索增强);还有工作记忆=当前任务状态。
  • 状态与编排模块:维护 State、控制循环次数、重试、超时、断点恢复——工程上的"骨架"。

3. 一个完整的链路举例(电商客服查订单)

4. 单 Agent 到多 Agent 的扩展

  • 流程变复杂、工具变多后,可把"规划/执行/验证"拆成不同 Agent(Supervisor、Executor、Critic),各自是上面这套循环的实例,共享状态协作。
面试官追问
Q:ReAct 和单纯的"让模型直接回答"差在哪?
直接回答只能靠模型内部知识,遇到需要实时数据、精确计算、调用系统的事就会瞎编;ReAct 让模型把"我需要什么信息"变成真实的工具调用,拿到真实结果再推理,把幻觉和不准确压下去。代价是多轮调用、更慢更贵,所以简单问答仍走直答。
Q:记忆模块短期和长期怎么分工?
短期记忆塞进上下文,快但有长度上限、跨会话丢失;长期记忆放向量库/结构化库,跨会话持久、需检索。实践:短期放"本次对话最关键的状态",长期放"可复用的知识/用户画像",需要时检索回来注入上下文。
Q:Agent 循环怎么防止一直转下去?
设最大迭代次数(如 8~10 轮)+ 总 token/时间预算,超限强制收敛:取当前最佳结果输出,或转人工/降级直答。再加"连续 N 轮无实质进展则熔断"的检测。
术语卡
ReAct:Reasoning+Acting,边想边调用工具的循环范式。
Function calling:模型按 schema 输出结构化工具调用。
短期/长期记忆:上下文内 vs 外置可检索的记忆。
State:Agent 在节点间流转的共享状态对象。
Observation:工具/环境返回的观察结果,喂回模型。
