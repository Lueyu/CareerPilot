Agent核心 · Q2

请详细解释 ReAct 框架。它是如何将思维链和行动结合起来，以完成复杂任务的？

⭐⭐⭐ #Agent#ReAct#核心范式 字节 / 阿里 / 腾讯（高频）
先说人话:这题问 Agent 的祖师爷范式:模型怎么「边想、边做、边看结果」地循环干活。大厂爱考,因为它是后续一切追问(工具调用、循环失控治理)的总纲;只会背 Thought/Action/Observation 三个词的人,被追问一句「循环停不下来怎么办」就露馅——暴露的是没真搭过 Agent。
30秒电梯稿

"ReAct = Reasoning + Acting,把「想」和「做」拧成一个循环:每一步模型先输出一段 Thought(推理)说明打算怎么干,再给一个 Action(行动)调用工具,你的代码真正执行工具后,把结果作为 Observation(观察)拼回上下文,进入下一轮思考,直到信息齐了输出 Final Answer。它治两个老毛病:纯思维链只会推理、知识过时会幻觉;纯行动缺规划、容易乱试。核心机制是用外部观察给推理做 grounding,错了当场被现实纠正。落地形态就两部分:一份 Thought / Action / Observation 三段式提示模板 + 一个带熔断的执行循环。"

通俗类比

ReAct(用「值班排障的假设-验证闭环」想):深夜备份作业失败,你的真实动作是:瞄一眼告警,心里判断「先分清是介质错还是网络错」(Thought)→ 敲命令查作业日志(Action)→ 回显显示 I/O 错误集中在某台驱动器(Observation)→ 修正判断「介质侧问题,查驱动器健康」(下一个 Thought)……如此往复,直到根因定位、写结单报告(Final Answer)。ReAct 这个 2022 年的工作,本质就是把资深运维的本能循环固化成 LLM 能照着执行的协议。

纯 CoT(用「只看旧文档脑补根因」想):思维链像一位只凭三个月前的架构文档推演、绝不动手的专家——逻辑链再长,文档一过时就步步皆错,而且没人给他回显纠错。纯行动(Act-only)则像不问青红皂白的值班新手:重启、切换、换盘一路乱试,事后写不出故障报告。ReAct 把两者拧成一股:推理决定往哪动手,动手结果反过来修正推理。

哪里像:每轮循环 = 一次「假设→验证→修正」;Observation 就是现实回显,不许脑补,这正是排障纪律;Thought 留痕 = 工单记录,全程可回放、可审计。

哪里不像:① 你的知识是活的,模型的参数知识是训练截止日的冻结快照,所以它更依赖观察来补鲜;② 你天然知道何时收敛,模型可能原地打转,必须外挂 max_iterations 这种熔断器;③ 你的「上下文」是记忆加笔记本,模型的上下文是每轮全量重放的有限窗口,任务一长就得像日志滚动归档那样压缩旧记录。

详细拆解

1. 背景:CoT 与 Act-only 各自的缺陷

2022 年之前,让 LLM 干「需要外部信息或真实副作用」的活只有两条路,各有各的病:CoT 让模型把推理一步步写出来,逻辑清楚了,但所有中间结论都来自参数里冻结的旧知识——相当于拿着过时文档排障,环境早变了还浑然不觉;Act-only 让模型直接发动作,能摸到真实世界,但没有推理串场,连发几个动作像无头苍蝇,一步走错整条链崩掉。ReAct 的贡献是发现:把两者交替编织,比各自单独跑都好。论文在 HotpotQA(多跳问答)和 FEVER(事实验证)上验证:纯行动容易在无关信息里打转,纯推理容易编造,ReAct 的可信度明显更高;先 ReAct 取证、再推理收尾的组合最佳。

范式优点缺点
CoT(纯推理)能拆解复杂问题、逻辑清晰,不依赖外部系统就能跑知识是过时的记忆(训练截止日的快照),会幻觉,错了不自知
Act-only(纯行动)能拿到真实信息、能改变外部世界没有推理规划,行动盲目、不可解释,一步走错没有纠偏机制
ReAct(融合)推理指导行动,观察反哺推理,互相纠偏多轮循环带来更高延迟,token 成本更高,还有不收敛风险

2. 循环结构(核心)

循环每一圈分三拍:Thought(模型写:这一步打算干什么、为什么)→ Action(模型写:工具名+参数,格式固定)→ Observation(不是模型写的:你的 controller 解析 Action、真正执行工具,把结果拼回上下文)。然后模型带着完整历史进入下一圈,直到输出 Final Answer。关键认知:模型永远只负责生成文本,真正碰外部世界的是你写的代码——这条分工线,面试官很爱挖。

角色谁产生值班排障里的对应物作用
Thought模型生成你写在工单里的判断:「疑似介质侧故障」规划下一步,留下可审计的推理痕迹
Action模型生成你敲的那条命令 / 点的那个按钮向外部世界要信息或施加改变
Observation外部程序执行工具后写入命令回显、监控曲线、作业日志用现实校准推理,提供纠错信号
Final Answer模型生成根因定位、结单报告循环终止信号
一轮 ReAct,上下文是怎么「滚雪球」的(▲=本轮新增):

第 1 轮发给模型:  Question
                  Thought#1 + Action#1     ▲ 模型生成
                  Observation#1            ▲ 工具执行后由你的代码拼回
第 2 轮发给模型:  Question + Thought#1 + Action#1 + Observation#1
                  Thought#2 + Action#2     ▲
                  Observation#2            ▲
第 N 轮发给模型:  [全部历史原样重放] + Thought#N
                  └→「信息齐了」→ Final Answer,循环终止

像运维工单:每步追加在案,全程可回放、可审计。
不像工单:上下文窗口有限,任务一长必须「滚动归档」——旧记录压成摘要,新记录留原文。

3. Prompt 模板(给模型的 few-shot 示例)

ReAct 的「框架」本体薄得出乎意料:几段 few-shot 示例,教模型按固定格式交替输出。下面是最小可用版(搜一道需要最新信息的题):

Question: 苹果公司现在的 CEO 是谁?
Thought: 这个问题需要最新信息,我用搜索工具查一下。
Action: search["苹果 CEO"]
Observation: 蒂姆·库克(Tim Cook)现任苹果 CEO……
Thought: 我已经拿到答案。
Final Answer: 蒂姆·库克(Tim Cook)。
  • Thought 行是模型的「自我独白」:写给它自己(先想后动,减少盲发动作),也写给人看(审计)。面试常问「Thought 到底有什么用」,答这两条就够了。
  • Action 行格式必须固定(如 search["查询词"]):解析它的是你写的正则/解析器,不是模型。格式散了 controller 就解析失败——这一行本质是模型与执行器之间的「接口契约」,和你写 API 的请求体一个地位。
  • Observation 行由你的代码写入:执行工具、截断/清洗结果、再拼回 prompt,模型只负责读。
  • Final Answer 是终止信号:controller 检测到它就退出循环,把它后面的内容作为最终输出。

4. Controller 骨架:剥掉神秘感,就是一个带熔断的循环

用你的 Python 后台视角看,所谓 Agent 框架拆开就是这副骨架:

def react_agent(question, tools, max_iterations=10):
    history = f"Question: {question}\n"
    for i in range(max_iterations):            # 熔断器:防死循环的最后一道闸
        output = llm(prompt_template + history) # 模型生成 Thought(可能带 Action)
        if "Final Answer" in output:            # 终止条件:模型自己喊停
            return parse_final(output)
        action = parse_action(output)           # 正则解析出 工具名 + 参数
        obs = tools[action.name](**action.args) # 真正执行工具的是你的代码
        history += output + f"\nObservation: {obs}\n"  # 滚雪球:历史全量重放
    return fallback()                           # 超轮次:降级 / 转人工 / 直接生成

看出熟悉的味道了吗?这就是分布式系统的经典三板斧:有限次重试 + 熔断 + 降级。max_iterations 是重试上限,fallback 是降级路径;parse_action 的解析失败、工具超时、结果超长,每个分支都得 try 住,否则一个异常就把整个循环打崩。

5. 为什么有效

  • 用外部观察 grounding 推理:每个关键结论都有现实回显背书,像备份系统的对账——「备份成功」不能只信任务返回码,要真恢复一次才算数。这直接压低幻觉和过时知识的危害。
  • 观察提供纠错信号:工具报错、结果与预期不符,这些「坏消息」会在下一轮 Thought 里被看见并改变路线;纯 CoT 推错了会沿错误一路滑到底,ReAct 相当于每步都有健康检查。
  • 可解释:完整轨迹像审计日志,事后能逐轮回放「当时为什么这么决策」。做基础设施出身的你一定懂:线上出事时,能回放的系统才是能运营的系统。

6. 局限与 trade-off

  • token 成本高:每轮把历史 Thought/Action/Observation 全量重放进上下文,越长越贵——像每处理一条新日志都把整个日志文件从头读一遍。缓解:截断+摘要、中间结果外置到状态存储只留引用。
  • 可能不收敛:模型反复调用却拿不到结果,像极了没配退避的 retry 风暴。必须 max_iterations 兜底,再加「连续 N 次相同动作且观察无变化 → 判定活锁」的检测。
  • 依赖工具描述质量:工具说明含糊,模型就选错或传错参——和接口文档一个道理,契约不写清副作用,调用方必然误用。工具越少越准,「工具海」反而拉低选对率。
  • 对简单任务「杀鸡用牛刀」,不如直接生成:查个天气也 Thought 三轮,延迟和成本都亏,路由层应先判断任务复杂度再决定走不走循环。

面试官追问
Q:ReAct 和 CoT 到底差在哪?
人话:CoT 是闭卷推演,ReAct 是开卷做题——推一步、查一步、验一步。类比:CoT 像排障时只凭三个月前的架构文档脑补根因,逻辑链再漂亮也可能全错,而且没人提醒你错了;ReAct 是标准排障流程:定假设、敲命令、看回显,每个结论都被真实回显锚定。技术:CoT 的所有中间结论都来自模型参数里的冻结知识,无法与外部世界交互,错了不会被发现;ReAct 在推理之间插入 Action-Observation,用外部结果做 grounding 和纠偏,代价是每轮交互的延迟与 token 成本。
Q:模型在 ReAct 里卡住,一直输出 Action 停不下来怎么办?
人话:三道保险丝:轮次上限、原地打转检测、预算熔断。类比:这就是治理 retry 风暴的三板斧——重试上限、退避、熔断降级,循环不能裸奔,max_iterations 就是那道熔断器。技术:① 设 max_iterations(如 10 轮)强制终止;② 检测重复模式:连续 N 次以相同参数调同一工具且观察无变化即判定死循环,可注入一条提示逼它换思路;③ token/时间预算超限即熔断,降级为直接生成或转人工,并保留全轨迹供复盘。
Q:有了 Function Calling,ReAct 还有用吗?
人话:不冲突:FC 升级的是「协议」,ReAct 提供的是「节奏」,现代 Agent 是 ReAct 的脑配 FC 的手。类比:像把自研 RPC 迁到 gRPC——调用契约更严、可校验了,但「先查状态、再定动作」的业务闭环一点没变。技术:FC 把 Action 变成带 JSON Schema 的结构化调用,参数可校验、可并行多工具,生产首选;ReAct 是其思想前身,在无原生 FC 的模型、或需要自由文本推理痕迹做审计调试的场景仍常用。讲清「文本协议→结构化协议」的演进是加分项。
Q:任务很长,历史把上下文窗口塞满了怎么办?
人话:老历史要归档:近期原文保留,远期压成摘要,中间结果外置。类比:就是备份系统的日志滚动归档——热日志原文放 SSD,冷日志压缩下沉磁带,不可能永远全量在线。技术:① 截断+摘要:早期 Observation 压成要点,只保留最近几轮原文;② 外置状态:中间结果写文件/数据库,上下文只留引用和结论;③ 分层:外层规划器拆子任务,子任务的 ReAct 轨迹不回流主上下文,只回传结论。
Q:Observation 经常返回一大坨(整页 HTML、几百 KB 日志),怎么处理?
人话:别让生数据进上下文——进去的应该是「信息」,不是「数据」。类比:你不会把 TB 级备份日志原样塞进监控面板,而是 grep 关键行、聚合成指标再给人看,Agent 也一样。技术:① 工具侧后处理:字段抽取、截断、只返回 top-k 条;② 检索类工具配 Rerank/分页,按需取;③ 超长内容先用小模型摘要再入上下文。观察质量直接决定下一轮 Thought 的质量,垃圾进、垃圾出。
术语卡
ReAct:Reasoning + Acting,推理与行动交织的提示框架,Agent 范式的地基。
Chain-of-Thought:让模型把中间推理步骤写出来的提示技术,ReAct 里「想」的那一半来源。
Thought:模型输出的推理步骤,写给自己的规划,也是给人的审计日志。
Action:模型输出的待执行动作(工具+参数),模型与执行器之间的接口契约。
Observation:工具/环境返回的结果,由外部程序写入上下文,不是模型写的。
Grounding:用外部事实锚定推理,减少幻觉。
幻觉:模型一本正经地编造事实,ReAct 靠观察压制它。
Max Iterations:循环轮次上限,防死循环的熔断器。
