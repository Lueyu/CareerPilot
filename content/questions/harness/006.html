Agent核心 · Q2

请详细解释 ReAct 框架。它是如何将思维链和行动结合起来，以完成复杂任务的？

⭐⭐⭐ #Agent#ReAct#核心范式 字节 / 阿里 / 腾讯（高频）
30秒电梯稿

"ReAct = Reasoning + Acting,核心是把「想」和「做」交织成一个循环:每一步模型先输出一段 Thought(推理)说明打算怎么做,再给一个 Action(行动)调用工具,拿到 Observation(观察)后继续下一轮思考,如此反复直到给出最终答案。它解决两个痛点:纯思维链(CoT)只会推理、知识过时会幻觉;纯行动又缺推理、容易乱试。把推理用外部观察来 grounding,错误能被及时纠正。整个框架就三行模板:Thought / Action / Observation。"

通俗类比

想象一个新手修电脑:他不会一上来就乱拆,而是边想边试——「屏幕黑?先看电源灯亮不亮」(Thought)→「检查电源线」(Action)→「哦灯也不亮,那是电源问题」(Observation)→「那就换根电源线试试」(下一个 Thought/Action)。这种"想一步、做一步、看结果、再想下一步"的节奏就是 ReAct。对比之下,纯推理像一个人只在脑子里盘算不动手(容易想当然),纯行动像一个人不问青红皂白乱试(低效)——ReAct 把两者拧成一股。

详细拆解

1. 背景:CoT 与 Act-only 各自的缺陷

范式优点缺点
CoT(纯推理)能拆解复杂问题、逻辑清晰知识是过时的记忆,会幻觉,错了不自知
Act-only(纯行动)能拿到真实信息没有推理规划,行动盲目、不可解释
ReAct(融合)推理指导行动,观察反哺推理互相纠偏,但 token 成本更高

2. 循环结构(核心)

3. Prompt 模板(给模型的 few-shot 示例)

Question: 苹果公司现在的 CEO 是谁?
Thought: 这个问题需要最新信息,我用搜索工具查一下。
Action: search["苹果 CEO"]
Observation: 蒂姆·库克(Tim Cook)现任苹果 CEO……
Thought: 我已经拿到答案。
Final Answer: 蒂姆·库克(Tim Cook)。

4. 为什么有效

  • 用外部观察 grounding 推理:减少幻觉与过时知识。
  • 观察提供纠错信号:行动失败或结果不符时,模型能据此调整下一步。
  • 可解释:思维轨迹可审计、可调试。

5. 局限与 trade-off

  • token 成本高:每轮把历史 Thought/Action/Observation 都拼进上下文,越长越贵。
  • 可能不收敛:模型反复调用却拿不到结果 → 死循环,需 max_iterations 兜底。
  • 依赖工具描述质量:工具写得含糊,模型选错。
  • 对简单任务「杀鸡用牛刀」,不如直接生成。
面试官追问
Q:ReAct 和 CoT 到底差在哪?
CoT 只有「推理」一条线,所有中间结论都来自模型内部知识,无法和外部世界交互,错了也不会被纠正;ReAct 在推理之间插入「行动-观察」,用外部结果给推理做 grounding 和纠偏。一句话:CoT 是"自己跟自己推",ReAct 是"边推边查边验证"。
Q:模型在 ReAct 里卡住,一直输出 Action 停不下来怎么办?
三层防护:① 设 max_iterations(如 10 轮)强制终止;② 检测重复动作(连续 N 次调用同一工具且观察结果无变化 → 判定死循环);③ 总 token/时间预算超限即熔断,转降级或要求人工介入。
Q:有了 Function Calling,ReAct 还有用吗?
两者是「通用文本协议 vs 结构化协议」的关系。Function Calling 把 Action 变成带 schema 的 JSON,可校验、可并行多工具、更稳定,现代生产首选;ReAct 是它的思想前身,在"没有原生 FC 支持的模型"或"需要自由文本推理痕迹"的场景仍常用(多跳推理调试、统一抽象各种工具)。能讲清这个演进关系很加分。
术语卡
ReAct:Reasoning + Acting,推理与行动交织的提示框架。
Thought:模型输出的推理步骤。
Action:模型输出的待执行动作(工具+参数)。
Observation:工具/环境返回的结果。
Grounding:用外部事实锚定推理,减少幻觉。
Max Iterations:循环轮次上限,防死循环。
