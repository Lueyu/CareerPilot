评估讨论 · Q10

如何持续监控和评估一个已经部署上线的 LLM 应用或 Agent 服务的表现，以应对可能出现的性能衰退或行为漂移？

⭐⭐⭐ #线上监控#性能监控 字节、阿里、腾讯（工程重点）
30秒电梯稿

"上线后的监控我分三层：模型质量层——输出对不对，用黄金集持续回归 + 线上流量抽样做 LLM-as-judge；服务质量层——延迟、错误率、token 成本、QPS；业务质量层——问题解决率、转人工率、用户满意度。应对漂移的核心手段：一是漂移检测（输入分布用 PSI/embedding 聚类监测，性能用回归分数监测）；二是版本化 + 金丝雀发布 + 秒级回滚，保证发现衰退能立刻切回。关键认知：漂移不只是"模型变了"——输入分布变、知识库更新、下游工具/API 改动、供应商静默升级，都会造成行为漂移。"

通俗类比

就像汽车上路后要装仪表盘 + 定期年检：油表水温表（实时指标）、发动机故障灯（告警）、每 1 万公里保养（定期回归）、发现油耗莫名变高就去查是轮胎没气还是油品变了（漂移排查）。不能车卖出去就不管了——LLM 应用也是一样，上线只是开始。

详细拆解

1. 为什么必须持续监控（漂移从哪来）

  • LLM/Agent 是概率系统，没有固定输出，也没有"一次测试通过就永远稳定"。
  • 漂移来源（都能在"模型没动"的情况下发生）：
漂移来源表现
输入分布漂移用户问法变了、新话题涌入、季节性需求
知识/数据变化知识库更新、政策变更，旧答案过时
下游依赖变化检索库、工具 API、第三方模型静默升级
自身变更Prompt、模型版本、参数的改动引入回归

2. 三层监控体系（可背的框架）

层级关注什么典型指标/手段
模型质量层输出对不对、有没有幻觉黄金集回归分数、LLM-as-judge 抽样、引用忠实度
服务质量层稳不稳、快不快、贵不贵错误率、P95/P99 延迟、单请求 token、QPS
业务质量层用户满不满意问题解决率、转人工率、留存、点踩率、NPS

3. 漂移检测怎么做

  • 数据漂移：监测输入分布的统计特征变化——结构化特征用 PSI（群体稳定指数）或 KL 散度；文本用 embedding 聚类，看是否有新的话题簇冒出来。
  • 性能漂移：定期把最新线上流量喂给"黄金集 + 回归集"，看分数是否跌破基线阈值。
  • 概念漂移：同一问题的"正确答案"本身变了（如政策更新），要靠业务方同步更新评估集，否则回归集自己就过时了。

4. 持续评估管线（把评估变成日常动作）

  • 黄金集持续回归：核心评估集接入 CI/CD，每次发版自动跑，分数低于基线自动拦截发布。
  • 线上流量抽样：每天从真实流量抽一小批，用 LLM-as-judge 打分 + 人工抽检，作为"线上真实质量"的代理指标。
  • Bad case 回流：用户点踩、转人工、投诉的样本自动进入评估集——线上 bad case 是最值钱的评估数据来源。

5. 发现衰退怎么快速止损

  • 版本化一切：Prompt、模型、配置都版本化，任何变更可定位、可回滚。
  • 金丝雀发布：新版本先切 5%~10% 流量，对比基线指标，异常自动扩大/回滚。
  • 告警分级：服务质量层（错误率、延迟）秒级告警；质量层（回归分数、judge 分）分钟/小时级；业务层日级复盘。
面试加分句："性能衰退"要看的是"相对基线的偏离"，而不是绝对值——先建立上线时的基线快照（各指标 + 评估分），之后一切监控都是"偏离基线多少就告警"。没有基线的监控只是看数字，不叫监控。
面试官追问
Q:模型根本没动，为什么质量会下降？
因为决定质量的除了模型权重，还有上下文里的所有东西：输入分布变了（用户换了问法）、知识库更新了（旧答案过时）、检索结果质量变了、下游 API 改了返回格式、甚至供应商静默升级了模型版本。所以"模型没动"不等于"系统没变"——这正是为什么要监控整条链路而不是只看模型。
Q:怎么区分是"模型变差"还是"用户需求变了"？
看回归集 vs 线上流量的对比：如果固定回归集分数没变、但线上质量指标下降，说明是输入分布漂移（来了新需求），要补评估集和训练数据；如果回归集分数也掉了，说明是系统本身退化（模型/Prompt/检索变了），要查变更记录定位。两者对策完全不同，所以一定要把两类数据分开看。
Q:黄金集怎么维护？会不会自己就过时了？
会，所以要持续维护：① 定期更新——把线上新出现的典型 bad case 和用户点踩样本加进去；② 业务方同步——政策、知识变化时更新标准答案；③ 去重防偏——防止评估集越来越集中在某类问题导致"应试优化"。维护评估集本身就是一个持续投入，把它当"活的资产"而不是一次性交付。
Q:告警了但一时半会儿修不好，怎么兜底？
分级降级：① 秒级回滚到上一个稳定版本（这是最快的止损）；② 没旧版可回就降级——Agent 降级成简单 RAG 直答、或对高风险请求转人工；③ 业务侧限流/熔断，避免坏体验扩散。原则是"先止损、后排查"，不要让有问题的版本继续服务用户。
术语卡
数据漂移:输入分布随时间变化,导致模型在新数据上失效。
概念漂移:同一问题的"正确答案"本身变了(如政策更新)。
PSI:群体稳定指数,衡量分布漂移的常用统计量。
黄金集:每次变更必跑的核心评估样本,防回归。
金丝雀发布:新版本先切小流量验证,异常回滚。
基线快照:上线时的指标基线,后续监控看"偏离多少"。
