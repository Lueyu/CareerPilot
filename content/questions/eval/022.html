请介绍几个目前行业内广泛使用的 LLM 综合性基准测试，并说明它们各自的侧重点。（例如：MMLU, Big-Bench, HumanEval）

⭐⭐ #基准测试#MMLU#HumanEval 字节 / 阿里 / OpenAI（高频）
30秒电梯稿

"我按能力维度介绍三个:MMLU 测知识与常识广度——约 1.6 万道四选一,覆盖 57 个学科,是通用能力的事实标准;Big-Bench 测任务多样性——200+ 个异构任务,从逻辑、常识到多步推理,考察模型能不能泛化到没见过的任务;HumanEval 测代码生成——164 道手写 Python 题,用 pass@k 按"能不能跑通单元测试"判对错。三个分别对应:知识、泛化、代码执行正确性。"

通俗类比

把模型想象成一个考生,这三个基准是三张不同的卷子:MMLU 是"百科知识竞赛"——57 门科目的选择题,考知识面广不广;Big-Bench 是"趣味全能综艺"——什么题型都有,考应变和举一反三;HumanEval 是"上机编程考试"——不是看代码写得像不像范文,而是直接跑测试用例,跑通了才算对。

详细拆解

1. MMLU——知识广度的事实标准

  • 全称:Massive Multitask Language Understanding。约 1.6 万道四选一选择题,横跨 57 个学科(数学、物理、法律、医学、历史、伦理等),分初高中/大学/专业级难度。
  • 测什么:模型的知识储备和常识推理,属于"世界知识"维度,是通用大模型发布必报的指标。
  • 局限:选择题形式容易被"背题"(数据污染),且四选一有随机猜对的成分(25% 基线)。

2. Big-Bench——任务多样性与泛化

  • 全称:Beyond the Imitation Game Benchmark,社区协作收集的 204 个任务,覆盖逻辑推理、常识、数学、编程、讽刺识别、因果判断等异构任务。
  • 衍生:BIG-Bench Hard(BBH) 从里面挑出当时大模型表现差、人类表现好的 23 个"硬"任务,专门测多步推理上限。
  • 测什么:模型在未见过的任务上的零样本/少样本泛化能力,而不是刷特定任务。

3. HumanEval——代码生成的执行正确性

  • 内容:164 道手写 Python 题,给出函数签名 + docstring,让模型补全函数体。
  • 关键设计:用 pass@k 打分——每个题采样 k 个答案,只要有一个跑通隐藏单元测试就算对。避免了"逐 token 匹配参考答案"的旧式代码评分缺陷。
  • 变体:HumanEval+ 加更严苛的测试;MBPP 是另一套社区编程题;LiveCodeBench 从 LeetCode 实时抓题,专门对抗数据污染。
基准任务形式侧重点判定方式
MMLU四选一(57 学科)知识广度、常识选项精确匹配
Big-Bench / BBH异构任务 200+/23任务泛化、多步推理任务特定规则/judge
HumanEvalPython 补全 164 题代码正确性pass@k + 单测
GSM8K(补充)小学数学应用题多步数学推理最终数值答案

4. 必答的"坑":数据污染与饱和

  • 污染(contamination):训练语料里混入了基准题目,模型"见过原题"就会虚高。对策:动态/私密测试集、去污染检测(n-gram 重叠检索)、LiveCodeBench 这种实时题源。
  • 榜单饱和:主流基准分数趋近天花板后区分度下降,于是行业不断推出更难的基准(如 BBH、更难的 Agent 基准),这也解释了为什么评估要"追新"。
面试官追问
Q:pass@1 和 pass@10 有什么区别,报告时用哪个？
pass@k 表示"每个题采样 k 次,至少一次通过就算对"。pass@1 测模型一次就写对的能力(生产里用户就看第一版);pass@10 反映模型"给足采样机会能不能解出来"(更接近自修复/多候选场景)。报告要看口径:同一模型 pass@10 天然远高于 pass@1,跨模型对比必须用同一个 k。生产落地我更关心 pass@1。
Q:怎么判断一个基准分数是不是被数据污染了？
几种信号:① 模型对改过字面、语义不变的题目分数骤降(说明背的是字面);② 题目在训练集里能被 n-gram 检索命中;③ 模型对"见过"的题有异常自信。工程上做去污染检查 + 用动态/私密测试集 + 定期换新题源。
Q:这些通用基准够不够用,还要看什么？
不够。它们是"体检"不是"诊断":能横向比模型,但和你业务不直接相关。落地必须补自有评测集——从真实用户 query 采样、按业务指标打标,再和通用基准一起看。通用基准负责"这个模型底子行不行",自建集负责"它在我的场景行不行"。
