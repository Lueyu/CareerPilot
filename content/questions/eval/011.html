Agent算法 · Q28

如何设计 Agent 规划能力的评估实验?

⭐⭐⭐⭐ #实验设计#Agent#评估 阿里 / 腾讯(真题)
30秒电梯稿

"评估规划能力我按四块设计:数据集——选任务型 benchmark(AgentBench / WebArena / ALFWorld)+ 自建分层测试集(线性→分支→需工具→需重规划),每条标黄金轨迹;Baseline——Zero-shot 直答(无规划)、ReAct、Plan-and-Solve、ToT/Reflexion 这几个梯度,再加 GPT-4 级强模型和人类上界;指标——任务成功率(最终状态)、规划质量(子目标/工具选择正确率)、效率(步数、token、延迟)、鲁棒性(注入失败看恢复率);消融——逐个拆掉 planner、反思模块、工具、few-shot 示例,看指标掉多少,把规划的价值归因清楚。"

通俗类比

就像考核一个项目经理的"拆解能力":给他一批从易到难的项目(数据集),简单的"订会议室"到复杂的"跨部门多步骤还中途翻车要补救";再安排几个不同水平的对照组(Baseline)——只会一步到位的实习生、边走边想的普通员工、会先列计划的老员工;打分时既看结果成没成(成功率),也看过程有没有瞎绕路(步数/成本),最后故意在项目里埋几个坑(扰动),看他会不会"重排计划"救回来——这才能评出真正的规划能力,而不是只会背流程。

详细拆解

1. 先定义"规划能力"(否则无法打分)

  • 规划 = 把目标分解为子任务 + 确定动作/工具序列与依赖顺序 + 执行中失败时重规划(replan)。
  • 因此实验要同时测三件事:分解对不对、顺序对不对、失败能不能救——缺一个都不叫规划能力。

2. 数据集设计

  • 现成 benchmark:AgentBench(OS/DB/网页等多环境)、WebArena(真实网页任务)、ALFWorld(文本交互式家务)、GAIA(通用助手推理)、PlanBench(纯规划逻辑题)。用它们保证可复现、可对标。
  • 自建分层集(按规划复杂度分级,是本题亮点):
层级任务形态考察点
L1 线性单一固定步骤链能否按序执行
L2 分支按条件选不同路径条件判断与分支选择
L3 多工具需调用多个工具并传参工具选择与参数正确性
L4 重规划中途工具失败/环境变化能否感知失败并改道
  • 标注:每条含目标、黄金轨迹(正确动作序列)、最终状态判据(可程序化校验:订单状态/页面元素/文件内容),避免只靠人工。

3. Baseline 梯度(对照要"有梯度"才说明问题)

  • Zero-shot 直答:不给规划,直接让 LLM 一步输出答案——下界。
  • ReAct:思考-行动交替,无显式事前规划——中间态。
  • Plan-and-Solve / ReWOO:先出计划再执行——规划主力变体。
  • ToT / Reflexion:树搜索或自我反思重规划——更强变体。
  • 强模型 + 人类:GPT-4/Claude 作模型上界,人类完成率作理论上界。

4. 评估指标(别只报成功率)

维度指标说明
结果任务成功率 / 目标达成率最终状态是否满足判据
规划质量子目标分解正确率、动作序列正确率、工具选择准确率过程对错,和结果分开看
效率平均步数、token 成本、P50/P99 延迟、重规划次数规划要"省"才有价值
鲁棒性扰动后成功率、失败恢复率注入工具故障/干扰信息后能否 replan
稳定性同 prompt 多次运行的方差LLM 有随机性,报均值+方差

5. 消融实验(把"规划"的价值单独拎出来)

  • 拆 planner:Plan-and-Solve → 退化成 ReAct → 再退化成 Zero-shot,看每层掉多少分。
  • 拆反思:去掉 Reflexion 的重规划回路,专门在 L4 集上看恢复率崩多少——证明"失败恢复"的贡献。
  • 拆工具:削减可用工具集,看工具选择准确率与成功率如何变化。
  • 拆 few-shot 规划示例:去掉 prompt 里的示例,证明示例是"教"而非"撞"。
  • 采样策略:temperature/多次采样取多数,看规划稳定性。

6. 实验控制(严谨性)

  • 固定模型版本与 prompt;每任务多次运行取平均 + 报告方差;用配对检验/bootstrap判显著性,而非"看着高了 2 个点"。
  • 训练/测试严格隔离:自建集的黄金轨迹不得进入任何 prompt 示例。
  • 程序化判据优先,人工/LLM-as-judge 兜底,并抽 5% 对齐 judge 与人的一致率。
面试官追问
Q:怎么证明"规划"真的有用,而不是模型本身更强?
用同一个基座模型跑所有 Baseline:Zero-shot 和 Plan-and-Solve 用完全相同的模型和工具,唯一变量是"是否显式规划"。若后者显著更好,提升就归因于规划机制而非模型能力;再做消融把 planner 拆掉看回退,双保险锁定因果。
Q:Agent 是多步的,中间对了最后错了怎么算分?
过程和结果分开计:轨迹级指标(子目标/工具/参数正确率)看"是不是真会规划",结果级(成功率)看"最终有没有成";再加"有效步占比"(多少调用是白干的)衡量绕路程度,避免只看终点掩盖过程混乱。
Q:规划 benchmark 会不会被刷(数据泄漏)?
会,公开集如 WebArena 的题目可能进过某些模型训练语料,分数虚高。对策:自建私域分层集 + 定期轮换题目 + 用程序化判据(而非选择题式可背的答案)+ 关键结论用私域任务二次验证,不把公开榜分数当绝对真理。
Q:规划能力和"多步调用工具能力"怎么区分?
规划强调"先想清楚整体再动"(事前分解+依赖排序+失败预案),工具调用强调"单步动作是否选对、参数是否正确"。实验上可对比:去掉事前计划、纯 ReAct 照样能正确调用工具但步数多、遇挫易卡死——两者在"工具准确率"上接近、在"重规划恢复率"上拉开差距,这个 gap 就是规划独有的贡献。
术语卡
ReAct:Reasoning+Acting,思考与行动交替的范式。
ToT:Tree of Thoughts,树状搜索多路推理路径。
Replan:执行失败后重新生成计划的机制。
黄金轨迹:标注好的正确动作序列,用于过程判分。
Bootstrap:重采样做置信区间/显著性检验的方法。
