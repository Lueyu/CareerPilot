评估讨论 · Q6

你了解哪些专门用于评估 Agent 能力的基准测试？这些基准通常如何构建测试环境和任务？

⭐⭐⭐ #Agent基准#测试环境 字节 / 阿里
先说人话:这题在问两件事:给 Agent 做摸底考,世界上有哪些靠谱考场,以及这些考场本身是怎么搭起来的。面试官爱考,因为它一眼分清「背榜单的人」和「搭过评测的人」——报得出基准名只算及格,讲不清环境隔离、执行式评估、防污染这套构建方法论,暴露的就是从没亲手搭过评测。
30秒电梯稿

"我按『考什么工种』分五类答。SWE-bench 考软件工程:从真实 GitHub issue 出题,Agent 提交 patch,拿隐藏单测定生死;AgentBench 考跨环境通用性:同一个考生不换脑子连闯 8 个环境;WebArena 考网页操作:自托管真实网站,按环境最终状态断言判分;GAIA 考通用助手能力:多步、自由用工具,答案可精确判定;τ²-bench 考工具调用 + 多轮对话:规则化用户模拟器按剧本提需求,数据库终态定对错。共性一句话:真实或高仿环境 + 执行式评估 + 防污染——不看 Agent 说什么,看它干完活之后世界变成了什么样。"

通俗类比

总纲:给 Agent 做基准测试,本质是给备份系统做恢复演练。行业里有句老话——没验证过恢复的备份不算备份;同理,没在真实环境里执行过任务的 Agent,榜单高分不算能力。传统 LLM 评测(比如 MMLU 这类)像笔试:发一张卷子、对标准答案,考的是「说」;Agent 评测像实战演练:把考生扔进一个真环境(操作系统、数据库、网站),让它真敲命令、真下订单,考的是「做」——判卷也不靠考官印象,靠验收脚本查环境的最终状态。

五个基准就是五个工种的演练场:SWE-bench 是「修复工单」——真实项目报了 bug,交修复方案,验收时既看坏的修好没,又看别的有没有被顺带弄坏;AgentBench 是「轮岗考核」——一个考生连闯 8 个岗位,操作系统、数据库、购物网站挨个值班;WebArena 是「自建仿真业务区」——像容灾里的复制数据中心,在自己机房 1:1 搭一套 GitLab/商城/论坛来办事;GAIA 是「综合应急处置」——不限工具、只看结果,搜索引擎、计算器、文件随便用,交卷只对最终答案;τ²-bench 是「带客户的服务台演习」——对面坐着一个按剧本演、还会临时改主意的模拟客户,后台是真数据库,考的是沟通和动手双在线。

哪里像:都是「真环境 + 真动作 + 结果验收」;都要可重置——每场考试的环境从同一个镜像克隆、演完即毁,像演练环境用完从模板重建;都要可复现——任务和验收标准像演练剧本一样做版本管理。哪里不像:容灾演练要真机器真数据,又贵又慢,一年跑不了几场;Agent 考场是 Docker/虚拟机秒级克隆,一晚上能并行开几千个考场,判卷全自动——便宜到可以拿 Agent 反复试错,这在容灾世界是不可想象的奢侈。

详细拆解

1. 为什么 Agent 评测必须换一套打法

LLM 评测判的是「生成的文本对不对」,Agent 评测判的是「世界的状态对不对」——订单有没有真的下进数据库、bug 有没有被真的修掉、文件有没有被真的创建。判卷对象从「一段话」变成「一堆状态」,整个评测体系就得重搭:要有能被改变状态的环境,要有能查状态的验收器,还要防止考生提前背题。下面按这个逻辑展开。

3. 逐个拆:每个考场考什么、怎么判卷

  • SWE-bench:输入 = 仓库快照 + issue 描述(相当于一张工单),输出 = 一份 patch(代码改动,相当于修复方案)。判卷不问「代码写得像不像」,只问「测试过没过」(流水线见下图)。衍生版 SWE-bench Verified 是人工逐条校验、去掉描述含糊和被污染题目后的 500 条精选,如今是软件 Agent 的硬通货——各家报分基本都报 Verified。
  • AgentBench:强调跨环境通用性——同一个 Agent 不做任何微调,连闯 8 个完全不同的环境(ALFWorld 家务、WebShop 购物、OS 命令行、数据库 SQL 等),考的是「通用干活能力」而非单点。像把一套备份软件原封不动部署到 8 种不同负载的集群,看哪些场景掉链子。
  • WebArena:把 GitLab、电商、论坛、CMS 四类站点自托管,任务从「找出某帖的最高赞评论」到「下单最便宜的符合条件商品」。判分不靠截图打分,靠查环境最终状态——数据库里那条订单对不对。真实感和可控性兼得,这是它比早期网页基准强的地方。
  • GAIA:设计哲学是「对人简单、对 AI 难」——不需要专业知识,但需要多步规划 + 工具组合(搜索、读文件、计算)。结果悬殊:人类平均 92% 左右,早期 GPT-4 配插件只有约 15%。防作弊两手:答案设计成精确可判定,且限制 API 直连——不让你绕过工具直接调服务把答案掏出来。
  • τ²-bench(tau²-bench):把「Agent + 工具 + 领域数据库 + 用户」打包成闭环——用户由规则化模拟器扮演,按剧本对话、会改主意、会追问,「双控」场景里用户侧也有动作权。评估对完话后查数据库终态,并用 pass^k(k 次独立重跑全部成功才算过)专测稳定性。

同族还可以点名:OSWorld 考真机操作系统上的 GUI 操作(让 Agent 像运维一样在桌面里点开文件管理器干活),ALFWorld 考文字模拟的家务环境——它们和上表五个共同构成「按环境分类」的版图。

4. 把 SWE-bench 的判卷摊开看(执行式评估的标本)

SWE-bench 判卷流水线(一次判卷 ≈ 一次恢复演练验收):

  考题 = 真实仓库快照 + issue 描述(工单)
     │
     ▼
  Agent 交卷 = 一份 patch(代码改动,相当于修复方案)
     │
     ▼  自动应用 patch,起 Docker 沙箱(从 golden image 克隆,秒级)
     │
     ├─ F2P 测试:修 bug 之前失败的用例 ──→ 现在必须全过   (恢复成功了吗?)
     └─ P2P 测试:修 bug 之前通过的用例 ──→ 现在也必须全过 (没弄坏别的吗?)
     │
     ▼
  两项全绿才算通过 —— "修好了"和"没修出新问题"缺一不可

5. 环境与任务通常怎么构建(方法论)

  • 环境隔离:Docker 沙箱/虚拟机隔离,像给演练环境打快照:每场考试从 golden image 克隆、演完即毁,Agent 再能折腾也碰不到宿主。顺带白捡两项工程红利:可并行(一晚几千个考场,和压测集群横向扩容一个道理)、可复现(所有考生见到同一个初始世界)。
  • 执行式评估优先:能用「结果状态」判定的——测试过没过、数据库终态对不对、页面到没到位——绝不用主观打分;让 LLM 当裁判只是无标准答案场景的兜底。这就是「恢复成没成功看 checksum 和应用校验,不看值班工程师感觉恢复了」的评测版,也是 Agent 基准和纯文本基准最大的分水岭。
  • 真实 vs 仿真权衡:真实环境(WebArena、SWE-bench)信度高、贴近生产,但搭建贵、维护难、跑一轮成本高;仿真环境(ALFWorld、部分 AgentBench 环境)便宜可控、可无限重置,但和现实有 gap。选型就是「真机容灾演练 vs 仿真推演」的取舍——在预算和结论可信度之间找平衡。
  • 防污染与可复现:数据集版本化(像备份集的版本管理,每版分数可追溯对比);隐藏测试不下发给被测方;GAIA 还限制 API 直连;私密集和定期换新题兜底。类比:演练剧本保密、验收标准不提前透给被测方——否则演练变表演、考试变背题,分数再高也不代表能力。
面试官追问
Q:SWE-bench 具体怎么判定一个 patch 对不对？
人话:判卷不看代码写得像不像,只看测试跑没跑过——原来挂的现在得过,原来过的还不能被改坏。类比:恢复演练验收也是两条线:坏的那份数据要能恢复,其他租户的正常业务不能被你的修复动作弄坏——只验前者,回归问题就漏进生产了。技术:每个实例 = 仓库快照 + issue;Agent 交 patch,在沙箱应用后跑两组单测:F2P(修复前失败 → 须通过)和 P2P(修复前通过 → 须仍通过),全绿才算过。SWE-bench Verified 是人工校验 500 条的去污染子集,报分基本认它。
Q:WebArena 和 GAIA 都是真实任务,区别在哪？
人话:一个是在自家封闭考场考「网页操作」这个单项,一个是开放世界考「综合办事」,环境可控性和自由度正好相反。类比:WebArena 像在自建机房搭一套 1:1 复制的业务系统做封闭演练,环境可控、验收精确;GAIA 像开放场景的应急处置,不限路径,只对最终结果验收。技术:WebArena 自托管 GitLab/电商/论坛/CMS(812 个任务),判分靠环境状态断言;GAIA 466 题、三级难度,允许自由组合工具但限制 API 直连,答案精确匹配。前者考交互技能,后者考多步规划 + 工具组合。
Q:为什么 τ²-bench 要用 pass^k,让同一道题连跑 k 次？
人话:Agent 跑同一道题,这次过、下次挂是常态,所以要看稳定性,不能看发挥最好的那次。类比:容灾演练季度连跑,一次超常发挥不算本事,连续每个季度都达标才敢写进 SLA——pass^k 就是「连跑 k 次全过」的及格线。技术:pass^k 要求 k 次独立重跑全部成功(k 常取 1/4/8),配合数据库终态校验,专治采样运气好。注意它和代码评测常用的 pass@k(至少一次成功)方向相反:pass@k 量能力上限,pass^k 量交付可靠性——Agent 要上岗干活,业务要的是后者。
Q:这些公开基准有什么短板,实际工作够用吗？
人话:公开基准管「选型和横向对比」,不管「你的业务行不行」——它考的是通用能力,不是你的任务分布。类比:行业容灾成熟度评估能给你对标分数,但兑现不了你自己的 RTO 承诺——那得拿自己的系统、自己的变更流量,建自己的演练。技术:短板四条:与业务任务分布有 gap;Agent 多步执行,全量评测成本高;公开题有数据污染风险;部分环境比真实系统简化。落地做法:公开基准做初筛和版本回归跟踪,上线前自建与业务对齐的评测集,分数只和自己历史比,不直接当 KPI。
术语卡
SWE-bench:用真实 GitHub issue 出题、拿隐藏单测验 patch 的软件 Agent 基准,Verified 是它 500 条人工校验的精选版。
AgentBench:8 个环境轮考、测跨环境通用性的 Agent 基准。
WebArena:自托管真实网站、靠环境状态断言判分的网页操作基准。
GAIA:466 题开放式助手任务,人类 90%+ 而早期 GPT-4 配插件仅约 15%。
τ²-bench:工具 + 规则化用户模拟器 + 领域数据库的多轮交互基准,pass^k 看稳定性。
执行式评估:靠跑代码、查状态判对错,不靠主观打分——「没演练过恢复的备份不算备份」的评测版。
F2P/P2P:修复前失败/修复前通过的单测组合拳,确保「修好了」且「没修坏别的」。
沙箱:与宿主隔离的一次性考场,从镜像克隆、演完即毁,天然支持并行和复现。
数据污染:考题泄进训练集,考试变背题——基准靠隐藏测试和定期换题来防。
