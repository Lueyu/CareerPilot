你了解哪些专门用于评估 Agent 能力的基准测试？这些基准通常如何构建测试环境和任务？

⭐⭐⭐ #Agent基准#测试环境 字节 / 阿里
30秒电梯稿

"我按场景分五类:SWE-bench 测软件工程——从真实 GitHub issue 出题,让 Agent 改代码、跑隐藏单测判对错;AgentBench 测多环境通用性——8 个环境(操作系统、数据库、网页购物、知识图谱等);WebArena 测网页操作——自建真实网站(GitLab/商城/论坛);GAIA 测真实世界助手能力——多步、需用工具、答案可用程序判定;τ²-bench 测工具调用 + 用户对话——用规则化用户模拟器和数据库评估。它们的共性:真实/仿真环境 + 执行式评估 + 防污染。"

通俗类比

这些基准就像给 Agent 办的不同工种的上岗实操考试:SWE-bench 是"程序员改 bug"——给你真实项目的报错单,改完代码跑测试用例验活;AgentBench 是"全能打杂"——一会儿查数据库、一会儿逛淘宝、一会儿玩卡牌;WebArena 是"网页办事员"——在真实网站上发帖、购物、建仓库;GAIA 是"私人助理"——交给你一个真实任务,过程随便你用什么工具,最后只看结果对不对。

详细拆解

1. 代表性 Agent 基准(逐个讲)

基准领域/环境任务来源判定方式
SWE-bench软件工程(真实 Python 仓库)真实 GitHub issue跑单测(隐藏测试补丁)
AgentBench8 环境:OS/数据库/知识图谱/网页购物/ALFWorld 等人工构造各环境自带成功函数
WebArena自建真实网站(GitLab/商城/论坛/CMS)人工编写任务环境状态断言
GAIA真实世界助手(自由用工具)人工出题、防检索捷径精确答案匹配
τ²-bench工具 + 对话(零售/航空/电信等域)领域数据库 + 用户模拟器pass^k + 数据库状态校验

2. 各自特点与侧重点

  • SWE-bench:任务 = "给 issue 描述 + 仓库快照,生成 patch"。评估 = 用test patch(测试补丁)跑测试,通过即通过。衍生出 SWE-bench Verified(精选 500 条、去污染)是当前软件 Agent 的硬通货。
  • AgentBench:强调跨环境通用性,同一个 Agent 不做微调去闯 8 个完全不同的环境(如 ALFWorld 家务、WebShop 购物、OS 命令、数据库 SQL),考的是"通用 Agent 能力"而非单点。
  • WebArena:把真实网站(GitLab、电商、论坛、内容管理)自托管,任务从"找帖子"到"购物下单",评估靠环境状态断言(最终页面/数据库是否达到目标),真实感强。
  • GAIA:466 个真实助手任务,需要多步 + 组合工具(搜索/计算/阅读文件);人类平均 90%+,而早期 GPT-4 配插件仅 15% 左右;故意限制 API 直连防止模型"作弊",答案做成可精确判定的形式。
  • τ²-bench(tau²-bench):把"Agent + 用户 + 工具 + 领域数据库"打包成一个闭环,用规则化用户模拟器按脚本对话,用 pass^k(k 次对话中至少一次成功)评估,能测"多轮交互 + 工具执行 + 策略遵循"。

3. 环境与任务通常怎么构建(方法论)

  • 环境隔离:Docker 沙箱 / 虚拟机隔离,保证 Agent 动作不影响宿主、可快速重置、可并行跑。
  • 执行式评估优先:能用"结果状态"(测试是否过、数据库是否对、页面是否到位)判定的,绝不用主观打分——这是 Agent 基准和纯文本基准最大的区别。
  • 真实 vs 仿真权衡:真实(WebArena、SWE-bench)信度高但贵、难维护;仿真(ALFWorld、部分 AgentBench 环境)便宜可控但可能与现实有 gap。
  • 防污染与可复现:数据集版本化、隐藏测试、限制 API 直连(GAIA),保证分数不被"刷题"污染。
面试官追问
Q:SWE-bench 具体怎么判定一个 patch 对不对？
每个实例给 Agent 的是代码仓库 + issue 描述,Agent 产出 patch(代码改动)。评估时应用 patch,再运行该 issue 对应的失败测试(F2P)+ 通过测试(P2P):要"原来失败的测试现在过了,且原来通过的测试没被破坏"。避免只看"通过了新测试"却引入了回归。这比用 LLM 看代码"像不像"可靠得多。
Q:WebArena 和 GAIA 都是真实任务,区别在哪？
核心在环境可控性和自由度:WebArena 把网站自托管,环境状态可控、评估靠状态断言,重"网页交互"这个特定技能;GAIA 不限定环境,让 Agent 自由组合外部工具(搜索、读文件、计算),重"多步规划 + 工具组合"的通用助手能力,并用精确答案 + 限制 API 直连来防作弊。一个是"限定考场考网页操作",一个是"开放考场考综合办事"。
Q:这些公开基准有什么短板,实际工作够用吗？
短板:① 和业务场景有 gap——测的是通用能力,不一定对应你的真实任务分布;② 成本高——Agent 多步执行,大测评一遍很贵;③ 污染风险——公开题可能被训进模型;④ 部分环境简化,和真实系统有差异。所以公开基准用于"选型 + 横向对比",落地一定要自建与业务对齐的评测集,公开基准分数不能直接当 KPI。
术语卡
SWE-bench:真实 GitHub issue 改代码、跑测试的软件 Agent 基准。
AgentBench:8 环境、测通用 Agent 能力的基准。
WebArena:自托管真实网站、测网页操作能力的基准。
GAIA:真实助手任务、多步规划 + 工具组合的基准。
τ²-bench:工具 + 用户模拟器 + 数据库的多轮交互基准。
执行式评估:通过跑代码/状态断言判定对错,而非主观打分。
