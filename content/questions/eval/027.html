评估讨论 · Q7

在评估一个 Agent 的任务完成情况时，除了最终结果的正确性，还有哪些过程指标是值得关注的？（例如：效率、成本、鲁棒性）

⭐⭐ #过程评估#效率指标 所有公司
30秒电梯稿

"除了『答对了没』，我会从四个维度看过程：效率——完成任务走了多少步、多快、有没有走弯路；成本——单任务消耗的 token、调用费用和延迟；鲁棒性——面对扰动或中途失败，能不能自恢复、重试是否收敛；过程质量——工具选得对不对、轨迹可不可审计。核心观点是：最终正确 ≠ 过程可靠——一个靠碰运气蒙对 10 次、但 50% 时间在乱调工具的 Agent，上线后一定翻车。过程指标就是用来区分『真会』和『蒙对』的。"

通俗类比

就像评价一个外卖骑手，不能只看"送到了没"，还要看：送得快不快（效率/延迟）、绕了多少冤枉路（步数/轨迹）、有没有超时投诉和闯红灯（鲁棒性/合规）、每单成本多少（成本）。一个次次送达但全程逆行闯红灯的骑手，早晚出大事——结果对不代表过程对，评估 Agent 同理。

详细拆解

1. 为什么只看最终正确性不够（先立论）

  • LLM 是概率系统，同一个任务可能"这次对、下次错"。只看单次结果，会把不稳定的 Agent 误判成"及格"。
  • 最终正确性是滞后且稀疏的信号——很多错误在过程中就能暴露（选错工具、重复调用、陷入循环），等到结果错了才意识到，上线已经晚了。
  • 过程指标能回答工程上最关键的三个问题：能不能规模化（成本/延迟）、能不能扛压（鲁棒性）、好不好排查（可观测）。

2. 四类过程指标（可背下来的框架）

维度指标怎么测揭示的问题
效率任务完成率、平均步数、TTFT/总延迟、重复调用次数从执行轨迹统计走弯路、低效规划
成本单任务 token 数、调用费用、模型调用次数网关/计费日志聚合烧钱、过度调用
鲁棒性失败后自恢复率、扰动下成功率、重试是否收敛注入故障、扰动重放脆弱、不可靠
过程质量工具选择准确率、轨迹可审计性、是否有越权/误操作LLM-as-judge + 人工抽检选错工具、行为异常

3. 效率类指标怎么落地

  • 任务完成率（task success rate）：离线评估集上跑 N 次，统计最终达成目标的占比。注意要和"过程分"分开看——同样完成，10 步完成的比 30 步完成的更优。
  • 步数（step count）：完成一个任务 Agent 平均走多少步、调用多少次工具。步数暴增通常意味着规划失效或工具不匹配。
  • 延迟：拆成 TTFT（首字/首动作时间）和总时长。Agent 是"多步串行"，每多一步都加一次 LLM 往返，延迟对步数高度敏感。

4. 成本类指标：token 消耗 = 上下文（每次调用都要重传历史）× 步数。一个 20 步的 Agent，上下文会随着轨迹越滚越大，token 成本可能是指数级的——步数优化和上下文压缩，本质就是成本优化。

5. 鲁棒性类指标（最容易被忽略）

  • 扰动鲁棒性：把输入做轻微改写、注入噪声、换一种说法，看成功率是否跳水。
  • 故障恢复：故意让某次工具调用返回错误，看 Agent 是能换策略继续，还是直接摆烂。
  • 收敛性：重试后是越来越好还是越陷越深（有的 Agent 会在失败循环里无限打转）。

6. 过程质量与可观测：完整保留执行轨迹（每步的输入、工具选择、中间产出），一方面供事后排查，另一方面用 LLM-as-judge 对"工具选择是否合理、步骤是否必要"打分，再人工抽检争议样本。这是过程评估区别于"只看最终分"的核心工程能力。

加分表达：最终正确性是必要条件，过程指标是上线决策条件——正确率高但步数/成本翻倍、鲁棒性差的 Agent，不该上线；反之过程干净利落、偶尔结果错的，往往值得再调一版 Prompt 而不是推倒重来。
面试官追问
Q:过程指标这么多，哪个最重要？为什么？
看业务阶段给优先级：上线前最重要的是任务完成率 + 鲁棒性——先保证"能稳定做对"，否则其他都白搭；规模化阶段看成本和步数——单任务便宜 10 倍，业务才能铺量；持续运营阶段看轨迹可观测性——线上出了问题能快速定位。一句话：正确性是入场券，成本决定能不能赚钱，鲁棒性决定会不会被用户骂下架。
Q:怎么区分 Agent 是"真会"还是"蒙对"的？
三点：① 看同一任务多次重放的方差——每次路径稳定、都选同一套正确工具 = 真会；每次靠猜、时对时错 = 蒙。② 看过程分和结果分是否一致——结果对但过程乱，大概率是碰运气。③ 做扰动测试——把题目换个说法、加个干扰条件，真会的依然对，蒙的立刻现形。
Q:这些过程指标能全自动测吗？还要不要人？
大部分能自动：完成率、步数、延迟、token 成本直接从轨迹里算；工具选择是否合理可以先用 LLM-as-judge 粗筛。但"这步有没有必要""轨迹是否合规"这类判断，judge 也不完全可靠，需要人工抽检争议样本。我的做法是"自动化打底 + 人工抽样仲裁"，人工只看机器拿不准的 5%~10%，把人力花在刀刃上。
术语卡
任务完成率:评估集上最终达成目标的比例,不看过程只看结果。
轨迹 Trace:Agent 每一步的输入/工具/产出记录,过程评估的数据源。
步数 Step Count:完成任务走的步数/工具调用次数,越低越高效。
鲁棒性 Robustness:面对扰动、噪声、故障时性能不跳水的程度。
LLM-as-judge:用强模型当裁判给输出/过程打分,替代部分人工。
单任务成本:一次任务的总 token/费用,规模化前的硬指标。
