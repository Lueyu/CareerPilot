评估讨论 · Q5

评估一个 Agent 为什么比评估一个基础 LLM 更加困难和复杂？评估的维度有哪些不同？

⭐⭐⭐ #Agent评估#评估难度 字节 / 阿里（高频）
30秒电梯稿

"难度主要来自四点:① 多步轨迹——LLM 只评一个最终答案,Agent 要评一整条"思考→调工具→观察→再决策"的轨迹,中间任何一步错都可能导致失败;② 环境交互——要和沙箱、浏览器、API 等外部环境互动,环境有随机性、有副作用,评估需要真实或可控环境;③ 结果定义复杂——"任务成功"不等于"答案正确",还存在部分完成;④ 维度更多——除效果外,还要看工具调用准确率、效率(步数/延迟/成本)、鲁棒性(错误恢复)、安全合规。所以 Agent 评估必须是轨迹级 + 任务级 + 环境执行式的组合。"

通俗类比

评估基础 LLM 像批改一道书面简答题——只看交上来的答案对不对。评估 Agent 像给一位上门维修师傅打分:你不光看"最后修没修好",还要看他中间的操作流(有没有乱拆零件)、会不会正确使用工具(该用扳手还是锤子)、效率(别人 1 小时他磨蹭一天)、遇到意外会不会救回来(螺丝滑丝了怎么办)、有没有造成破坏(修好水管却把墙砸了)。维度从"一道题"变成了"一次完整任务执行"。

详细拆解

1. 为什么更难(五个根本差异)

  • ① 从"单点答案"到"多步轨迹":Agent 的执行是 ReAct 式的循环(推理→行动→观察→…),要评估每一步决策是否合理。中间选错工具、用错参数、提前终止,都会让"最终答案"失去意义。
  • ② 环境交互带来随机性与副作用:Agent 操作真实/仿真环境(数据库、浏览器、文件系统、API),环境状态会变、有随机因素(搜索结果顺序、网络抖动),还有不可逆副作用(真的下了单、删了文件)——评估要考虑隔离和可重置。
  • ③ 成功标准模糊 + 部分正确:很多任务没有唯一答案("帮我订个性价比高的酒店"),存在部分完成(查到了但没下单)。要给"部分正确"设计分数,不能简单 0/1。
  • ④ 非确定性与方差:同一任务跑多次,轨迹和结果都可能不同,评估要多次采样 + 报告方差,不能只看一次。
  • ⑤ 成本与时长:Agent 一次任务几十上百步、烧大量 token,评估集大一点就很贵很慢,需要控制规模和采样次数。

2. 维度差异(核心对比)

维度基础 LLM 评估Agent 评估
评估对象单次输入→输出完整任务轨迹(多步、多轮)
核心指标答案正确性、相关性任务成功率、轨迹正确率
工具/行动一般不涉及工具选择/调用/参数准确率
效率延迟、成本步数、延迟、token/金额成本、绕路率
鲁棒性几乎不看错误检测与恢复、失败重试
安全合规内容安全越权操作、危险副作用、约束遵循

3. 评估维度拆解(可落地)

  • 效果类:任务成功率(端到端)、轨迹正确率(中间步骤判定)、部分完成度。
  • 交互类:工具选择准确率(该用哪个工具)、参数准确率(调用的参数对不对)、无效调用率。
  • 效率类:平均步数、工具调用次数、P50/P99 延迟、单任务成本。
  • 鲁棒类:遇到失败后的恢复率、重试后成功率、对无关扰动的稳定性。
  • 安全类:越权/危险操作数、是否遵循约束(如"不得改动数据库")。

4. 评估方式的三层组合

  • 执行式(最可信):在沙箱/仿真环境里真跑,用"结果状态"判定(代码是否过测试、订单是否创建成功)。
  • 轨迹判定:用规则/模型逐步检查轨迹是否合理,给"过程分"。
  • LLM-judge + 人工:对开放目标、部分完成做综合打分,再人工抽检校准。
面试官追问
Q:中间步骤怎么自动评估？
三层:① 对工具调用做结构化校验——对比期望的工具名、参数 schema,这是最可靠的;② 对轨迹合理性用 LLM-judge 按 rubric 逐步判(这一步是否必要、是否走弯路);③ 关键任务保留人工标注的黄金轨迹做对齐。实践里"工具/参数准确率"通常能程序化,是性价比最高的过程指标。
Q:环境有随机性,同一个任务跑一次分不准,怎么办？
多次采样取平均 + 报告方差:固定 temperature 但多次运行,报"平均成功率 ± 标准差";对高方差的样本单独分析是模型不稳还是环境不稳。同时尽量控制环境随机源(固定种子、固定数据集版本)。预算有限时,先用大样本跑出稳定基线的任务,只对高方差子集加采样。
Q:Agent 评估里"部分正确"怎么打分？
定义分级的成功函数:例如酒店预订任务分成"查到了→选对了→下单成功→回传了凭证"四级,给 0/0.33/0.66/1 的阶梯分;或按"关键子目标完成数"给分。这比 0/1 更细,能看出模型是"差一点"还是"完全没做对",也更好指导优化。
术语卡
轨迹(Trajectory):Agent 从开始到结束的完整行动序列。
任务成功率:端到端完成任务的比例。
工具调用准确率:选对工具且参数正确的比例。
部分正确:未完全达成但有正确子步骤的中间状态。
沙箱:隔离环境,让 Agent 安全执行、可重置。
