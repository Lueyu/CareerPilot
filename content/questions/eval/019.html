设计模型蒸馏效果的评估实验

⭐⭐⭐ #蒸馏#实验设计#对比实验
30秒电梯稿

"我会做四组对照 + 双维度评估:① 同一学生模型分别用三种策略训练——KD(软标签/温度蒸馏)、Feature Matching(中间特征对齐)、Response-based(教师生成文本当监督),外加 hard-label 基线;② 指标看效果(学生 vs 教师性能差、校准度、OOD 泛化)+ 效率(参数量/延迟/显存);③ 控制变量:同学生架构、同训练数据、同训练步数;④ 消融:温度 τ、软损失权重 α、对齐哪一层;⑤ 报告每种策略的『性能-成本』画像,而不是只吹一个数字。"

通俗类比

就像老师教学生三种学法:第一种抄老师给的"解题概率分布"(KD——连"哪题多难"都学);第二种抄老师"演算过程的中途草稿"(特征匹配);第三种直接背老师写好的"标准答案"(Response-based)。评估就是考同一个人,看哪种学法练出来的分数最高、还没把学生喂成和老师一样胖。

详细拆解

1. 先把三种策略讲准(别把黑话混为一谈)

  • KD(Knowledge Distillation):Hinton 式,用教师 logits 经温度 τ 软化的软标签,学生最小化与教师的 KL 散度——学的是"输出的概率分布"。
  • Feature Matching:让学生中间层特征回归到教师对应层特征(FitNets 的 L2 对齐,或注意力图对齐)——学的是"中间表征"。
  • Response-based:用教师生成的文本/轨迹作为监督,学生做 SFT——学的是"教师怎么答",LLM 时代主流(无需教师 logits)。
# 温度软化 softmax
p^τ_i = exp(z_i / τ) / Σ_j exp(z_j / τ)      τ 越大分布越"软"

# KD 总损失:硬标签 CE + 软标签 KL
L = (1−α)·L_CE(y, p_s) + α·τ²·KL(p_t^τ ‖ p_s^τ)   α 为软损失权重

2. 实验设置:只变"监督信号",其余全锁死

  • 学生(同一小模型)、教师(同一大模型)、训练数据、优化器、训练步数全部一致——唯一变量是"从教师那里拿什么信号"。
  • KD / Feature Matching 用任务硬标签 + 教师软信号;Response-based 需要教师生成的样本(SFT 数据)。

3. 指标:效果 + 效率双维度

维度指标说明
效果测试集准确率、相对教师的性能差多 benchmark 平均 + 方差
可靠性校准度 ECE、OOD 泛化、幻觉率蒸馏可能牺牲校准
效率参数量、推理延迟、显存、吞吐蒸馏的初衷就是降本

4. 对照组与消融

  • 对照:教师(上界)、学生从零训练 / 纯 hard-label(下界)、随机基线。
  • 消融:温度 τ ∈ {2,4,8,16}、软损失权重 α、特征对齐的层(浅/中/深)、蒸馏数据量。

5. 高频坑

  • 只报一个 benchmark 会过拟合:多集平均 + 多 seed 方差。
  • τ 太小 ≈ 硬标签,蒸馏退化;τ 太大信息太稀,都要扫。
  • Response-based 高度依赖教师生成质量,要控制教师采样(温度、是否 CoT),否则垃圾进垃圾出。
  • 蒸馏后 校准度(ECE) 常变差,要单独看,不能只看准确率。
面试官追问
Q:KD 和 Response-based 的本质区别是什么,什么时候选哪个?
KD 要教师输出 logits(软标签),学生学分布,信息更密集、但要求能拿到教师内部输出(白盒);Response-based 只要教师生成的文本(黑盒也行),适合只能调 API 的大模型蒸馏,但信息有损、依赖生成质量。能拿 logits 且任务有明确标签选 KD;只有 API 时选 Response-based。
Q:温度 τ 怎么调?
没有固定值,要扫(常见 2~16)。τ 小分布接近硬标签、丢失"类间相似性"信息;τ 大分布过软、噪声放大。做法是在验证集上扫 τ 和 α,报告曲线,而不是拍脑袋用一个值。
Q:学生超越了老师怎么办,正常吗?
可能发生,尤其老师本身有噪声或标签本身比老师更"正确"时,软标签能起到正则化作用。出现这种情况要检查指标口径和数据泄漏,确认无误就正常,说明老师也有犯错被纠正的空间。
Q:三种策略能叠加吗?
能,而且常见:KD 软标签 + Feature Matching 一起用、或 Response-based 数据 + KD 软标签联合训练。叠加要作为额外的实验组,配合消融证明"1+1 > 1",别默认叠加一定更好。
术语卡
KD:用教师软标签(logits)训练学生。
软标签:经温度 τ 软化后的概率分布,含类间相似信息。
特征匹配:对齐学生与教师的中间层表征。
Response-based 蒸馏:用教师生成文本做监督信号。
ECE:Expected Calibration Error,衡量置信度校准。
教师/学生模型:大模型输出知识,小模型学习它。
