Agent算法 · Q5

多模态 RAG 的检索融合算法

⭐⭐⭐⭐⭐ #多模态#RAG#融合算法 所有公司（通用）
先说人话:这道题在问:用户用一句话提问,答案却可能藏在图片或表格里,怎么把三条检索通道的结果合成一份靠谱榜单。面试官爱问「三路的分数能直接相加吗」——答「加权求和」的当场暴露没踩过量纲的坑,答「要先归一化或干脆用 RRF」的才算真碰过异构数据。
30秒电梯稿

"融合文本、图像、表格,我分三层由浅入深:第一,桥接式(最常用、最稳)——把图和表先翻译成文字(图像做 OCR + caption,表格转 Markdown),统一进文本检索通道,整套文本 RAG 直接复用;第二,分路检索 + 结果融合——文本、图像、表格各自建索引各自检索,三份榜单用 RRF 合并成一份;第三,统一向量空间(最优雅、最难)——用 CLIP 类多模态模型把图文映射进同一 embedding 空间,拿文字直接搜图。最大的坑是三路的打分体系不可比,直接加权相加必翻车——RRF 只看排名不看原始分,就是为这个坑生的。工程主线:桥接打底 + RRF 融合 + 跨模态重排收尾。"

通俗类比

整体像备份系统纳管异构数据源:同一套备份软件要吃下「文件、数据库、虚机镜像」三种格式完全不同的数据,还得让用户一条查询全搜到——多模态 RAG 面对的就是同款问题。三种融合架构正好对应三种纳管思路:桥接式像各备份 agent 先把数据转成统一备份格式再进目录索引,实现最快,代价是转换有损耗;分路融合像各源保留原生格式、查询时扇出到三个存储池、结果在聚合层合并,保真但聚合逻辑要自己写;统一向量空间像一切数据天生说同一种格式,查询天然跨源。哪里像:核心矛盾都是「异构数据怎么归一化」,都在「转换损耗」和「保真复杂度」之间做取舍。哪里不像(关键):备份转格式是确定性转换,转出来对就是对;图像转 caption 是概率性、有偏差的转换——模型可能把图描述错,而且错了还悄无声息。备份工程里「转换器自己写坏数据」几乎不存在,多模态里这就是日常,所以评估护栏必须全程跟着。

语义鸿沟用编码想:文本 embedding 和图像 embedding 是两套坐标系,就像 GBK 和 EBCDIC 的两段字节——不是谁好谁坏,是根本没法直接比大小,这个现象叫语义鸿沟;CLIP 的意义相当于给图和文统一「编码表」。哪里像:都是先统一坐标系再比较;哪里不像:编码表是人工规定、绝对准确的,CLIP 的「编码表」是学出来的、天然带误差——所以它适合粗筛,精排还得靠重排。RRF 用榜单汇总想:三路检索给出三份榜单,分数体系各不相同(一路给余弦相似度、一路给 CLIP 分、一路给 BM25 分),像三个监控系统一个报百分比、一个报星级、一个报指数——直接相加毫无意义,聪明的合并法是只看「每个候选在各榜单里排第几」,这就是 RRF 的全部思想。

详细拆解

1. 为什么多模态检索难(先讲清本质)

一句话:三样东西的「语言」不通。具体难在三处:

  • 语义鸿沟:文本 embedding 和图像 embedding 通常不在同一个语义空间,直接算相似度没意义——就像 GBK 和 EBCDIC 的两段字节逐字节比大小,比了也白比,坐标系都没对齐。
  • 信息形态不同:图里的信息可能是「视觉布局/流程关系」——一张架构图最值钱的是「框和箭头怎么连」,OCR 把文字抄下来,恰恰把空间语义丢了;表格是「表头-单元格」的结构化数值关系,拍平成一行字后「哪列是什么意思」就没了。
  • 查询通常是纯文本:要用一段文字去命中「图片内容」,本质是跨模态匹配(cross-modal matching),比同模态检索难——相当于拿一份中文工单去匹配德文日志。

2. 三种融合架构(对比清楚,面试必问选型)

架构做法优点缺点
桥接式图像→OCR+caption 转文本;表格→Markdown;统一进文本索引实现快、复用文本 RAG 全套、稳定丢失视觉/版式语义,caption 可能失真
分路融合各模态独立建索引独立检索,结果 RRF/加权合并保留各模态本征特征,灵活跨模态语义靠不上,融合权重难调
统一向量空间CLIP 类多模态模型把图文映射到同一空间真跨模态检索,语义对齐好训练/算力贵,对表格/长文效果一般

这张表是面试主轴,但别背成「三选一」——它们更像一条演进路线,和备份系统纳管异构源的顺序一样:先桥接(统一格式、快速覆盖),再分路(业务大了保留原生格式),最后才考虑统一空间这种长线投入。绝大多数团队的答案:桥接式打底 + 分路融合,统一向量空间按业务需要点状增强。能主动说出「我从桥接式起步,因为分块、索引、重排、评估整套文本 RAG 都能直接复用,两周能上线;图表查询占比高的场景再引入统一空间」,比背表格加分得多。

3. 各模态的预处理与索引(桥接式落地细节)

桥接式的核心动作是「翻译」:把不会说文字的模态翻成文字。翻译质量决定后面所有环节的上限——garbage in, garbage out。

  • 图像:① OCR 抽文字(管「图里写了什么字」);② 视觉 caption/描述(LLM 或多模态模型生成,管「这张图是什么意思」,技术参见图像描述生成);③ 视觉 embedding(CLIP / ViT)。三者分别建「文本索引」和「视觉索引」,图既可以被文字命中、也可以被相似图命中。效果是一张图有了两个「分身」:一段文字描述加一个视觉指纹——文字搜图命中文本分身,以图搜图命中视觉分身。
  • 表格:转 Markdown 或结构化 JSON(保留表头-单元格对齐),单元格级切片(chunk)建索引,而不是整张表一个大 chunk——否则检索粒度太粗;同时保留「表格标题 + 表头」作为上下文。道理和切 extent 一样:切片必须挂上元数据,否则命中了也读不懂——「24 小时」三个字单独出现,谁知道它是 RPO 还是备份窗口?
  • 文本:常规分块 + 文本 embedding,保持作为「锚点」——文本路是三路里最成熟、最不容易翻车的,负责兜底。
表格切片对比(为什么必须「带表头的单元格级 chunk」):
原始表格: 表头 = [备份策略 | RPO | 恢复时长]
  行1: 全量备份 | 24小时 | 4小时
  行2: 增量备份 | 1小时  | 30分钟

✗ 错误切法一: 整张表一个 chunk
  → 大表动辄几千 token,embedding 被「平均」掉,细粒度问题检索不到
✗ 更差的切法: 裸单元格 chunk = "24小时"
  → 就算被「RPO 是多少」命中也白搭:三个字脱离表头没有语义,模型不敢用
✓ 正确切法: 每行(或每单元格)一个 chunk,并注入表头上下文:
  "[表:备份策略对比] 全量备份的 RPO 是 24小时,恢复时长 4小时"
   ↑ 相当于给每个 extent 挂上对象元数据——切片走到哪,上下文跟到哪

4. 融合算法(结果怎么合成一个榜单)

先看整条链路,自上而下读:一个文本 Query 扇出到三条路,各自出候选;RRF 融合成合并榜单;跨模态重排精排;输出最终 top-k。这就是「分路检索 + 融合」的标准形态。

三路各自吐出一份带排名的榜单,怎么合成一份?动手前先想清楚那个坑:三路的分数根本不可比——文本路余弦相似度落在 0~1,表格路 BM25 理论上不设上界,图像路 CLIP 分在 -1~1。拿它们直接加权相加,等于拿 MB 和 KB 的数值直接加,单位都没统一。所以按工程顺序有三种做法:

  • RRF:与具体分数量纲无关,天然适合融合异构路,score = Σ 1/(k + rank_i),是打底首选。k 取 60 是论文默认,作用是「摊薄」单个第一名的权重——让「三路都排得靠前」的候选赢过「只有一路排第一」的候选,和多副本投票「少数服从多数」是一个哲学。
  • 加权融合:按模态重要性加权(如文字 0.6 / 图像 0.2 / 表格 0.2),权重可离线调或学习得到;注意各模态分数要先归一化(min-max 或 z-score),把三套量纲先拉到同一刻度再加权,否则权重的物理含义都是错的。
  • 跨模态重排:用能同时吃「文本 + 图像」的重排模型(多模态 reranker,思想同 Cross-Encoder)对合并后的候选精排,显著提升图文匹配精度,是提升效果的关键一步。为什么它行、第一路检索不行?因为它只在 top 几十个候选上做「逐对精读」——粗筛便宜、精排贵,贵的只花在小集合上,和「先查目录再拉数据」的两阶段是同一个道理。
RRF 实算(k=60):看「排名投票」怎么把榜单合出来
候选A(一张部署架构图): 文本路第2名, 图像路第1名, 表格路未上榜
  RRF_A = 1/(60+2) + 1/(60+1) + 0 ≈ 0.0161 + 0.0164 ≈ 0.0325
候选B(一段文字):      文本路第1名, 图像路第30名, 表格路未上榜
  RRF_B = 1/(60+1) + 1/(60+30) + 0 ≈ 0.0164 + 0.0111 ≈ 0.0275
→ A 反超 B:A 在两路都靠前,「多个通道都说相关」比「单路第一」更可信

反例(为什么不能拿原始分直接加):
  文本路余弦相似度 0.87 + 表格路 BM25 18.4 + 图像路 CLIP 分 -0.3 = ?
  三套量纲各不相同,加出来的数没有任何含义——这就是 RRF「只看排名」存在的原因

5. 跨模态对齐(统一空间那套怎么做)

  • CLIP 思路(CLIP 论文):对比学习把成对的(图,文)在向量空间里拉近、不配对的推远,得到共享 embedding 空间;训练用海量图文对(约 4 亿对)。可以想成「刷海量图文对照本」:见得多了,模型就知道「一张猫的照片」和文字「a photo of a cat」是同一件事——对比学习就是把这个「对上号」的过程变成训练目标。
  • 难点:① 表格/长文档不是「一张自然图」,直接用 CLIP 效果一般,需要专门的多模态文档模型(如把版式也编码进去);② 对齐质量决定检索上限,通常桥接式打底 + 少量对齐模块增强是最务实的路线。

6. 评估与鲁棒性

  • 指标:跨模态检索 Recall@k、端到端问答准确率;分别评「纯文本 / 纯图 / 图文混合 / 表格」四类查询,暴露短板。为什么要分桶?和分业务线看备份成功率一个道理——总分 99% 可能全是文本桶撑的,图像桶可能只有 60%,不分桶短板永远看不见。
  • 模态缺失鲁棒性:某模态索引挂了或数据缺图,系统要能降级(图路 miss 就只用文字路),不能整体崩——就是分布式系统「部分组件不可用时服务降级而非停摆」的老原则:某路索引挂了,其余路照常服务,注入 Prompt 时标注「本次检索未覆盖图像内容」。
  • 成本:多模态 embedding 和 caption 都贵,预生成 + 缓存——像去重指纹在备份窗口就算好、而不是恢复时现算:一次性离线成本,换在线查询零额外开销;重排只对合并后的少量候选做,别全量。
面试官追问
Q:用户只问文字问题,要不要去检索图像?
人话:别无脑全查,也别永远不查——关键是判断「答案可能住在哪个模态里」,按需开通道。类比:像恢复请求先查在线存储池,元数据说「这文件在归档池」才去拉磁带——按线索升级通道,而不是每次把所有介质扫一遍。技术:两道闸:① 轻量意图分类器,查询含「图/表/架构图/对比/长什么样」等线索时打开图像/表格路;② 兜底规则,文字路命中分数不足时自动升级到多模态路。纯事实问答只走文字路,省成本。
Q:图像里的文字(OCR)和视觉语义(caption)怎么平衡?
人话:不冲突,都要——OCR 管「图里写了什么字」,caption 管「这张图是什么意思」,一个管字面一个管语义,互补而不是二选一。类比:像备份里块级指纹与文件级元数据并存:指纹管「数据是哪一块」,元数据管「这块属于谁、什么语义」,两层合起来才找得又准又全。技术:OCR 文本和 caption 都进图像路的文本侧索引,检索时各自打分再路内小融合(RRF 即可);caption 用多模态模型离线预生成并缓存,OCR 结果同样沉淀成资产,别查询时现算。
Q:跨模态 embedding 对齐不好,检索效果差怎么办?
人话:先诊断是「翻译官不行」还是「语料不行」,拿到证据再动手,别上来就换模型。类比:像备份作业失败先分清是网络慢还是源端数据问题——直接扩容网络可能白花钱;这边「直接换更大的多模态模型」就是白花钱的典型动作。技术:用少量人工标注图文对做相似度回测,量化对齐质量;确认对齐差后再动:① 领域图文对 + 难负样本做对比学习微调;② 换更强的多模态模型;③ 务实路线:不死磕统一空间,桥接式打底 + 跨模态重排兜底,把重排器当「最后一公里的对齐器」,成本低见效快。
Q:多路融合的权重怎么定?
人话:起步阶段根本别调权重——用免调参的 RRF 先跑通;有了评测数据再谈权重,最后才谈学习。类比:像多副本读策略:先轮询把服务跑通,等各副本历史延迟数据攒够了,再做动态加权路由——先有 SLA 数据,再谈智能调度。技术:三阶段:① RRF,量纲无关免调参;② 有评测集后网格搜索固定权重,或按各模态历史命中率赋先验;③ 用学习排序把融合+重排一起训。进阶按查询类型动态切权重——图表类查询自动抬图像/表格路,固定权重很难全场景最优。
Q:现在的多模态大模型能直接看图读表,为什么不把文档全塞给它,还要搞三路检索?
人话:能塞不等于该塞——文档几千页时直接全读又贵又慢,答案埋在中间还容易被「看丢」。类比:恢复一个 1KB 文件,没人会把 10TB 备份集整个解一遍——先查目录定位,再只拉需要的那块;检索就是「先查目录」,端到端读就是「全量解包」。技术:① token 成本随文档量线性涨,长上下文还有「中间遗忘」问题;② 无引用溯源,答错定位不到出处,不满足可审计要求;③ 多模态 RAG 只注入 top-k 相关片段,便宜、快、可引用。小文档场景端到端多模态确实够用——两者互补,不是替代关系。
术语卡
CLIP:用约 4 亿图文对做对比学习训练的模型,把图和文映射进同一向量空间,让「拿文字搜图」成为可能。
跨模态检索:用一种模态的查询命中另一种模态的内容——比如拿一句中文,从一堆图里找出对应的那张。
RRF:倒数排名融合,只看候选在各榜单的名次、不看原始分——异构检索结果合并的免调参利器。
caption:为图像自动生成的文字描述,是「图不说话、文字代言」的那座桥。
OCR:光学字符识别,把图里的字抄成文本,让「图里的字」也能被文本检索命中。
跨模态重排:能同时理解图文的重排模型,对粗筛出的小候选集精排,补回粗排丢掉的跨模态精度。
语义鸿沟:不同模态的特征空间互不兼容——文本向量和图像向量直接算相似度,比了也白比。
