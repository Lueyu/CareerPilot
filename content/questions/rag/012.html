Agent算法 · Q5

多模态 RAG 的检索融合算法

⭐⭐⭐⭐⭐ #多模态#RAG#融合算法 所有公司（通用）
30秒电梯稿

"融合文本、图像、表格,我讲三种层次,由浅入深:第一,桥接式(最常用、最稳)——图像先做 OCR + caption 生成文本描述,表格转成 Markdown/结构化文本,统一进文本检索通道,再按模态标记来源;第二,分路检索 + 结果融合——文本、图像、表格各自建索引独立检索,结果用 RRF 或加权重排合并;第三,统一向量空间(最优雅、最难)——用 CLIP 类多模态模型把图文映射到同一 embedding 空间做跨模态检索。难点是模态间语义对齐和融合权重,通常用桥接打底 + 跨模态重排提升精度。"

通俗类比

就是整理一份"图文表格混合"的复习资料:一道题的答案可能藏在文字段落、也可能在那张流程图里、还可能在那张 Excel 表里。单一的文字搜索根本搜不到图片里的答案。多模态 RAG 就是同时开三条检索通道——文字通道、图片通道、表格通道,各找各的,最后把三路找到的东西按相关度合并成一份。难点在于"图和文字说的是同一件事"怎么判断——这需要一个能同时看懂图和字的翻译官(跨模态模型)。

详细拆解

1. 为什么多模态检索难(先讲清本质)

  • 语义鸿沟:文本 embedding 和图像 embedding 通常不在同一个语义空间,直接算相似度没意义。
  • 信息形态不同:图里的信息可能是"视觉布局/流程关系",表格是"结构化数值关系",OCR 出来的文字又会丢失版式语义。
  • 查询通常是纯文本:要用一段文字去命中"图片内容",本质是跨模态匹配(cross-modal matching),比同模态检索难。

2. 三种融合架构(对比清楚,面试必问选型)

架构做法优点缺点
桥接式图像→OCR+caption 转文本;表格→Markdown;统一进文本索引实现快、复用文本 RAG 全套、稳定丢失视觉/版式语义,caption 可能失真
分路融合各模态独立建索引独立检索,结果 RRF/加权合并保留各模态本征特征,灵活跨模态语义靠不上,融合权重难调
统一向量空间CLIP 类多模态模型把图文映射到同一空间真跨模态检索,语义对齐好训练/算力贵,对表格/长文效果一般

3. 各模态的预处理与索引(桥接式落地细节)

  • 图像:① OCR 抽文字;② 视觉 caption/描述(LLM 或多模态模型生成);③ 视觉 embedding(CLIP/ViT)。三者分别建"文本索引"和"视觉索引",图既可以被文字命中、也可以被相似图命中。
  • 表格:转 Markdown 或结构化 JSON(保留表头-单元格对齐),单元格级切片(chunk)建索引,而不是整张表一个大 chunk——否则检索粒度太粗;同时保留"表格标题 + 表头"作为上下文。
  • 文本:常规分块 + 文本 embedding,保持作为"锚点"。

4. 融合算法(结果怎么合成一个榜单)

  • RRF:与具体分数量纲无关,天然适合融合异构路,score = Σ 1/(k + rank_i),是打底首选。
  • 加权融合:按模态重要性加权(如文字 0.6 / 图像 0.2 / 表格 0.2),权重可离线调或学习得到;注意各模态分数要先归一化。
  • 跨模态重排:用能同时吃"文本 + 图像"的重排模型(多模态 reranker)对合并后的候选精排,显著提升图文匹配精度,是提升效果的关键一步。

5. 跨模态对齐(统一空间那套怎么做)

  • CLIP 思路:对比学习把成对的(图,文)拉近、不配对的推远,得到共享 embedding 空间;训练用海量图文对。
  • 难点:① 表格/长文档不是"一张自然图",直接用 CLIP 效果一般,需要专门的多模态文档模型(如把版式也编码进去);② 对齐质量决定检索上限,通常桥接式打底 + 少量对齐模块增强是最务实的路线。

6. 评估与鲁棒性

  • 指标:跨模态检索 recall@k、端到端问答准确率;分别评"纯文本 / 纯图 / 图文混合 / 表格"四类查询,暴露短板。
  • 模态缺失鲁棒性:某模态索引挂了或数据缺图,系统要能降级(图路 miss 就只用文字路),不能整体崩。
  • 成本:多模态 embedding 和 caption 都贵,预生成 + 缓存;重排只对合并后的少量候选做,别全量。
面试官追问
Q:用户只问文字问题,要不要去检索图像?
要看任务:纯事实问答只走文字即可省成本;但像"这个产品长什么样""流程怎么走"这类答案就在图里的,必须走图像路。工程上可以先让分类器判断查询是否可能指向图片/表格(含"图/表/示意图/对比"等词,或答案在文字路命中不足时兜底升级到多模态路),而不是无脑全查。
Q:图像里的文字(OCR)和视觉语义(caption)怎么平衡?
两者互补:OCR 保证"图里的字"能被文字检索命中,caption 保证"图的意思"(没有文字的示意图/照片)能被语义命中。实践中两者都做,OCR 文本和 caption 都进图像路的文本侧索引;检索时两者各自打分再融合,而不是二选一。
Q:跨模态 embedding 对齐不好,检索效果差怎么办?
先诊断是"对齐差"还是"数据差":用少量标注对做相似度回测。若对齐差,可加对比学习微调(图文对 + 难负样本)或换更强的多模态模型;更务实的做法是别死磕统一空间,改用桥接式 + 跨模态重排——把重排模型当"最后一公里"的对齐器,成本低见效快。
Q:多路融合的权重怎么定?
起步用 RRF(无需调权、量纲无关)先跑通;有评测集后可以网格搜索权重,或把"各模态 top 命中率"作为先验赋权(某模态历史上贡献大的加权);再进阶用学习排序把融合和重排一起训。权重要按查询类型动态化,固定权重很难在所有场景最优。
术语卡
CLIP:对比学习把图/文映射到同一向量空间的模型。
跨模态检索:用一种模态的查询命中另一种模态的内容。
RRF:倒数排名融合,异构检索结果的合并利器。
caption:为图像生成的文字描述,是桥接图文的关键。
跨模态重排:能同时理解图文的模型对候选精排。
语义鸿沟:不同模态特征空间不一致导致不可直接比较。
