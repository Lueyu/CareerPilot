Agent算法 · Q3

设计一个自适应的 RAG 检索策略

⭐⭐⭐⭐ #RAG#自适应#检索优化 所有公司（通用）
30秒电梯稿

"核心是先给查询分级,再按级配检索深度,而不是所有查询一视同仁。三步:第一,查询分析——分类器判断难度(简单事实 / 单跳 / 多跳 / 需推理)和时效性、意图;第二,策略路由——简单题走浅检索(BM25/向量 top3 就够),难题走多路混合检索 + 大 topk + 多跳迭代;第三,自适应升级——首轮召回质量不达标(置信度低、答案无法支撑)就自动改写 query、扩 topk、二次检索,最多 N 轮。这样平均延迟和成本下降,同时难题召回率不降——这是它相比固定策略的价值。"

通俗类比

就是调度员按件派活:有的快递就在隔壁小区(简单问题,直接拿就完事);有的要跨几个中转站(多跳,得多跑几趟);有的地址写得含糊(模糊查询,得先问清楚再跑)。聪明的调度不会让每个快递员都跑全城,而是看"这单有多难"决定派几趟、跑多远。统一策略就像不管啥件都按"最难的"处理——又慢又贵;或都按"最简单的"处理——难件就丢了。自适应是两者之间动态取平衡。

详细拆解

1. 为什么需要自适应(先讲清统一策略的痛点)

  • 查询难度差异极大:"公司地址"一个精确匹配就中,"X 与 Y 的共同投资者"要跨多个实体多跳。固定 topk/固定策略只能取折中,结果是简单题过度检索(浪费)、难题检索不足(漏召回)。
  • 自适应的收益不是"把难题变简单",而是把省下来的算力投到真正难的地方:简单题省 90% 检索开销,难题用多出来的预算做更深检索。

2. 查询分析(路由的依据)

  • 维度:难度(是否单跳/多跳/需跨文档推理)、类型(事实 / 定义 / 对比 / 汇总 / 实时)、时效(是否要求最新)、歧义度(是否需澄清)。
  • 实现:小模型/规则分类器(快、便宜、可控)做主路由,拿不准的交 LLM 细判;关键是要"快",路由本身的开销必须远小于它省的检索开销。

3. 策略分档(核心设计表)

档位典型查询检索策略topk
L0 简单精确事实、单一关键词("CEO 是谁")BM25 或向量,单路3
L1 常规一般语义问答混合检索(BM25+向量)+ RRF10~20
L2 复杂多跳、跨文档、需推理/对比子问题分解 + 多路融合 + 图/多跳扩展30~50
L3 迭代首轮不确定、需自我反思L2 + Query 改写 + 二次检索,最多 N 轮动态

4. 自适应升级(怎么判断"检索够了"并动态加深)

  • 升级触发信号:检索分数分布过平(没有明显峰值)、rerank 后 top 相关度仍低于阈值、LLM 自评"无法回答/信息不足"。
  • 升级动作:Query 改写(补全/消歧)、HyDE(生成假设答案再检索)、子问题分解、扩大 topk、换/加索引路(如加关键词或图谱)。
  • 上限保护:最多 N 轮(如 3 轮),避免"越查越慢";到上限仍不够就诚实降级("没找到充分证据")而不是硬编。

5. 工程与评估

  • 路由开销控制:分类器用缓存 + 规则优先;同一查询幂等重放。
  • 评估要分档看:不能只看全局 recall,要拆 L0~L3 各自的 recall / 延迟 / 成本;自适应的价值体现在"简单题延迟显著下降、难题 recall 持平或提升"。
  • 冷启动:初期用规则/人工标注的难度标签起步,积累线上日志后用真实 query 训练分类器。
面试官追问
Q:查询分类器判错了(难题被判成简单题)怎么办?
靠"升级机制"兜底:即使被判成 L0,只要首轮质量自检不通过,就会自动升级到更深策略重查。所以路由判错不致命,真正要保证的是质量自检这一环灵敏——宁可简单题偶尔多查一次,也不能难题在浅检索上直接出答案。
Q:怎么量化判断"检索结果够了"?
几个可操作信号:① rerank 后 top1 相关度是否过阈值;② 生成答案的引用覆盖度(答案每个关键论断是否都有检索片段支撑);③ LLM 自评(带结构化输出"充分/不充分")。组合使用比单一阈值稳,能显著降低误判。
Q:自适应会不会反而引入额外延迟?
会,但净收益为正:简单题占大多数,它们省下的检索时间远大于难题多花的几轮;关键是路由要便宜(小模型/规则,几十毫秒内)且难题只占小头。用分档 P99 延迟 + 平均延迟一起看,别只看最坏情况。
Q:这和 Query Rewriting、HyDE 是什么关系?
它们是自适应策略的"工具"而非替代:Query 改写、HyDE、子问题分解都是"升级动作"里可选的算子,由自适应框架决定"什么时候该用哪个"。没有自适应的调度,这些技巧就变成对所有查询无差别开启,又贵又不一定有用。
术语卡
查询路由:按查询特征把它分派到不同检索策略。
迭代检索:首轮不够就改写再查,多轮逼近答案。
HyDE:先让模型生成"假设答案"再拿它去检索。
RRF:倒数排名融合,合并多路检索结果。
质量自检:生成前判断检索结果是否足以支撑回答。
