Agent算法 · Q3

设计一个自适应的 RAG 检索策略

⭐⭐⭐⭐ #RAG#自适应#检索优化 所有公司（通用）
先说人话:这题问的是:检索要不要按查询难度区别对待,而不是所有问题一套固定 topk。面试官爱考它,因为它一眼分清「搭过 demo」和「管过线上成本」的人;最大暴露点是答不出「怎么判断检索够了」「路由判错怎么兜底」——没有兜底的自适应是空中楼阁。
30秒电梯稿

"核心是先给查询分级,再按级配检索深度,而不是所有查询一视同仁。三步:第一,查询分析——分类器判断难度(简单事实 / 单跳 / 多跳 / 需推理)和时效性、意图,这一步必须便宜,几十毫秒内搞定;第二,策略路由——简单题走浅检索(BM25/向量 top3 就够),难题走多路混合检索 + 大 topk + 多跳迭代;第三,自适应升级——首轮召回质量不达标(置信度低、答案无法支撑)就自动改写 query、扩 topk、二次检索,最多 N 轮,到顶就诚实说"没找到"。这样平均延迟和成本下降,同时难题召回率不降——本质是把简单题省下的预算,花到难题身上,这是它相比固定策略的全部价值。"

通俗类比

「分级」这件事,你每天都在做(用备份等级想):备份软件不会对所有数据都上全量——天天全量,备份窗口爆炸;也不会只做增量——恢复链一长,RPO 就靠不住。成熟做法是看数据变化率:变化小的走增量,变化大的、关键的走全量,窗口和可靠性才都保得住。自适应 RAG(检索增强生成)是把同一个思想搬进检索:查询难度差异极大——"公司地址"一次精确匹配就中,"A 和 B 的共同投资方"得拆开查两轮——固定策略只能取折中,简单题浪费、难题漏召回。哪里像:都是"按需配资源,把省下的预算投给真正贵的部分"。哪里不像:备份的变化率是数据的固有属性,可以离线慢慢统计;查询难度必须在线、毫秒级判断,而且判断本身就有开销——这个差别决定了查询分级只能用便宜手段,判错了靠升级机制兜底。

整套机制像急诊分诊台(triage):分诊护士 30 秒扫一眼把病人分级(查询分析,必须快、必须便宜——要排 10 分钟队的分诊台本身就是事故),轻症走快速通道开盒药(L0),普通门诊(L1),重伤进抢救室多科会诊(L2);治疗中发现病情比预想重,当场升级处理(质量自检不过 → 加深检索再来一轮)。哪里像:先分级再配资源、误判有升级兜底、重症是少数但绝不能耽误。哪里不像:急诊分诊判错可能出人命,所以护士必须资深;检索分级判错的代价只是"多查一轮",所以敢用便宜的小模型当分诊护士——分诊可以便宜,因为错了能救,这个设计取舍是整套自适应成立的前提,面试讲出来很加分。

质量自检这一环,用备份校验想:你的行话是"没做过恢复演练的备份不算备份"——作业状态"成功"不等于数据真的可恢复,必须有校验和演练兜底。检索同理:topk 拿回 50 个片段 ≠ 里面有答案,必须有"够不够"的验收信号,不够就升级重查。反过来说也成立:不做自检的自适应,和不做校验的备份一样,是纸面可靠性——指标好看,出事的时候才知道全是漏的。

详细拆解

1. 为什么需要自适应(先讲清统一策略的痛点)

  • 查询难度差异极大:"公司地址在哪"一次精确匹配就中,连向量检索都算杀鸡用牛刀;"A 公司和 B 公司的共同投资方有哪些"得拆成两个子问题、各自检索、再对齐——这是典型的多跳(multi-hop)问题,单轮检索天然够不着。固定 topk/固定策略只能取折中,结果是简单题过度检索(浪费)、难题检索不足(漏召回)——相当于为最难的 1% 查询,给 100% 的查询都上了全套豪华配置。
  • 自适应的收益不是"把难题变简单",而是把省下来的算力投到真正难的地方:简单题省 90% 检索开销,难题用多出来的预算做更深检索。
  • 前提:简单题得占大头。典型企业知识库六到八成查询是简单事实/FAQ 类——这个分布必须拿自己线上日志验证,不能抄别人的;若你的场景难题占大头,自适应收益被摊薄,得先从知识库质量下手。
策略简单题(大头)难题(小头)结论
全走浅检索(只 BM25 top3)80ms,便宜Recall 掉到 0.3,大面积答错不可接受
全走深检索(分解+多跳+迭代)2s+,成本 ×20Recall 0.9延迟和账单都炸
固定中间档(一刀切)偏慢偏贵仍漏召回两头平庸
自适应分档80ms,便宜Recall 0.9 保住两端兼得

2. 查询分析(路由的依据)

路由器要看哪些特征、怎么又快又便宜地拿到,是这一步的全部。维度先定清楚:

维度判断什么示例对路由的影响
难度单跳 / 多跳 / 要不要跨文档推理"共同投资方" = 多跳定档 L0~L2 的主依据
类型事实 / 定义 / 对比 / 汇总 / 实时"对比 A 和 B 的优劣" = 对比对比/汇总类倾向升档
时效是否要求最新数据"现在的最新版本" = 实时走外部搜索或直接拒答,本地库再深也没用
歧义度是否需要先澄清"苹果怎么样" = 歧义先反问用户,别急着检索
  • 实现分三层,由便宜到贵:规则(实体数量、比较词"共同/对比/区别"、问句长度、是否命中 FAQ)→ 小模型分类器(轻量 BERT 级别,毫秒级)→ 拿不准的交 LLM 细判。目标:90% 的查询在前两层定档,LLM 只处理边角。
  • 开销红线:路由本身必须远小于它省下的检索开销——就像备份调度器做变化率检测,检测不能比备份本身还贵。工程上控制在几十毫秒内,超了就是本末倒置。

3. 策略分档(核心设计表)

档位典型查询检索策略topk
L0 简单精确事实、单一关键词("CEO 是谁")BM25 或向量,单路3
L1 常规一般语义问答混合检索(BM25+向量)+ RRF10~20
L2 复杂多跳、跨文档、需推理/对比子问题分解 + 多路融合 + 图/多跳扩展30~50
L3 迭代首轮不确定、需自我反思L2 + Query 改写 + 二次检索,最多 N 轮动态

逐档说透:

  • L0:本质是"能不检索就不检索"——FAQ 精确匹配、语义缓存优先,检索只是兜底。类比:能查元数据索引解决的事,不扫数据卷。
  • L1:标准管线:混合检索(BM25 + 向量)→ RRF 融合 → Rerank 精排。绝大多数语义问答在这档解决,这档的质量决定口碑基本盘。
  • L2:核心算子是子问题分解——"A 和 B 的共同投资方"拆成"A 的投资方""B 的投资方"两个单跳子查询,各自检索再对齐合并;知识库有图谱,就顺实体边做多跳扩展。
  • L3:严格说不是一档,而是所有档位失败后的升级通道——见第 4 节。
流量分布(示意,务必拿自己日志验证):
  L0 简单 ██████████████ 70%   ← 大头:优化它们 = 优化平均值
  L1 常规 ████ 22%
  L2 复杂 █ 7%
  L3 迭代 ▏1%                 ← 小头,但丢一个都是事故

成本账(相对成本,设 L0 = 1×):
  一刀切(全部按 L2 档跑):  100% × 20× = 20×
  自适应:                   70%×1 + 22%×5 + 7%×20 + 1%×60 ≈ 3.8×
  → 平均成本降到约 1/5,省下的预算正好养得起难题的深检索

4. 自适应升级(怎么判断"检索够了"并动态加深)

这一环要回答两个问题:够不够(质量自检给验收信号)、不够怎么办(升级动作加深度)。整条链路如下——注意"质量自检 → 不够 → 升级再检索"这个回环,它是自适应的灵魂:

拿一个真实难题走一遍全流程:

Query: "A 公司和 B 公司的共同投资方有哪些?"

第 1 轮(L1 直查):混合检索 top20 → Rerank
  分数: 0.31, 0.29, 0.27, 0.25 ...   ← 又平又低:没有一个文档真正相关
  自检: top1 相关度 0.31 < 阈值 0.6  → 不通过,触发升级

第 2 轮(升级到 L2):子问题分解
  ├─ 子查询1: "A 公司的投资方" → top1 相关度 0.82 ✓
  └─ 子查询2: "B 公司的投资方" → top1 相关度 0.79 ✓
  两路证据合并 → 生成答案,每个论断带引用 → 通过,停止迭代

若第 2 轮仍不通过 → 第 3 轮(改写 / HyDE / 扩 topk)
若第 3 轮仍不通过 → 到达上限,诚实降级:"未在知识库找到充分证据"

升级触发信号(验收"够了没",三个信号组合用,别单押一个):

  • 检索分数分布过平(没有明显峰值):top 之间分差极小——像一卷备份 checksum 全对不上:不是"质量差一点",是"这批根本不是要找的东西"。
  • Rerank 后 top 相关度仍低于阈值:精排之后最相关的片段都不够格,说明不是排序问题、是召回问题,该加深度而不是调排序参数。
  • LLM 自评"无法回答/信息不足":让模型用结构化输出(充分/不充分)给判断——离最终任务最近的信号,但也最贵,放最后当仲裁。

升级动作(工具箱,按触发原因选,不是全上):

  • Query 改写(补全/消歧):问题写得含糊,先把问题修好再查。
  • HyDE:先让 LLM 编一个"假设答案"拿去检索——专治"问题和文档措辞对不上"(用户问"怎么扩容",文档标题叫"容量规划")。
  • 子问题分解:多跳拆单跳,各自检索再合并。
  • 扩大 topk、换/加索引路(加关键词路、知识图谱)。

上限保护:

  • 最多 N 轮(如 3 轮),避免"越查越慢"——和重试预算、熔断器是同一个纪律:无限重试等于重试风暴。
  • 到上限仍不够就诚实降级("没找到充分证据")而不是硬编。用你的行话说:备份失败必须亮红灯告警,绝不能静默标成功——"检索不到还硬编答案"就是静默失败,比"没找到"危害大一个量级,因为它直接污染用户信任。

这一环学术界有四篇代表作,面试点出名字和分工很加分:Adaptive-RAG(arXiv:2403.14403)按查询复杂度把请求路由到"不检索/单步/多步"三档,是本题主线的直接出处;Self-RAG(arXiv:2310.11511)让模型边生成边自我反思,用反思 token 决定"要不要再检索、检索结果采信多少";CRAG(arXiv:2401.15884)给检索结果配一个轻量评估器,分成正确/模糊/错误三档,错了就触发改写+补检索——和我们说的"质量自检"是同一件事;FLARE(arXiv:2305.06983)在生成过程中预测到低置信片段时主动触发检索。

5. 工程与评估

  • 路由开销控制:分类器用缓存 + 规则优先;同一查询幂等重放。展开说:规则层先拦 FAQ 和精确重复,分类器结果按 query 缓存,重复提问零路由开销;LLM 兜底设并发上限,防止边角流量把贵的那层打爆。
  • 评估要分档看:不能只看全局 recall,要拆 L0~L3 各自的 recall / 延迟 / 成本;自适应的价值体现在"简单题延迟显著下降、难题 recall 持平或提升"。

读表:一刀切多花 5 倍延迟、5 倍成本,只换来 1 个百分点的 recall——那 1 个点主要来自被 L0 误放行的极少数难题,而它们还有升级机制兜底。数字是示意,面试要讲的是这套"分档记账"的方法论,不是背数。

  • 冷启动:初期用规则/人工标注的难度标签起步,积累线上日志后用真实 query 训练分类器;新路由器先影子模式(只记录它会怎么分流,不动线上流量),比对无误再小流量灰度。
  • 监控防劣化(自适应系统的专属体检项):分档流量占比漂移 = 分类器在退化;各档升级率 = 路由误判率的代理指标;自检失败率突增 = 知识库更新和查询分布脱节。像备份成功率按作业类型分桶监控,哪个桶掉下来,立刻知道是哪类策略出了问题。
面试官追问
Q:查询分类器判错了(难题被判成简单题)怎么办?
人话:路由一定会错,所以这套设计从第一天就不指望它全对——判错的账,交给升级机制兜底。类比:增量备份误判"这块没变过"不可怕,可怕的是没有校验;有恢复演练兜底,误判会在校验环节暴露,大不了回退全量重备一次——贵一点,数据不会坏。技术:被误判成 L0 的难题,首轮质量自检(Rerank 分数、引用覆盖度)不过就自动升级重查;要保的是自检灵敏——宁要简单题偶尔多查一次,不要难题在浅检索上直接出答案;线上盯各档"升级率",它是路由误判率的代理指标。
Q:怎么量化判断"检索结果够了"?
人话:"检索完了"不等于"检索够了",得有像 checksum 一样客观的验收信号。类比:备份作业显示成功 ≠ 数据可恢复,必须靠校验和恢复演练验收——没有验收的"成功"是纸面成功。技术:① Rerank 后 top1 相关度过阈值;② 分数分布要有峰(全是 0.3 左右 = 没有真相关);③ 生成答案的引用覆盖度,每个关键论断都有片段支撑;④ LLM 结构化自评(充分/不充分)。单押任何一个都易误判,组合投票最稳,阈值拿标注集调。
Q:自适应会不会反而引入额外延迟?
人话:会引入,但算总账是净赚——前提两个:简单题占大头、路由本身足够便宜。类比:分级备份每天多花几分钟做变化率检测,换来全量窗口大幅缩短;要是检测比备份本身还慢,这套就不成立。技术:路由控制在几十毫秒(规则+小模型,拿不准才上 LLM);简单题占 70% 时,加权平均延迟远低于固定深检索;评估要分档 P50/P99 加平均一起看,别只盯最坏情况否定整套方案。
Q:这和 Query Rewriting、HyDE 是什么关系?
人话:它们是工具箱里的单个工具,自适应是决定"什么时候抄哪个工具"的调度层。类比:重试、退避、换副本都是恢复手段,但没有策略的无差别重试就是轰炸;自适应之于这些技巧,等于重试策略之于重试本身。技术:改写、HyDE、子问题分解都是"升级动作"里的算子,由框架按触发信号选用;对全部查询无差别开 HyDE 既贵又不一定涨点;Self-RAG 的反思 token,本质就是把"何时触发"这件事学进模型里。
Q:档位怎么定?分几档是拍脑袋的吗?
人话:档位不是拍脑袋,是从真实查询"答对所需的最小检索配置"反推出来的。类比:全量/差量/增量这几档备份等级,是从 RPO/RTO 需求和数据变化率反推的,不是谁规定的;档位对不上需求,调度再聪明也白搭。技术:抽样线上 query,人工标注"答对需要的最小检索配置",按策略复杂度聚类看自然断层;典型 3~4 档——档太多,分类器的活变细,误判率反而上升,得不偿失。
Q:这套策略怎么安全上线,怎么防止越跑越差?
人话:新路由器先影子模式跑——只记录它会怎么分流,不动线上流量,和旧策略比对无误再切。类比:新备份策略先在测试卷上试跑、对比成功率,再切生产;直接全量切换等于拿生产数据赌运气。技术:影子分流与旧策略对比一致率 → 小流量灰度 → 分档 recall/延迟/成本看板 + 告警回滚;防分布漂移:定期用新标注刷新分类器,监控分档流量占比,漂移即重训。
术语卡
查询路由:按查询的难度、类型、时效,把它分派到不同深度的检索策略——自适应 RAG 的总开关。
迭代检索:首轮结果不够就改写再查,多轮逼近答案,靠自检信号决定何时停。
HyDE:先让 LLM 生成一段"假设答案",拿它代替原问题去做向量检索,专治问题和文档措辞对不上。
RRF:倒数排名融合,把 BM25 和向量两路结果按排名合成一张榜,简单且稳。
质量自检:生成前判断检索结果是否足以支撑回答——没有它,升级机制就没有触发信号。
多跳检索:答案要串起多个文档或实体才能得出(如"共同投资方"),单轮检索天然够不着。
