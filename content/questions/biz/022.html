评估讨论 · Q16

对于想要进入Agent领域的初学者，你会给他/她什么建议？应该重点学习哪些技术？

⭐ #学习路径#建议 所有公司
30秒电梯稿

"三条建议。第一,先动手做出一个能跑的东西,再补理论——别从读论文开始,先从『用 API 搭一个能查知识库的问答机器人』开始,一周内跑通。第二,学习顺序是『用起来 → 会调优 → 懂原理 → 会评估』,不是反过来。第三,重点学四样:扎实的 Python 工程能力、LLM 基础(API/prompt/RAG/上下文管理)、一个 Agent 框架(推荐 LangGraph),以及评估与调试。最怕两类人:只刷教程不写代码的,和一上来就啃 Transformer 数学的。"

通俗类比

学 Agent 就像学开车:没人先背完发动机原理再上车。正确姿势是——先坐进车里把车开起来(跑通一个 demo),再慢慢搞懂"为什么踩刹车要提前"(理解原理),最后学会"怎么判断这车状态好不好"(评估监控)。一上来啃《内燃机原理》的人,三个月后还在纠结热力学,而别人已经上路、已经出过几次小事故、已经知道哪里容易翻车了。

详细拆解

1. 一条可执行的路线图(四阶段,每阶段有明确里程碑)

阶段学什么做出什么(里程碑)
① 用起来(1-2周)Python 基础、调用 LLM API、prompt 写法、SSE 流式一个命令行问答机器人,会流式输出、能带系统提示词
② 会调优(3-6周)RAG(切分/向量检索/重排)、Function Calling、工具调用一个"能查自己知识库、能调用工具"的 RAG Agent
③ 懂原理(2-3月)Transformer 直觉、token/上下文窗口、缩放定律、微调概念能解释"为什么 prompt 顺序影响结果、为什么上下文太长会退化"
④ 会评估(持续)评估集构建、LLM-as-judge、回归测试、可观测性给自己的 Agent 建一套"改一次能自动发现退没退化"的评测

2. 重点技术的优先级(别平均用力)

  • Python 工程能力是第一优先级:Agent 开发的日常是处理数据、调 API、写并发、处理异常——这是地基,比背模型公式更先被用到。
  • RAG 和上下文工程:这是绝大多数业务 Agent 的骨架,把"怎么检索、怎么把上下文喂给模型"搞透,胜过读十篇 Agent 论文。
  • 一个框架选 LangGraph:它能让你理解"图、状态、checkpoint、条件分支"这些 Agent 的底层概念,比只会拖 LangChain 全家桶更有迁移价值。学框架是为了理解思想,不是为了背 API。
  • 评估(Eval)越早建立越好:多数人学到"会调"就停了,而真正拉开差距的是"会用指标判断自己做得对不对"。

3. 三个最常见的坑

  • 坑1:从读论文/啃数学开始 → 热情三个月耗光,一行代码没写。应先跑通 demo,再回头补理论,理解会快得多。
  • 坑2:囤教程、复刻 demo,却从不做自己的项目 → 换一个场景就不会了。必须有一个"自己定义问题、自己踩坑"的项目。
  • 坑3:只追求"跑通",不建立评估 → 改个 prompt 看似变好了,其实是幻觉,反复返工。没有评测的调优等于蒙眼开车。

4. 时间与心态:业余每天 2 小时,约 3 个月能独立做出一个"能调用工具、带评估"的业务级 Agent。关键是前两周跑出第一个能用的东西,这是唯一能把你留在牌桌上的动力。

面试官追问
Q:数学基础要多好才能入门?
入门几乎不需要数学,高中数学 + 线性代数/概率的直觉就够;API 层面你面对的是 prompt、JSON、HTTP,不是矩阵。数学是在你往算法方向走(想自己训模型、做 RL、理解注意力机制细节)时才需要补。所以我的建议是:先不设数学门槛,等你自己产生"这里为什么是这样"的好奇时再针对性地补,比一上来补微积分高效得多。
Q:LangChain 现在争议很大,还值得学吗?
值得"理解",但不必"迷信"。LangChain 的价值在于把 RAG、Agent、Memory 这些概念用一套 API 串起来了,对建立心智模型很有帮助;争议在于它的抽象层太厚、版本变动快、生产上常被绕开。我的建议:用它快速理解概念和跑 demo,但生产上更倾向用更薄的 LangGraph 或直接手写编排,把控制权拿在自己手里。
Q:零基础最快多久能做出第一个作品?
按上面的路线,一周内能做出"会流式输出、能带提示词的问答机器人",3~6 周做出"能查自己知识库的 RAG Agent"。前提是别卡在环境配置和"选哪个模型最完美"这种无意义的纠结上——先跑通,再优化。能快速做出小东西的能力,本身就是 Agent 工程师的核心素质。
术语卡
RAG:检索增强生成,先查资料再让模型作答。
Function Calling:让模型以结构化方式调用外部工具。
Prompt Engineering:设计提示词以稳定引导模型行为。
LLM-as-judge:用强模型给输出打分,做自动化评估。
上下文工程:精心组织喂给模型的上下文,是 RAG 的核心手艺。
