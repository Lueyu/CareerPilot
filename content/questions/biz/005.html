Memory 框架选型:Mem0 vs Zep vs LangChain Memory

⭐⭐⭐⭐ #Memory#框架选型
30秒电梯稿

"按记忆复杂度递增选:LangChain Memory 只适合原型(窗口/摘要这些基础实现,现在更常用其新实验接口);Mem0 是生产级轻量选择——抽取-冲突消解-检索的完整管道,开源活跃,接入成本低;Zep(Graphiti) 是重度记忆场景的选项——时间感知知识图谱,实体关系带生效时间,能回答'用户上个月还是素食者'这种时序问题,但复杂度高。我的默认答案:Mem0 起步,记忆成为产品核心卖点时再评估 Zep。"

通俗类比

像记笔记的工具:LangChain Memory 是便签纸(撕一张记一条,够用但很快乱);Mem0 是智能笔记本(自动整理、去重、旧笔记自动更新,"已离职"自动划掉"在职");Zep 是带时间线的活页档案柜(不仅记事实,还记"这件事什么时候开始什么时候结束",能查历史状态)。

详细拆解
维度LangChain MemoryMem0Zep (Graphiti)
定位记忆接口+基础实现生产级记忆层时序知识图谱记忆
机制窗口/摘要/向量存储历史LLM 抽取事实 → 冲突消解 → 向量+图存储 → 按需检索实体/关系/事件构建时间感知图谱,支持时序查询
部署随框架开源可自部署/托管云开源+云服务
复杂度/成本低中(抽取调用 LLM 有 token 成本)高(图谱构建维护成本)
适合原型、demo大多数产品的长期记忆记忆即核心的陪伴/CRM 类产品

选型时真正要评估的四件事(框架只是实现载体)

  • 抽取质量:用你自己的对话样本试,看抽出来的事实准不准、噪音多不多。
  • 检索注入效果:记忆加进 Prompt 后,回答改善多少(多会话一致性测试)。
  • 成本:每轮对话的抽取/检索要花多少 token(异步抽取才不拖慢响应)。
  • 可控性:记忆能不能导出、删除(合规)、能不能人工修正——生产系统必须能。

诚实的备选答案(加分):记忆系统核心逻辑(抽取-消解-检索-注入)自己实现并不复杂(几百行+一次 LLM 调用),自研的收益是完全可控;用框架的收益是省前两周。两者我都做过,按团队节奏选。

面试官追问
Q:Mem0 的记忆抽取每轮都要跑,成本高吗?
用便宜模型异步跑(不阻塞回复),增量只抽新信息;实测每轮几百 token,可接受;再配合"仅会话结束/每 N 轮抽取"的降频策略进一步省。
Q:什么信号说明该从 Mem0 升级到 Zep?
业务开始问时序问题("他之前是做什么的""这周偏好变了吗")且占比可观;实体关系网络复杂(多方当事人、组织关系);简单事实检索已不能满足产品差异化。
术语卡
Graphiti:Zep 的时间感知知识图谱引擎。
事实抽取:从对话中提取结构化事实。
时间感知:记忆带生效/失效区间。
