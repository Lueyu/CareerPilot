工程实践 · Q2

如何将 Agent 系统的 API 成本降低 70%?

⭐⭐⭐⭐ #成本优化#Agent#API
先说人话:Agent 每调一次模型 API 就扣一笔钱,这题问的是你的「账单压缩施工单」:钱花哪了、按什么顺序砍、怎么砍 70% 还不出事故。面试官爱考它,是因为成本优化最能分清「背过名词的」和「真管过账单的」——开口就答「全换便宜模型」暴露你没守过线上质量,先答「成本归因」的才是干过活的。
30秒电梯稿

"先建立每请求成本账单(按环节归因 token),不测量就动手等于盲调参。然后组合拳:语义缓存吃掉高频重复问题,省 30%;模型分级把 70% 简单流量切到便宜 10 倍的小模型,整体再 ×0.4;Prompt 压缩(LLMLingua + 检索内容精简 + 历史摘要)再省 20%;离线任务走 Batch API 半价;输出限长防废话——输出 token 比输入贵 3~5 倍,少废话是最便宜的优化。数学上:0.7 × 0.4 × 0.8 ≈ 0.22,降幅 78%,超额完成。关键是每招都配质量护栏,省钱不能省出事故。"

通俗类比

这题你要是干过备份软件,可以直接从肌肉记忆里搬答案:给 API 账单做一次「容量治理」——先出容量报告(成本归因),再上重删(语义缓存)、冷热分层(模型分级)、落盘前压缩(Prompt 压缩)、夜间备份窗口(Batch API)。备份产品的容量优化就这五板斧,Agent 成本优化一模一样,只是介质从「磁盘块」换成了「token」。

语义缓存(用备份里的「重复数据删除」想):备份系统每天全备同一批 VM,块指纹相同就不再落盘;语义缓存发现新问题与老问题的 Embedding 相似度 > 0.95,就不调模型,直接回缓存答案。哪里像:都是拿「重复」换成本——企业问答里 30%+ 的提问是同一个问题换皮,和每日增量 80% 的块指纹不变是同一现象;「指纹表」对应「向量索引」,指纹未命中才落盘对应语义未命中才调 LLM。哪里不像:重删是哈希精确匹配,同指纹必同数据,误删率约等于零;语义缓存是模糊匹配,「相似」不等于「相同」,存在长得像、实则会答错的问题对,所以要额外配阈值、TTL、点踩下架这套护栏——这是它比重删多付的钱。

模型分级(用「冷热数据分层」想):SSD 放热数据,大容量便宜盘放冷数据,介质成本按负载价值分配;模型分级把简单问答路由到便宜 10~50 倍的小模型,复杂推理留给旗舰。哪里像:都是「按价值分配昂贵资源」,而且 70% 简单流量/30% 复杂流量的分布,和热冷数据的 80/20 一样稳定可预测。哪里不像:存储分层看的是历史访问统计,放错介质可以静默迁回、用户无感;模型分级要在执行前预判难度,判错了用户当场看到烂答案,没有「再迁一次」的机会,所以要多一道 escalation(小模型不行自动升级重答)兜底。

Prompt 压缩(用「zstd 落盘前压缩」想):备份软件把数据流先压缩再写介质,同样容量更小占用;LLMLingua 把 prompt 里低信息量的词删掉再发给 API。哪里像:都是在负载进管道前先瘦身,收益直接乘在成本上。哪里不像:zstd 是无损压缩,解压后 bit 级还原;LLMLingua 是有损压缩,压狠了语义会丢——所以每档压缩率都要跑黄金集回归,这是它比传统压缩多付的风险税。

Batch API(用「夜间备份窗口」想):没时效要求的任务(文档摘要、离线评估)攒批走慢通道,半价换 24 小时 SLA。哪里像:拿延迟换价格,和把复制任务排到凌晨低峰窗口一个思路,备份排程干了一辈子的事。哪里不像:备份窗口是错峰用自己的资源,Batch API 是厂商的定价通道,你只是「换条车道」;24h 是硬约束,任务得能拆成相互独立的批。

输出限长(用「写放大」想):SSD 写一个逻辑字节要放大成几个物理字节还耗寿命,所以能不写就不写;LLM 输出 token 单价是输入的 3~5 倍,还逐 token 串行生成,少废话同时省钱和延迟。哪里像:贵的那一侧要省着用,收益立竿见影。哪里不像:写放大是介质物理特性只能接受,输出贵是厂商定价,后者还能靠「直接给结论」的指令和 max_tokens 保险丝去绕。

至于成本归因,就是你天天出的容量报告/租户计费:不知道哪个租户哪个作业吃了容量,任何优化都没法证明「省了多少」——面试官问「70% 怎么证明」,答案全在这份账单里。

详细拆解

第 0 步:成本归因(和延迟优化同理,先测量)

做延迟优化你不会上来就调参,会先看 P99 找热点;修成本同理,先出账单。账单的前提是懂计费规则:LLM 按 token 计费,一个 token ≈ 0.75 个英文单词,汉字一般一个字烧 1~2 个 token;费用 = 输入 token × 单价 + 输出 token × 单价,而输出单价通常是输入的 3~5 倍(下文按 4 倍算)——所以账单不能只数 token 数,必须按单价折算。

网关给每次调用记流水:系统提示词 1.2K + 检索注入 2.5K + 历史 1K + 输出 0.8K,按单价折算。典型发现:60% 成本在输入侧,其中检索注入占大头——这就指明了优化方向。

两个直接结论:① 输入侧占 60%,其中检索注入一家占 32%,招式三先拿它开刀;② 输出只占 token 数的 15% 却贡献 40% 成本,「少废话」是性价比最高的一招。实现上就是网关中间件打日志:各段 token 数 × 单价表 × 请求 ID,落到监控里聚合——和备份系统的容量报告一个地位,没有它,后面每一招的收益都说不清,「省了 70%」的分子分母都来自这里。

招式一:语义缓存(-30%)

  • 问题 Embedding 相似度 > 0.95 直接返回缓存答案;企业场景命中率 30%+ 很常见。「怎么报销」「报销流程是啥」「我该如何报销」是同一个问题换三张皮——这类重复在内部问答里占比惊人,命中一次省一次全价调用(只剩一次向量检索的钱),整体成本 ×0.7。
  • 进阶:FAQ 预生成(Top 1000 高频问题离线生成好)。从日志统计 Top 1000 问题,离线用旗舰模型生成答案 + 人工抽审,直接灌进缓存——相当于先做好一个「全量」,后续增量才靠在线逻辑,这批流量同时享受最高质量和最低延迟。
  • 护栏:缓存 key 绑定知识库版本(内容更新缓存失效);抽样监控缓存答案质量。语义缓存是「相似≠相同」的模糊匹配,误命中的代价是答非所问,所以阈值宁高勿低——漏缓存只是多花一次 API 钱,错缓存是赔掉一次用户信任。

招式二:模型分级(-40%)

核心判断:不是所有请求都配得上旗舰模型。先判难度、再路由,让每一次调用按价值花在刀刃上:

  • 轻量分类器(或规则)判断难度:简单事实问答/格式转换 → 小模型;复杂推理/多工具编排 → 旗舰模型。
  • 成本差 10~50 倍,70% 流量是小模型后:整体成本 × (0.7×0.1 + 0.3×1) ≈ ×0.4。
  • 护栏:分级错误率监控;小模型回答置信度低时自动升级重答。

分级器怎么来?冷启动用规则:query 长度、是否命中 FAQ/缓存(能命中的本来就不难)、历史同类问题的准确率;日志攒几周后,拿「该问题最终有没有触发升级」当弱标注,训练一个 BERT 级小分类器,推理成本毫秒级可忽略——这一步就是存储里的 ILM 策略引擎:先拍静态策略,再让访问统计接管。判错方向也要看:难判简单 → 小模型答崩,靠 escalation 兜底,只浪费一次小模型的钱;简单判难 → 多花点钱但质量无虞——宁可误升,不可误降。

招式三:Prompt 压缩(-20%)

  • 系统提示词减肥:删掉装饰性文字,指令合并(实测能砍 30~50%)。「你是一个乐于助人的、知识渊博的 AI 助手」这类自我介绍,模型一个字都不需要;这段脂肪每次请求都带一遍,乘上全月请求量是笔冤枉钱——和每个备份作业都要重写一遍的元数据一个道理,固定开销最值得先砍。
  • LLMLingua 类工具:算法压缩提示词,语义基本不损。原理:用一个小语言模型给 prompt 逐 token 打「信息量分」,删掉低分词,论文报告最高 20 倍压缩;生产建议用温和档位(30~50%),因为它是语义上的有损压缩,压狠了会丢信息。
  • 检索注入精简:top-k 从 5 降到 3(top3 而不是 top5);文档段落(chunk)做"相关句抽取"而不是整段塞。检索注入是账单最大头(32%),top5→top3 直接砍 40% 注入量;再只保留命中关键词的句子 ± 一句上下文,又省一半——思路就是增量备份「只传变化块」:按需最小负载,不整卷搬运。
  • 历史对话摘要化(见 Q4):10 轮历史压成一段「任务 + 关键实体 + 已定结论」,防止会话越滚越贵;像定期把 20 个增量归并成新全量(合成备份),控制链路长度。

招式四:输出与调度

  • max_tokens 限制 + Prompt 要求"直接给结论";输出 token 通常比输入贵 3~5 倍,少废话是最便宜的优化。账单里输出占 40% 成本却只占 15% token 数;输出还是逐 token 串行生成,少废话同时把总时长和长尾请求一起救了。max_tokens 是保险丝,防模型车轱辘话循环烧钱;「直接给结论、不要复述问题」一句指令,实测能砍输出 30%+。
  • 离线任务(文档摘要、评估)走 Batch API(半价,24h 内返回)。盘点任务清单:离线评估、批量摘要、向量重建、日志分析——凡是没有实时 SLA 的,全部挪到批通道,同样 token 半价。
  • 网关比价路由:同一档位的模型按当前单价/延迟动态选。同能力档位往往有多家模型可选,而且单价每月都在变,路由表要能热更新——像多路径存储,哪条链路性价比高走哪条。

算总账(面试时主动展示数学)

四招近似独立,连乘起来:缓存 ×0.70(命中 30% 的流量近乎零成本)→ 分级 ×0.40(剩余流量里 70% 打一折)→ 压缩 ×0.80(输入侧砍 1/3、输入占 60%)。顺序也有讲究:缓存排最前——命中的请求连模型都不调,后面三招对它免费;batch 和输出限长是通道级优化,对剩余流量再打个折。

0.70 × 0.40 × 0.80 ≈ 0.224,成本只剩 22%,降幅 78%,超额完成 70% 的目标。面试加分点:现场改参数重算。如果缓存命中率只有 15%?0.85 × 0.4 × 0.8 ≈ 0.27,降幅 73%,依然达标;如果小模型只便宜 5 倍?0.7×0.2+0.3 = 0.44,×0.8 后总账变成 0.25,降幅 75%。数字随场景变,方法不变——能现场重算,才说明这套公式是你自己的,不是背的。

防劣化:每招上线跑黄金集;线上监控点踩率/解决率,省钱但质量掉了要立刻回滚——成本优化是"在质量约束下的优化问题",这句话说出来很加分。展开成四条可落地机制:

  • 一次只开一个开关:每招单独灰度发布,劣化才能归因到具体招式;三个开关一起开,出问题只能互相甩锅。
  • 黄金集回归:几百条人工标注的「标准问题 + 可接受答案」,每个改动放量前跑一遍,通过率不掉才放量——像上重删前先做恢复演练,不演练不给上生产。
  • 线上护栏:点踩率、解决率、人工转接率三个指标盯屏;缓存命中答案抽样人审;分级错误率和 escalation 触发率单独告警(触发率暴涨 = 分级器在漂移)。
  • 秒级回滚:所有招式都做成网关开关,质量护栏一响就关,先保质量再查原因。

施工顺序按「收益/风险比」排:归因(W0)→ 语义缓存(收益 30%,纯路由层不碰语义,风险低)→ 模型分级(收益最大 40%,同样不碰语义)→ 输出限长(一行配置)→ Batch API(搬家不改造)→ Prompt 压缩(动语义,风险最高,放最后)。每一步都有数字可汇报:第几周、降了多少、质量指标动没动——这份施工单讲完,面试官基本会认你真管过账单。

面试官追问
Q:语义缓存返回了过时/错误的答案怎么办?
人话:三道防线兜住:过期靠 TTL 和版本绑定,答非所问靠点踩下架加抽样人审。缓存省的钱抵不过一条错答案赔掉的信任,宁可命中率低一点。类比:这就是备份里「用旧恢复点恢复生产」的事故——源数据已经变了,引用旧版本的备份集必须级联失效,不能等用户恢复出一个旧状态才发现。技术:① TTL 24~48h,到期强制失效;② 缓存 key 绑定知识库版本号,内容更新即批量失效;③ 缓存答案带「生成于 X 时」戳和反馈入口,点踩率超阈值自动下架并告警;④ 黄金集抽样复验兜底。
Q:模型分级怎么判断"简单/复杂"?
人话:三步走:冷启动用规则,数据攒够了换小分类器,运行时拿小模型自己的置信度兜底升级。类比:存储分层起步也只能按目录拍静态策略,跑半年攒了访问统计,ILM 引擎才能按真实频率自动迁介质;区别是介质放错能静默迁回,请求路由错用户当场看到,所以必须有升级重答这道保险。技术:规则期看 query 长度、是否命中 FAQ/缓存、历史同类题准确率;数据期拿「是否触发升级」当弱标注训练 BERT 级分类器,推理毫秒级可忽略;运行期置信度低或自检不过就自动升级旗舰重答,分级错误率回流迭代。
Q:为什么不直接全换便宜模型?
人话:能更便宜,但复杂任务会崩。Agent 是多步任务,一步错步步错;省出事故就不叫优化,叫事故。类比:像把所有数据都下沉到最便宜的介质——账面成本好看,热数据的读延迟直接拖死业务。介质要和负载匹配,模型也一样,核心问题永远是「哪些流量配得上旗舰」。技术:小模型在工具选择、多步规划、长指令遵循上断崖式落后,一次错路由会级联放大(调错工具 → 参数错 → 下游全错);分级只对 70% 简单流量降级,保住复杂任务的质量下限。另外旗舰模型还在离线干「再生产」:生成 FAQ、蒸馏标注、跑评估,全换小模型会断了这条供给线。
Q:相似度阈值 0.95 是怎么定的,拍脑袋吗?
人话:不是拍的,拿标注数据选,而且方向上宁高勿低——漏缓存只是多花一次 API 钱,错命中是答非所问。类比:和重删选块大小是同一类权衡:块越小去重率越高,但碰撞和元数据开销越大。语义缓存的「碰撞」就是两个不同问题恰好向量很近,不该共享的答案被共享了,所以阈值要压在低碰撞区。技术:标注「同义问题对/易混淆问题对」两组,画相似度分布取交叉点偏保守一侧;再按类目分桶设阈值:事实型严(0.96+)、闲聊型松(0.90);上线后按点踩率微调。另外 Top 1000 FAQ 走精确匹配,不占模糊阈值的心智。
Q:给你三个月落地,施工顺序和里程碑怎么排?
人话:先花两周记账,然后按收益/风险比动工:缓存、分级两个大头先上,压缩风险最高放最后,batch 和限长顺手收掉;每步灰度加护栏。类比:备份治理的老剧本:先出容量报告,再上重删(收益大、不碰数据语义),然后压缩(要恢复演练),最后错峰调度。顺序由「出事时的可解释性」决定:一次只动一个开关,劣化了才知道是谁的责任。技术:W1-2 网关记账+归因;W3-4 语义缓存+Top 1000 FAQ 预生成(-30%);W5-8 分级路由+escalation(再 ×0.4);W9-10 系统提示词减肥+输出限长(低风险顺手做);W11-12 LLMLingua 灰度+离线任务迁 Batch API;全程黄金集回归+点踩率监控,任何一步质量下滑即回滚。
Q:怎么证明"省了 70%"不是拿质量换的?
人话:两张仪表盘同屏:成本曲线往下走,质量指标必须纹丝不动——点踩率、解决率、转人工率,一个都不许变差。类比:备份省容量也一样:压缩比再漂亮,恢复演练不过关等于白省。「省容量」和「可恢复」必须一起汇报,否则总有一天翻车。技术:① 同口径成本归因,上线前后对比每万次请求成本;② 质量三件套 + escalation 触发率 + 缓存答案抽样人审;③ 每招的「成本-质量」对照留档,trade-off 发生在哪随时能讲;④ 灰度期新旧链路并行,同一批流量回放对比,差异显著即停。
术语卡
LLMLingua:微软开源的提示词压缩工具,小模型给 token 打信息分、删低分词,论文报告最高 20 倍压缩。
Batch API:批量异步通道,约半价,承诺 24 小时内返回,适合没有实时 SLA 的离线任务。
Escalation(升级重答):小模型置信度不足或自检失败时,自动升级旗舰模型重答的兜底机制,是模型分级的安全网。
GPTCache:开源语义缓存实现,按问题向量相似度命中直接返回缓存答案。
重复数据删除(重删):备份系统只存唯一数据块、相同指纹直接引用的容量优化技术,语义缓存的思想原型。
分层存储(HSM):按数据价值/访问频率把数据放到不同成本介质上,模型分级的存储版原型。
黄金集(Golden Set):几百条人工标注的标准问答,每个优化放量前回归跑一遍,质量不降才上线。
