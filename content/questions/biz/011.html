业务落地 · Q4

如何处理 Agent 的幻觉问题?

⭐⭐⭐⭐ #幻觉#Agent#可靠性
先说人话:Agent 有时一本正经地编造事实,这题问的就是怎么让它少编、编了也能被兜住。面试官爱考,因为这是业务上线的第一道坎:只会答"调温度、写严 prompt"的是背参数的,能按风险分级设防线、拿指标度量幻觉率的,才是真带过生产系统的人。
30秒电梯稿

"先立前提:幻觉是概率模型的出厂设定,不是 bug,根除不了,只能分层设防。预防层——用 RAG 把答案锚在检索资料上,Prompt 声明知识边界"资料里没有就答不知道",温度调低,实时数据一律走工具查询。约束层——强制逐句/逐结论带 [1][2] 引用,再用程序校验每个引用真的撑得住那句话,撑不住就删句或打标。检测层——置信度信号 + LLM-as-judge 线上抽检,数字/日期/人名这类高危词自动触发复核。兜底层——按场景风险分级:医疗、金融类高风险场景关键结论人工审核后才生效;闲聊、推荐类低风险场景打个'AI 生成,请核实'标注即可。收尾给观点:高风险场景要靠工程流程保证下限,不能把可靠性寄托在模型自觉上。"

通俗类比

幻觉就是"一本正经地胡说八道":模型答不上来的时候,不报错、不承认不会,而是按概率现编一个看起来很像的答案。先记住一个画面:一个特别自信的实习生——知识渊博,但没底气说"我不知道",于是现场编一份看起来很专业的材料交上来。治理思路从来不是骂他,而是给他资料库、教他说"不知道"、关键文件领导签字、会议纪要标注"未经核实"——这四件事,正好对应下面的四层防线。

幻觉(用存储里的"静默数据损坏"想):模型编造事实,像极了磁盘上的 bit 翻转——没有报错、没有异常,读出来的数据格式完好、语气笃定,内容却是错的。存储工程师对静默损坏的第一反应从来不是"换块更靠谱的盘",而是"上 checksum、上 ECC、上巡检"——因为你无法让介质天生不出错,只能让错误被拦住。哪里像:都是"静默失效"——系统不会自己举手认错,必须靠外挂校验机制才能发现;也都信奉"不信任单点输出"。哪里不像:bit 翻转能用校验和做二值硬校验,对就是对、错就是错;幻觉是概率补全,"错"有灰度——过时、夸大、张冠李戴各不相同——校验只能靠语义比对(NLI 或 embedding 相似度),天然带误判率,所以要靠多层叠加摊薄。

四层防线(用备份的纵深防御想):备份工程师常挂嘴边一句话——RAID 不是备份,备份不是容灾,单层机制永远兜不住一切。预防、约束、检测、兜底四层,对应的就是"主存储冗余 → 定期备份 → 恢复演练 → 异地容灾"的层层退路,每一层都假设上一层会漏。哪里像:越靠后的层越贵、越慢,但确定性越高;最后一层(人工审核/异地容灾)是 SLA 的最终保底。哪里不像:备份恢复是确定性操作,一次演练能覆盖整批数据;人工审核是逐条、有吞吐上限的,要为确定性付出时延代价——所以才需要风险分级,不能无脑全上人审。

RAG(用"查主库,别让服务端瞎猜"想):与其让模型闭卷答题,不如先检索再作答,并要求每句话注明出自哪份资料——就像查询必须打到权威数据源,绝不允许服务端"凭经验"造一条记录返回。哪里像:都把"权威来源"当唯一事实来源,生成过程被外部数据锚定。哪里不像:数据库查询是精确匹配,查到什么就是什么;检索回来的 chunk 只是"相关",模型仍可能读岔、漏读、张冠李戴——所以 RAG 之后还要加一道引用校验,相当于恢复完成后再验一次数据完整性:介质对了,流程还会错。

风险分级(用 RTO/RPO 分级保护想):备份系统从不给所有业务同等待遇——核心交易库是金级(分钟级 RPO、异地多活),边缘日志是铜级(天级备份一次)。幻觉治理一模一样:闲聊场景打"AI 生成"标注即可(铜级),客服答疑强制引用校验(银级),医疗/金融/HR 关键结论人工审核(金级)。哪里像:保护等级跟着"出错的业务代价"走,人审和算力跟备份带宽一样永远稀缺,必须按影响面分配。哪里不像:RTO/RPO 度量"多快能恢复",幻觉分级度量"多确定才放行"——指标方向不同,但"按代价分级投入"完全同构。

详细拆解

0. 先讲成因(体现理解,不是只会背方案)

LLM 本质是"下一个词的概率分布":给它一段前文,它算出下一个词的概率表,然后挑一个续上去。训练目标是流畅(像不像人话),而不是真实(对不对);知识截止日期后的事、语料里没有的细节,它就用概率"合理地补全"。幻觉不是 bug,是这类模型的出厂设定——就像你无法要求一块没配 ECC 的内存在 bit 翻转时主动报错,失效模式是"体质"决定的,治理只能靠外挂机制。

用户问: "咱们产品 2026 年 Q3 的退款率是多少?"

模型内部其实在算: P(下一个词 | 前文)
   "0.9%"          ← 语料里见过一堆相近数字, 挑个读着最顺的
   "1.2%"          ← 也像那么回事
   "暂无相关数据"    ← 概率低到几乎不可能被选中

它不查库、不报错, 只是"接着写" → 一本正经地编

所以面试先把这句立住:治理思路是管理和约束,不是根治。带着这个前提,再展开四层防线。

1. 四层防线(每层都假设上一层会漏)

先看全景图,和备份的纵深防御逐层对上:

用户提问
   │
   ▼
[预防] RAG 锚定 · 知识边界声明 · 温度调低 · 实时数据走工具查询
   │      ≈ 源端数据质量门禁: garbage in, garbage out
   ▼
[约束] 强制 [1][2] 引用 + 程序校验"引用真能撑住这句话"
   │      校验不过 → 删句 / 打标降权
   │      ≈ 备份完成后的恢复校验: 备份成功 ≠ 能恢复
   ▼
[检测] logprob 置信度 + judge 抽检 1~5% + 高危词(数字/日期/人名)触发复核
   │      高危 → 转人工
   │      ≈ 线上 scrubbing 巡检: 定期扫静默损坏
   ▼
[兜底] 风险分级: 高风险人工审核放行 / 低风险打"AI生成"标注
          ≈ 异地容灾: 最慢最贵, 但是 SLA 的最终保底
防线手段细节
预防RAG grounding、知识边界、低温采样答案必须有资料支撑;Prompt 明确"资料里没有就回答'暂无相关信息'";temperature 调低;工具化查询实时数据(订单号去查,别猜)
约束强制引用 + 引用校验输出格式要求逐句/逐结论带 [1][2] 引用;后处理程序验证每个引用确实在检索结果里且语义支持该句(NLI 模型),不支持的句子删掉或打标
检测置信度 + judge 抽检生成模型的 logprob/自评置信度;线上随机抽 1~5% 会话 LLM-as-judge 打"幻觉分";发现高危关键词(数字、日期、人名)时自动复核
兜底风险分级 + 人工审核 + 用户告知见下
  • 预防层治的是三类源头:RAG 治"知识没有或过期";Prompt 写死知识边界("资料里没有就回答'暂无相关信息'",连语气都规定好)治"死撑面子";温度调低治"发散式编造"——采样分布更尖,模型倾向挑最高概率的词;工具化查询(订单号、库存这类实时数据让模型调 API,别猜)治"拿参数里的旧世界硬答新问题"。四招各管一段,面试时别混成一团。
  • 约束层的核心是"引用必须程序验真":"带引用"和"引用为真"是两回事——模型完全可以编一个像模像样的 [3]。所以校验必须由程序做:先硬校验,引用编号确实存在于检索结果里(像 checksum);再软校验,语义上确实支持那句话(NLI/embedding)。类比就是:备份完成不算数,恢复演练通过才算数。
  • 检测层是"线上巡检":存储集群要定期做 数据巡检(scrubbing)才能发现静默损坏,生成系统同理——线上随机抽 1~5% 会话让 judge 打"幻觉分";数字、日期、人名这类高危词自动触发复核,因为经验上幻觉最爱藏在具体数字和专有名词里;再配合 logprob(输出 token 的对数概率)聚合成句级置信度,低分离谱的句子重点关照。
  • 兜底层是唯一确定性的一层,也是唯一贵的一层:人审把响应从秒级拖到分钟级,所以必须分级使用——见下一节。

为什么要叠满四层:因为每层都有漏网率——引用校验拦不住"引用真实但推理接错",judge 自己也会误判(所以先拿人工标注校准 judge)。这和"RAID 也可能双盘齐坏,所以还要备份 + 异地"是同一道数学题:让多层独立漏过的概率乘积小到业务能接受。单层追求完美,不如多层摊薄风险。

2. 按场景风险分级(业务思维,很重要)

面试官问这题,一半考技术,一半考你会不会花公司的钱:人审资源永远稀缺,不能撒胡椒面。做法和备份按 RTO/RPO 给业务定金/银/铜级一模一样——按"出错的业务代价"定级设防:

特别看最底下那条红线:退款、改数据这类高危操作,永不基于纯生成结果直接执行。DBA 世界有现成对应物——生产库变更要走审批 + 回滚预案,谁也不能在 prod 上裸奔一条 update;Agent 侧同理:模型输出最多算"起草",执行前必须过规则引擎或人工确认,把破坏性动作从生成链路里解耦出来。

3. 幻觉率的度量(说得出指标才有说服力)

讲完防线不给指标,面试官会默认你没上线过。三个口径,顺带和备份世界的指标对齐:

  • 离线:黄金集上"无依据陈述占比"(judge 判定每句是否有检索支持)。建 500~1000 条标注集;judge 上岗前先用人工标注校准一致性——裁判自己也会幻觉,先治裁判。
  • 在线:引用校验拦截率、用户纠错率、点踩归因分析(抽样把差评标记为幻觉类)。
  • 回归:把幻觉率当核心质量指标进 CI 回归——新的 Prompt/模型让它变高了就拦截发布,再配合灰度发布小流量验证后放量。
口径怎么算备份世界的对应物
无依据陈述占比(离线)黄金集逐句判"是否有检索支持"备份校验发现的坏块率
引用校验拦截率(在线)约束层删句/打标占比scrubbing 巡检发现的静默损坏数
用户纠错/点踩归因差评抽样标注,归因到幻觉用户报障工单里的数据不一致占比

理念就一句:没演练过的备份等于没有备份;不进回归的幻觉率等于没有度量。

4. Agent 特有的坑(比单轮问答多两个)

  • 级联幻觉:多步 Agent 中幻觉会级联——第一步编了一个假工具返回值,后面步步当真、全链皆错。数据 pipeline 的铁律在此完全适用:脏数据不流向下游,每一跳都验校验和。落地就是每步工具结果做真值校验:调用的返回原样记录、原样注入上下文,不允许模型"脑补"或转述工具输出;关键多步任务再设 checkpoint,一步纠错不必全链重跑。
  • 注入是幻觉的近亲:Prompt 注入让模型"故意"说假话,幻觉是"无意"说假话——两者同属"输出可信性"工程,引用校验、人工审核、操作解耦这些防线是复用的,设计时统一规划,别各建一套。

5. 主动交代 trade-off(把"背方案的人"甩开的最后一步)

四层防线不是免费的:RAG 加一跳检索时延,引用校验多一次 NLI 推理,judge 抽检烧 token,人审把响应从秒级拖到分钟级。低风险场景全上等于烧钱,高风险场景省掉等于埋雷。风险分级的本质,就是在延迟、成本、可靠性这个三角里,按业务出错代价找位置——面试里能主动把这句说出来,你就从"背了四层防线"升级成了"理解为什么是四层"。

面试官追问
Q:引用校验具体怎么实现?
人话:分两档——便宜的先上,贵的兜底,两档都不过的句子才处理。类比:就像备份校验,先跑 checksum(便宜、快,拦得住大多数损坏),核心库再上全量恢复演练(贵、慢,但确定性高)。技术:轻量级:句子 embedding 与所引 chunk 相似度阈值;进阶:NLI(自然语言推理)判断"该资料是否蕴含该结论";双保险都不过的句子——删除或替换为保守表述,并对整个回答降权标记。低风险场景跑相似度就够,高风险场景两档叠加。
Q:业务要求幻觉率必须 0 怎么办?
人话:直接摊牌:纯生成做不到 0,但"对外可见的幻觉"可以做到 0——用流程换确定性。类比:备份的世界观从来不是"盘不坏",而是"盘坏了业务无感"——任何硬件都会坏,所以才有了 3-2-1 备份和异地容灾。技术:①高风险输出全部人工审核,通过才放行;②模板化——让模型做数据填充而非自由生成,只填槽位不写正文;③白名单式回答(FAQ 精确匹配)。最后把选择权交还业务方:自由度和可靠性是 trade-off,要零幻觉就得接受牺牲自由度。
Q:上了 RAG,为什么还是有幻觉?
人话:RAG 只保证"资料递到了模型手里",不保证它读对了、用对了、没夹带私货。类比:备份软件把正确的磁带取出来了,恢复程序仍可能读错版本、恢复错字段——介质对了,流程还会错。技术:四个典型漏点:①检索召回不准,top-k 里根本没有答案;②模型无视检索内容,沿用参数记忆里的旧答案;③引用张冠李戴——资料在,但撑不住那句话;④多跳推理自己接错逻辑。对应修法:混合检索 + Rerank 提召回、引用强制对齐 + 程序校验、faithfulness 指标进回归。
Q:把温度调到 0,是不是就没有幻觉了?
人话:不是。温度管的是挑词的随机性,不管模型脑子里有没有这条知识——没有的知识,采样再确定也编不出真的。类比:相当于把磁盘从"随机坏"变成"每次坏在同一个位置":错得更稳定、可复现了,但坏块还在——静默损坏不会因为读取顺序固定就消失。技术:温度调低能压住发散式编造、提高复现性,但参数化知识缺失导致的幻觉依旧存在;还会牺牲创造类任务的质量。它只是预防层里最便宜的一颗螺丝,把"温度调 0"当解药答,恰恰暴露没理解成因。
Q:多步 Agent 的级联幻觉怎么防?
人话:每一步都给"真值锚点",任何一步都不许靠记忆续命。类比:数据流水线的铁律——每一跳都验 checksum,脏数据不流向下游;备份快照链同理,一环脏了环环脏,绝不把坏副本复制到所有节点。技术:①工具返回值原样落库、原样注入上下文,禁止模型转述关键数值;②订单号、金额这类硬参数从工具结果直通下游模板,绕开生成环节;③每步之后跑轻量校验(NLI/规则),失败就重试或降级;④关键链路设 checkpoint,一步纠错不必全链重跑。
术语卡
Grounding:答案有出处支撑、被外部资料"锚定",是 RAG 治理幻觉的核心思想。
NLI:自然语言推理,判断前提与假设是蕴含、矛盾还是中立,引用校验的语义级武器。
级联幻觉:上游错误被下游当真并放大,多步 Agent 的头号可靠性杀手。
Logprob:模型输出每个 token 的对数概率,可聚合成句级置信度信号。
LLM-as-a-Judge:用另一个 LLM 按评分标准给输出打分,线上质量抽检的常用手段。
Prompt 注入:通过输入内容诱导模型违背原指令,与幻觉同属输出可信性工程。
幻觉综述:想系统搞懂幻觉的成因与分类,从这篇 survey 入门。
