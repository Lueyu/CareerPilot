业务落地 · Q4

如何处理 Agent 的幻觉问题?

⭐⭐⭐⭐ #幻觉#Agent#可靠性
30秒电梯稿

"幻觉是概率模型的固有属性,没法根除,只能分层设防:预防(RAG grounding、声明知识边界、温度调低)、约束(强制引用来源 + 后处理校验引用真实性)、检测(judge 抽检 + 事实一致性校验)、兜底(按风险分级:医疗/金融类高风险场景关键结论人工审核,低风险场景给用户标'AI 生成,请核实')。核心观点:高风险场景要靠工程流程保证下限,不能把可靠性寄托在模型自觉上。"

通俗类比

幻觉是"一本正经地胡说八道"——像一个特别自信的实习生:知识很渊博,但答不上来的时候他不承认不会,而是现编一个看起来很像的答案。治理思路不是骂他,而是:① 给他资料库,要求"每句话都注明出自哪页"(RAG+引用);② 明确说"不知道就说不知道"(边界声明);③ 关键文件交上去前主管签字(人工审核);④ 会议纪要标注"未经核实"(风险提示)。

详细拆解

0. 先讲成因(体现理解,不是只会背方案)

LLM 本质是"下一个词的概率分布",训练目标是流畅而非真实;知识截止日期后的事、语料里没有的细节,它就用概率"合理地补全"——幻觉不是 bug,是这类模型的出厂设定。所以治理思路是管理和约束,不是根治。

1. 四层防线

防线手段细节
预防RAG grounding、知识边界、低温采样答案必须有资料支撑;Prompt 明确"资料里没有就回答'暂无相关信息'";temperature 调低;工具化查询实时数据(订单号去查,别猜)
约束强制引用 + 引用校验输出格式要求逐句/逐结论带 [1][2] 引用;后处理程序验证每个引用确实在检索结果里且语义支持该句(NLI 模型),不支持的句子删掉或打标
检测置信度 + judge 抽检生成模型的 logprob/自评置信度;线上随机抽 1~5% 会话 LLM-as-judge 打"幻觉分";发现高危关键词(数字、日期、人名)时自动复核
兜底风险分级 + 人工审核 + 用户告知见下

2. 按场景风险分级(业务思维,很重要)

3. 幻觉率的度量(说得出指标才有说服力)

  • 离线:黄金集上"无依据陈述占比"(judge 判定每句是否有检索支持)。
  • 在线:引用校验拦截率、用户纠错率、点踩归因分析(抽样把差评标记为幻觉类)。
  • 把幻觉率当核心质量指标进 CI 回归——新的 Prompt/模型让它变高了就拦截发布。

4. Agent 特有的坑

  • 多步 Agent 中幻觉会级联:第一步编了一个假工具返回值,后面全错——每步工具结果要真值校验(调用的返回原样记录,不允许模型"脑补"工具输出)。
  • Prompt 注入让模型故意说假话,和幻觉治理同属"输出可信性"工程,注意统一防线设计。
面试官追问
Q:引用校验具体怎么实现?
轻量级:句子 embedding 与所引 chunk 相似度阈值;进阶:NLI(自然语言推理)判断"该资料是否蕴含该结论";双保险都不过的句子——删除或替换为保守表述,并对整个回答降权标记。
Q:业务要求幻觉率必须 0 怎么办?
纯生成做不到 0,工程上可以做到"对外可见幻觉=0":高风险输出全部人工审核;模板化(数据填充而非自由生成);白名单式回答(FAQ 匹配)——诚实告知"自由度和可靠性是 trade-off",用流程换确定性。
术语卡
Grounding:答案有出处支撑。
NLI:自然语言推理,判断蕴含关系。
级联幻觉:上游错误被下游放大。
Logprob:模型输出的对数概率,可做置信度。
