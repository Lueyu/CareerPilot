Agent 框架选型:LangGraph vs CrewAI vs AutoGen

⭐⭐⭐⭐ #Agent#框架选型
30秒电梯稿

"按控制力需求排序选:生产级复杂流程我选 LangGraph——显式图 + 共享 State + checkpoint 持久化,可控、可调试、支持人工介入,是三个里唯一把'工程化'做到位的;CrewAI 主打角色协作、快速上手,demo 和轻量场景舒服,但流程黑盒些;AutoGen 是对话式多 Agent,研究探索强,生产控制力弱。一句话:要掌控选 LangGraph,要快选 CrewAI,要研究选 AutoGen。"

通俗类比

像三种组织形式:LangGraph 是流程手册驱动的公司——每步谁做、怎么流转、卡住了从哪重来,白纸黑字(显式图+checkpoint);CrewAI 是小团队分工——"你是研究员,你是作家,你俩配合完成任务",氛围好但具体怎么配合靠默契(模型自由发挥);AutoGen 是圆桌会议——大家开会讨论直到出结果,idea 火花多,但会议可能跑题、没人管时间(控制力弱)。

详细拆解
维度LangGraphCrewAIAutoGen
编排模型显式有向图 + 状态机角色(Role)+ 任务(Task)委派Agent 对话循环
控制力最强(每个分支/循环你定义)中(框架管流程,细节偏黑盒)弱(对话自组织)
状态与持久化Checkpoint 一等公民,断点恢复/HITL基础基础
调试图结构清晰,LangSmith 配套中等对话日志翻起来费劲
上手成本陡(要自己想清楚图)缓(半天出 demo)中
适合生产级复杂工作流轻量协作、POC多 Agent 模式研究

我的实战选择路径

  • POC 阶段:CrewAI 快速验证"这个任务多 Agent 值不值得做"。
  • 生产阶段:把验证过的流程翻译成 LangGraph 的显式图(或直接自研状态机)——因为生产要的是:循环防护、断点恢复、人工审批、每步可观测,这四样 LangGraph 都原生给。
  • 特别场景(需要 Agent 间自由讨论的,如辩论式评审):AutoGen 的对话模式反而是对的工具。

反过来想:什么时候不选 LangGraph?

  • 流程是纯线性的(RAG 问答):普通代码/管道就够,上图框架纯属过度设计。
  • 团队完全不想学新抽象:自研 300 行状态机 + 自由定制,比学框架划算——能说出"不选"的条件,说明你真理解选型。
面试官追问
Q:LangGraph 的 checkpoint 怎么用在你的场景?
例:客服 Agent 走到"退款审批"节点挂起 → checkpoint 存 Redis → 人工在后台审批 → invoke 恢复继续;再加一个例子:长任务跑一半进程重启,从最后 checkpoint 恢复,不用用户重新说一遍需求。
Q:三个框架的流式输出和可观测性呢?
LangGraph 节点粒度对齐 trace(每个 span=一个节点),观测最清晰;CrewAI 靠日志;AutoGen 对话式 trace 要自己拼——可观测性是生产的硬指标,这也是我生产偏 LangGraph 的主要原因之一。
术语卡
显式图:节点和边全部明确定义的流程图。
黑盒编排:框架自动决定执行顺序。
HITL:人工介入节点。
