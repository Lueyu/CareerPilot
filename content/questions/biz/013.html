业务落地 · Q6

如何处理用户数据隐私?

⭐⭐⭐⭐ #隐私#安全#合规
30秒电梯稿

"按数据生命周期设防:采集端数据最小化(能不收就不收);处理端PII 实时脱敏(NER 识别后替换/掩码再进 LLM);存储端传输 TLS + 落盘加密 + 分级访问控制;共享端选不用于训练的企业 API 条款或私有化模型;治理端合规映射(个保法/GDPR)+ 用户权利实现(查询/更正/删除)+ 审计。LLM 特有的一点:除了传统脱敏,对话日志和 Memory 里的 PII 也要治理——这是新系统最容易漏的口子。"

通俗类比

像医院的病历管理:挂号只收必要信息(最小化);病历本上身份证号印成 330**********(脱敏);病历柜上锁、只有主治医生能开(分级访问);外包检验科时签"样本不得留存他用"(API 不训练条款);病人有权复印、修改、要求销毁病历(用户权利);所有查阅留痕(审计)。

详细拆解

1. 按生命周期设防(框架)

2. PII 脱敏(LLM 场景的核心手段)

  • 识别:NER 模型/正则识别姓名、手机号、身份证、银行卡、住址;识别后按用途处理:替换("用户A")、掩码(138****5678)、令牌化(双向映射表单独加密保存,需要时可反查)。
  • 过滤位置:入口处(进 LLM 前最关键)——prompt 里的 PII 不脱敏就等于把数据发给了第三方;出口也要脱敏(模型输出回带的敏感内容)。
  • 和效果的平衡:有些场景 PII 是任务必需(给用户查自己的订单)——按数据流向区分:进自家私有化模型=可;出去到第三方 API=脱敏或签 DPA。

3. 存储与访问

  • 传输 TLS、落盘加密(KMS 管密钥)、密钥轮换;对话日志是隐私重灾区(用户会聊一切),日志里 PII 自动识别打标,超期自动删除(TTL),查询走审批。
  • 分级:公开/内部/机密三级 + 行级权限(谁能看哪个用户的记忆)。

4. 第三方模型的合规(必聊)

  • 选企业 API 且合同明确"不用于训练";敏感行业干脆私有化部署模型(金融/医疗常态)。
  • 跨境注意:调用境外模型 = 数据出境,需过安全评估(个保法框架下);"模型在哪、日志在哪、备份在哪"三个都要答上。

5. 用户权利与治理

  • 实现"查询/导出/更正/删除(被遗忘权)"的工单化通道;删除是级联的:对话、Memory、向量库(该用户的所有 chunk)、缓存、备份策略都要覆盖。
  • 隐私政策里如实披露"AI 如何处理你的数据";上线前过法务评审,日常做审计留痕。
面试官追问
Q:用户要求删除 Memory 里的数据,向量库怎么删?
记忆写入时带 user_id 元数据,删除时按 metadata filter 批量物理删除+重建索引碎片回收;同时清缓存(语义缓存可能残留答案);提供删除回执。这就是为什么 Memory 设计一开始就要带租户/用户标签——删除才能执行得下去。
Q:怎么平衡"模型效果好(需要更多数据)"和隐私?
分级数据策略:脱敏后用于改进(统计/评估)、原始数据最小授权;用"差分隐私/聚合"思路做分析;采集时征得明确同意(opt-in 而非默认勾选)。
术语卡
PII:个人可识别信息。
令牌化:敏感值替换为可逆的假名。
KMS:密钥管理系统。
被遗忘权:用户要求删除其数据的权利。
