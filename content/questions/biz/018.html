你的 Agent 系统Prompt 是怎么设计和迭代的？有没有做过 Prompt 自动优化？当用户提出不完整的请求时，如何补全用户意图的？

30秒电梯稿

"系统 Prompt 我用四段式:① 角色与目标(你是谁、服务谁、边界在哪);② 能力与工具清单(能用什么、何时用);③ 行为规范(何时澄清、何时拒绝、格式要求);④ 输出契约(JSON schema、引用来源等)。迭代靠评测集驱动:固定一批任务,用 LLM-as-judge + 人工抽检打分,每次改动看分数而非感觉。自动优化做过两层:DSPy 式签名优化、以及"LLM 生成候选 + 评测筛选"的进化搜索。意图补全用槽位填充:先抽已知槽位,只对缺失的关键槽位主动澄清一次,不搞连环追问。"

通俗类比

系统 Prompt 就像给新员工写的岗位说明书 + 工作手册:先告诉他"你是谁、对谁负责"(角色),再列清楚"你有哪些权限和工具"(能力),然后规定"遇到什么情况怎么做、什么不能做"(规范),最后定死"交作业的格式"(输出契约)。写得含糊,员工就天天来问你;迭代就是看绩效打分改手册。用户请求不完整,就像顾客只说"我要那个",服务员不会瞎猜,而是先看已知信息(常点的、刚买的),只问缺的那个关键信息——补全意图是最小化提问,不是连环审问。

详细拆解

1. 系统 Prompt 四段式结构(给出骨架)

2. 设计要点(区别于单轮 Prompt)

  • 分层:系统 Prompt 放"稳定不变"的规则,任务 Prompt 放"本次任务"指令,用户消息放"具体输入"。改任务不改系统,改系统不动全局。
  • 少样本:关键分支(澄清、拒绝、多工具协同)各给 1~2 个高质量示例,比长篇说明更有效。
  • 约束要具体可验证:"要礼貌"没用,"价格一律带货币单位和来源"才有用。

3. 迭代方法(评测集驱动,别凭感觉)

  • 建回归集:真实+构造的 100~300 条任务,覆盖边界(歧义、越权、工具失败)。
  • 打分:LLM-as-judge(带 rubric)+ 每月人工抽检,双轨;记录"改 Prompt → 跑评测 → 看分数 diff"。
  • 灰度:线上 AB,看任务成功率/澄清率/用户满意度——离线分数好不等于线上好。

4. Prompt 自动优化(做过的两层)

  • 方法 A · DSPy 思路:把 Prompt 变成可调参模块,用少量标注对"指令/示例"做搜索式优化,而非手写。
  • 方法 B · 进化搜索:LLM 生成 N 个候选 Prompt,在评测集上排序,保留高分交叉变异再迭代几轮。
  • 结论:自动优化能收敛出"过得去"的起点,但关键语义(安全边界、格式契约)仍需人工兜底审查,防优化器"过拟合评测集"钻空子。

5. 意图补全(不完整请求的处理)

  • 槽位填充:intent + 槽位集合。先抽取已有槽位,计算缺失槽位的"关键度"。
  • 只问关键槽位:缺的槽位影响决策才问(如"退款"必须知道订单号);能用默认值/历史上下文补的就补(收货地址用历史默认)。
  • 澄清话术:给选项式澄清("您是要退货还是换货?"),比开放式"请详细描述"更高效。
  • 置信度阈值:意图置信度低于阈值才澄清,否则直接给"最可能解读 + 一句确认",减少来回。
  • 一次最多问 1~2 个缺失槽位,避免连环追问激怒用户。
面试官追问
Q:自动优化有没有翻过车?怎么防?
翻过——优化器为了刷评测分,把 Prompt 改得"只在评测集上灵",上线后泛化差;还出现过它生成"绕过安全约束"的表述。防线三条:① 评测集持续加入真实线上样本,防止过拟合;② 自动优化的候选必须过人工/规则审查(尤其安全与格式契约段);③ 线上灰度 AB + 回滚,离线分数只作参考不作决策。
Q:系统 Prompt 太长会被模型忽略怎么办?
这是真实问题——越靠后的指令权重越低(lost in the middle)。解法:① 精简+分层,把稳定规则固化到代码/工具层(工具描述、JSON schema 本身就是约束),少写在 Prompt 里;② 关键约束前置或重复;③ 用结构化格式(列表、XML 标签)而非大段散文;④ 定期删减,保证系统 Prompt 占总 token 预算的合理比例。
Q:用户请求不完整,但澄清次数太多体验差,怎么权衡?
设"澄清预算":一个会话最多主动澄清 2 次;第 1 次问最关键槽位并给选项,第 2 次仍不清就"用默认假设执行 + 明确告知假设,用户可纠正",绝不无限问。同时用历史上下文和用户画像把大部分槽位预填,把需要澄清的比例压得很低——好的意图补全应该"大部分静默补全,极少显式提问"。
术语卡
系统 Prompt:设定 Agent 角色、规则、能力的持久指令。
LLM-as-judge:用强模型按 rubric 给输出打分做自动评估。
DSPy:把 Prompt 当可优化参数、用标注数据自动调优的框架。
槽位填充:从对话中抽取意图与关键字段。
少样本(Few-shot):在 Prompt 里给少量示例引导格式与行为。
