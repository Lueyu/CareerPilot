# 项目发现

1. 读 [项目目标与决定](../../../docs/agent/workflow.md#按已确认的产品决定推进) 和本次任务指令。记录授权范围、Git HEAD 和相关工作区状态。没有指定题目时，从近期反馈、失败记录、核心用户路径和最近改动中查找偏离当前目标的行为。
2. 从实际用户入口追到接口、实现或测试。记录复现条件、实际结果及当前源码路径与符号。区分提交、未提交工作区和历史报告中的证据。缺少观察时保存可查证的假设。
3. 用“用户路径 + 失败行为”写稳定的候选编号，例如 `learning:failed-score-updates-profile`。在当前分支和本机已有发现、交付、复盘记录中核对同编号、同一行为和进行中的工作。已有修复或待评价候选时沿用其证据。问题在当前版本复现，或先前阻塞条件已解除时，记录变化后再考虑重试。
4. 在本次运行目录的 `discovery.md` 写下至多三项候选。每项记录候选编号、对应目标、证据、用户可见结果、精确改动路径、验收条件、所需前置和停止条件。选一项可在现有授权和预算内闭环的改进。没有合适候选时记录原因，夜间走 `finish no_task`。
