# 项目发现

1. 读 [项目目标与决定](../../../docs/agent/workflow.md#按已确认的产品决定推进) 和本次任务指令。记录授权范围、Git HEAD 和相关工作区状态。没有指定题目时，从近期反馈、失败记录、核心用户路径和最近改动中查找偏离当前目标的行为。
2. 从实际用户入口追到接口、实现或测试。记录复现条件、实际结果及当前源码路径与符号。区分提交、未提交工作区和历史报告中的证据。缺少观察时保存可查证的假设。
3. 用项目编号标识建议，例如 `CP01` 或 `SQ01`，标题写明用户路径和具体行为。查阅当前分支、过往批次和正在进行的工作，为新问题使用未占用的编号。已有修复或待评价候选时沿用其证据。问题在当前版本复现，或先前阻塞条件已解除时，记录变化后再考虑重试。
4. 沿真实用户旅程、工程可靠性、AI 能力评估、开源上手体验和新功能机会扩展建议。基于假设的想法标明「探索」和验证假设的最低成本实验。对照两个项目正在进行的工作、PR 和以往的反馈，重复问题复用原编号。
5. 按[晚间工作流](../../../docs/agent/nightly.md)登记待审批次。每项给出价值、来源、方案、工作量、允许的改动范围、可观察的验收条件和真实依赖。按价值和开工顺序推荐组合。将当晚已有结果及时发到 Codex 审核聊天。用户可以直接回复编号，未点名的建议继续待审。
