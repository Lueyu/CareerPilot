# 项目交付

1. 读[本地交付工作流](../../../docs/agent/workflow.md)。从上游最新 `dev` 为本次改动创建独立分支和工作树。夜间从[审批账本](../../../docs/agent/nightly.md)读取已采纳任务和验收要求。独立任务并行，依赖项先合入 `dev`。
2. 对缺陷先复现，再完成足以满足验收条件的改动。涉及评分、学习、复测或项目材料归因时，保留原答、有效证据、进度和用户本人经历各自的来源。路径冲突或隔离环境缺前置时保留现场并记录 `blocked`。
3. 每项单开一个合入 `dev` 的 PR。运行与验收条件直接相关的检查，独立复核预定合入的提交和证据。页面改动用回环地址和隔离数据执行实际操作。通过后合入 `dev` 并登记回执。
4. 用[本地应用部署入口](../../../docs/agent/candidate-preview.md)启动已合入的 `dev`，用合成数据走一遍本次批准的用户路径。交给负责人定期测试，记录 PR、完整 `dev` SHA、运行地址、体验步骤、证据和回退定位。负责人明确验收该 SHA 后，按[发布流程](../../../docs/agent/release.md)走同仓 `dev → master` PR。日常交付止于 `dev`。
5. 检查失败就定位、修复、重新冻结并复验。遇到外部前置、无法继续的错误或待决产品取舍，在账本记下原因及恢复条件，继续其余获批项。跨日可继续使用原领取记录。
