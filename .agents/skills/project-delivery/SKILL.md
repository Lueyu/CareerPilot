# 项目交付

1. 读 [本地交付工作流](../../../docs/agent/workflow.md)。核对候选编号、目标、基线、授权路径和用户可见的验收条件。夜间按 [运行说明](../../../docs/agent/nightly.md) 领取项目唯一的运行记录，在返回的工作树修改。已有授权覆盖的本地改进可直接交付。提交、推送、部署及定时任务变更另依明确授权。
2. 对缺陷先复现，再完成足以满足验收条件的改动。涉及评分、学习、复测或项目材料归因时，保留原答、有效证据、进度和用户本人经历各自的来源。路径冲突或隔离环境缺前置时保留现场并记录 `blocked`。
3. 夜间先 `checkpoint`，再将工作树、基线和补丁传给 `verify.ps1`。读固定尝试目录的 `verify.json`、退出状态和日志。补跑与验收条件直接相关的检查。页面改动用回环地址和隔离数据执行实际操作。按 [预览步骤](../../../docs/agent/workflow.md#运行验收并打开预览) 保存同一验收尝试的预览。补丁有变化时重新验收并生成预览。
4. 在本次运行目录的 `delivery.md` 记录基线、候选、逐项结果、证据路径和回退定位。执行夜间终结命令前，核对验收尝试和产物。记录失败、阻塞或未覆盖的实际原因。
