# 工作流复盘

1. 读 [本地交付工作流](../../../docs/agent/workflow.md) 和本次运行目录里的发现、交付、固定尝试的 `verify.json` 及实际反馈。用同一候选编号关联结果。核对引用的文件、版本和结果。缺少反馈时记录待评价。有采纳、部分采纳或拒绝反馈时，保留用户说明的理由。
2. 找到能追溯到原始证据的原因，说明问题发生在选题、实现、验收还是工作方法。区分本次退步、基线问题和仍待查证的判断。对值得复用的经验，写清建议修改的技能或检查，以及它应改变的行为。
3. 把能重放的场景写成候选用例，记录旧方法、新方法、预期结果和何为退步。选题回放检查优先级，技能改动用对应工作场景复验。证据不足时保留提议。日常复盘输出建议，技能与策略的启用另依授权。
4. 将结论写入本次运行目录的 `retro.md`，链接发现、交付、反馈和复验记录。记录已解决、待评价或值得重试的原因，供下次发现去重。失败、阻塞或中断时保留可复验的证据及重试条件。宿主状态未知时记录未知。
