# H4：两种导入共用有资源限额的文档解析

目标是让个人版与注册版导入文档时，解析器的资源消耗有明确归属，同时保留文件顺序、部分成功、来源审查和人工批准流程。

## 背景

个人版原来把 DOCX/PDF/图片解析交给线程。线程避免占用事件循环，但仍共享 API 进程的内存；取消等待线程也不会终止解析。注册版已有短期子进程与 Linux 限额，但 Windows 没有相应边界，协议输出也没有在父进程聚合前限字节。

## 选项与决定

采用每份文档一个短期子进程。`document_policy.py` 定义不可变的策略和结果，`document_runner.py` 独占准入、进程树、管道和取消，`document_worker.py` 在限额内做格式检查及提取。两端保留薄适配器。

未采用常驻进程池。常驻池可复用 OCR 模型，但还需要损坏进程替换、累计预算和单任务取消协议。H4 没有测量证据证明这些复杂度值得引入，也不承担 F1 的队列。

Windows 先创建不可继承的 Job，设置 Job 总内存、CPU 时间、最多四个进程和关闭句柄即终止，再成功归属 worker，最后发送输入。赋限失败直接拒绝。Linux worker 在读输入与导入解析库前设置 `RLIMIT_AS`、`RLIMIT_CPU` 和禁用 core；父进程为其创建独立进程组并负责清理。两者都是资源隔离，不是文件系统或网络权限沙箱。

## 具体政策

个人版保持 12 MiB、原文字和图片格式、最多保留 60,000 字符以及原始字符计数；注册版保持 6 MiB、PDF/DOCX/Markdown、超过 24,000 字符拒绝。两端 PDF 最多 30 页，DOCX 最多 512 条目、16 MiB 声明和实际展开量、200 倍单成员压缩比。ZIP 成员不落盘解包，读到末尾验证 CRC。图片在 RGB/数组/OCR 分配前检查最多 12,000,000 像素和单边 12,000。这里的数字是拒绝政策，不是攻击防护效果的测量结论。

注册版保留 256 MiB、6 秒 CPU 与 10 秒墙钟预算。个人版为可选 OCR 冷启动使用 768 MiB、6 秒 CPU 和 20 秒墙钟预算。进程内最多同时三个直接解析 worker，等待准入、stdin 阻塞和输出读取都算入墙钟预算。stdout 最多聚合 400,001 字节，超出 400,000 字节拒绝，stderr 丢弃。成功和异常返回都会清理残留子孙及管道。异步取消设置共享事件，重复取消期间仍等待清理。

## 后果与验证范围

短期 worker 重复支付解释器和 OCR 启动成本。有效但过于复杂的文档可能被拒绝，用户需要拆分或换格式。OCR 未安装单独返回依赖错误，损坏图片、超像素和超时分别处理。不新增 PDF 渲染或扫描 PDF OCR。

Windows Job 内存是进程树总预算；Linux `RLIMIT_AS` 是每进程虚拟地址空间，继承给子进程，并不是 cgroup 的总内存或部署级配额。Linux 进程组不能阻止主动 `setsid` 脱离。多个 API 进程各有三个槽位，部署级资源政策仍由运行环境提供。未知异常退出只能报告异常或资源限制，不能认定一定发生了内存耗尽。

针对性测试覆盖真实 Windows Job 分配拒绝、归属、不可继承句柄、超时及重复取消的子孙清理；离线、非 root 的 Linux 容器检查实际 rlimit、合成文档和进程组清理。精简镜像仅精确放行三个新增模块。全新镜像及浏览器制品验收由父代理随后执行，本 ADR 不将挂载源码的 Linux 检查冒充全新构建制品验收。
