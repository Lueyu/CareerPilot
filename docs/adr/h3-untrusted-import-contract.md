# H3 导入面经的资料权限与原文审核

目标是让导入面经在提取、补答案、项目改写和生成审核中保持资料身份，保留来源与原文，并在原有审核区显示可疑指令提示。基线为 `e3d25715cb45a8877cb579d96a2ceeb3a4088eeb`，实施范围由 Wave1 H3 批准。

## 背景

个人版和注册 native 经同一 bank 导入流水线。注册 beta/seed 仍有独立 public_library 导入服务。个人提取器原先把文本直接作为 user 消息，局部提示约束没有覆盖同源标题补答案的二次输入。生成工作台已有严格事实引用验证和资料块，注册导入也已有 JSON 与数据声明。H3 统一这些边界，不迁移解析器、计费或审核状态机。

## 选项与决定

采用共享 `untrusted_source.py`，集中固定权限合同、JSON 序列化和纯函数告警检测。所有现有同源消费者使用该合同，外部内容不能成为 system 或 tool 角色、改变工作区/计费/预算/权限/审核，或要求访问秘密。API system 与可复制到外部聊天的完整生成 prompt 均包含合同。JSON 只在模型消息中转义尖括号，解码后与输入一致。数据库里的解析文本不做安全清洗。

拒绝在提取前删除或拦截命中语句。安全面试题会正常引用攻击文字；删除会损坏原文和来源，误报亦无法由少量词法规则可靠消除。告警不是运行失败，也不决定批准或拒绝。

## 数据与状态归属

`ImportSession.meta.source_review` 保存 `{version: 1, flags, truncated}`，独立于 `progress`、`error` 和文件解析警告。每条 flag 包含文件名 `source`、零起始片段序号 `source_index`、半开区间 `start/end` 与固定 `reason`。相同文件名仍按片段序号区分。

个人流水线先按现有 60000 字符预算保留片段，再以两个换行连接。告警和提取消费同一组保留片段，区间指向确切保存的 `extracted_source_text`，不包含被预算截去的内容。模型仍只看每份前 8000 字符，规则和告警覆盖保留的全文。区间是 Python Unicode code point，不是原文件字节或 JavaScript UTF-16 索引。前端直接展示全文，不依据未经转换的区间切片。文件解析器本身可能规范化文本，本项不承诺原始文件逐字节保持。

生成工作台在冻结请求时根据实际 `source_text` 计算告警。建立新的 REVIEW 会话时再次依据实际快照重算，不能继承被替换正文的旧标记。资料告警不送给模型生成或修改。注册服务在解析入库时用同一检测器，显式投影给现有原文审核区。

检测使用五组固定规则，覆盖忽略既有指令、伪造角色、闭合资料容器、越权工作区/审核及窃密指令。窗口长度有上限，每组最多保留 101 次匹配，最终最多 100 条，超出时 `truncated=true`。没有共享可变检测状态，不用模型判断安全。无命中不代表安全；混淆、编码、其他语言或间接语义仍会漏报。

## 输出边界与兼容

bank 提取器继续接受对象 `questions`、兼容裸数组和 JSON 围栏，缺少非必填字段时采用既有默认值，未知技能仍使用已有关键词回退。字段采用白名单，字符串不再接受对象/布尔值强转，confidence 必须是有限、非布尔的 0..1 数值，0 保留为 0。模型不能附加 workspace、审批状态、来源或检测元数据。保留的候选中任何一行不合法都放弃本次模型候选，沿用既有规则回退。20 题上限、标题截断以及长文后段规则扫描保持。预算或出站策略拒绝继续抛出，不能转成规则成功。

已有 generation 严格 schema、batch 身份、事实 ID、允许事实集合、缺口与本人归因检查保持。合法 JSON 不证明答案正确、引文真实，或事实足够支持结论。合法结构的错误语义仍只能产生待审草稿。导入和学习材料不产生本人掌握或能力证据。

## 后果与验证边界

原有 InterviewNotes、Bank 和 seed 原文区展示持久化文本及提示，复用状态和来源区域，不增加审核动作或页面。源码中的消息、受控 adapter、真实隔离数据库与同源消费链测试证明应用如何传递数据、拒绝非法结构、保存来源和维持 DRAFT/REVIEW。native 测试运行真实 forward 和 bank 路由，服务器选定身份与 billing scope 不取正文伪造值。受控模型不证明真实模型攻击成功率或抵抗率。父任务在源码冻结后执行真实隔离浏览器验收、独立审核和发布管理。

不扩展 H4 解析资源限制、F8 降级可观测性、其他模型消费者或个人实例。前端代码与验证由父任务协调的独立所有者提供；H3 后端作者不据代码静态阅读宣称浏览器已通过。

## 必要配套修复 H3-import-trace

新的并发来源测试实际捕获 `traces_short_code_key` 唯一约束冲突。原导入 trace 使用 `int(perf_counter())` 的秒级编号，两方同时完成编号查询后会插入同一值，在解析前使一方 FAILED。父任务明确将最小修复纳入 H3，因为它阻断同一导入流水线的并发来源验收。

导入 trace 基础编号改为 `TR-IMPORT-{import_id}`，使用数据库已分配的批次 ID，并保留既有 `_unique_trace_code` 对历史编号及重复运行的去重行为。不修改其他 trace 生产者或全局 ID 策略。回归控制 bank 本地时钟一致，并让两个真实导入都完成现有编号选择后才插入；旧实现稳定触发冲突，修复后两方均 REVIEW，trace 分别绑定各自 import_id，来源和告警不串批次。

另有三项既有 starter 计费测试在指定基线的独立只读归档上复现失败。旧夹具未声明 H2 本地 origin，且仍拦截旧 HTTP 客户端入口。经父任务授权只修正测试的精确 origin 和 `model_client` 接缝，计费账本与出站生产闸未改动。保留基线失败和修正后相同节点通过的证据。

追加真实计费入口回归时，离线本地化测试留下的空 `_CACHE` 会使 import/memory 用例在合成配置下仍判断 adapter 不活跃。相同测试顺序在 e3d2571 归档上复现。只在该 paid-path 测试的合成配置范围内用 monkeypatch 隔离缓存，保留真实保留/结算过程和必须一次到达调用的断言，不改生产 active 或计费逻辑。
