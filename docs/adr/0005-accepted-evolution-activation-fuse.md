# ADR 0005: evolution 策略激活默认熔断（B5）

- 状态: `ACCEPTED`（明确接受取舍，含已知代价）
- 日期: 2026-11-27
- 关联: `KNOWN_ISSUES.md` B5；代码 `../../server/app/services/evolution.py`、`../../server/app/config.py`（`evolution_activation_enabled`）、`../../server/app/api/v1/evolution.py`
- 决策者: Lueyu

## 背景

「进化实验室」已实现候选生成（确定性规则）+ 离线投影评估 + 版本管理，
状态机为 `PROPOSED → EVALUATED →(人工批准)→ ACTIVE →(回滚)→ ROLLED_BACK`，
也可 `REJECTED`。但激活被硬编码关闭：`approve` 返回 403、
`get_active_candidate` 恒 `None`、`config.py` 的 `evolution_activation_enabled` 恒 `False`；
没有 A/B、canary 或自动停损。`KNOWN_ISSUES.md` B5 已把该项标为 `ACCEPTED`。

## 决定

**保持默认关闭，不在当前阶段放开策略激活。** 离线评估是「基于历史指标与技能状态的
确定性投影」，不是在线实验；样本量不足以支撑「这个策略真的让得分率/复测率变好」的因果结论。
按 ADR 0002 的 fail-closed 原则，证据不足时不允许把候选策略写入个人学习路径。

## 备选方案

| 方案 | 放弃理由 |
|---|---|
| 立即放开 approve 与激活 | 用投影结论冒充实验结论，会污染个人归因，且与 ADR 0002 冲突 |
| 小流量 workspace 灰度 + 指标守护 + 自动回滚后放开 | 方向正确，但需要先建指标体系与回滚基建，属于后续独立工作，不是本阶段「顺手打开」 |
| 删掉实验室代码，只留文档 | 丢失确定性的候选生成与评估链路，也丢掉后续灰度的载体 |

## 后果

**收益**：不会在证据不足时改变用户的学习路径；熔断本身是正确的 fail-closed 设计；
保留了候选/历史版本与评估链路，灰度基建就绪后可直接接上。

**代价**：作为「自进化学习系统」叙事，生效环节缺失使闭环断在最后一步；
面试若只讲「我有 evolution 实验室」而不讲熔断，会被追问击穿。

## 表述口径

> 熔断不是没做完，是刻意不开。我的评估是离线投影、不是在线实验，样本量不足以证明
> 策略能提升得分率或复测率；与其用投影结论污染个人归因，不如保持关闭，
> 等小流量灰度、指标守护和自动回滚齐备后再激活。

## 复核触发条件

具备「小流量 workspace 灰度 + 得分率/复测率指标守护 + 自动回滚」后，
新建 ADR 取代本文并更新 `KNOWN_ISSUES.md` B5 的状态。
