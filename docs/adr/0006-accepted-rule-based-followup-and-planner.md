# ADR 0006: 追问建议与学习计划保持确定性规则（B6）

- 状态: `ACCEPTED`（明确接受取舍，含已知代价）
- 日期: 2026-11-27
- 关联: `KNOWN_ISSUES.md` B6 / D3；代码 `../../server/app/services/followup.py`（文件头）、`../../server/app/services/planner.py`
- 决策者: Lueyu

## 背景

`followup.py` 文件头明确写着：「LLM 不参与——追问建议必须稳定可复现」。
实现是按作答结果把「下一层考察点」归入 7 类 Gap
（Concept / Mechanism / Application / Boundary / Trade-off / Expression / Verification），
每题最多 2 条且都附 `why`；`planner.py` 从 rubric 缺失项确定性生成学习任务，
文件头写明「Plan from observed answer gaps, never from absence of domain evidence」。
`KNOWN_ISSUES.md` B6 已把「纯规则、无个性化排序」标为 `ACCEPTED`。

## 决定

**追问建议与学习计划的主干保持确定性规则，不引入 LLM 生成或 LLM 个性化排序。**
理由与 ADR 0002 一致：学习路径必须可复现、可解释、可归因到具体失分项。
难度校准（`KNOWN_ISSUES.md` D3）先行；在难度未标定前引入排序，只会把
「千人一面」换成「不可复现的千人千面」，并不能提高「按失分学习」的精度。

## 备选方案

| 方案 | 放弃理由 |
|---|---|
| LLM 直接生成学习计划 | 不可复现、不可归因，且会把 LLM 幻觉引入个人学习路径 |
| 规则产出候选 + 模型排序的混合个性化 | 方向可接受，但依赖 D3 难度标定与评测基线，属于后续增量 |
| 按用户历史行为做协同过滤排序 | 当前个人实例样本量太小，冷启动问题比收益更突出 |

## 后果

**收益**：输出稳定可复现、每条建议可解释（附 `why`）、无额外 LLM 成本与漂移；
与评分证据链（ADR 0002）使用同一套确定性信号。

**代价**：确实「千人一面」，难度无校准（D3）限制了「按失分学习」的精度；
个性化是学习产品的核心卖点，这一取舍需要在复盘时主动说明而不是回避。

## 表述口径

> 学习路径我刻意放在确定性节点上：建议必须能回溯到具体失分项，且同一份作答
> 每次得到同样的结果。个性化排序不是没想过，但难度没标定之前，模型排序只会
> 牺牲可复现性而换不来精度。D3 做完之后我会用「规则候选 + 模型排序」做增量。

## 复核触发条件

`KNOWN_ISSUES.md` D3 难度标定落地并产出可对比的评测基线后，
评估「规则候选 + 模型排序」并新建 ADR 取代本文。
