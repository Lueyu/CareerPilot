# ADR 0007: 代码题不执行用户代码，保持静态评审（D7）

- 状态: `ACCEPTED`（明确接受取舍，含已知代价）
- 日期: 2026-11-27
- 关联: `KNOWN_ISSUES.md` D7；代码 `../../server/app/services/project_practice.py`（limits 与虚假声明拦截）
- 决策者: Lueyu

## 背景

`coding_debugging` 题只接收文本/diff 做静态评审 + 行号引用校验，limits 明确写
「无自动执行 / CI 验证」。评分结果显式标注
`test_verification: 'NOT_EXECUTED'`、`understanding: 'UNVERIFIED'`
（`project_practice.py:250-262`），并用正则拦截「测试已通过 / all tests have passed /
CI 通过了」类虚假声明；回答还必须引用本次快照源码的直接行号，用户说明或日志不能冒充源码。
`KNOWN_ISSUES.md` D7 已把该项标为 `ACCEPTED`。

## 决定

**不执行用户提交的代码，评分证据链明确标注未执行。**
在个人实例里运行不可信代码的安全成本（隔离、网络、资源、逃逸面）高于当前收益；
与其给出「跑过了」的暗示，不如诚实标注边界并保证证据可审计。

## 备选方案

| 方案 | 放弃理由 |
|---|---|
| Docker 一次性容器 + 网络禁用 + CPU/内存/时限 + 只读挂载 + 输出限额 | 方向正确，但需要受控执行环境与运维面；属于后续独立增量，不是静态评审顺手加的功能 |
| 本地直接跑测试命令 | 不可信代码 + 个人实例数据同机，安全不可接受 |
| 让 LLM 判断「这段代码能不能跑对」 | 把未验证的结论伪装成验证结果，直接违反 ADR 0002 |

## 后果

**收益**：诚实标注边界、证据可审计、不会把静态评审包装成动态验证；
无逃逸面与资源滥用风险；与 ADR 0002 的 fail-closed 证据链一致。

**代价**：代码能力的最终证据是「能跑对」，静态评审无法验证正确性；
这是能力上限的真实缺口，不能靠话术抹平。

## 表述口径

> 我的评分证据里明确写了 `NOT_EXECUTED`，不会把静态评审说成跑过测试。
> 沙箱执行（一次性容器、禁网、资源限额、输出限额）是受控环境就绪后的增量，
> 执行结果会进入同一条 rubric 证据链；现在选择不跑，是因为在个人实例上跑
> 不可信代码的代价高于收益。

## 复核触发条件

具备隔离执行环境（一次性容器、网络禁用、CPU/内存/时限、只读挂载、输出限额）
并把执行结果接入同一 rubric 链路后，新建 ADR 取代本文并更新 `KNOWN_ISSUES.md` D7 的状态。
