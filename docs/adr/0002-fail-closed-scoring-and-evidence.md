# ADR 0002: 评分与证据链 fail-closed

- 状态: `ACCEPTED`（记录既有实现）
- 日期: 2026-11-27
- 关联: `KNOWN_ISSUES.md` B5 / D7 / C5；代码 `../../server/app/services/llm.py`（文件头 PRD）、`../../server/app/services/evolution.py`（文件头）、`../../server/app/services/project_practice.py`、`../../server/app/config.py`
- 决策者: Lueyu

## 背景

产品的核心承诺是「用真实作答找出差距、按失分项学习，再以独立新题验证改进」。
评分结论与个人归因一旦被 LLM 幻觉、样本不足或未验证的证据污染，后续所有学习路径
都会建立在错误前提上。因此「拿不到可靠证据时」必须比「给出一个看似确定的结论」更优先。

`llm.py` 文件头写明可靠性要求：所有 LLM 依赖必须有规则引擎降级，取值/网络失败返回
`None` 走规则路径，不阻塞主流程；`evolution.py` 文件头写明「样本不足 →
`INSUFFICIENT_EVIDENCE`（诚实标注，不给假结论）」。

## 决定

1. **LLM 依赖全部可降级**：配置读取失败或网络失败返回 `None`，调用方走确定性规则路径
   （`llm.py:1-11`）。规则模式（未配置 LLM）是一等公民，不是异常分支。
2. **证据不足时显式标注**：策略评估样本不足输出 `INSUFFICIENT_EVIDENCE`，不投影出结论
   （`evolution.py:1-8`）；候选来源全部是真实 DB 信号（复测完成率、任务完成率、
   历史得分率），不让 LLM 补写事实。
3. **未执行的验证不得伪装成已验证**：代码题评分证据显式写
   `test_verification: 'NOT_EXECUTED'`、`understanding: 'UNVERIFIED'`
   （`project_practice.py:250-262`），并用正则拦截「测试已通过 / all tests passed /
   CI 通过」类虚假声明；同时要求回答附本次快照源码的直接行号引用。
4. **策略激活默认关闭**：`config.py` 的 `evolution_activation_enabled` 恒为 `False`，
   与 ADR 0005 一致。

## 备选方案

| 方案 | 放弃理由 |
|---|---|
| LLM 调用失败后重试到成功 | 把可用性问题变成延迟与账单问题，且失败原因未必可重试 |
| 用模型补全缺失的评分证据 | 直接违反「证据必须来自真实作答」的产品归因原则 |
| 样本不足时输出「大概率」结论 | 看似 helpful，实际把不确定性藏进措辞，无法审计与回放 |

## 后果

**收益**：结论可复现、可审计；个人归因不会被幻觉写入；LLM 不可用时系统仍能给出
规则化输出。面试官追问「模型挂了怎么办 / 你怎么防止编造证据」时有可指向的代码路径。

**代价**：降级输出的能力上限受规则覆盖限制；自进化闭环断在激活这一步（B5）；
静态评审无法证明代码「能跑对」（D7）。

## 复核触发条件

- B5 具备小流量灰度、指标守护与自动回滚后，重新评估激活开关；
- D7 引入隔离执行环境、把运行结果接入同一 rubric 证据链；
- C5 或任何让「LLM 参与评分结论」的改动——必须先新建 ADR 说明边界，不得静默放宽。
