# 私有模型按部署预留与结算货币预算

私有模型请求必须在联网前留下独立的资金记录。业务事务回滚、删除工作空间、后台任务取消和供应商用量缺失，都不能让已经可能发生的费用消失。

## 账本及状态

`private_model_calls` 每次实际请求保存一个 UUID。记录冻结工作空间、操作来源、UTC+8 账期、provider、endpoint、model、输入与输出单价、每日限额、输入预留上界、实际发送的输出上限、预留金额和最终状态。金额使用整数 nano-CNY，一元等于十亿 nano-CNY。该表不引用 trace、message、job 或 workspace 的可删除外键。

准入和结算使用同一把 PostgreSQL 事务级全局 advisory lock。准入汇总本部署所有私有工作空间在原始账期的 `charged_nano_cny`。当前总额加上新预留超过限额时，拒绝请求并返回 429 和到下一个北京时间自然日的 `Retry-After`。锁只覆盖独立账本事务，网络调用不持锁。

首次结算把 `RESERVED` 改成 `SETTLED` 或 `UNKNOWN`。有效输入、输出用量分别按冻结单价计算；总量存在时还要与两者之和一致。输入为零、非空输出的输出用量为零、布尔值、缺失字段或矛盾数据不能证明零费用。此时 `UNKNOWN` 保留原预留。没有按时间自动退款的路径。结算重复执行不会覆盖第一次结算。

供应商报告的真实费用超过预留时，记录真实金额。只要本账期存在任何一笔超预留记录，后续准入返回 `RESERVATION_EXCEEDED`，即使日总额仍低于上限也拒绝，包括另一个工作空间发起的请求。该保守拒绝持续到下一个 UTC+8 账期；本项没有自动改账或管理页面，异常金额保留供操作者人工核对。预留是风险上界，无法替供应商保证账单绝对不会超额。

## 部署配置

`PRIVATE_LLM_DAILY_BUDGET_CNY` 是部署级每日人民币总限额，默认 `10`。它不是按空间重复发放的额度。设为零或缺失有效值会拒绝计费请求。

`PRIVATE_LLM_PRICES` 是按 provider、base_url 和 model 精确匹配的 JSON 列表。默认空列表会阻止所有已配置私有模型联网，直到操作者提供价格。价格必须来自操作者确认的供应商计价规则。`PRIVATE_LLM_MAX_OUTPUT_TOKENS` 是普通私有请求的默认输出上限，默认 4096。具体业务可以显式提供更小或已验证的上限，统一出口拒绝非法值，并实际发送 `max_tokens`。

下面仅演示格式。域名和价格都是合成数据，不能作为真实报价使用。

```json
[{"provider":"synthetic","base_url":"https://billing.invalid/v1","model":"model-a","input_cny_per_million":"2","output_cny_per_million":"8"}]
```

价格使用十进制字符串，输入与输出分开配置。显式零单价代表操作者声明免费；响应全零用量代表用量证据不足，两者不能混同。价格更改只影响新请求，历史结算读取账本中的价格快照。

## 可信归属与业务边界

`BillingScope` 是不可变的工作空间与操作标识。API 从鉴权结果构造它，后台任务从已持久化并核验归属的任务构造它。已经有 Trace 的调用使用 `Trace.workspace_id`。请求体中的 provider、model 或自选空间不能替代可信归属。provider 名字为 `fixture` 也必须经过计费闸。

预算策略异常不返回供应商失败使用的 `None`，不会触发备用或修复。聊天记录持久化预算错误码、重试时间和拒绝终态。其他后台任务保留可解释的策略失败。每次实际备用或修复请求有独立预留和结算记录。

计费异常还记录 `admission` 或 `settlement` 阶段。前者发生在联网前，调用结果为 `denied`。后者发生在已准入的请求之后，调用结果保持 `unknown`，保留 `billing_call_id`、已有 usage 和安全传输诊断，禁止备用调用。结算数据库不可用时，已经提交的 `RESERVED` 继续占用预算，不能把这类失败写成“没有联网”。

现有费用页接收可空的费用值。未知显示“费用未知”，有效零元显示 `¥0`，已知金额按配置计量显示。该兼容修正不改变页面结构。

项目自动分析复用已有 `max_model_calls` 和 `max_source_bytes`。默认分别为 40 和 2000000；旧空预算按字段与默认值合并。货币限额与这两个资源限制同时生效。

## 验证及保留边界

`tests/test_private_model_billing.py` 使用全新隔离 PostgreSQL 数据库与 `httpx.MockTransport`，验证真实预留、可见的已提交记录、模拟网络以及真实结算。已有传输单元测试显式替换计费边界，不依赖个人数据库。测试包含跨空间最后额度竞争、业务回滚、删除空间、冻结价格、幂等结算、跨午夜、取消、流失败后的用量、真实聊天备用与修复，以及 HTTP 429。

输入上界采用 UTF-8 字节数加 384 模板开销，输出按实际发送上限预留。它没有证明所有供应商的隐藏模板、工具定价、缓存和额外收费规则。真实供应商、真实账单对账、人工处理 UNKNOWN、G3 告警、连接池和 URL 出站策略均不在本项验证范围。
