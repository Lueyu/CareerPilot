# CareerPilot 学习助手如何选模型、找证据和恢复中断

面试演示可以从一次真实操作开始。在学习助手选择 Auto，先问一句概念题，再选中一个已扫描的项目，追问某个实现和对应测试。展开回复下方的「模型与运行记录」，比较首选档位、请求模型、上游报告的模型和首段正文时间。点击项目引用，检查文件、行号和版本是否支持回答。缺少代码时，再看系统向用户说明了什么。

## 一次请求的决策顺序

1. 接收消息后先保存用户输入和待生成的回复，返回消息 ID。浏览器按该 ID 订阅快照。相同提交使用请求 ID 去重。
2. 从当前会话分支取得上下文。项目问题只检索该工作空间选中的项目，区分用户自述、分析报告和仓库观察。资料版本、所需产物和本轮问题共同决定教学任务。
3. 策略给出首选档位与原因。简单解释通常选择 Flash。需要综合实现证据、比较多个约束或生成结构化产物时可以选择 Strong。项目没有源码时，把缺口呈现给用户。模型升级无法补出缺失的事实。
4. 检查实际配置的模型、文本流能力、上下文和输出预算，才发起请求。记录首选、首次实际调用和最终调用的档位。一个档位可能未配置，两个档位也可能指向同一物理端点和模型。注册版由服务端代理控制可用模型，独立上游使用自己的连接和凭据。
5. Auto 最多调用两次，两次共用截止时间和输出预算。可恢复故障发生在普通正文发布前时，才允许尝试另一可用模型。显式结构化产物在发布前校验，修复也消耗同一份重试额度。手动选档一次只调用所选档位。已经显示的普通正文保留，失败可由用户重试。每次尝试分别记录请求模型、上游报告、用量和错误类别。

确定性策略省掉了一次分类模型往返，可以用同一输入重放一次决策。代价是中文省略、专业术语和多轮指代会导致误判。如果将来引入学习型分类器，可以保持档位资格校验、预算、失败处理和 trace 契约，独立比较意图分类器的收益。

## 怎样判定资料真的被找到了

本地绑定的代码按内容哈希标记版本。注册用户没有本地检出目录时，可检索本账户已保存、带版本的扫描材料。查询结合代码标识符、文件路径、中文词和英文字段，排序时兼顾定义、调用和测试。每次最多返回八段。过期、内容哈希不符、超出扫描范围或缺少材料时，都可能留下证据缺口。代码摘录只表示仓库里出现了对应实现，个人贡献需另有自述或履历证据。

评测的一个相关项由目标文件和指定行共同定义。同一个正确文件，引用错行也不得分。对每个有答案的问题，先计算前 K 个引用覆盖了多少个相关项，再按问题等权平均，得到宏平均 Recall@K。MRR 只看第一个有效引用的倒数排名。对于确实没有答案的问题，另算系统能否返回空引用，防止通过多给材料制造虚高的召回率。

## 怎样量首字时间

| 观察位置 | 计时起止 | 对应问题 |
| --- | --- | --- |
| 上游模型 | 发起模型调用到收到第一段非空正文 | 模型什么时候开始给答案？ |
| 服务端 | 开始本次调用到服务端放出第一段可显示正文 | 校验和流处理耽搁了多久？ |
| HTTP 客户端 | 提交消息到 SSE 收到第一段可显示正文 | 用户设备什么时候拿到答案？ |
| 浏览器 | 点击发送到动画帧中正文进入可视区域 | 用户什么时候能看到答案？ |

建连、心跳、空白和模型推理片段都可能早于回答正文。另记整轮到终态的耗时、失败及超时，避免只给成功请求报一个漂亮数字。回复详情内的毫秒数来自服务端。浏览器指标需要单独实测。

操作方可为支持该协议的 Flash 模型设置 `STUDY_FLASH_THINKING=disabled` 或 `enabled`。未设置时遵循供应商默认，Strong 使用自己的配置。注册部署的模型代理只转发受支持的参数。不同思考配置会同时影响速度、用量和回答内容，比较时需报告两侧配置。

本地注册网关使用 `--use-personal-model` 时，Flash 优先采用显式 `STUDY_FLASH_MODEL`，否则采用当前生效的模型。Strong 需要 `STUDY_STRONG_MODEL`；若使用独立连接，还需一并提供该连接的 URL 和凭据。模型代理保留独立凭据，租户仅获得访问自己代理的身份。两个档位落在同一上游地址、模型名也相同时，切换凭据仍只算同一个重试目标。手动 Strong 可以继续使用自己的凭据。

## 恢复与运行边界

- 浏览器断线后按消息 ID 重连。若流仍不可用，读取已经保存的会话直到终态。整个恢复过程只读，避免重复生成与计费。
- 数据库存储生成尝试编号、阶段和草稿。写入受尝试编号与租约约束。进程中断后，读取方可把过期尝试收敛到可重试状态。运维可以查看草稿；用户主动重试时会启动新的尝试。供应商是否已经扣费可能未知。
- 每一轮后台调度都给评分、笔记、项目各一次服务机会，避免连续评分把后两类一直排在队尾。耗时任务仍会占用 worker，其吞吐和尾延迟需要按混合负载测量。
- 当前评测覆盖本地回环、独立数据库、固定工作负载和合成材料。真实招聘岗位的回答偏好、高并发、多地域网络、供应商账单和生产可用性需要各自的证据。

## 面试追问

### 本次测到了什么

2026-11-24，以开发基线 `70660b2` 与策略 `study-auto-v2.2` 做配对比较。实现者依据主集的汇总反馈修改过策略。独立评测代理另行编写并冻结了 24 道跨岗位新题，在策略定稿前对实现者隐藏题目和结果。两组都是合成数据，每个岗位只有少量样本。

| 指标 | 基线 | v2.2 | 样本与含义 |
| --- | ---: | ---: | --- |
| 初选档位命中 | 23/44 | 28/44 | 原始题集，复杂题从 2/10 到 4/10 |
| 跨岗位盲测命中 | 12/24 | 19/24 | 运营、产品、财务、设计、招聘、后端各 4 题 |
| 跨岗位 Macro F1 | 0.333 | 0.782 | 两档等权。新策略选对全部 12 道 Flash 题、7/12 道 Strong 题 |
| 资料 Recall@3 / @8 | 51.5% / 54.5% | 73.5% / 78.0% | 22 个有答案的问题，36 个文件及行号目标 |
| MRR | 0.439 | 0.761 | 按第一个有效引用排名计分 |
| 没有答案时返回空引用 | 3/6 | 4/6 | 新版仍有两次给出无关引用 |
| HTTP 首段正文 p50 / p95，首次对照 | 14.17 / 18.83 秒 | 12.80 / 17.90 秒 | 每版 10 次真实模型调用，两个固定问题各五轮 |
| HTTP 首段正文 p50 / p95，复跑 | 10.15 / 14.28 秒 | 10.92 / 18.06 秒 | 相同提示与次数，候选代码为 `21fdf5e` |
| 整轮耗时 p50，复跑 | 11.20 秒 | 12.31 秒 | 从 POST 消息到 SSE 终态，两侧均完成 10/10 |
| 供应商报告总 token，复跑 | 5,242 | 5,414 | 默认生成策略和实际档位有所变化，货币账单未知 |

两端都在本机，按轮交替先后顺序，候选 Flash 显式关闭思考。复跑时概念题的首段正文 p50 从 10.15 秒降到 9.73 秒，取舍题从 10.34 秒升到 13.44 秒，候选在这五次都走 Strong。两轮对照的总体变化方向相反，当前证据不足以声称整体提速。每侧十次时，最近秩 p95 就是最大的那一次。供应商对同一请求别名报告过不同发布版本。另一次浏览器冒烟从点击到可见正文分别为 17.94 和 13.73 秒，每侧各一次。[两轮逐次测量、用量和离线指标](benchmarks/auto-20261124.json)

项目演示比两个短请求更慢。选中一份合成的排班项目扫描，追问发布逻辑和并发测试，Strong 从接收消息到服务端放出首段正文用了 42.11 秒，46.55 秒进入最终写入阶段。回答中的三处引用均落在保存的相应文件和版本范围内。长材料的实际等待时间值得在面试中主动交代。

**90 秒介绍。** 我做的是一个帮助求职者学习自己题库和项目的助手。原来的 Auto 看到几个工程词就升级，注册账户的代理还只允许一个模型，所以界面上的档位不足以证明请求真的到了对应模型。我把教学任务、可用资料和实际可调用的模型分开，给每次决策留下理由，并在预算内处理一次失败。检索评测要求引用命中真实版本里的具体行。22 个有答案的问题上，Recall@8 从 54.5% 到 78.0%。另做的跨岗位盲测从 12/24 到 19/24。最难的是避免一个指标掩盖另一个：升级 Strong 对复杂题有帮助，这批取舍题的首段正文也确实变慢。现在我可以打开一次请求，展示选择、证据、真实模型和等待时间，也能演示服务中断后如何保住已写下的回复。

**为什么同时记录首选档与实际模型？** 用户可能配置两个同名档位，预算也可能放不下请求。只统计首选档，会把分类器的判断误写成供应商调用结果。逐次调用还原了真正发生的行为；供应商返回的模型名仍属于其自报信息。

**为什么不能一出错就切模型？** 用户读到一半的措辞、结论或建议可能已经被采纳。第二个模型无法接管第一个模型的内部状态，重放也可能重复计费。发布前只允许受预算约束的补救，发布后保留部分文字和明确终态。

**为什么先用词法检索？** 这个产品同时面对文件路径、精确代码符号和中文自然语言。固定版本的摘录易核对，也能离线评估。改进应看哪个分层仍然漏检，例如中文改写或间接调用，再用同一标注对比混合检索和重排的收益及延迟。

**下一批数据怎么收？** 在用户同意后抽样匿名真实任务，按岗位、任务难度及是否含资料分层；多人盲评回答正确性和引用支持度。冻结新题，分别测意图、实际模型、回答质量、速度和费用，再决定是否调整默认档位。
