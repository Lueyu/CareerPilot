## 背景与目标

- CareerPilot（agent-interview）本地运行：考试、诊断、评分、画像、学习、项目、记忆、Worker 均已有实现；本轮做增量学习闭环，不重写产品、不覆盖考试 #25、不切换个人模型配置、不开放公共发布。
- 设计文档（2026-11-17）目标：把**考试、记忆、概念练习、真实项目实践、反馈、复测**连成连续学习过程，而不是增加几张页面或再生成一份静态学习清单。
- 设计核心流程：`有效考试记录 → 具体诊断 → 学习目标 → 小组练习/项目实践 → 提交 → 检查反馈 → 修改/换教学方式 → 新情境复测 → 延迟复测 → 更新记忆和下一步`。
- 采用混合式路径：概念缺口先短练习；应用缺口优先项目任务；表达缺口先复述/答辩；诊断不确定先补测；同一目标不必同时做所有活动。
- 系统始终区分：完成活动、辅助下做对、独立做对、能迁移、延迟后仍会；这些不是同一个状态。
- 实现前差距（`LEARNING_LOOP_GAP_AUDIT.md`）：短练习提交与修改后再反馈、提示/完整答案/AI 辅助记录、项目基线/明确变更/代码引用检查、来源撤回/局部计划调整均缺失；学习路径页面与自动候选记忆仅部分实现。
- 前置阻塞：Project Autopilot 完整真实分析受预算阻塞；考试 #25 评分修复已有独立报告和通过的机制测试，但评分标准仍未人工校准。
- 实现原则：先完成/保存 Project Autopilot 与考试 #25 的阻塞状态，再做增量；不擅自提升预算、不伪造映射、不用合成答卷填补真实用户验收。

## 核心发现与结论

1. **单一评分源**：新增 `LearningGoal`、`LearningActivity`、`LearningSubmission` 以及项目提交的 `LearningProjectSnapshot`；提交通过既有 `Exam`、`AnswerRevision`、`ScoringRun/ScoringStep` 关联评分，反馈由已校验的逐项结果投影，不另存第二套独立成绩。
2. **PRACTICE 边界**：练习运行标记 `PRACTICE`，不执行正式考试的能力发布，不新增个人 `Evidence`、`SkillState` 或 `CompetencySnapshot`；内部练习题不进入正式题库列表、自动选题、人工选题或补题的合并目标。
   - 根因：原非正式运行拒绝自动发布；仅把 `ScoringRun.mode` 改为 `PRACTICE` 不够，claim、结果保存、发布及只读反馈都需接通（`assessment_worker.py:218`、`:258`）。
   - 决策：PRACTICE 需要独立发布分支，不能直接复用正式考试的 Evidence/SkillState/CompetencySnapshot 更新。
3. **学习页面**：沿用 `/learning/task/:id`，显示当前活动、为何安排、练习提交、最近反馈、修改入口和验证状态；历史与完整标准可展开；进入新路径不会隐式调用旧教学生成接口。
   - 注意：`GET /learning/tasks/{id}/content` 仍会同步生成教学内容，不能把它算作后台练习反馈；阅读步骤仅在浏览器内存。
4. **确定性练习框架**：每个目标先生成三个不同目的的练习框架——解释机制、结合情境、设计验证；题面要求写入对应冻结标准，标记 `deterministic_prompt_template` / `AI_DRAFT`。这是透明框架，不是已由模型生成并校准的个性化课程。
5. **提交与幂等**：提交返回 202；成功步骤、失败类别、重试和版本持久化；新修订必须关联最新提交；重复请求不重复创建；旧提交反馈留作历史但不覆盖新提交状态；评分引用必须真实存在于本版回答中。
   - 浏览器首次发现“已有 goal 但 activities 为空时没有准备按钮”，按“先补失败回归再修复”处理，随后以全新数据库重走路线通过。
6. **反馈合同**：页面把正确部分和具体缺口并列展示；反馈至少包含正确之处、待补之处（区分错误/遗漏/无法判断/表述歧义）、为什么、如何改（最小提示→可请求完整讲解）、下一步；按约束接受合理替代方案，不按参考答案逐字匹配。
   - 检查失败不等于答错；系统失败（`SCORING_FAILED`、模型超时、代码审查失败）只表示系统未能完成评估，不生成“不会”的个人结论。
7. **辅助与曝光**：提示、参考答案、已看反馈、用户声明的 AI 辅助都会保存；题库返回参考材料会记录题族曝光；正式复测排除已知曝光和已有同族答卷。
   - 独立性在提交时冻结，但仍依赖用户如实声明系统外辅助；系统无语义去重能力保证识别所有同义改写/相似模板。
8. **阅读/即时 vs 延迟**：点击阅读完成只保存进度；正式复测必须有新答卷、新评分；只有覆盖具体原项且有冻结独立性记录时才更新验证状态；即时通过不改写延迟保持；不同 Rubric 版本不直接相减来宣称进步。
9. **项目实践**：从当前完整有效报告中选择有源码依据的问题或已有机制，建立固定基线 SHA、允许路径、相关已读调用、验收条件和排除范围；默认先诊断/验证已有机制，不凭一个技术名词要求重复加功能；无完整报告或相关源码时明确阻塞，仍可先做概念练习。
10. **三种项目提交入口**：
    - 选定本地文本文件（浏览器明确选择，不接受服务器任意磁盘读取）；
    - 标准 unified diff；
    - 授权 GitHub 仓库的完整 commit SHA（不自动追踪可变 PR 头，不声称看到本地未推送修改）。
    - 服务端先展示生成的范围与 diff，再由用户确认检查。
11. **快照与只读检查**：快照保存规范化/敏感过滤后的文本、前后指纹、固定基线与来源说明；补丁只能在冻结基线上精确应用；错误基线、未知读取失败和过大输入不被静默忽略；调用模型前后不执行提交代码、不安装依赖、不运行任意命令。
    - 代码评分项的引用不仅要在答卷中出现，还必须来自快照真实源码区域；用户说明和日志中的伪行号不能冒充源码。
    - 界面区分测试文件、用户日志与实际运行，显示“代码检查已完成，运行效果未验证”；项目答辩问题目前是后续提示，尚未自动成为正式答辩考试。
12. **记忆候选**：学习事实与反馈自动保存；阶段摘要为 `LearningObservation/CANDIDATE`；可批量确认、编辑或忽略，检查候选版本和来源新鲜度；确认接受描述，不代表测评已校准。
    - 只有相关、已确认且仍有效的摘要进入后续练习上下文，并记录实际引用的记忆 ID 与版本。
13. **撤回传播**：纠正/撤回记忆会使真正依赖它的目标和派生摘要进入复核状态；未完成反馈被原子取消并使旧 Worker 失效；Worker 在新外部调用前再次核对来源；已发出的外部请求无法撤回，不能承诺供应商不会收费。
14. **计划调整边界**：反馈只调整未开始的必要活动，保留已开始工作；用户可缩短、暂停、恢复、跳过并留下理由；操作本身不影响能力；连续需要修改时，下一步建议改用小反例解释，同时保留原评分要求。
15. **自进化仍为候选**：真实重复困难事件可形成教学改进候选；离线评估只核对版本/来源关系，试用效果样本仍为 0、效果未知；不把考试选题投影或同题练习当作教学效果；策略自动激活继续关闭。
16. **测试与验收分层**：代码实现、测试夹具/真实进程验证、真实模型验证、真实用户表现验证是四种不同结论；夹具、空答卷规则、历史其他模块成功或自动生成的“用户答卷”均不能填补真用户表现验收。
17. **设计验收矩阵**：T01–T28 覆盖评分失败不生成个人失败结论/能力升级、目标可追溯到具体答案修订与 criterion、重复提交不重复计分、辅助记录、引用校验、项目基线/未运行测试/恶意内容、候选撤回、跨 Workspace、备份恢复等。
    - 设计要求多维验证状态：理解（未验证/有辅助正确/独立正确）、实践（未提交/待检查/需修改/本任务已验证）、迁移（未验证/待复测/本次通过）、保持（未到期/待复测/本次通过），不设单一“已掌握”开关。
