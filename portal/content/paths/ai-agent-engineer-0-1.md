## 这条路线解决什么问题

「会调大模型 API」和「能交付一个可靠的 Agent 系统」之间隔着一整个工程学科。这条路线把后者拆成 **8 个能力域、4 个阶段**，每个阶段有明确的"能做什么"验收标准，学完一个再进下一个。

## 能力域全景

1. **Agent 架构与规划**（权重 18%）：ReAct / Plan-then-Execute、多智能体协作、任务分解。
2. **工具调用与 MCP**（14%）：函数调用、工具设计、MCP 协议、错误处理。
3. **状态管理与 Memory**（12%）：显式状态、记忆压缩、长期记忆分层。
4. **RAG 与上下文工程**（10%）：检索质量、上下文窗口管理、重排。
5. **Agent Evaluation**（16%）：评测集、分层指标、LLM 裁判、回归测试。
6. **后端与系统设计**（12%）：异步、队列、并发控制、成本预算。
7. **可靠性与安全**（12%）：幻觉治理、注入防御、幂等与重试。
8. **部署与可观测性**（6%）：灰度、回滚、追踪、告警。

> 权重来自对目标岗位 JD 的种子分析（P5 级），是假设不是统计结论，但作为学习顺序的优先级参考足够用。

## 阶段一：跑起来（第 1-2 周）

目标：写一个能调工具的最小 Agent，并让它稳定跑 100 次不出崩溃。

- 学完 ReAct 循环：Thought → Action → Observation 怎么写、在哪写。
- 用官方 SDK 的 function calling 接入 2-3 个真实工具（搜索、计算、文件读写）。
- 给每次调用加超时、重试、幂等键——**第一周就建立工程习惯**。
- 验收：你的 Agent 能完成「查三个城市天气并给穿搭建议」这类三步任务，失败可重放。

## 阶段二：让它靠谱（第 3-6 周）

目标：从 Demo 到能用的原型，把不可控变可控。

- 记忆与状态：显式状态存储，别依赖对话上下文；学会记忆压缩。
- RAG 基础：分块、embedding、Recall@k / MRR 怎么算、怎么排查召回差。
- 错误分类：哪些错该重试、哪些该转人工、哪些该直接失败。
- 验收：给系统加 20 个测试用例（含 5 个边界），通过率 ≥ 90%，失败原因可定位。

## 阶段三：让它可评估（第 7-10 周）

目标：能证明「改了之后没有变差」——这是业余和专业的分水岭。

- 建评测集：从真实失败 case 沉淀 50-100 条，覆盖正常/边界/对抗。
- 分层指标：任务完成率、工具调用准确率、延迟、成本分开看。
- LLM 裁判：怎么写 prompt 让打分稳定（锚点、few-shot、双盲）。
- 回归测试：每次改 prompt / 换模型，跑一遍评测集再合入。
- 验收：任何一个改动，你能拿出前后对比数据。

## 阶段四：让它可交付（第 11-16 周）

目标：生产级——别人敢用、你敢睡。

- 可观测性：每次执行有 trace，每个决策有记录，成本可核算。
- 灰度与回滚：新策略小流量先试，指标变差自动回退。
- 安全：注入防御、输出过滤、私有数据不外泄。
- 验收：一次真实发布——灰度 → 观察 → 全量（或回滚），全程有数据支撑。

## 学习原则

- **证据优先**：不要自评「我懂了」，用测试通过率、评测分数说话。
- **缺什么学什么**：先做一次诊断，找到最大差距，优先补权重高且差距大的域。
- **每个知识点走五步**：类比 → 小例子 → 原理术语 → 结合自己项目实践 → 用新问题验证。

## 自测问题

- 你能说清 ReAct 的 observation 为什么要显式写入状态吗？
- 你的 Agent 上线后 P95 延迟劣化 30%，第一步看什么指标？
- 为什么评测集要包含对抗样本？
- 幂等键解决什么问题？不带幂等键的重试会发生什么？
